# 多模态输入 — 架构设计

> 状态：v1.6 · 2026-09-18 · 含 ADR-001~006 · ADR-003 修订（2026-09-18 用户裁决：能力以显式定义为准，未定义按不支持处理，废除"未知放行"） · 留档存储归属对齐持久化域 ADR-007（SDR-004，2026-09-16） · §5.2 占位构造器补压缩退场成因、四成因口径同步（2026-09-16 审查修复批，对齐 SDR-003） ·
> 本文描述多模态输入域的**终态技术设计**（机制、数据流、接口形状）；动机只保留抽象问题陈述，现状证据与代码事实见 [multimodal-input-context.md](multimodal-input-context.md)，需求见 [multimodal-input-requirements.md](multimodal-input-requirements.md)。
> 基线说明：本文记录 TS 引擎已落地的机制作为 Rust 对齐基线；基线是 Rust 要达到的底线，不是 Rust 的上限。

## 1. 概念与分层

多模态输入域由六个角色组成，职责单向依赖：

| 角色 | 职责 |
|---|---|
| **媒体内容部件（media content part）** | 图片/视频/音频在消息内容中的统一表示：`image_url` / `video_url` / `audio_url`，载荷为 data URL（或远端 URL）+ 可选隐藏属性 `id`（承载留档路径） |
| **媒体持久化层（prompt persistence）** | 用户提交媒体的原始字节留档（存入全局内容寻址附件存储，持久化域 ADR-007——跨会话共享去重、fork 不复制本体、删除不级联；TS 现状为会话目录内，待迁移）；把留档路径写进内容部件的 `id` 字段；入口格式门控（不支持的图片格式替换为文本通知） |
| **模型能力目录（model capability）** | 每个模型一条输入模态能力记录（`image_in` / `video_in` / `audio_in` 布尔）；**以显式定义为准，未定义按不支持处理**（ADR-003 修订） |
| **消息投影管线（message projection pipeline）** | 每次模型请求组装时对历史做只读投影：能力缺口适配（本域核心）、视频引用解析等；**投影永不写回会话历史** |
| **能力缺口注入器（capability gap injector）** | 回合级系统提示：检测"模型缺模态 × 用户消息含该模态"的交集，注入能力导向的委派建议（引导模型在可用模型清单中自选支持该模态的模型派发，并列出留档路径） |
| **媒体工具与委托通道** | 读媒体工具按模态能力门控注册；子代理派发的模型覆盖参数与能力标注，构成提示式委托的执行面 |

核心不变量：

1. **会话历史是唯一真相**——模态适配、降级、剥离全部发生在"本次请求的投影"上；被替换的是发给服务商的那份内容，不是历史本身。同一历史可对多个模型重复投影出不同请求。
2. **留档路径是恢复句柄**——剥离必须伴随"原件在哪"的信息；没有路径的剥离剥夺了委托的可能性（上游不能只说"没有图"，还要说"图在哪"）。
3. **能力声明语义（ADR-003 修订）**——能力以显式定义为准（用户设置最高优先，外部目录次之，名字推断仅在无声明时兜底）；**未定义 = 按不支持处理**（请求前剥离 + 占位 + 注入提示）。旧"未知放行"语义废除：把未定义当支持放行会造成可预期的失败与误导性恢复（session-8999 证例），而委托链路（留档句柄 + 子代理读图）使"剥夺"始终可恢复。

## 2. 数据流

```text
用户提交媒体
  │  (web: 上传凭证 → 服务端解析并留档;  TUI: 粘贴压缩 → 原件留档;  工具读图: ReadMediaFile)
  ▼
媒体内容部件 { type:'image_url', url: dataURL, id: 留档路径 }   ← 进入会话历史（含图片本体）
  │
  ▼  每次模型请求组装（消息投影管线）
  ├─ 能力缺口（含未定义，按不支持处理）→ 能力缺口适配：image_url ⇒ 占位文本（省略声明 + 留档路径 + 三条恢复指引）
  └─ （体积超限/格式被拒的上游错误 → 降级/剥离投影重试，同样只动投影）
  ▼
回合上下文（新回合首步）→ 能力缺口注入器：可行性扫描 + 委派建议 + 留档路径提取
  ▼
主模型读到占位文本/提示 → 自主派发子代理（指定支持该模态的模型）→ 子代理用 ReadMediaFile 读留档路径
```

## 3. 媒体内容部件与入口

### 3.1 引擎内表示

内容部件判别联合中的三个媒体变体，形状同构：

```ts
{ type: 'image_url', imageUrl: { url: string; id?: string } }
```

- `url`：几乎总是 `data:<mime>;base64,<bytes>`；远端 `https://` URL 原样透传。
- `id`：**隐藏的留档路径通道**。由媒体持久化层在入口写入（仅文件系统路径形态有效；协议式标识如 `ms://` 会被读取方拒绝），能力缺口适配、压缩说明、子代理读图全部消费它。它不进入服务商请求。

### 3.2 消费端 wire 形态（REST / RPC）

图片内容的 `source` 三态：`url`（远端地址）/ `base64`（`media_type` + `data`）/ `file`（`file_id`，上传凭证）。通用附件用 `file` 部件（`file_id` + `name` + `media_type` + `size`）。

### 3.3 入口分派（服务端解析职责）

| 入口 | 处理 |
|---|---|
| `file`（上传凭证）图片 | 读字节 → MIME 嗅探门控 → 压缩 → 转 base64 部件并写入 `id: 原件留档路径` |
| 内联 base64 图片 | MIME 门控 → 压缩 → 原始字节留档 + `id` 写路径（**无论是否压缩都留档**，这是能力缺口恢复的句柄） |
| `url` 图片 | 按扩展名门控后原样透传 |
| 任意 `file` 附件 | 物化到全局内容寻址附件存储（持久化域 ADR-007；TS 现状为会话附件目录，待迁移），替换为"附件已保存到某路径，用读文件工具打开"文本 |
| 不支持的图片格式 | 替换为格式说明文本 + 原件留档，不进入后续请求 |
| 视频 | 解析为 provider 可接受的引用（或内联 base64 兜底） |

终端（TUI）入口：粘贴字节 → 入口压缩（可配最长边）→ 原件留档 → 占位标记 `[image #N (宽×高)]` 进输入框 → 提交时展开为 base64 部件（有压缩时附压缩说明行，说明中含原件路径）。@ 引用插入纯文本路径，由模型用读媒体工具读取。

### 3.4 媒体压缩预算体系（入口 / 读时 / 上下文估值）

三层预算各管一段、互不越权；**数值的规格归属分层**（避免双源漂移）：

| 预算层 | 生效位置 | 角色 | 数值口径与规格归属 |
|---|---|---|---|
| **入口预算** | 消息进入引擎时（web 服务端提交解析 / TUI 粘贴） | 限定单张图片进入会话历史（进而进入每次请求投影）的体积——媒体对上下文与请求体的**字节压力上界**（E8 的"单图体积由入口压缩限定"） | 本域口径：单图字节预算 3.75 MB、最长边默认 2000px（TUI 可配 `maxEdgePx` 覆盖）、安全解码上限 64 MB。现状数值以 [context](multimodal-input-context.md) §2.1–2.3 代码证据为准；入口与读时共用 v2 压缩模块（`agent/media/image-compress.ts`） |
| **读时预算** | 读媒体工具读文件时 | 限定单次工具读图交付给模型的体积；字节档比入口预算**更紧** | **规格归属工具调用域**（[tool-calling-builtin-tools.md](tool-calling-builtin-tools.md) §ReadMediaFile 非功能）：默认压缩目标 256 KB + 最长边 2000px，`full_resolution` ≤3.75 MB，`region` 裁剪全保真。本域只引用，不复制数值 |
| **上下文估值** | 摘要压缩压力评估时 | 媒体对"记忆压力"的贡献（US8.1） | 每媒体部件按固定 2000 token 估值（与分辨率/字节无关；证据见 context §6）；按模型视觉定价细化为可选增强（SDR-003 裁决⑤） |

行为契约（压缩视图与原件的关系）：

1. **模型默认看到压缩视图，原件是保真升级源**：入口压缩版进入消息并驻留历史；读图工具读的是留档原件、但按读时预算**现压交付**（不持久化压缩副本）——保证单一真相（只有原件被持久化）、按当前模型预算适配（入口版绑定的是提交当时的预算）、保真可升级（`region` / `full_resolution`）。工具侧契约见工具调用域。
2. **恢复路径预算闭环**：能力缺口与压缩退场（5.5）后的重读——自行读或委托子代理读——默认同样拿到读时预算的压缩视图，恢复路径不引入新的字节压力；需要细节时用 `region` 升级。
3. **压缩与留档正交**：入口压缩只改写消息内的视图；留档（ADR-004）无条件保存原始字节，**无论是否压缩都留档**——两份副本独立存在。

## 4. 模型输入能力目录

能力记录（媒体相关视图）：

```ts
interface MediaInputCapability {
  readonly image_in: boolean;
  readonly video_in: boolean;
  readonly audio_in: boolean;
}
```

**未定义的收敛**（ADR-003 修订）：`MediaInputCapability` 是纯布尔视图，不再有第三态——无任何声明且推断无意见的模型，其能力记录为全 false（与 TS 内核 `UNKNOWN_CAPABILITY` 的消费语义一致：投影器与注入器都按 `!caps[x]` 处理）。

**能力解析（优先级制，声明为王）**：

1. 用户声明（最高优先）：持久化配置中模型条目的显式能力定义——勾选 = 支持，未勾选 = 不支持。显式声明双向压过推断（用户说不支持，名字带 marker 也不翻案）。
2. 外部目录数据（models.dev 形态）：`modalities.input` 数组换算为显式 boolean；用户未覆盖时作为条目的默认声明。
3. 协议前缀推断目录：各协议适配器对已知模型名前缀的能力表（含"推理系列不支持图片"这类反向标注）——仅在条目无任何声明时兜底。
4. 以上皆无 → 全 false（未定义 = 不支持）。

判定结果挂到 LLM 对象的能力字段，随模型切换刷新；子代理按各自裁定的模型取各自能力（模型裁定链见术语 M5）。

## 5. 请求前适配（本域核心机制）

### 5.1 消息投影管线中的能力缺口适配步骤

请求组装管线含两个内置投影步骤，按序执行：视频引用解析 → **能力缺口适配**。后者逻辑：

1. 计算不支持模态集合（`image_in/video_in/audio_in` 为 false 的项——含未定义模型的全 false 收敛）。
2. 逐消息逐部件替换：命中不支持模态的媒体部件 → 占位文本部件；无媒体或全部支持 → 原数组引用直返（零分配）。
3. 投影纯函数：不修改输入消息；只有受影响的消息被替换为新对象，其余保持引用。

该步骤对全部请求形态生效（正常 / 严格 / 媒体降级 / 媒体剥离），适配发生在协议编码之前。

### 5.2 占位文本（四种成因统一构造器）

| 成因 | 内容 |
|---|---|
| **能力缺口**（有留档路径） | 省略声明 + `The original <kind> has been saved to: <path>` + 三条恢复指引：① 派发专用多模态子代理（默认模型已支持该模态，免模型覆盖），让它 ReadMediaFile 读该文件；② 派发通用子代理并设模型参数为支持该模态的模型（参阅代理工具说明中的可用模型清单），让它 ReadMediaFile；③ 无任何多模态模型可用时，如实告知用户并建议换模型或文字转述 |
| 能力缺口（无路径） | 仅简短省略声明 |
| **压缩退场**（有留档路径；SDR-003 新增） | 省略声明 + 路径 + 认知声明：既有结论是解释而非证据，原文未必被逐字记录，核对请重读路径（L1）；替换物完备性另依赖 L2 读图约定（工具调用域 F-16） |
| 体积超限 | 省略声明 + 路径（可得时）+ "重读文件即可查看"提示 |
| 格式被拒 | 省略声明 + 路径（可得时）+ 转换指引提示 |

路径有效性：仅文件系统路径形态（绝对/相对且含分隔符、非协议头）被采信为留档路径。

### 5.3 上游拒绝的降级链

- HTTP 413 → 先按"媒体降级"投影重试（较早消息中的媒体被替换）；仍超限 → 按"媒体剥离"投影重试（按首次被拒请求的剥离快照精确执行，本回合后续重放保持该投影）。
- 图片格式类错误（解码/编码/MIME 拒绝，**不含**"模型不支持图片输入"类能力错误）→ 直接媒体剥离投影重试。
- 能力型错误不在此列：能力按声明收敛后不允许走到上游（5.1 已拦截）。残留通路仅剩推断误报（名字带 marker 但实际不支持）触发的上游能力拒绝——按普通错误上抛，提案 P-4（能力学习）保留为该残留的增强。

### 5.4 视频投递通道（服务商差异）

视频引用按**三级回退**投递：provider 上传通道 → 内联 base64 → 留档路径文本标签（`<video path>` 形态）。声明 `video_in` 的模型若其协议既无上传钩子又不支持内联，视频最终以路径引用文本进入对话（模型无法直接观看）；需要真正读取视频内容时，读媒体工具对该类 provider 按设计报错（明确告知该服务商不支持视频投递），不静默失败。该差异与模态能力缺口是两回事：能力缺口是"模型收不了"，投递通道缺失是"服务商送不进"。

### 5.5 媒体退场：压缩时机与恢复句柄（E8 · 终态设计，经 SDR-003 修订）

满足需求 E8 的机制设计（需求裁决见 SDR-002/SDR-003）：

1. **退场时机 = 压缩边界**：媒体随摘要压缩退场——被摘要的头部媒体 → 文本标记，最近尾部媒体原样保留。两次压缩之间媒体持续在场，**不引入任何逐轮改写历史的机制**。理由（前缀缓存经济性）：缓存按"从首个变更点到结尾"失效，滚动退场/主动驱逐每轮付窗口回合量的全价重写，而老图保留的代价仅每图每轮 0.1× 缓存读；压缩本身整体重写历史（缓存必灭），退场搭车边际代价为零（工程先例：工具调用域 F-15 的工具集稳定有序即同源原则）。
2. **文本化携带留档路径**：压缩文本化（摘要输入的媒体标记与摘要指令）必须携带原件留档路径——路径是压缩后模型重读老图的唯一句柄（现状缺口：v1 `[image]` 标记无路径、v2 fullCompaction 无媒体专项处理，见 context §6）。标记同时携带认知声明：既有结论是解释而非证据，原文未必被逐字记录，核对请重读路径（L1）。
3. **413 反应式降级链保留为字节防线**：压缩触发是 token 维度（媒体按固定 2000 估值计入，现状），413 是字节维度，两者不同轴——大上下文窗口模型可容纳数百图（token 维）但请求体早已超限（字节维）。5.3 的媒体降级 → 媒体剥离链不可删，作为请求体超限的反应式兜底（罕见触发，缓存代价可忽略）。
4. **与能力缺口路径同构复用**：退场状态与能力缺口状态共享占位构造器（`buildMediaPlaceholder`，四成因：能力缺口 / 压缩退场 / 体积超限 / 格式被拒）、留档路径句柄、`ReadMediaFile` 重读通道；差异仅在转换时机（压缩时 vs 入场时）与指引分叉（自己重读 vs 委托子代理）。E8 净增量 = 压缩文本化带路径 + 请求级媒体观测 + 同构确认，**无新退场机制**。
5. **观测（US7.5）**：`llm.request` wire 记录追加请求级媒体数量/字节字段（主落点，持久可回放）；引擎日志输出结构化行（实时诊断），替换类事件按签名去重（沿用投影修复日志先例）；server 事件流可透出（web 展示可选）。不进 `usage.record` Op（累积型 token 模型）与遥测。
6. **file-id 文件引用（提案 P-8，低优先级）**：服务商支持时（DeepSeek Files API 形态）图片以稳定文件 id 入史——缓存永续 + 零字节跨网，退场问题对该类服务商消解；服务商专属能力，非通用解。
7. **读图证据约定（L2，工具调用域落地）**：读媒体工具说明要求对含文字的图片把决定性内容（报错原文、代码片段、关键数字）逐字引用进回复——证据在第一时间沉淀为文本，退场后替代物完备；L3（退休转录，专门提取调用）为可选增强，默认关。

## 6. 能力缺口注入器（回合级提示）

注册为上下文注入提供者，仅新回合首步触发：

1. 取主模型能力与最后一条用户消息。
2. 交集判定：模型缺模态 × 消息含该模态（含真实媒体部件，**或**客户端替换出的"图片已省略/已留档"文本通知——两种形态都算"用户给了图"）。
3. **可行性检查**：模型目录快照中存在任一支持缺口模态的模型才注入（不说做不到的空话）；快照为空（standalone 流无法验证）时不压制，按可行处理（permissive）。
4. **子代理点名**：扫描子代理档案，覆盖缺口模态的 profile 名仅作为括注便利信息随主文案出现（不再是指令主体——选型由模型自判）。
5. **路径提取**：从用户消息文本部件中按留档标记（`saved to:` / `saved at "…"` / `Attached file "…" (mime, bytes): path` 等形态）提取路径，随提示列出并指示子代理读这些文件。
6. 产出提示文本为**能力导向**格式（TS `capabilityGapInjection.ts` 对齐）：主句声明缺口并指向 `model` 参数与代理工具说明中的 "Available models" 清单，由模型自判选型；覆盖缺口模态的 profile 名仅作括注便利信息；无任何可行模型时不产出一条（"告知用户"由占位文本第 ③ 条恢复指引承担）。示例（image 缺口 + 留档路径 + media profile 覆盖）：

   > Your current model does not support image input, but the user's prompt contains this modality. To process the content, image: dispatch a subagent and set its model parameter to a model that supports image input (see the "Available models" list in the Agent tool description; e.g. the 'media' profiles' default models already support it). The attachment is saved at "/tmp/screenshot.png" — instruct the subagent to ReadMediaFile on that path.

## 7. 媒体工具门控与委托通道

- **读媒体工具（ReadMediaFile）**：仅当模型能力含 `image_in` 或 `video_in` 时注册；说明文案按实际模态裁剪；模型无图片输入能力时调用返回错误并指引派发子代理（接口规格见工具调用域 [tool-calling-builtin-tools.md](tool-calling-builtin-tools.md)）。普通读文件工具对图片文件硬拒绝并指引改用读媒体工具。
- **代理工具（Agent）**：输入含模型覆盖参数（必须为已配置模型，非法值校验拒绝）；子代理模型按裁定链裁定（显式指定 → 类型默认 → 派发者当前模型）。工具说明中每个可用模型带模态能力标注（`image_in` → vision）、每个子代理档案带"默认模型及其能力"——**这是占位文本指引②成立的信息基础**：主模型在派发前就能查到哪个模型看得懂图。可用模型清单以"带用途描述"为收录门槛（无描述的已配置模型对 LLM 不可见），指引②的能力标注作用面以此清单为准。
- **子代理档案**：用户可自定义档案并绑定默认模型（如出厂外的 media-reader 形态）；注入器点名逻辑按能力动态发现，不依赖固定档案清单。

## 8. 消费端门控

- **终端（TUI）**：提交前校验——带图片附件且当前模型已知无 `image_in` → 阻止提交并提示；能力数据缺失时放行（不误拦）。粘贴入口的提示条同样按能力显隐。
- **Web**：无发送前能力预检，带图消息无条件提交；失败走通用错误提示（含服务商消息）。引擎侧 5.1 适配是两种消费端共同的最终保障。

## 9. 观测与非功能截面

- 观测/钩子序列化：媒体部件替换为体量标记（`size_bytes`），不灌 base64。
- 最近输入摘要/标题派生：图片文本化为 `[image]`。
- 会话日志（wire journal）与转录投影的形状换算：引擎 `image_url` ⇄ wire `image{source{kind}}`；服务端回显以 `<image path="…">` 文本标签形态出现在转录中，消费端反解为附件渲染。
- 路径安全：留档路径经与读文件工具一致的共享路径解析（越界拒绝）。

## 10. 设计决策记录（ADR）

### ADR-001 提示式委托，而非引擎自动改道

- **背景与动机**：模型缺模态而对话含该模态时，存在两种出路——引擎检测后自动改道（把请求路由给有能力的模型/子代理，结果缝合回主对话），或把出路信息提供给主模型、由其自主派发。自动改道保证结果可用，但让主模型失去"谁在回答/为什么"的感知，审批归属、上下文共享、结果引用全部复杂化。
- **决策**：采用**提示式委托**：请求前把不支持内容替换为带路径占位文本（指引三种出路）+ 回合级注入器点名可行子代理与文件路径，主模型自主决定派发。引擎保证的是"委托通道顺畅 + 信息充分"，不保证"必然委托"。
- **被拒方案**：引擎自动路由（保证性强但主模型失感知、审批链复杂）；硬错误中止（用户遭遇不可恢复失败，违背"带不带图都能聊"）。
- **影响范围**：US5 全部、ADR-002；未来增强提案 P-1 是对该决策的受控重开。

### ADR-002 适配发生在请求投影，永不写回会话历史

- **背景与动机**：若在消息进入历史时就剥离媒体，切换到有能力的模型后图已丢失，委托无从谈起；且人类视图将不再呈现用户当时提交的内容。
- **决策**：模态适配/降级/剥离全部是每次请求组装时的只读投影；历史与人类视图保留媒体本体。留档路径经由内容部件隐藏属性（`id`）随历史流转，投影时可零成本取回。
- **被拒方案**：入口即替换（丢失可恢复性）；每次投影后回写历史（破坏唯一真相不变量）。
- **影响范围**：US4.1、US7.1；与压缩域的"模型视图是投影"不变量同构。

### ADR-003 能力以显式定义为准，未定义按不支持处理（2026-09-18 修订）

- **背景与动机**：能力目录不可能覆盖全部自定义/新模型，原裁决为此引入"未知放行"（让服务商裁决，拒绝时走降级链）。实践证伪（session-8999，2026-09-18）：未定义模型（配置只有正面向量，无法表达显式否定）把图片原样发给 provider 被拒后，落入 413/格式降级链的"格式被拒"成因——得到的是**转换格式**指引而非委托指引，模型徒劳尝试七步。同时委托链路修复（留档句柄沙箱准入）后，"剥夺"已可恢复（子代理读图），剥夺成本与放行失败成本的天平反转。
- **决策**（2026-09-18，用户裁决）：
  1. **未定义 = 不支持**：模型输入能力必须在设置（或外部目录）中显式定义；没有定义的模态按已知不支持处理——请求前剥离（5.1）+ 占位文本 + 注入器提示 + 读媒体工具剔除。
  2. **声明优先级制**：用户显式声明（双向：勾选 = 支持、未勾选 = 不支持）> 外部目录（models.dev 显式 boolean）> 名字推断（仅无声明时兜底，正反皆可）；显式声明压过推断，不再取并集。
  3. **未知第三态废除**：`MediaInputCapability` 收敛为纯布尔；无声明的模型按全 false 消费（与 TS 内核 `UNKNOWN_CAPABILITY` 的投影/注入消费语义对齐）。
- **被拒方案**：维持原"未知放行"（session-8999 证伪——徒劳重试 + 误导性恢复指引，且依赖降级链正确分类能力型错误，实际分类为格式错误）；未知时主动探测（额外请求成本与误判面，维持原否决）；三态持久化（"未触碰 ≠ 明确关闭"，复杂化设置模型——用户裁决以修复 models.dev 数据源取代语义复杂化）。
- **影响范围**：US3.1（两态语义重写，需配套 SDR）、US4.1、US5.2（注入器触发条件从"已知不支持"放宽为"按不支持收敛"）；提案 P-4 降级为推断误报残留的增强；models.dev 目录自动填充的正确性是其数据前提（rust core + web 的该缺陷另立修复）。
- **修订记录**：2026-09-18 用户裁决，取代原决策（"能力未知时放行，已知不支持时拦截"——2026-09-16 v1.5 基线）。原裁决的"用户配置声明与目录检测取 OR"改为上述优先级制。

#### 原 ADR-003（2026-09-16，已被修订取代）

- **背景与动机**：能力目录不可能覆盖全部自定义/新模型；把未知当不支持会无谓剥夺（服务商可能完全接受）；把不支持当未知会发出注定失败的请求。
- **决策**：未知 → 媒体原样放行，由服务商裁决，拒绝时走 5.3 降级链；已知不支持 → 请求前必剥离（5.1）。用户配置声明与目录检测取 OR，保证用户声明的支持能力不会被目录缺失剥夺。
- **被拒方案**：未知一律剥离（过度剥夺）；未知时尝试探测（引入额外请求成本与误判面）。

### ADR-004 原始字节无条件留档，路径是恢复句柄

- **背景与动机**：委托的前提是子代理有东西可读。若只在压缩发生时留档，未压缩的内联/上传图片在能力缺口时就没有恢复句柄；若不留原件，占位文本只能"报告损失"而无从恢复。（纯网络地址入口现状豁免留档，见需求文档 US2.1 与提案 P-6。）
- **决策**：入口层（服务端解析 / 终端提交）对用户提交的媒体**无论是否压缩都持久化原始字节**，路径写入部件 `id`；占位文本与注入器消费该路径。路径有效性仅限文件系统形态。存储归属（SDR-004 对齐）：留档存入**全局内容寻址附件存储**（持久化域 ADR-007——跨会话共享、fork 不复制、删除不级联、引用感知回收），本域只约定留档语义与路径句柄，不约定存储位置；sha256 内容寻址路径仍是合法文件系统路径，本条句柄语义不变。
- **被拒方案**：仅压缩时留档（未压缩路径无句柄）；不留档仅记文件名（子代理无从读取）。
- **影响范围**：US2.1、US2.2、US4.1、US5.1。

### ADR-005 媒体退场：压缩时机，而非滚动驱逐（2026-09-16 经 SDR-003 修订）

- **背景与动机**：SDR-002 将媒体在场经济性升格为正式需求后，初始设计方向为"确定性预算驱逐"（最旧优先、按量子成批退场，参考外部产品 deepseek-harness 的实践）。推演发现两个否定性事实：① 前缀缓存按前缀比对计费，任何历史中部变更使"变更点之后"全部失效——滚动退场/主动驱逐每轮付窗口回合量的全价重写，省下的仅是每图每轮 0.1× 缓存读与网络字节，token 维度净亏损；② 压缩触发（token 维，媒体按固定 2000 估值）与请求体超限（字节维）不同轴，主动驱逐不能替代反应式 413 兜底，反而引入系统性缓存代价。
- **决策**：媒体退场发生在摘要压缩边界（缓存必灭时刻，边际代价零）；413 降级链保留为字节维度防线；**压缩文本化携带留档路径**（恢复句柄跨压缩存活）与认知声明（既有结论是解释而非证据）；退场状态与能力缺口状态同构复用占位构造器与重读通道。E8 净增量 = 压缩文本化带路径 + 请求级媒体观测 + 同构确认，无新退场机制。
- **被拒方案**：确定性预算驱逐（最旧优先量子成批——缓存失效系统性代价）；逐轮在场窗口（同因）；"只发一次、永不重发"（剥夺近期媒体在场价值，助手无法回看）；压缩文本化不带路径（恢复句柄断裂，用户须重发图）。
- **影响范围**：E8（US8.1/8.2）、US7.5；复用 5.2 占位构造器（新增压缩退场成因与认知声明文案要素）；压缩域联动（文本化带路径）；工具调用域 L2 读图约定（其 ROADMAP F-16）；提案 P-8。
- **登记同步（2026-09-16 审查修复批）**：压缩域联动已跨域登记至其 ROADMAP 开放项 25；本域附录 A「占位文本」与架构 §5.2/§5.5.4 的四成因口径（含"体积超限"术语统一）于本批补同步。

### ADR-006 媒体压缩预算体系：三层分权与数值规格归属分层（2026-09-16）

- **背景与动机**：入口、读时、上下文估值三层预算的数值与契约此前散落在验收条款与代码证据之间，无统一归属声明；读时参数同时存在于本域与工具调用域文档时存在双源漂移风险（需求 SDR-005 同批）。
- **决策**：§3.4 确立三层预算各管一段、互不越权：入口预算（本域口径——单图 3.75 MB、最长边默认 2000px、安全解码上限 64 MB，TUI 可配 `maxEdgePx`）限定进入会话历史的单图体积；读时预算规格归属工具调用域（本域只引用）；上下文估值按固定 2000 token/媒体部件（现状证据见 context）。行为契约三条：模型默认看到压缩视图、原件是保真升级源；能力缺口与退场后的重读默认同样拿读时预算视图，恢复路径不引入新字节压力；压缩与留档正交（无论是否压缩都留档，两份副本独立存在）。
- **被拒方案**：本域复制读时数值（双源漂移）；入口与读时不分权（消息内视图预算与工具读图交付预算语义不同，混用会互相钳制）。
- **影响范围**：§3.3–§3.4；需求范围边界与 US1.2/US8.1（SDR-005）；工具调用域 ReadMediaFile 规格（被引用方，其归属不受影响）。
