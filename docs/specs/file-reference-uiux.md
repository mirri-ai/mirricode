# 工作区文件与文件夹引用 — 交互设计（web / 桌面）

> 状态：v1.0 · 2026-10-26 · 随 SDR-007（Epic E9）建立 ·
> 本文是多模态输入域 E9（工作区文件与文件夹引用）在 web 与桌面端的**交互契约**（域内已登记的设计子文档，同 `tool-calling-builtin-tools.md` 的登记方式）：触发、候选菜单、键盘与鼠标、引用芯片、各状态的呈现规格。需求语义见 [multimodal-input-requirements.md](multimodal-input-requirements.md) §9（Epic E9）；技术机制（索引、注入、wire 契约）见 [multimodal-input-architecture.md](multimodal-input-architecture.md) §11。
> 消费端范围：web 与桌面端共用同一界面（桌面端是 web 界面的外壳），本文只描述一次。终端的 `@` 补全沿用终端界面域规格，不在本文范围。
> 术语：文件引用（MI3）的规范定义见 [glossary.md](glossary.md)；域内术语见需求文档附录 A。本文「文件夹」与「目录」同义，统一写「文件夹」。

## 0. 设计原则

1. **不打断输入**：候选菜单的一切行为（打开、更新、关闭）都不夺走焦点、不阻塞按键；检索慢时用户先看到骨架，而不是卡住的输入框。
2. **结果可解释**：候选为什么排前面，靠命中高亮 + 稳定排序规则让用户「看懂」，而不是靠猜。
3. **两个意图不混淆**：「引用这个文件夹」和「进这个文件夹找文件」是两个真实意图，用两个显式动作分别承接（Enter 引用 / Tab 进入），互不触发对方。
4. **状态诚实**：索引没就绪就说「结果可能不全」，检索不可用就说「不可用」；绝不静默变慢或静默给残缺结果。

## 1. 触发与关闭

### 1.1 触发条件

- 在输入框内，当 `@` 出现在**行首或紧随空白字符之后**、且从 `@` 到光标之间没有空白时，`@` 候选菜单进入激活态。引用芯片视为非空白字符，紧贴芯片输入 `@` 不触发（需先留出空白）。
- 电子邮件式的 `user@host` 不触发（`@` 前是非空白字符）。
- 支持引号形态 `@"a b.ts"`：引号内的空格不终止 token；用户手打开引号后菜单保持打开。
- 触发判定在每次输入时运行，菜单内容的更新有输入防抖（毫秒级），且前一请求必须可取消——快速连续输入时，最终呈现的候选与光标处的输入一致（旧请求的结果不覆盖新输入的结果）。

### 1.2 关闭条件

- 光标移出 token（退到 `@` 之前，或 token 与光标之间出现未引用的空白）。
- 按 `Esc`：关闭菜单，`@` 及已输入片段保留为普通文本，用户可继续编辑。
- 发送消息、切换会话、输入框失焦（可配置：桌面端失焦不关闭，见 §7）。
- **Esc 的记忆**：用户按 Esc 关闭菜单后，把光标移回同一 token 的同一位置**不重新弹出**；只有继续输入新字符才重新唤起。同一份未发送草稿内的 dismiss 才被记忆；发送或切换会话后清零。

## 2. 候选菜单

### 2.1 布局与容量

- 浮层锚定在输入框上方（贴近光标所在行），宽度与输入框一致，最大高度按可用空间换算为整行数。
- **一次可见 8 行**，超出在列表内滚动（不分页、无「加载更多」），键盘移动时选中项始终自动滚入可见区。
- 行内容：`图标 + 文件名（命中字符高亮） + 父目录（灰字，右对齐）`；文件夹行的名称带结尾 `/`，图标用文件夹样式。多根工作区时，父目录从**根名起算**显示（如 `webapp/src/components`），保证每一行可辨别所属根。
- 鼠标悬停即选中；键盘移动后悬停失效，直到鼠标再次移动（静止的指针不抢占键盘导航）。点击行主体 = 引用，点击文件夹行尾的箭头 = 进入。
- 菜单顶部显示当前检索词（含路径分段后的搜索范围），让用户知道「我在哪一层、搜的什么」。

```
┌────────────────────────────────────────┐
│ 🔍 comp            （搜索范围：src/）   │
├────────────────────────────────────────┤
│ 📄 Composer.vue        src/components › │
│ 📄 useComposer.ts     src/composables   │
│ 📁 components/        src             ▸│
├────────────────────────────────────────┤
│          ↑↓ 移动 · Tab 进入 · Esc 关闭  │
└────────────────────────────────────────┘
```

### 2.2 排序规则（对用户可预期的稳定顺序）

1. 文件名精确匹配 > 文件名前缀 > 文件名包含 > 全路径包含 > 子序列（驼峰缩写）。
2. 同分时：文件夹略优先于文件；路径更浅者优先；再按字典序。
3. 「通过进入文件夹收窄范围」后，结果只来自该文件夹内。
4. 输入以 `.` 开头的片段时，隐藏/被忽略条目（如 `.env.example`）按需放出（US9.6 的逃逸口）。

### 2.3 路径分段与面包屑

- 输入含 `/` 时按路径分段处理：`@src/comp` 的检索范围收进 `src/`，只在其下做模糊匹配。
- **通过 Tab 进入某文件夹**到达的层级，菜单顶部显示面包屑（如 `src / components /`），点击任一级回到该层继续检索；面包屑在用户手打路径时不显示（手打自带上下文，替换式导航会欠用户一条回路）。

### 2.4 空态与提示

- 无匹配：菜单保持打开，显示「当前工作区没有匹配的文件」+ 一行提示（可继续输入路径分段、`.` 开头可搜隐藏条目）。
- 超出工作区：用户输入绝对路径指向工作区外时，显示明确的「超出工作区范围」说明（不出现任何「搜到但打不开」的结果，US9.6）。

## 3. 键盘映射

| 键 | 菜单打开时的行为 |
|---|---|
| `↑` / `↓` | 移动选中项（循环）；与鼠标共享高亮 |
| `Enter` | 选中当前项为**引用**（文件或文件夹），菜单关闭 |
| `Tab` | 文件夹：**进入**该文件夹继续检索（菜单保持打开，token 改写为该文件夹前缀）；文件：等同 Enter |
| `Esc` | 关闭菜单，文本保留（见 §1.2） |
| `Backspace` | 光标紧邻引用芯片时整体删除芯片；在普通文本内行为不变 |
| 其他字符 | 正常输入，菜单随 token 更新 |
| 会话级快捷键（发送等） | 菜单打开时**不拦截**会话级快捷键 |

- 候选加载中（当前输入的结果未返回）时，`Enter` / `Tab` **不落到旧行**上——要么消费按键等待，要么按当前可见的已就绪结果行动，绝不误选过期行。

## 4. 引用芯片（输入框内形态）

```
请帮我重构这段逻辑 ⬡UserMenu.vue·src/components⬡ ×   ⬡src/utils/⬡ ×
                    └ 文件芯片（名 + 灰字父目录）      └ 文件夹芯片（带 /）
```

- **形态**：图标 + 名称（主）+ 父目录（灰字，过长中段省略）+ 删除角标；芯片内**不显示 `@` 字符**（图标承担「这是引用」的语义）。
- **整体性**：光标进入芯片边界时 Backspace 一次整体删除；不可进入芯片内部逐字符编辑（避免半截引用的中间态）。
- **交互**：点击文件名打开该文件的预览面板（复用现有文件预览）；点击 `×` 移除。文件夹芯片点击无操作（不可预览），仅展示与删除。
- **截取标记**：引用的文件超过注入截断上限时，芯片上出现「已截取」标记（与「内容已更新」同位展示）。
- **去重**：指向同一目标的重复引用不重复插入（同一消息内）。
- **手打 `@xxx` 不构成引用**：只有从候选里选中的才成为芯片；手打文本在发送时按普通文本处理（US9.4）。

## 5. 发送前的引用检查

- 发送时逐个检查引用目标是否仍然成立（存在、类型未变、可读）。
- 有失效引用：**阻止直接发送**，弹出汇总提示「N 个引用已失效」，列出失效项及原因（已删除 / 已移动 / 已变为文件夹 / 无法读取），提供「移除失效引用并发送」与「取消」两个动作（US9.5）。
- 引用文件在插入后被修改：芯片上出现「内容已更新」的标记；送入的是发送时刻的内容。
- 部分失效不株连：其余引用照常注入（US9.8）。

## 6. 状态规格

| 状态 | 触发 | 呈现 |
|---|---|---|
| 索引构建中 | 首次 `@` 且后台扫描未完成 | 菜单可开，候选来自已扫到的部分，底部固定一行「正在建立索引，结果可能不全」；不打断输入；单次查询未返回时才显示骨架行 |
| 索引截断 | 工作区超过索引容量上限 | 底部固定一行「工作区过大，结果可能不全」；其余行为同就绪 |
| 就绪 | 扫描完成 | 底部提示消失，其余不变 |
| 检索降级 | 文件监听失效等，退回实时遍历 | 候选照常返回，出现一次性的「文件变化跟踪暂不可用」提示，不静默变慢（US9.8） |
| 检索不可用 | 检索服务失败 | 菜单内显示明确的不可用说明；输入不受影响；能力恢复后无需操作即恢复 |
| 加载中 | 某次检索未返回 | 对应组显示骨架行；Enter/Tab 不落到旧行（§3） |

## 7. 桌面端差异

- 输入框失焦时菜单默认关闭（与 web 一致）；桌面端可配置为失焦保持（偏好项，默认关）。
- 其余交互与 web 完全一致——桌面端是 web 界面的外壳，不维护独立的交互分支。

## 8. 可访问性

- 菜单容器 `role="listbox"`，候选项 `role="option"`，键盘移动时维护活动项的对应属性，屏幕阅读器可朗读「第 N 项，共 M 项：文件名，所在目录」。
- 命中高亮只用字重与颜色，不同时依赖颜色作为唯一信号（图标区分文件/文件夹）。
- 全部键盘操作不依赖鼠标；鼠标操作不产生键盘无法完成的路径（点击箭头 = Tab 的等价物）。

## 9. 与终端的边界

- 本文所有规格只约束 web 与桌面端。终端 `@` 补全的交互（触发、候选、`@path` 文本形态）见终端界面域 [tui/interaction-requirements.md](tui/interaction-requirements.md)；两侧的注入语义差异登记在需求文档 §10（消费端差异），终端对齐结构化引用的提案见 P-9。
