## 1. 问题背景（PM 可读）

### 1.1 Bash 工具承担什么

Bash 是 agent 唯一能与操作系统做任意交互的通道——构建、测试、git、包管理、进程管理全靠它。它也是权限系统里**最危险**的工具：一次调用可以读写任意文件、访问网络、修改系统状态。正因如此，它的问题会同时伤到三条线：**稳定性**（长输出把会话拖垮）、**安全性**（凭证暴露、过度授权）、**效率**（模型为绕开缺陷付出额外轮次）。

本设计不新增能力，只修复已确认的缺陷。每一类都先陈述其自身的痛点，不依赖与任何外部产品的对比。

### 1.2 缺陷一：一次「允许」等于放行一切命令

用户面对的第一条 Bash 命令请求批准时，界面上只有「允许 / 拒绝」两个选项；无论选哪个，效果都是全有或全无：

- 选「允许一次」，下一条命令（可能是完全不同风险级别的操作）又要再问一遍——高频操作下用户被审批弹窗疲劳轰炸，最终为了图省事切到全自动模式，**安全性反而倒退**；
- 选「本会话均允许」，此后**任何**命令（包括删库、外发数据）都不再询问——用户以为批准的是"跑跑构建"，实际交出的是整个 shell；
- 想自己写规则「只允许 git 命令」，配置系统接受这个写法，但它**静默不生效**——用户以为有防护，实际没有；用户写「禁止 rm 命令」的拒绝规则，同样静默不生效。

痛点的本质：权限系统承诺了命令级粒度（规则语法支持「工具名(命令模式)」），交付的却是工具级粒度，且没有任何报错提示这个落差——放行与拦截两个方向都失效。

### 1.3 缺陷二：一条命令可以把整个会话拖垮

模型执行的命令，输出量不可预知——一次全量测试、一个失控的日志循环、一次误操作的大文件打印。当前实现把命令输出**全部累积在内存里**，直到命令结束才做截断。也就是说：

- 截断保护在输出已经撑爆内存**之后**才介入，过程无保护；
- 一个失控进程在数秒内可以产生 GB 级输出，直接拖垮引擎进程，用户失去整个会话（包括上下文中未保存的其他工作）。

痛点的本质：保护机制的位置错了——它应该发生在输出**产生的过程**中，而不是结束后。

### 1.4 缺陷三：所有命令都能看到宿主的登录凭证

引擎进程启动时从用户环境继承全部环境变量——包括云厂商密钥、API token、数据库密码。任何 Bash 命令（一次简单的 `env` 打印、或被诱导执行的恶意命令）都能读到它们。模型没有理由访问这些凭证，用户也没有理由为「让 agent 跑构建」交出全部钥匙。

### 1.5 缺陷四：长任务的产出要等结束才能看

用户把构建、测试放到后台执行后，任务面板只能显示"运行中"——看不到任何实时输出，必须等任务完成后读取快照。构建挂了还是还在跑？卡在哪一步？用户只能干等。前台命令反而有实时输出——这不是能力缺失，是任务输出增量面缺一条接线。

### 1.6 既有规格-实现偏差

本设计覆盖的工具存在四处规格与实现不一致（两流合并方式、`disable_timeout` 生效范围、`exempt_lifetime` 未登记、后台 `description` 必填性；详见 context §1.6），本设计统一收敛到终态，不留双轨。

### 1.7 长命令「黑盒等待」的痛点

模型跑了一个很重的测试（全量测试、大构建），命令超时转入后台后，会进入一个长达十分钟的「黑盒」：完成要等自动通知，卡死要等到重布防超时被杀才知道——期间模型没有任何手段确认「执行到哪了、卡在哪了」。这不是查询能力完全缺失（任务查询工具本身非阻塞且全模式免审批），而是三个断点的叠加：

- **被文案禁止查询**：转后台返回文案明示「勿等待、勿轮询、勿调用任务查询」——防模型空转的原意被写成了绝对禁令，模型被引导傻等；
- **查了也没有判据**：查询结果只有尾部输出，没有「已运行多久、静默多久」的信号，模型无法区分正常慢（长编译本来就是静默的）与死锁；
- **全量读取路径被权限拦截**：完整日志的恢复路径依赖「用文件读取工具读沙箱外的落盘绝对路径」，manual 模式下被工作区边界拦住，模型拿着路径也读不到。

此外还有一个数据丢失面：前台命令被取消时，已累积的输出被直接丢弃——用户想复盘「取消前为什么没动静」都无从查起。

### 1.8 执行目录「双轨失守」的痛点

模型执行命令时频繁在命令文本前缀 `cd <绝对路径> &&`，而不是使用工具的 `cwd` 参数——即使目标就是当前 workspace。这造成两重失守：

- **审查失守**：`cwd` 参数本是可以做结构化审查的入口（workspace 边界、审批、grant），但命令内的 `cd` 完全绕开它；更糟的是 `cwd` 参数本身也没有任何校验——任意绝对路径直接放行。执行目录这条线在参数与命令两个轨道上都没有守卫。
- **规则匹配污染**：`cd /abs/path &&` 前缀使命令级授权规则的匹配串变长变噪（批准 `git status` 的记忆对 `cd x && git status` 不生效）。

### 1.9 macOS 受保护目录「绕道触发系统弹窗」的痛点

桌面宿主未启用 App Sandbox（仅 hardened runtime），子进程继承宿主身份。当命令触碰 macOS 受保护目录（桌面、文稿、下载、iCloud 等 TCC 类别）时，引擎层面静默放行，随后在**操作系统层**撞上 TCC 授权——用户看到的是「是否允许 MirriDesktop 访问桌面」这类系统级弹窗，而不是带命令上下文的产品审批面板。我们的整个权限体系被绕过：既没有事前知情（Ask），也没有品牌一致性（弹窗名义是宿主应用而非命令）。

## 2. 需求定义（US 条目）

> 编号 `US-BH*` 为本设计域内编号，裁决后并入 tool-calling-requirements US4.6。验收句式「假如…、当…、那么…」。契约文案保留英文原文。分批见 §8 Rollout。

### US-BH1 命令级授权粒度（P0）

用户应当能够把 Bash 的批准与规则精确到命令级别，从而高频安全命令免于反复弹窗、危险命令不被"一刀切放行"波及。

- 假如用户在权限面板选择「本会话均允许」，当本次命令形如「命令首词 + 限定参数」，那么记忆的是本次**命令文本**对应的命令级刻面（如 `Bash(git status --short)`），不是整个 `Bash`——此后的**相同命令**不再询问；首词相同、参数不同的命令（`git push`、`git status -s`）仍会询问
- 假如批准时面板明示记忆范围，当用户选择「本会话均允许」时，那么面板展示本次将记忆的命令文本（用户知道自己批准的是什么粒度，而非误以为放行了整个工具）
- 假如用户书写权限规则 `Bash(git status)`，当引擎评估任何 Bash 调用时，那么命令文本逐字匹配的调用被规则覆盖；不匹配的调用不受影响
- 假如用户书写通配规则 `Bash(git *)`，当调用的命令以 `git ` 开头，那么该规则覆盖此调用
- 假如命令是复合命令（`git status && rm -rf /`），当授权评估发生时，那么**每一段**都必须匹配放行规则才整条放行；任何一段不匹配则整条按未匹配处理（进询问）——复合命令不能靠"前半段合法"夹带后半段；若批准的规则本身就是整条复合命令的刻面，则相同复合命令重跑不再询问
- 假如复合命令的某段无法可靠提取（引号跨段、命令替换等），当评估发生时，那么该段按不匹配处理（保守失败，进询问，不拒绝执行）
- 假如用户书写 deny 或 ask 规则（如 `Bash(rm *)`），当命令命中该模式，那么按规则语义拒绝或询问——匹配语义对放行（allow/会话记忆）、询问（ask）、拦截（deny，含否定形式）三类规则对称生效
- 假如历史或外部来源产生的刻面是裸工具名（旧会话记忆恢复、旧客户端），当评估发生时，那么按工具名匹配继续生效（向后兼容线，不强迫迁移）

### US-BH2 前台输出过程保护（P0）

任何前台命令的内存占用都应当有硬上限，从而单条命令无法拖垮引擎与会话。

- 假如前台命令持续输出超过内存上限，当输出仍在产生时，那么引擎丢弃**最旧**的输出、保留最新部分，内存占用恒定有界
- 假如输出触发了丢弃，当命令结束时，那么返回给模型的结果明示「输出已被丢弃头部、只保留尾部 N 字节」及丢弃总量
- 假如输出超过模型可见上限，当命令结束时，那么完整已保留输出落盘并在结果中给出恢复路径（沿用既有截断契约）
- 假如命令输出在合理范围内，当命令正常结束时，那么模型看到的输出与现状完全一致（保护对正常路径零侵扰）

### US-BH3 凭证卫生（P0）

Bash 子进程不应当看到与命令执行无关的宿主凭证，从而模型的一次失误或一次被诱导的命令不等于凭证泄漏。

- 假如宿主环境变量名命中敏感模式（含 `KEY` / `TOKEN` / `SECRET` / `PASSWORD`，不区分大小写），当 Bash 命令 spawn 时，那么该变量不进入子进程环境
- 假如变量名命中敏感模式但其值来自引擎自身的显式注入（引擎标注的受管变量），当 spawn 时，那么受管变量正常注入（引擎注入优先于剔除）
- 假如某个被剔除的变量确实为构建所需，当用户提供配置豁免清单时，那么清单内变量照常传递（提供逃生门，不搞一刀切）
- 假如工具向模型描述自身，当描述文案生成时，那么描述包含过滤行为与豁免方法的说明（模型缺变量时能从契约文本找到原因，不依赖失败原因猜测）

### US-BH4 后台任务实时输出（P1）

用户应当能在任务面板看到后台命令的实时输出尾部，从而判断"卡住了还是在正常跑"。

- 假如命令以后台方式运行，当输出持续产生时，那么任务输出面持续追加最新输出（复用任务输出既有缓冲与落盘管线，面板按既有读取面看到增量）
- 假如用户需要完整输出，当任务结束后，那么既有落盘文件与读取路径不变（增量能力，不改存量契约）

### US-BH5 交错合并落地（P1，规格收敛）

模型看到的命令输出应当与真实执行顺序一致，从而"日志在 stderr、数据在 stdout"的场景不被拼接顺序误导。

- 假如命令同时向两流输出，当结果返回时，那么两流内容按**到达顺序**交错合并
- 假如某一流为空，当结果返回时，那么输出与现状一致（不引入分隔标记）

### US-BH6 工具描述与实际行为一致（P0，规格收敛）

作为依赖工具描述规划行为的模型，我需要 Bash 描述如实反映超时与豁免语义，从而不按错误契约规划任务。

- 假如模型传入 `disable_timeout`，当命令为前台时，那么无超时执行，且描述文案如实披露该范围（前台后台均生效）
- 假如模型传入 `exempt_lifetime`，当注册任务时，那么按 US14.4 豁免生命周期天花板，且参数在规格参数表中登记
- 假如模型未传后台 `description`，当后台任务启动时，那么以命令预览为默认标签（描述如实反映，规格参数表的必填性同步收敛为「可选、缺省取预览」）

### US-BH7 运行中任务的日志自助可观察性（P0）

作为运行了长命令的模型，我需要在不打断自己当前工作的前提下随时读取该命令已产生的日志与进度信号，从而确认执行到哪、卡在哪，而不是傻等通知或重新跑一遍。

> 本 US 覆盖工具调用域 US4.14（任务三件套）的消费面增强；查询工具自身（TaskOutput/TaskList）属既有契约，本条只定义 Bash 转后台后模型对其的新可见性。

- 假如模型对**仍在运行**的后台任务调用 TaskOutput（非阻塞），当快照返回时，那么头部包含：任务已运行时长、最近一次输出距今的静默时长、累计输出字节数——模型据此区分「正常慢」与「疑似卡死」
- 假如模型需要读取超过内联窗口的完整日志，当调用 TaskOutput 时，那么可通过字节偏移分页（`offset_bytes` / `max_bytes` 参数组）读取日志任意区间，返回头带总字节数与窗口区间；该调用在**任何权限模式（含 manual）**下都不触发审批（按任务 id 寻址，不经过文件读取的沙箱边界）
- 假如分页偏移越过日志末尾，当调用返回时，那么给出明确的越界提示与总字节数（不返回空串——与「无输出」歧义）
- 假如多个后台任务并行，当模型调用 TaskList 时，那么每行包含各任务的运行时长与静默时长——无需逐个 TaskOutput 即可定位异常任务
- 假如命令因前台超时转入后台，当转后台结果返回时，那么文案告知：完成仍靠自动通知（勿阻塞等待）；在处理其他工作的间隙，可有理由地（异常静默、用户询问、怀疑卡住）做一次非阻塞进度快照，至多数分钟一次；仍禁止以 `block=true` 空转等待
- 假如模型查询自己启动的任务日志，当任何权限模式评估发生时，那么 TaskOutput/TaskList 既有免审批待遇保持不变（现状确认——真正被沙箱拦的是「用 Read 读落盘绝对路径」，本设计以分页内置使其失去必要性）

### US-BH8 后台静默预警（P1，引擎兜底推送）

作为可能错过异常的用户/模型，我需要引擎在后台任务长时间无产出时主动告知一次，从而在「傻等到重布防超时被杀」之前发现死锁。

- 假如后台命令任务的输出静默时长超过阈值（默认 5 分钟、会话配置可调），当引擎检测到时，那么向会话注入**一次性**事实性通知：「任务 X 已静默 N 分钟」+ 尾部输出摘要（约 1-2 KB）+ 可行动指引（查 TaskOutput、考虑 TaskStop 或告知用户——引擎只预警，不自动杀）
- 假如同一任务再次静默（先前恢复过输出），当新的静默周期超过阈值时，那么可再次预警（每个静默周期至多一次，绝不周期性重复）
- 假如预警触发时用户侧任务面板打开，当展示任务时，那么静默标记同步可见（用户侧与模型侧同源）
- 假如任务在本设计外已终态（完成/失败/停止），当预警检测运行时，那么不再为其触发预警
- 假如任务是子代理（Agent kind）而非命令进程，当预警扫描发生时，那么不在本批预警范围（输出活动语义不同，先行排除，待核实后另行裁决）

### US-BH9 前台取消时的输出保全（P1）

作为取消了前台命令的用户，我需要已产生的输出被保留，从而诊断「为什么取消前就没动静」或决定下一步。

- 假如前台命令被取消（回合取消），当结算发生时，那么已累积输出落入任务行与日志（对齐后台任务的落盘语义；现状为直接丢弃）
- 假如取消后模型或用户查询该任务，当 TaskOutput 调用时，那么可读到取消前的部分输出与取消状态

### US-BH10 执行目录的结构化审查（P0，三层防线）

用户应当能够让命令的执行目录（无论经 `cwd` 参数还是命令内 `cd`）受同一套工作区边界审查，从而不存在「换一条轨道就绕过守卫」的通道。

- 假如模型以 `cwd` 参数指定沙箱外目录，当权限评估发生时，那么该目录按既有沙箱外路径语义处理（Ask，带目录授权选项；与文件工具的边界策略同构）
- 假如命令文本中的目录切换段（`cd`/`chdir`/`pushd` 等的目标）指向沙箱外目录，当权限评估发生时，那么该目标目录与 `cwd` 参数**平权**——合并送同一套边界审查，任一越界即整条命令进 Ask
- 假如目录切换段的目标含变量或无法静态解析，当评估发生时，那么该段退回为命令段参与命令级授权匹配（保守处理，不静默放行）
- 假如目录切换目标是 workspace 内相对路径，当命令级授权评估发生时，那么该 cd 段从命令匹配串中剔除（`cd src && git status` 的规则匹配只有 `git status`）——cd 段不污染授权规则
- 假如模型使用 `cwd` 参数或命令内 cd 进入非默认目录，当工具描述被模型读到时，那么描述显式引导「优先传 `cwd` 参数，不在命令里 `cd`」（反 cd 引导落地到工具描述）

### US-BH11 受保护目录的事前知情（P1，桌面宿主）

作为桌面产品用户，我需要命令触碰 macOS 受保护目录（桌面/文稿/下载等系统级保护位置）之前先得到**产品自己的**审批询问，而不是事后看到不知来由的系统弹窗。

- 假如命令文本（含参数、路径形态）命中受保护目录模式（如 `~/Desktop`、`~/Documents`、`~/Downloads` 及其绝对路径展开形态），当命令尚未执行、权限评估发生时，那么按沙箱外路径语义进 Ask，且询问面板如实告知「此命令将触碰系统受保护目录（可能触发系统授权）」
- 假如用户在 Ask 中批准（含目录授权），当命令执行时，那么该受保护目录在本会话内不再重复询问（系统级 TCC 授权仍由 macOS 自行管理，产品不代答）
- 假如命令以非字面形态触碰受保护目录（变量拼接、间接寻址），当静态模式无法识别时，那么本条不拦截（诚实边界：字符串级检测不是沙箱，不做运行时路径追踪）
- 假如宿主不是桌面应用（TUI/CLI/server），当受保护目录模式命中时，那么同样进 Ask（目录敏感性在所有宿主一致；只是桌面宿主的未授权后果是系统弹窗，其余宿主是直接访问）

## 3. 目标与非目标

### 目标

- 权限粒度从工具级降到命令级（记忆、用户 allow/ask/deny 规则三条线全部生效，拦截与放行对称）。
- 前台输出内存有界；丢弃可感知、完整输出可恢复。
- 子进程环境不含宿主凭证，豁免有门、契约可自诊断。
- 后台任务输出有增量；两流按到达顺序合并。
- 运行中任务的日志与进度信号可自助读取（分页 + 运行/静默时长 + 诊断性检查权），任何权限模式免审批。
- 执行目录在参数与命令两个轨道上都受同一套边界审查；受保护目录触碰前有事前知情。

### 非目标（明确不做）

- **不做**完整 shell 语法扫描器（复合命令解析只做 `&&`/`;`/`||`/`|`/换行 拆分，不做引号/替换的完整状态机——保守失败兜底）。
- **不做** OS 级沙箱（bwrap/Seatbelt 类）——量级独立，若立项另成域。
- **不做**持久 shell / PTY 会话——与「fresh shell」既有契约冲突，无场景诉求。
- **不做**后台任务跨重启恢复——与生命周期天花板语义冲突，未裁决前不动。
- **不做**文件读取工具的通用输出分页扩展——任务日志分页已内置 TaskOutput（US-BH7），其他工具的输出游标分页等真实需求出现再立项。
- **不做** PowerShell 工具的同批改造（它共享执行骨架与同样的环境继承问题，登记为后续跟进项，见 §9）。

## 4. 内部设计（架构）

### 4.1 命令模式提取与匹配（US-BH1）

```
BashTool (bash.rs)
  resolve_execution 阶段：
    command_text（模型传入的 command 原文，不含 cwd 包装）
      → 刻面生成：approval_rule = "Bash(<command_text>)"（单串，原文嵌入；
        分段只用于匹配阶段，不做 per-segment 多刻面拼接）
```

- **刻面生成与转义**：`ExecutionPlan.approval_rule` 从裸 `"Bash"` 改为 `Bash(<command_text>)`，command_text 原文嵌入。刻面串中的 glob 元字符（`*` `?`）与括号在生成时**转义**（防止记忆串被解析为通配而静默扩大范围）；命令以 `!` 开头时首字符转义（防止记忆串被解析为否定模式——否则一条会话记忆会变成"放行所有非 X 命令"，方向完全反转）。转义后的刻面作为字面量参与匹配。
- **匹配闭包**：`PermissionPolicyContext` 增加 command_text 通道（`resolve_execution` 已持有命令原文），匹配闭包接入**全部参数化规则调用点**：`UserConfiguredDenyPolicy`、`SessionApprovalHistoryPolicy`、`UserConfiguredAskPolicy`、`UserConfiguredAllowPolicy`；`PrivateNetworkFetchAskPolicy` 是 FetchURL 专属，保持现状（调用点清单见 context §1.5）。闭包语义（两步合一，先整条后分段）：
  1. **整条逐字匹配**：规则模式（去转义后）与命令全文逐字等价 → 命中（保证复合命令批准后自身重跑不弹窗）；
  2. **分段匹配**：按 `&&`/`||`/`;`/`|`/换行拆段、每段做空白归一后**对段全文**做 glob 前缀匹配（`first_word` 仅用于空段/首词提取失败的判定，不做"只匹配首词"——那会把 `Bash(git)` 扩大成放行任意 git 子命令）；**全段命中才算命中**。
  - 解析失败的段保守视为不匹配 → 进询问，不拒绝执行。
  - 匹配语义对 deny/ask/allow/会话记忆四类规则统一（对称拦截与放行）。
- **审批面板选项**：session 批准的记忆串从裸 `Bash` 变为本次命令的刻面（approval_rule 已携带）；面板展示本次命令文本（US-BH1 第 2 条），文案结构不变。

### 4.2 前台输出环形缓冲（US-BH2）

- 前台累积改为**单一 merged 流**（见 §4.5）的定长尾部缓冲，总量上限 **1 MiB**（与后台任务既有 `MAX_TASK_OUTPUT_BYTES` 的每任务总量语义对齐，非每流）：push 时超限丢头，记录 `dropped_bytes`。
- 命令结束时：`dropped_bytes > 0` 则结果头部插入一行 `[Output truncated: kept the last N bytes, dropped M bytes from the start]`；此后仍走既有 `ToolResultTruncator`（50k 字符落盘）。
- 前台转后台交接（`hand_over_to_background`）：环形缓冲内容即「前台窗口输出」，写入任务行语义不变。

### 4.3 敏感环境剔除（US-BH3）

- `noninteractive_env()` 扩展为「覆盖 + 剔除」双职责：敏感名模式（大小写不敏感子串 `KEY|TOKEN|SECRET|PASSWORD`）命中的父环境变量，经 `ExecOptions` 新增的 `env_remove: Vec<String>` 在 `mirri-os` spawn 侧显式 unset（`command.env_remove(name)`；`ExecOptions` 的接口注释已预留该机制位）。
- 引擎自身注入项（`NO_COLOR` 等）在剔除后写入，天然满足「受管优先」。
- 配置豁免：`[bash] env_allowlist = ["HTTPS_PROXY", ...]`（config 域新增键，同批登记 glossary），豁免名单在剔除后回填。
- 描述文案追加一句：`Credentials-bearing environment variables are filtered from command environments; allowlist via config if a build genuinely needs one.`

### 4.4 后台输出增量（US-BH4）

- `run_bash_background` 的输出路径改为**逐 chunk 调 `tasks.append_output`**（该方法已存在且自带 1 MiB 丢头保尾 + `output.log` 落盘）：任务运行中输出即持续进入任务行，面板经既有任务输出读取面（轮询/快照）看到尾部增量。不走前台 progress 通道——那是回合作用域的 live-event（生命周期归属当前回合），与跨回合存活的后台任务不对齐。
- 本条是**复用既有任务输出面**，不新增 wire 事件；若未来需要真正的任务作用域推送流，归 background-tasks 域另行裁决。

### 4.5 交错合并（US-BH5）

- 前台 pump 的 `ShellChunk` 携带 `kind`；累积阶段维护单一 `merged: String` 按 chunk 到达顺序追加（`kind` 仅用于 progress 区分）。§4.2 的环形缓冲作用于该 merged 流。
- 兼容：某一流为空时输出与现状逐字一致（无分隔标记，既有规格 D-1 收敛完成）。

### 4.6 规格收敛（US-BH6）

- builtin-tools §2.1 参数表：`disable_timeout` 描述改为 `If true, no timeout is applied (foreground and background). Background tasks still fall under the global lifetime ceiling; use exempt_lifetime to lift it for one task.`；补登 `exempt_lifetime` 行；`description` 必填性改为「可选、缺省取命令预览」；非功能节「仅后台生效」句同步修正。

### 4.7 运行中可观察性（US-BH7）

- **分页读取**：TaskOutput 参数组增加 `offset_bytes`（≥0，默认 0）与 `max_bytes`（1..256000，默认 50000）；不传即现行尾窗快照行为（向后兼容——快照是「尾部分页的糖」）。持久层的窗口读取（按字节偏移取任意区间，只读窗口不产生全量 IO）已就绪，本设计将其暴露为模型可见参数。字节寻址而非行寻址：日志是字节流（无换行保证的编译输出常见），行号会错位；快照头已有的总字节数使字节寻址自洽。窗口起点向后对齐 UTF-8 字符边界（跳过 continuation bytes）；无持久化的内存缓冲路径（≤1 MiB）同样支持窗口切片，两条路径行为不分叉。
- **进度信号**：快照头（与 TaskList 行）增加三项——已运行时长（由任务创建时刻计算，零新状态）、静默时长（新增 `last_output_at` 打点，append 时刷新；会话恢复后可由日志 mtime 兜底推导）、累计输出字节数（已有）。**不**在引擎侧计算输出增长率——模型两次快照自行差分即可，引擎不维护滑动窗口状态。
- **静默信号与心跳正交**：进程心跳是「进程活着」（长静默命令必须照常跳心跳，这是心跳机制的既有设计约束），静默时长是「活着但没有产出」——两者刻意分离，静默检测不得复用心跳/stale 判定。
- **文案改写（连同锁定旧文案的测试）**：转后台返回与后台启动文案中的 "do NOT wait, poll, or call TaskOutput" 改为「完成仍靠自动通知；有理由时（异常静默、用户询问、怀疑卡住）可做一次非阻塞进度快照，至多数分钟一次；勿以 block=true 空转等待」。反空转的原始意图保留（完成信号仍是通知机制，检查只是诊断动作）；此为规格变更，记 SDR。
- **权限语义**：TaskOutput/TaskList 的免审批待遇（default-approve 清单）保持不变——按任务 id 寻址天然不经文件读取的沙箱边界；分页内置后，「用 Read 读落盘绝对路径」这条 manual 下被拦的路径失去必要性，无需任何目录白名单。

### 4.8 静默预警（US-BH8）

- 检测宿主：任务驱动循环的既有扫描 tick（stale 检测旁边）新增静默检查——读取 `last_output_at`（复用 US-BH7 打点）+ 周期状态（每静默剧集 edge-triggered 一次，新字节到达即重置剧集）。
- **通知通道不复用终态通知账本**：终态通知是「每 task+terminal 恰好投递一次」的持久化语义（undo/resume 依赖）；静默预警是瞬态、可重置、可复发的信号——走合成消息注入路径，去重状态留在驱动循环内存，不持久化、不污染终态账本。
- 阈值：`[task] silence_warn_secs`（config 新键，默认 300，0 = 关闭）；预警文案为事实性陈述（静默时长 + 尾部 1-2 KB 摘要 + 行动指引「查 TaskOutput / 考虑 TaskStop 或告知用户」），不判定死活、不自动杀——判断与决策权留给模型和用户。文案可附重布防剩余时长提示（任务带二次截止时）。
- 作用域：仅 Process 类任务；Agent 类任务的输出活动语义不同，先行排除待核实。
- 用户侧：任务面板同步展示静默标记（消费端参考项，非引擎对齐）。

### 4.9 取消保全（US-BH9）

- 前台取消路径（回合取消、终态 release）在任务结算前补输出落盘（对齐正常完成路径的落盘语义——`append_output` 对任意状态安全）。取消时刻的返回文案模型大概率看不到（走回合取消结算），真正的验收面是「取消后 TaskOutput 可读」。
- 前台任务本就有任务行与持久化接线，本条是补齐两条取消路径的落盘调用，属 bug-fix 级；按测试纪律先写红测试（运行中任务有累积输出 → 取消 → 日志含该输出）再修。

### 4.10 执行目录三层防线（US-BH10）

- **第 1 层·引导**：工具描述补充反 cd 引导——「要用其他目录时传 `cwd` 参数，不在命令里 `cd`」（rust 实现的 `description()` 现状没有这句，规格里有；两处对齐）。
- **第 2 层·参数审查**：`cwd` 参数过工作区边界策略——outside 沙箱的 cwd 走 Ask（带 grant_dir）；实现与文件工具的 `WorkspaceBoundaryPolicy` 同构，Bash 的 `resolve_execution` 已持有 cwd 与 workspace_paths。
- **第 3 层·命令内 cd 提取**：复用 B-ADR-1 的分段器，扩展识别目录切换段（`cd`/`chdir`/`pushd`，穿透 `builtin cd`/`command cd` 写法），提取目标目录与 `cwd` 参数**合并**送边界审批（opencode 的平权设计）；静态可解的 workspace 内 cd 段从命令匹配串中剔除（不污染授权规则）；含变量/无法解析的 cd 目标退回为命令段参与命令级授权（保守处理）。
- 三层共线：都在 `resolve_execution` 的权限评估阶段，不新增裁决面。

### 4.11 受保护目录检测（US-BH11）

- 在 4.10 的评估阶段增加一道**字符串级模式匹配**：命令文本命中受保护目录模式（`~/Desktop`、`~/Documents`、`~/Downloads`、`/Users/*/Desktop` 等展开形态；`~` 单独出现时保守命中）→ 按沙箱外路径语义 Ask，面板如实告知触碰系统受保护目录。
- 复用 4.10 的 Ask + grant 管线，不新增裁决面；一次目录授权后本会话不再重复询问。
- **诚实边界（写入描述与文档）**：字符串级检测不是运行时沙箱——变量拼接、间接寻址不可见；检测的价值是「高频字面形态的事前知情 + 用户体验与品牌一致性」，不是强制边界。彻底消除系统弹窗需 App Sandbox（改变桌面应用安全模型，不现实）或用户在系统设置预授权（可登记为 doctor 检查项）。

## 5. 决策记录

### B-ADR-1：命令级授权用「刻面 + 整条逐字 OR 分段 glob」，不做完整 shell 扫描器

- 背景：权限规则 DSL 已定义 `工具名(参数模式)`，但引擎侧无任何工具实现参数匹配，参数化规则在放行与拦截两个方向全链路静默失效；会话级批准记忆粒度为整工具。
- 决策：Bash 刻面携带命令全文（glob 元字符与 `!` 前缀转义为字面量）；匹配闭包两步合一——整条逐字等价优先，否则按 `&&`/`||`/`;`/`|`/换行拆段、逐段对段全文做 glob 匹配，全段命中才命中；解析失败的段保守视为不匹配（进询问，不拒绝执行）。语义统一适用于 deny/ask/allow/会话记忆。
- 被否决备选：① 完整扫描器——2500+ 行状态机、命令替换与 heredoc 全拒，维护成本与误拒风险不成比例；② 只按首词匹配——`Bash(git)` 会放行任意 git 子命令，粒度失控；③ 只整条逐字匹配——复合命令批准后无法覆盖子段规则（`Bash(git *)` 对 `git status && ls` 失效），通配规则形同虚设；④ 每段独立多刻面拼接——刻面 DSL 是单串形态，多刻面需要改 DSL 语法，收益不抵。
- 影响范围：US-BH1；glossary AP3 的 Bash 例句更新为命令模式形态（同批修订）；`PermissionPolicyContext` 形状扩展属 permission 接口演进。

### B-ADR-2：前台输出尾部保留 1 MiB（merged 总量）+ 丢弃量披露，不做「先全收后截」

- 背景：前台输出无界累积，截断器在进程结束后才介入，失控输出可在截断生效前耗尽内存。
- 决策：单一 merged 环形缓冲丢头保尾，总量 1 MiB（对齐后台每任务语义），丢弃量在结果中披露；完整输出沿用截断器落盘路径。
- 被否决备选：① 边执行边全量落盘 + 事后读尾——双写路径复杂度高，前台命令多为短输出，落盘收益低；② 缩小截断器 50k 上限——治标不治本，过程内存仍然无界；③ 每流各 1 MiB——两流交错合并后口径不清，且总量翻倍无必要。
- 影响范围：US-BH2；`hand_over_to_background` 的前台窗口输出语义（US2.6/US14.1 引用面）不变。

### B-ADR-3：敏感环境用「模式剔除 + 豁免清单」，不做白名单重建

- 背景：子进程全量继承父环境，宿主凭证对任意命令可见。
- 决策：按敏感名模式（KEY/TOKEN/SECRET/PASSWORD，大小写不敏感）剔除父环境变量，受管注入随后写入，配置豁免清单提供逃生门，工具描述披露过滤行为。
- 被否决备选：① `env_clear` + 白名单重建（PATH/HOME/LANG 全手动枚举）——破坏工具链可用性，枚举遗漏即功能回归；② 按值启发式（检测值像密钥）——误伤率高且不可预测。
- 影响范围：US-BH3；`ExecOptions` 形状扩展（`env_remove`）属 mirri-os 接口演进，随 changeset minor。

### B-ADR-4：两流合并按到达顺序交错（规格 D-1 收敛）

- 背景：规格已裁决「按到达顺序交错合并」，实现是分开累积顺序拼接（stdout 全前）；mpsc 单通道天然保序，仅最终合并丢序。
- 决策：合并策略在 chunk 消费点改为按到达顺序单流追加，环形缓冲随后。
- 被否决备选：改规格承认「stdout 全前」——顺序错乱误导模型定位问题（日志/数据混排场景），规格本就正确。
- 影响范围：US-BH5；builtin-tools §2.1 输出契约（实现侧收敛，规格文本不变）。

### B-ADR-5：`disable_timeout` 前台生效保留为实现终态

- 背景：规格曾写「仅后台生效」，实现是前台也生效（前台无超时 + 回合取消仍可终止）。前台 `disable_timeout` 的语义是「模型明确声明此命令值得无限期等待」，回合取消（用户打断）仍是逃生门；转后台重布防路径不受影响（disable 状态随任务移交）。
- 决策：以实现的「前后台均生效」为终态，规格描述同步收敛；不引入前台禁用超时的额外限制（无证据表明需要）。
- 被否决备选：① 收敛回规格原义（前台拒绝 disable_timeout）——剥夺模型对已知长任务（长测试、大迁移脚本）的显式声明手段，逼迫模型拆命令或预判后台化，徒增轮次；② 前台 disable_timeout 钳制到一个大上限——「disable 却有上限」语义自相矛盾。
- 影响范围：US-BH6 第一条；builtin-tools §2.1 参数表与非功能节。

### B-ADR-6：日志全量读取走「任务 id 分页内置」，不做沙箱白名单

- 背景：任务全量日志的恢复路径是「用 Read 读落盘绝对路径」，该路径在工作区沙箱外，manual 模式被边界策略拦截——模型拿着路径读不到。业界两条对照路线：deepseek 的权限哲学是「只围写不围读」（读取零围栏，落盘日志天然可读）；opencode 曾对引擎自产目录注入免审批白名单后又主动移除（回到外部目录一律询问）。
- 决策：把字节偏移分页（`offset_bytes`/`max_bytes`）内置进 TaskOutput——按任务 id 寻址，不经过文件读取的沙箱边界，所有权限模式免审批（TaskOutput 本就在 default-approve 清单）。分页内置后「用 Read 读绝对路径」失去必要性，无需白名单。
- 被否决备选：① 引擎目录白名单免审批——opencode 已实践并撤销的路线，且与「拒绝后不得绕路」的越权合同打架；② 「只围写不围读」的权限哲学——影响全部边界工具，是比本设计更深层的裁决，应另立项（approval 域）而非夹带。
- 影响范围：US-BH7；task-calling-builtin-tools 的 TaskOutput 规格（参数组与输出契约）。

### B-ADR-7：「可观察」与「不空转」的划线——完成靠通知，检查是诊断

- 背景：转后台文案曾绝对禁止查询任务输出（防模型空转轮询烧 token 的原意被写成禁令），模型被迫从转后台一刻纯等到重布防超时（600s）被杀——「黑盒等待」痛点的主因。改写文案是规格变更（既有测试锁定了旧文案），须连同测试与意图一起改。
- 决策：完成信号仍是通知机制（唯一）；周期性检查降格为「有理由时的诊断动作」（异常静默、用户询问、怀疑卡住），频率锚点「至多数分钟一次」，`block=true` 空转等待仍被劝阻。静默预警（US-BH8）作为引擎侧兜底，与模型侧主动检查互补：主动查覆盖「我在做别的事、顺带看一眼」，被动推覆盖「模型没意识到的异常」。
- 被否决备选：① 保持绝对禁令——把「防空转」异化为「禁止一切观察」，与运行中可观察性诉求直接冲突；② 放开为自由轮询——回到空转烧 token 的老问题。
- 影响范围：US-BH7 第 5 条；`bash.rs` 转后台与后台启动两处文案 + 锁定文案的测试（记 SDR）。

### B-ADR-8：执行目录用「参数审查 + cd 提取」平权合并，不硬禁 cd

- 背景：模型频繁以 `cd <绝对路径> &&` 前缀绕开 `cwd` 参数，且 `cwd` 参数本身无任何校验——执行目录在两个轨道上都失守；cd 前缀同时污染命令级授权的匹配串。业界对照：opencode 用扫描器提取 cd 目标目录与 workdir 合并送审（不硬禁），deepseek 把边界下沉到写权限沙箱（cd 天然不构成逃逸）。
- 决策：三层防线——描述反 cd 引导（第 1 层）；`cwd` 参数过工作区边界（第 2 层）；分段器扩展提取 cd/chdir/pushd 目标目录，与 `cwd` 参数平权合并送同一套边界审批（第 3 层，opencode 路线适配）。workspace 内静态可解的 cd 段从命令匹配串中剔除（治规则污染）；无法静态解析的 cd 目标退回为命令段（保守）。
- 被否决备选：① 硬禁 cd——三家无一先例，`cd a && build`、子 shell `(cd x && ...)` 等合法用法误伤面大，把审查盲区变成功能残废；② 检测「`cd xxx &&` 前缀」字符串做拦截——命令串身份脆弱（deepseek 显式否决按命令串做安全边界），且只治前缀形态不治参数形态；③ deepseek 的写权限根沙箱——结构性最优但需 OS 级沙箱（本设计非目标，独立立项）。
- 影响范围：US-BH10；工具描述（rust + builtin-tools 规格）；B-ADR-1 分段器的目录提取扩展；`cwd` 参数的边界审查接线。

### B-ADR-9：受保护目录用「字面模式检测 + 事前 Ask」，不试图替代 TCC

- 背景：桌面宿主未启用 App Sandbox，命令触碰 macOS 受保护目录时引擎静默放行、OS 层弹 TCC 系统授权——产品权限体系被整体绕过，用户看到不知来由的系统弹窗（品牌与体验双重损伤）。
- 决策：在命令评估阶段做字符串级受保护目录模式匹配，命中即按沙箱外路径语义 Ask（面板如实告知将触碰系统受保护目录），复用 Ask + grant 管线；检测的定位是「高频字面形态的事前知情」，不是强制边界——诚实边界（变量拼接不可见）写入描述。
- 被否决备选：① 无所作为——系统弹窗继续以宿主名义出现，产品权限体系名存实亡；② 运行时路径追踪/沙箱拦截——等价于实现 OS 级沙箱（非目标）；③ 开 App Sandbox——改变整个桌面应用的安全模型与文件访问方式，工程量与兼容性风险不成比例。
- 影响范围：US-BH11；doctor 潜在检查项（系统设置预授权建议，登记为后续跟进）。

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 复合命令拆段误判（引号内 `&&`） | 该段保守视为不匹配 → 进询问，不拒绝执行；误判代价是多一次弹窗，不是错误放行 |
| 命令级刻面使既有会话批准记忆失配（旧记忆存裸 `Bash`） | 裸工具名匹配语义保留（`match_permission_rule` 无 arg pattern 时按工具名匹配），旧记忆继续生效 |
| 刻面串被解析为通配或否定模式（命令含 `*` `?` 或以 `!` 开头） | 刻面生成时对 glob 元字符与 `!` 前缀转义为字面量（B-ADR-1） |
| 敏感剔除误伤构建所需变量 | 豁免清单 + 工具描述披露过滤行为；模式只覆盖四个高置信词 |
| 环形缓冲丢弃关键头部信息（如测试统计头） | 丢弃量披露行 + 既有落盘恢复路径不变 |
| 交错合并改变输出字节序影响既有测试 | 某一流为空时逐字节等价；双流测试用例按到达序断言 |
| 后台 append_output 增量频率带来的写放大 | chunk 粒度沿用前台泵的 8 KiB 块，append_output 自带内存上限与落盘路径，无新增上限面 |
| `exempt_lifetime` 规格补登记与 wire 契约快照 | 参数表登记即可，schema 已是现状（无 wire 变更） |
| 静默预警误报（长编译本就静默，误报一次 = 一次注入 = 可能一个空闲 turn 的 token 成本） | 事实性文案不判死活；默认阈值 5 分钟且可配置可关闭；每静默周期 edge-triggered 一次，绝不周期重复 |
| 静默预警污染终态通知的「恰好一次」语义 | 通道分离：预警走合成消息注入 + 驱动循环内存去重，不进终态通知账本（§4.8） |
| 文案放开检查后模型滥用轮询 | 完成仍靠通知 + 频率锚点入文案 + block=true 劝阻保留（B-ADR-7） |
| 分页窗口切碎 UTF-8 多字节字符 | 窗口起点向后对齐字符边界（§4.7） |
| 取消保全路径遗漏（取消路径不止一条） | 先写红测试覆盖「运行中累积输出 → 取消 → 日志可读」再修 |
| cd 目标提取的变体遗漏（`cd..` 无空格、子 shell 内 cd） | 子 shell `(cd x && ...)` 不影响宿主目录、语义上无审查必要；`cd..` 类变体由受保护目录/路径模式检测兜底；未知变体按普通命令段处理（命令级授权仍生效） |
| 受保护目录检测误报（路径含字面子串） | 误报代价是一次 Ask + 面板明示原因，不是错误放行；模式限定完整路径形态（`~/Desktop`、`/Users/*/Desktop`），不匹配正文内子串 |
| TCC 检测造成用户两次确认（产品 Ask + 系统 TCC） | 面板如实预告；一次目录授权后产品侧不再问，TCC 授权由 macOS 持久化管理——第二次起只剩单层 |
| `cwd` 参数审查误伤既有工作流（模型惯用绝对 cwd） | 引导文案与审查同批落地（B-ADR-8 第 1+2 层）；workspace 外 cwd 本就是沙箱外路径语义，Ask 带 grant 是既有产品惯例 |

## 7. 成功标准（可测量）

1. 命令级授权：`Bash(git status)` 规则命中 `git status` 调用、不命中 `git push`；`Bash(rm *)` deny 规则命中 `rm -rf /tmp/x` 并拦截（集成测试断言）。
2. 复合命令：批准 `git status && ls` 后相同命令重跑不再询问；`Bash(git *)` 覆盖 `git status && ls` 的两段。
3. 内存保护：失控输出命令（如 `yes`）前台执行 60s，引擎 RSS 增量 < 10 MiB。
4. 凭证卫生：带 `FOO_API_TOKEN` 的宿主环境中 `env` 命令输出不含该变量（除非豁免）。
5. 后台增量：后台任务运行中，任务输出读取面可见尾部增量。
6. 零回归：单流命令输出逐字节等价；既有 Bash 契约快照通过。
7. 运行中可观察：运行中任务的 TaskOutput 快照含运行时长/静默时长/总字节数；分页可读任意区间且 manual 模式免审批；TaskList 行含运行时长与静默时长。
8. 静默预警：静默 5 分钟的任务收到恰好一次事实性通知；恢复输出再静默可再次触发；用户面板同步可见静默标记。
9. 取消保全：取消后 TaskOutput 可读到取消前的部分输出。
10. 执行目录：`cwd` 指向沙箱外目录时进 Ask；`cd /outside && cmd` 的 `/outside` 同样进 Ask（参数与 cd 双轨同权）；`cd src && git status` 的命令规则匹配串仅为 `git status`。
11. 受保护目录：`ls ~/Desktop` 在命令执行前进产品侧 Ask，面板明示将触碰系统受保护目录；同目录一次授权后会话内不再重复询问。

## 8. Rollout

1. **批次 1（P0）**：US-BH1 命令级授权 + US-BH2 环形缓冲 + US-BH3 凭证卫生 + US-BH6 规格收敛 + **US-BH7 运行中可观察性**（分页 + 进度信号 + TaskList 信号 + 文案改写同批——文案与判据必须同批落地：只给许可不给判据等于没给）+ **US-BH10 执行目录三层防线**（引导 + cwd 审查 + cd 提取与 B-ADR-1 分段器同一实现面，同批交付）——同批 PR（rust core 为主，规格文档同改），changeset `minor`。
2. **批次 2（P1）**：US-BH4 后台输出增量 + US-BH5 交错合并 + **US-BH9 取消保全**（bug-fix 级，先红后绿）+ **US-BH8 静默预警**（依赖 US-BH7 的 `last_output_at` 打点；先决条件：通道分离、config 阈值、限 Process kind 三点写入实现计划）+ **US-BH11 受保护目录检测**（依赖 US-BH10 的评估阶段接线）——独立 PR，US-BH9 changeset `patch`、US-BH8/11 与 US-BH4 `minor`。
3. 上线一个观察期后复测 §7；命令级授权的使用率（规则命中数 vs 弹窗数）、静默预警的误报率、受保护目录 Ask 的触发频率与 TCC 弹窗的减少率决定是否进入下一批（如 cd 目标目录纳入外部目录审批、PowerShell 工具同款硬化、Agent 类任务的静默语义、doctor 的 TCC 预授权检查项）。

## 9. 与相邻域的边界

| 相邻面 | 分工 |
|---|---|
| approval 域 | 本设计只生产 Bash 的刻面与匹配语义；刻面匹配的消费（会话记忆、用户规则、面板选项）归 approval 域的既有管线，本设计不重复定义；「只围写不围读」的权限哲学若立项归该域 |
| background-tasks 域 | 任务注册/结算/生命周期天花板（US14.4）语义不变；本设计只改输出增量接线（append_output 路线）、任务查询工具的可见信号与前台窗口输出的内存形态；任务作用域推送流若立项归该域 |
| config 域 | `env_allowlist`、`silence_warn_secs` 新键的登记归 config 域惯例，本设计同批登记 glossary 并引用 |
| glossary | AP3「审批刻面」的 Bash 例句更新为命令模式形态（同批修订）；`env_allowlist` 若达收录标准同批登记 |
| PowerShell 工具 | 共享执行骨架与环境继承现状，凭证卫生等同类硬化**不在本批范围**，登记为后续跟进项（Rollout §3） |
