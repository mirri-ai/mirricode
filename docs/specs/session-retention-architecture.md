# 会话归档存储管理 — 架构设计（面向 Rust 核心）

> 状态：v2 基线 · 2026-10-23 · 待需求评审后校准 ·
> 本文是会话归档存储管理域设计侧的唯一事实源（内部规格文档，不进文档站构建，中文单语）。
> 需求契约：见 [session-retention-requirements.md](session-retention-requirements.md)（本设计的验收依据）；现状证据见 [session-retention-context.md](session-retention-context.md)；执行状态见 [session-retention-ROADMAP.md](session-retention-ROADMAP.md)。
> 引擎分层锚点：`rust-core-design/00-overview.md`（mirri-core 内核 / mirri-session-index 存储 / mirri-persistence 存储原语 / mirri-embedded 接线）。
> 术语规范：SR1 自动压缩、SR2 归档时点、SR3 压缩态（含压缩时点）、SR4 档位清理、SR5 附件回收的唯一定义见 [glossary.md](glossary.md)；S 域术语（S2 归档会话、S5 会话日志、S4 会话索引、S1 会话恢复）沿用会话持久化域。

## 1. 目标与设计原则

本设计描述**终态**：Rust 核心及配套界面中会话归档存储管理域的完整架构。设计原则（对应需求编号）：

1. **策略与存储分离**：压缩判定是策略（"何时压缩谁"），压缩/删除是存储原语（会话持久化域能力上的扩展）。策略层不直接摸文件，存储层不理解天数（US1.2、US2.1）。
2. **删除只有人工入口**：删除全部由用户动作（管理页/RPC）驱动，后台任务与自动判定路径**不存在删除分支**（SR1 铁律，US3.3/US3.4）。
3. **只读扫描、单向推进**：自动路径的每个动作都是可逆的（压缩可还原）；判定基于持久化事实（归档时点），不是内存状态（US1.2、US2.5）。
4. **并发安全优先于吞吐**：与另一进程赛跑时宁可跳过本轮（US5.1）。
5. **崩溃安全复用既有原语**：压缩与删除的落盘走临时文件 + 原子替换；删除顺序沿用既有删除路径（先目录后索引行，既有孤儿收敛覆盖），中途崩溃不留第三态（US2.1、US3.3）。
6. **默认即无操作**：配置缺省时压缩任务不被装配（不是装配后空转），保证"不开启 = 行为与现状一致"（US1.1）。

## 2. 域模型与数据流

### 2.1 压缩管线（自动路径，只压缩）

```
进程就绪 ──延时(常量,见§8)──► 检查周期开始 ──每 H 小时──► 扫描 ──► 判定 ──► 压缩 ──► 休眠
```

- **扫描**：由接线层（embedded，索引持有方）从会话索引（S4）取归档候选（`archived = 1`），逐条读磁盘元数据核实（索引是缓存、磁盘是事实源——持久化域原则），注入 core 的清理引擎。候选排除：运行态会话表中的会话。
- **判定**：纯函数——输入（归档时点、当前时刻、归档压缩天数 N），输出（不处理 / 压缩）。无删除分支（原则 2）。
- **执行**（锁内重验）：拿目录锁（§5）后、动作前**重读 state.json 重验候选条件**——仍 `archived = 1` 且磁盘形状为非压缩态才执行压缩（候选核实与拿锁之间存在他进程恢复归档/压缩的窗口，重验闭合之）。单条失败记日志跳过，不中断批次。
- **立即压缩**（US3.1 管理页行内操作）：绕过天数判定，走同一压缩原语、同一目录锁与同一锁内重验（重验条件：会话存在且磁盘形状为非压缩态），当轮生效。

### 2.2 删除管线（手动路径，RPC 驱动）

```
管理页/客户端 ──RPC──► 删除(单条) / 批量清理(档位) ──► 同一删除执行体 ──► 附件联动回收(SR5)
```

- **单条删除**：**新增**管理页单删 RPC（embedded 路由，§4 管理页 API 组件）；复用既有删除**存储顺序**（先目录、后索引行——与既有 workspace 清空路径同序），索引行即时删除（而非懒收敛），并在尾部追加附件联动回收。既有删除存储函数（`delete_session_files` + `SessionIndex::delete_session`）继续作为执行体的底层原语。
- **批量清理（档位）**：服务端按"已压缩天数 > 档位"筛选（判定纯函数同款时间计算，从压缩时点起算），逐条调用同一删除执行体；部分失败逐条回报（US3.4）。
- **入口收敛**（SDR-004）：附件回收是删除执行体的内建行为，**所有删除入口**（本域管理页单删/档位批删、会话列表删除、工作区清空、ACP 删除）收敛到同一执行体——任何入口删除会话后附件回收语义一致，杜绝"删了没降"绕过。
- **幂等收敛**：目录删除中途失败（IO/权限）留下的部分删除状态，由下一次删除尝试收敛（重删即清尾）；不依赖后台修复任务。
- 两条入口收敛到**同一执行体**，杜绝两套删除语义。

### 2.3 状态机（单会话视角）

```
active ──归档(写 archivedAt)──► archived ──归档压缩天数到期──► compressed(SR3)
                                    ▲                              │ │
                                    │ 恢复归档(还原+清标记) ◄────────┘ │
                                    │                                ▼
                                    └── 恢复归档(仅清标记)        删除(仅手动: 管理页/档位批量)
```

## 3. 数据契约

### 3.1 元数据新增字段：`archivedAt`、`compressed`、`compressedAt`

`state.json`（跨引擎共享文档，字段集归会话持久化域 §4.1 管辖）新增三个可选字段，**所有权与写入方在本域、字段登记回写持久化域**（见该域 ADR 修订，及本域 ADR-006）：

| 字段 | 形态 | 写入时机 |
|---|---|---|
| `archivedAt` | RFC 3339（读取端兼容 epoch 毫秒，与既有时间字段同规则） | 归档时写、恢复归档时清空、再归档时重写；存量归档无此字段时由压缩检查首次遇到补写为检查时刻（SDR-008） |
| `compressed` | 布尔 | 压缩原子替换成功后写、还原完成后清 |
| `compressedAt` | RFC 3339（同上双拼法） | 与 `compressed` 同批写；档位清理的"已压缩天数"从它起算 |
| `preCompressedSize` | 正整数（字节数） | 与 `compressed` 同批写（压缩前 wire 日志体积，"压缩节省量"的依据）；还原完成时与 `compressed`/`compressedAt` 一并清除（避免"还原 → 再压缩"间字段悬空） |

- 会话索引（S4）同步新增 `archived_at`、`compressed`、`compressed_at` 列（行从磁盘派生、可重建——持久化域自愈规则覆盖）。
- 老版本引擎读到这些字段按"不认识的字段透传保留"（持久化域既有规则），不丢字段。
- **压缩态判定唯一真值源：磁盘形状**（`wire.jsonl.gz` 在且 `wire.jsonl` 不在 → 压缩态；反之非压缩态；`state.json` 的 `compressed` 标记是缓存）。所有消费方（扫描、恢复、读路径、列表）共用这一判定；标记与形状不一致时以形状为准并自愈补写标记（ADR-007）。
- **压缩节省量**（管理页列）：`compressedAt` 写入时记录压缩前字节数 `preCompressedSize`（同批写入 state.json），当前占用即时读盘；节省量 = preCompressedSize − 当前 wire.jsonl.gz 大小（US3.1）。

### 3.2 配置段：`[retention]`

个人配置文件新增顶层段（全部子项可缺省，缺省 = 功能关闭）：

| 键 | 类型 | 缺省 | 语义 |
|---|---|---|---|
| `enabled` | bool | `false` | 自动压缩总开关（US1.1） |
| `archive_grace_days` | 正整数（≥1） | `30` | 归档压缩天数（US1.2） |
| `interval_hours` | 正整数（≥1） | `24` | 检查间隔小时数（US1.2） |

- 校验失败逐项回退：天数/间隔不合法 → 该项用默认值；`enabled` 解析失败 → 视为 false（US1.2、US6.1）。
- 段缺失或 `enabled = false`：压缩任务不装配（原则 6）。
- 登记要求：`KNOWN_CONFIG_TOP_LEVEL_KEYS` 白名单 + wire 层 round-trip（`rust/crates/mirri-core/src/config/wire.rs`）两道工序（context §6）。
- **无删除相关配置**（原则 2）：不存在 `delete_after_days`；档位集合（30/90/180/365）是产品常量，非配置（US3.4、非目标）。

### 3.3 压缩态的磁盘形态（SR3）

- 会话目录内：`wire.jsonl` → `wire.jsonl.gz`（gzip 单文件，流式压缩，临时文件 + 原子替换）；`state.json`、`snapshot.json` 不动。
- 压缩量级承诺（US2.1 的"一小部分"）：JSONL 文本日志 gzip 后为原始体积的一小部分，量级按实现批次实测固化到测试断言（如断言样例日志压缩后 < 50%），不在本设计锁死具体数字（避免漂移基线）。
- **读路径 gzip 感知**（ADR-001）：`JsonlAppendLog` 的读契约扩展为双形态流——未压缩走现有路径；压缩态经流式 gzip reader 逐行读（内存占用与文件大小解耦）。所有读消费方（重放折叠、回放、导出、搜索、ACP 读取）经由该统一入口，无一旁路（US2.2）。
- **写路径强制未压缩形态**（ADR-004）：任何追加写入（恢复归档后继续干活）之前，若磁盘形状为压缩态，先解压还原回 `wire.jsonl` 再追加。
- **复制（fork）拒斥**（SDR-003）：复制管线入口检查源会话压缩态——压缩态返回明确业务错误（带用户可读提示语），不触发解压、不产生残缺产物（US2.3）。

### 3.4 附件引用与回收（SR5）

- **引用提取范围**：会话目录内**全部**记录流与检查点——主 `wire.jsonl(.gz)`、`agents/<agent_id>/wire.jsonl(.gz)`、`snapshot.json`（折叠状态可含附件引用）。漏任何一个都会误删共享附件。
- **存活判定**：惰性反查清单（ADR-003）："哈希 → 引用会话数"的进程内缓存，可丢弃重建（非正确性依赖）。删除会话时扣减计数；计数归零时记录**归零时刻**。
- **老化窗口锚点 = 引用计数归零时刻**（ADR-003，闭合 TOCTOU）：附件文件删除条件 = 反查清单归零时刻距今超过 T（T = 常量，量级为小时级，实现批次定死并写入测试）。锚点必须是"归零时刻"而非文件创建时间——内容寻址附件不可变，创建时间恒早于窗口，对"他进程复用旧附件"零保护；而复用必然写入新引用并使计数离开零，重置锚点。跨进程的"存在检查 → 日志落盘"毫秒级残余窗口由 T 的量级覆盖（他进程的引用在归零后 T 内落盘即可被下轮复核看到）。
- **复核宿主**：附件复核（检查归零超 T 的附件并删除文件）**搭载在自动压缩的检查周期上**（同一后台任务的尾段步骤；功能关闭时无周期、也无新归零产生——已归零项保持暂留，符合一致性单向边界）。删除执行体内即时回收仅针对"清单已归零且超过 T"的项；未过窗口的项留给周期复核，**不存在无人认领的附件**。
- **一致性单向边界**：允许"附件暂留"（多占空间、不损坏），不允许"附件已删而引用仍在"（US2.4）。

## 4. 组件与分层

| 组件 | 所属 crate（分层锚点） | 职责 |
|---|---|---|
| 压缩任务（retention task） | mirri-embedded（接线层，孤儿治理任务同模式） | 装配、延时启动、周期调度、启动随机抖动、日志 |
| 扫描候选供给 | mirri-embedded（索引持有方） | 从 S4 索抽取归档候选、磁盘核实、运行态排除，注入清理引擎 |
| 清理引擎（retention engine） | mirri-core（内核） | 压缩判定纯函数、执行编排、存量补写 `archivedAt`；**不含索引访问**（索引在 embedded） |
| 删除执行体 + 档位批量 | mirri-embedded（RPC 层） | 单删（**新增** RPC）/批删收敛、所有删除入口统一（含既有列表删除/工作区清空/ACP 删除）、附件回收触发、逐条成败回报、删除动作日志（US3.5：哪条会话、做了什么、何时） |
| 压缩/解压原语 + 双形态读 | mirri-persistence（存储原语层） | gzip 流式压缩/解压、原子替换、压缩态探测、gzip reader |
| 附件引用清单（blob ledger） | mirri-core（附件服务同层） | 全量引用提取（含 agents 流与 snapshot）、反查计数、归零时刻记录、老化窗口复核（搭载压缩检查周期） |
| 配置段 | mirri-core（config） | `[retention]` 解析、校验、缺省、白名单登记 |
| "已压缩"标识与压缩元数据面 | wire 协议（mirri-proto）+ 索引行 + `SessionInfo` | 列表/搜索/管理页的压缩态呈现（US2.1 第 4 条、US3.1） |
| 管理页 API | mirri-embedded（RPC 层） | 归档/压缩两视图列表 RPC（含占用、节省、已压缩天数；**占用口径**：会话目录内全部文件——`wire.jsonl(.gz)` + `snapshot.json` + `state.json` + agents 子目录——的磁盘字节数；**确认框释放量口径**：会话占用 + 独占附件估算，明示附件部分随后回收）、立即压缩、单删、档位批删、当前策略读取（US3.5 策略提示的载体） |

- 依赖方向：embedded → core → persistence，与既有分层一致；清理引擎对持久化域的依赖仅限公开存储契约。
- 管理页的排序/统计（占用降序、已压缩天数）由 RPC 响应携带完整数据，客户端本地排序（列表规模 = 用户归档量，无需服务端排序协议）。

## 5. 并发与锁策略（US5.1）

分三档，越靠前越便宜：

1. **候选排除**（主要手段）：运行态会话表中的会话不进入候选；跨进程场景下，会话是否活跃的探测 = **尝试获取会话目录的 advisory lock**（能拿到即无人持有动作锁 → 视为非活跃；拿不到 → 有人正在执行动作，跳过）。注意：**锁文件的存在性不是活跃信号**（锁文件常驻目录、崩溃后残留，只有锁持有状态有意义）。
2. **目录级互斥**（兜底，ADR-002）：对即将压缩/还原/删除的会话目录持有 `lock` 文件 + OS advisory lock（`flock`/`LockFileEx`）：拿不到 = 本轮跳过（US4.2"跳过不是终局"）。锁文件本身是会话目录内固定名文件，进程崩溃即释放（OS 语义）；持有窗口 = 单个动作完成，秒级以内。这是**新增**设施（现状无目录级跨进程锁），所有权归持久化域原语层（登记回写，见 ADR-006）。**锁内重验**（§2.1）：拿锁后重读 state.json 确认候选条件仍然成立（会话运行态的追加写入不持锁，"核实 → 拿锁"窗口内他进程可能已恢复归档并开始写入；重验兜住该窗口——重验时该会话已在运行态表中，条件不成立即放弃动作）。
3. **动作原子性**：压缩/还原用临时文件 + 原子替换；删除沿用既有"先目录后索引行"顺序（目录删除中途失败由下一次删除尝试幂等收敛，见 §2.2），崩溃残留由既有启动孤儿收敛（目录已删的行清除）覆盖，零新增机制（US3.3 的"不半删"）。

**多进程同时压缩**：检查周期启动延时随机抖动（分钟级）天然错开；同时到达时目录锁保证同一会话只被处理一次（第二个进程拿到"目录已锁/已变更"即跳过）。

**压缩 vs 恢复方竞态**（US5.1 第 2 条）：恢复归档走还原流程也先拿目录锁——恢复方拿不到锁 = 压缩进行中，等待或失败重试；压缩方拿不到锁 = 恢复进行中，本轮跳过。任一顺序下用户看到的都是完整形态（前或后），无半成品。

## 6. 恢复（取回）路径（US1.3、US2.2）

```
恢复归档请求
  └─► 拿目录锁
        └─► 磁盘形状判定: 压缩态?
              ├─ 否 ──► 清 archivedAt + 清标记（既有路径，零变化）
              └─ 是 ──► 解压还原 wire.jsonl.gz → wire.jsonl（临时文件 + 原子替换）
                         └─► 删 .gz ──► 清 compressed/compressedAt ──► 清 archivedAt + 清标记
                               └─► 进入 S1 会话恢复（既有路径）
```

- 还原完成前不清任何标记——中途崩溃的结果是"仍是压缩归档态"，恢复动作幂等可重试。
- 还原后该会话与从未被压缩的会话在数据形态上不可区分（日志内容逐字节等价）。

## 7. 崩溃恢复与自愈矩阵

所有收敛都是既有检查流程的一部分，无独立修复任务。磁盘形状是压缩态唯一真值源（§3.1），所有行先按形状归位、再自愈补标记。

| 中断点 | 留下的状态 | 收敛动作 |
|---|---|---|
| 压缩写临时文件中 | 原样未压缩 + 临时文件残留 | 重新压缩（临时文件覆盖）；持久化域"临时文件不可见"规则兜底 |
| 压缩原子替换后、标记写入前 | `.gz` 已在、`compressed` 标记缺失 | 形状判定为压缩态 → 补写标记 |
| 还原：`wire.jsonl` 已建、`.gz` 未删 | 双文件并存 | 形状判定：`.jsonl` 在 → 非压缩态；删残留 `.gz`、清标记 |
| 还原：`.gz` 已删、标记未清 | 非压缩态形状、标记残留 | 形状判定非压缩态 → 清标记 |
| 删除：目录已删、索引行残留 | 孤儿索引行 | 既有启动孤儿收敛（目录已删的行清除）覆盖，零新增 |
| 删除：目录删除中途失败（IO/权限，非崩溃） | 部分文件已删、目录残留 | 删除执行体幂等收敛：下一次删除尝试（用户重试或档位批删重入）清尾；用户重试前该会话在列表中呈现但读取按缺省降级（持久化域损坏容忍规则） |
| 删除：目录已删、附件未回收或未过老化窗口 | 附件暂留 | 压缩检查周期尾段的附件复核步骤（§3.4 复核宿主）：归零超 T 即删 |
| 附件文件删除中 | 不适用 | 文件删除是原子操作 |

## 8. 性能与开销

- **扫描**：索引起点，只读归档会话元数据；不触碰未归档会话。
- **压缩**：gzip 流式，固定缓冲区，内存与文件大小解耦；后台线程低优先级，不与用户操作争抢（US4.1）。
- **附件反查清单**：首次全量构建（流式扫描所有存活会话全部记录流），之后增量维护；缓存可重建。
- **启动延时**：首查延时常量（分钟级）+ 随机抖动（多进程错峰）；不配置化（避免配置面膨胀）。
- **管理页列表 RPC**：单页拉取全量归档/压缩会话元数据（含占用统计）。规模假设：归档量为千条级；超万条的分页需求出现时另行立项（非目标边界）。

## 10. 决策记录

### ADR-001 压缩态读路径：统一双形态流（新增，补 v1 空洞）

- **日期**：2026-10-23
- **背景**：v1 设计只覆盖了写路径还原与恢复路径，只读消费（查看、导出、搜索、ACP）被当成免费赠品，无设计面（评审 Defect 1）。US2.2 的 P0 验收要求压缩态不解还原地透明消费。
- **决策**：`JsonlAppendLog` 读契约扩展为双形态流（未压缩原路径 / 压缩态流式 gzip reader），作为持久化域原语；全部读消费方（重放折叠、回放、导出、搜索、ACP）经由统一入口，无一旁路。fork 是唯一例外——入口直接拒斥（SDR-003），不走读路径。
- **备选**：各消费方各自解压读（N 处重复逻辑、易漏）；读时透明解压到临时文件（多一次全量落盘，长会话慢）。
- **影响范围**：§3.3；持久化域读契约扩展（ADR-006 登记项）。

### ADR-002 目录级跨进程互斥：lock 文件 + OS advisory lock（新增，补 v1 空洞）

- **日期**：2026-10-23
- **背景**：v1 的"文件锁（或等价的探测-确认窗口）"未裁决；持久化域无既有目录锁设施，"活跃标记"不存在（评审 Defect 2）。US5.1 四条 P0 验收全部依赖此机制。
- **决策**：会话目录内固定名 `lock` 文件 + OS advisory lock（进程崩溃即释放）。压缩、还原、删除三类动作前必须持有；拿不到即本轮跳过/等待。所有权归持久化域原语层，本域登记回写（ADR-006）。锁文件对既有消费方不可见（不读它的代码无感）。
- **备选**：改造 snapshot 语义当运行标志（改变既有契约语义，侵入大）；集中式全局锁表（单点、跨进程状态难维护）。
- **影响范围**：§5；持久化域新增原语（ADR-006 登记项）。

### ADR-003 附件回收：惰性反查清单 + 归零时刻锚定的老化窗口（修订 v2，闭合 v1 TOCTOU）

- **日期**：2026-10-23（v2 修订：锚点从文件时间改为归零时刻，补复核宿主）
- **背景**：跨进程删除附件与"他进程新建引用"存在 TOCTOU；v1 的"文件 mtime 早于 T"锚点失效——内容寻址附件不可变，mtime = 创建时刻，老附件的 mtime 恒早于 T，窗口对其零保护。"下轮复核"无宿主（删除是一次性 RPC）。
- **决策**：反查清单记录每个附件哈希的**引用计数归零时刻**；文件删除条件 = 归零时刻距今超过常量 T（小时级）。他进程复用必然写入新引用使计数离开零、重置锚点；毫秒级残余竞态（存在检查与日志落盘之间）由 T 的量级覆盖。**复核宿主**：压缩检查周期尾段（功能关闭时无新归零产生，已归零项保持暂留，符合单向边界）。引用提取范围显式包含 agents 子记录流与 snapshot。
- **备选**：文件 mtime 锚点（v1，上述失效）；全量重扫代替复核（正确但每次删除全量 IO）；持久化引用计数表（自身一致性维护成本，违背"磁盘是唯一事实源"）。
- **影响范围**：§3.4、§7。

### ADR-004 写路径强制未压缩形态

- **日期**：2026-10-23
- **背景**：压缩态会话被恢复归档后继续使用时，可选持续压缩态读写或一次性还原。
- **决策**：恢复归档即完整还原为 `wire.jsonl`，工作态会话永远未压缩。保证压缩前后行为严格一致（US2.2 的逐字节等价验收）。
- **备选**：持续压缩态读写（双形态逻辑侵入所有读写路径，回归面不可控）。
- **影响范围**：§3.3、§6。

### ADR-005 gzip 整文件压缩而非分块/列式格式

- **日期**：2026-10-23
- **背景**：会话日志是追加式 JSONL。压缩可选整文件 gzip、zstd 分帧、列式存储。
- **决策**：整文件 gzip（`wire.jsonl.gz`）。实现与恢复语义最简（一次性原子替换/还原）；JSONL 文本压缩率高；压缩态只读（写路径强制还原，ADR-004），不需要随机追加。
- **备选**：zstd 分帧（"可边追加边压缩"能力因 ADR-004 无用武之地，徒增依赖）；列式存储（改变文件形态，跨引擎兼容成本高）。
- **影响范围**：§3.3。

### ADR-006 持久化域契约回写（新增，治 v1 违规）

- **日期**：2026-10-23
- **背景**：本域实际扩展了持久化域三个资产：`state.json` 字段集（`archivedAt`/`compressed`/`compressedAt`/`preCompressedSize`）、索引 schema（三列）、附件存储删除语义（原 ADR-007"删除不连带清理附件"修订为"条件联动回收"），以及新增目录锁原语。v1 未回写被依赖域（评审 Defect 6）。
- **决策**：以本 ADR 为指针，在 `session-persistence-architecture.md` 追加修订记录：字段登记（§4.1 表）、索引列登记、附件联动回收修订（其 ADR-007 影响面）、目录锁原语登记；所有权声明——字段写入方为本域（归档/压缩动作的副产物），存储布局与版本链仍归持久化域。
- **备选**：字段所有权归持久化域（写入时机全是本域动作，域外维护语义割裂）；不回写、靠本域文档单向声明（治理规则禁止）。
- **影响范围**：§3.1、§3.4、§5；`session-persistence-architecture.md` 修订记录。

### ADR-007 压缩态判定唯一真值源：磁盘形状（新增，治 v1 双真值源）

- **日期**：2026-10-23
- **背景**：压缩态有两个候选真值源（state.json 标记 vs 磁盘文件形状），v1 只为扫描器定义了形状优先，恢复路径只看标记，读路径无规则（评审 Defect 7）。崩溃矩阵的还原路径行缺失。
- **决策**：磁盘形状是唯一真值源（`.gz` 在且 `.jsonl` 不在 → 压缩态），所有消费方（扫描、恢复、读路径、列表）共用；标记是缓存，不一致时形状优先并自愈补写。崩溃矩阵覆盖还原路径两个中断点（§7）。
- **备选**：标记为真值源（标记写入失败即状态错乱）；双真值源按场景选择（回到 v1 缺陷）。
- **影响范围**：§3.1、§3.3、§6、§7。

### ADR-008 分层：索引访问归 embedded，core 不依赖 session-index（修订，治 v1 矛盾）

- **日期**：2026-10-23
- **背景**：v1 组件表把含索引扫描的清理引擎放在 mirri-core，但代码事实是 mirri-core 不依赖 mirri-session-index（索引由 embedded 持有）（评审 Defect 3）。
- **决策**：扫描候选供给在 embedded（索引持有方，converge 逻辑同侧），取出候选后注入 core 清理引擎；core 保留判定纯函数与原语编排，不做索引读写。索引行删除归 embedded 的删除执行体。
- **备选**：core 新增对 session-index 的依赖（打破既有分层）；扫描整体上移 embedded（判定逻辑散落接线层，不可独立测试）。
- **影响范围**：§2.1、§4。

### ADR-009 域独立与交付范围

- **日期**：2026-10-23
- **背景**：对应 SDR-007。v1 曾把 UI 后置，评审指出 P0 验收（列表"已压缩"标识）与无 UI 交付矛盾；且删除手动化后，管理页是删除的唯一入口，与管理页是一体的。
- **决策**：独立域；第一批交付核心 + 界面（网页端为准绳、桌面同构、终端标识）。复用持久化域全部存储契约与原子原语，不重复定义（跨域扩展经 ADR-006 回写登记）。
- **备选**：并入持久化域（范围稀释，SDR-006 已论）；仅核心后置 UI（P0 无法闭环）。
- **影响范围**：本文档与需求文档的立项结构、ROADMAP 批次。
