# Provider 凭据（provider-credential）需求文档

> 状态：v4（SDR-005：D.5 自动上报接线裁决；Epic G 补 G.8 通知刷新） · 2026-10-28 ·
> 本文档是 provider 凭据管理功能形态的唯一事实源（内部规格文档，不进文档站构建，中文单语）。
> 运行目标为 **Rust core + web/ACP**（TypeScript core 处于退役线，不为其做计划）。
> 技术机制见 [provider-credential-architecture.md](provider-credential-architecture.md)（下称「架构文档」）；现状盘点（代码事实、竞品调研）见 [provider-credential-context.md](provider-credential-context.md)（下称「context 文档」），本文不重复。
> 验收标准统一采用「假如-当-那么」三段式（Given-When-Then 的中文形态）。

## 0. 领域边界

**本域覆盖**：用户为「调用大模型供应商」而持有的密钥（API key）的完整生命周期——集中保管、更新覆盖、通过命令行与界面管理、运行时统一取用、失效后的状态呈现与重授权引导、从旧配置的一次性迁移。

**不在本域**（引用相邻域，不重复定义）：

| 相邻域 | 边界划分 |
|---|---|
| auth-oauth（用户身份认证） | 平台账户登录（设备码流、托管账户）的**流程**归 auth-oauth 域；本域只提供登录成功后的令牌**保管基建**（值类型的存储槽位）。托管登录当前已全线退役（该域 SDR-004），本域不因它阻塞。 |
| model-settings（模型设置页） | 设置页的**界面容器**（供应商详情页布局、表单组件）归 model-settings（其 US-6 的目标态即本域 Epic G 的落点）；本域定义凭据管理的全部操作语义与数据契约。 |
| mcp（MCP 服务器认证） | 远程 MCP 服务器自身的 OAuth 授权归 mcp 域；本域只管「模型供应商」的密钥。 |
| 服务访问鉴权 | 本地守护进程自身的访问凭证（server token）是服务运行域，不是供应商凭据。 |
| non-functional（遥测） | 凭据操作的遥测事件命名归遥测面；本域只定义「哪些事件必须可观测」。 |

**术语表**（域内规范名；跨域术语的登记见 glossary「PC. Provider 凭据域」节，本文为其域内视图）：

| 规范名 | 形态/示例 | 含义 | 禁止的叫法 |
|---|---|---|---|
| 凭据库 | 用户数据目录下的独立保管区 | 全部供应商密钥的唯一存放地；与普通配置文件物理分离 | ~~密钥文件~~、~~auth.json~~ |
| 凭据条目 | 一条密钥记录，含类型、创建时间 | 凭据库的最小管理单元；每个供应商恰有一条（SDR-004） | ~~账户~~、~~凭据槽位~~（多密钥时代的历史词） |
| 外部凭据引用 | 记录「密钥在本机某个云命令行工具里」 | 凭据库只存引用不存密钥本体 | ~~CLI 凭据~~、~~托管密钥~~ |
| 凭据回读 | 在终端显示某条凭据的完整内容 | 供用户核对的显式动作，区别于界面上的掩码展示 | ~~导出~~（另有整库迁移语义） |

## 1. 角色与场景总览

- **P1 · 换密钥用户**：密钥轮换、渠道办错了、换了新账号——需要把某供应商的密钥换成另一把，期望覆盖后即生效、不用重启。
- **P2 · 脚本与无头用户**：在 CI / 远程 / 无浏览器环境经命令行参数化操作凭据；以及所有需要**核对密钥明文**的用户（回读只在命令行，SDR-002/SDR-003）。
- **P3 · web/desktop 用户**：**日常管理的主用户群**——在设置页完成凭据的查看、更新、移除与状态关注；桌面端是 web 的外壳，行为一致。
- **P4 · 云 CLI 用户**：本机已通过 `az` / `gcloud` 等云厂商命令行登录，不希望把长期密钥再抄进产品。
- **P5 · 审慎用户**：想随时核对「产品到底在用哪把密钥、密钥内容是什么」，确认没有配错或泄错。

**功能闭环**（每个环节都是验收点，任何一环缺失即闭环未合拢）：

```
保管（密钥集中入库存放）
  → 管理（CLI / 设置页更新与移除）
  → 消费（会话调用模型时统一取用该供应商的凭据）
  → 核对（用户可回读密钥内容验证）
  → 失效呈现（调用被拒 → 明确的"需重新配置"状态与行动指引）
  → 迁移（旧配置中的密钥一次性、幂等地搬入凭据库）
```

## 2. Epic A：凭据库（每供应商一条，SDR-004）

作为 P1 用户，我给供应商换密钥后新密钥立即生效，不用重启、不用改文件；旧密钥不留副本。

- **A.1 集中保管**：供应商密钥存放在用户数据目录下的**独立凭据库**中，与普通配置文件（可分享、可进版本管理的那份）物理分离；普通配置文件里不再出现密钥明文。
- **A.2 每供应商一条**：每个供应商在凭据库中**恰有一条**凭据条目（可为空）；不存在多密钥并存、激活切换（SDR-004 砍除）。
- **A.3 添加即覆盖**：为已有凭据的供应商添加新密钥 = **覆盖**该条目（旧密钥即被替换，不留副本、不需先删后加）；原先没有凭据则新建。类型随添加值而定（密钥本体 ↔ 外部引用互换同理）。
- **A.4 更新即时生效**：**假如**我把供应商 S 的密钥从 A 换成 B、**当**保存完成，**那么** S 的**下一次模型调用**即使用 B；进行中的请求不中断、不重发。
- **A.5 移除**：移除供应商的凭据后，该供应商回到「未配置密钥」状态（不是报错，不是残留半删状态）。
- **A.5b 删除供应商的级联**：**假如**我删除供应商 S（在设置页或配置中）、**当**删除完成，**那么** S 的凭据条目一并移除——不产生孤儿条目；万一出现孤儿（如外部改配置），读取时跳过并在诊断中告警。
- **A.6 环境变量旁路保留**：通过环境变量供给密钥的老用法继续有效（作为「不落库的临时凭据」参与解析，见 D-M3 解析链）；界面在供应商连接清单中如实显示该来源。
- **A.7 一致性事件**：凭据的新建、更新、移除发出全局通知，正在运行的会话与界面据此刷新（更新的生效语义即 A.4）。

## 3. Epic B：命令行管理面（辅助面：回读、无头与脚本）

作为 P2 用户，我在终端核对密钥内容，并在无浏览器/无服务环境管理凭据。终端交互以**无交互子命令**形态交付——不含 TUI 斜杠命令（既有 TUI 短期不维护，rust 内核 TUI 就绪后经同一服务层另行接入，SDR-003）。

- **B.1 列表**：命令列出全部凭据——供应商、类型（密钥 / 外部引用）、创建时间；**不显示密钥内容**。
- **B.2 添加/更新**：命令以交互方式（或管道传入）为供应商设置密钥；密钥输入不回显；供应商已有凭据时为覆盖（A.3）。
- **B.3 移除**：命令移除指定供应商的凭据（A.5 语义）。
- **B.5 回读（P5 核心诉求）**：**假如**我显式执行回读命令指认某条凭据、**当**命令运行，**那么**终端显示该凭据的**完整明文内容**，供我核对；直接输出到终端（非管道）时，先打印一行「输出包含密钥明文」的警示。对外部凭据引用执行回读时输出其**引用配置**（来源与参数）并提示「该条目不持有密钥本体，请到来源工具核对」。
- **B.6 非交互可用**：全部子命令支持参数化（供应商以参数给出），脚本与管道可用；仅密钥本体从标准输入读取，不出现在命令行参数中。
- **B.7 错误诚实**：指认不存在的供应商时，错误列出**当前有凭据的供应商清单**，不是裸「未找到」。


## 4. Epic G：Web 管理界面（第一管理面）

作为 P3 用户，我在 web 设置页（桌面端为其外壳）完成凭据的**全部日常管理**——这是本产品当前唯一受维护的图形界面，管理体验必须完整（SDR-003）。

- **G.1 凭据状态**：设置页供应商详情呈现其凭据信息——类型（密钥 / 外部引用 / 未配置）、外部来源在场状态、凭据健康状态（D.1 口径）；不出现密钥明文。
- **G.2 更新**：Web 表单为供应商设置凭据——输入新密钥，或登记外部凭据引用（C 组语义）；已有凭据时为覆盖（A.3）。
- **G.3 移除**：移除供应商凭据（A.5 语义）；删除供应商的级联语义同 A.5b。
- **G.4 状态呈现**：「需重新配置」状态以供应商级徽标呈现并附行动指引（D.1）；徽标来源 = 凭据状态查询与变更通知刷新（G.8）；换密钥后徽标即时消失（D.2）。
- **G.5 明文不出现在 web**：Web 面编辑密钥**只写不读**——编辑框对已有密钥留空（不回显、无掩码预填），提交新值即覆盖；密钥明文核对走命令行回读（B.5，唯一明文出口）。
- **G.6 依赖服务在线**：Web 面经服务端接口操作，要求服务在运行（与命令行直连不同，Web 不提供浏览器直读凭据库文件的服务外路径）。
- **G.7 通知刷新**：凭据变更通知（`credential.updated`）到达时，设置页刷新受影响供应商的凭据状态与徽标——用户在另一入口（命令行）换密钥后，打开中的设置页不重启即反映（A.7 的 web 消费面；订阅走专用通道，不受「无会话事件默认过滤」影响）。

## 5. Epic C：外部凭据引用

作为 P4 用户，我复用本机云命令行已登录的身份，不把长期密钥抄进产品。

- **C.1 引用而非复制**：为供应商登记一条**外部凭据引用**（指明密钥来源为本机哪个云命令行及必要参数）后，凭据库**不保存任何密钥本体**；需要密钥时由产品在调用现场向该来源实时取用。
- **C.2 与普通密钥平等**：外部引用是一条普通凭据条目（类型不同），同样适用 Epic A 的更新、移除与即时生效语义。
- **C.3 来源缺失的呈现**：**假如**供应商的凭据是外部引用、**当**其来源工具在本机不可用或未登录，**那么**调用失败呈现为**该来源不可用**的明确错误（含「请先完成该工具登录」指引），不表现为「密钥错误」。
- **C.4 范围**：本批至少覆盖 Azure CLI（Azure OpenAI）；其它云命令行（gcloud 等）按同一契约扩展，不另立机制。

## 6. Epic D：失效呈现与重授权引导

作为用户，密钥失效时我看到的是「哪里坏了、下一步做什么」，而不是含糊的调用报错。

- **D.1 失效状态**：供应商的连接信息中呈现凭据健康状态——正常 / **需重新配置**（调用被拒且原因在凭据）；「需重新配置」状态下附**行动指引**：指明可去终端凭据命令或设置页的供应商密钥编辑两处任一更新密钥。
- **D.2 即时恢复**：状态即时重算、无需重启——换上新密钥后状态即恢复。
- **D.3 界面一致**：web 设置页供应商列表与终端列表呈现同一状态语义（同一枚举，各自适合的展示形态）。
- **D.4 会话内引导**：模型调用因凭据被拒而中断时，会话错误信息包含指引（供应商名 + 去哪里更新密钥），不重复技术细节。
- **D.5 自动上报（SDR-005）**：**假如**模型调用因凭据被服务端拒绝而失败、**当**该失败定局（不再重试）、**那么**该供应商的状态**即时**变为「需重新配置」（无需等任何界面轮询）；上报覆盖全部轮次来源（交互、后台任务、定时、目标），不漏报、不重复打扰（同一供应商的连续失败只维持状态，不重复计次）。

## 7. Epic E：迁移与兼容

作为存量用户，升级后我的密钥自动进入凭据库，无感可用。

- **E.1 自动迁移**：首次以新机制启动时，普通配置文件中已有的供应商密钥被**搬入**凭据库（成为各自供应商的凭据条目），随后普通配置文件中的密钥字段**清除**；未搬完不删、搬完才清，中断后重跑安全。
- **E.2 幂等**：迁移可重复执行——已存在于凭据库的供应商跳过入库，**不产生重复条目**；但若该供应商在配置文件中的密钥字段因上次中断而未被清除，重跑时仍执行清除（清理最终一定完成）。
- **E.3 宽松解析**：迁移读取旧密钥时对无法识别的条目**跳过并告警**（告警注明：该密钥不迁移也不再参与解析，需手动处理），不因个别畸形条目放弃整体迁移。
- **E.4 环境变量不迁移**：经环境变量供给的密钥保持原样（A.6 旁路继续有效），迁移只处理写死在配置文件里的密钥。
- **E.5 手动迁移与预览**：用户可通过命令手动触发迁移；预览模式（不落盘）列出将迁移的供应商清单（仅供应商标识，**不含密钥明文**）。
- **E.6 迁移后手写密钥的兜底**：**假如**迁移完成后用户又在配置文件里手写了密钥、**当**服务下次启动，**那么**该密钥被自动迁移入库并清除字段（启动期迁移每次启动都检查，不是只跑一次）。

## 8. Epic F：非功能需求

- **F.1 明文存储（SDR-002 裁决）**：凭据库以明文存放，**不做**系统钥匙串 / 静态加密；安全边界 = 本机文件权限（凭据库目录仅所有者可访问）+ 产品内不回显。存储格式**预留每条凭据的加密形态声明**（本批恒为「明文」）——为未来的加密演进留出格式空间，不因此引入任何当前行为。
- **F.2 回读是唯一明文出口**：除 B.5 的显式回读外，任何界面、列表、日志、遥测、错误信息、网络接口**不出现密钥明文**；普通配置读取面维持既有脱敏规则；**供应商错误报文中可能回显的密钥片段在进入任何展示前先经脱敏**；会话内的文件读取工具对凭据库文件维持既有「敏感文件需问询」保护。
- **F.3 并发安全**：多个进程（服务 + 终端命令同时操作）对凭据库的读写不产生半条记录或丢失更新（同一时点至多一个写者落盘）。
- **F.4 损坏容错**：凭据库文件损坏时按「空库」处理并告警，不崩溃、不阻断服务启动；用户可凭备份或重录恢复。
- **F.5 可观测**：凭据新建 / 更新 / 移除 / 迁移完成是可观测事件（不携带密钥内容）。
- **F.6 平台覆盖**：文件权限收紧在 Windows 上尽力而为，机制不因平台缺失而不可用。

## 9. 契约级裁决

- **D-M1 凭据库唯一持久真值**：供应商密钥只存凭据库一处；普通配置文件与凭据库不互相复制。被否决备选：密钥继续留在普通配置文件中、凭据库仅作索引（否——「配置文件可安全分享」这一用户价值即建立在密钥不在其中）。
- **D-M2 明文可回读、不加密（SDR-002）**：终端提供显式回读命令输出密钥明文；不做系统级加密存储。被否决备选：a) 系统钥匙串（Keychain / DPAPI）——跨系统对接测试成本高，本批不做；b) 只回显脱敏提示（尾 4 位）——不满足「核对密钥内容」的诉求（详见 SDR-002）。
- **D-M3 解析链保持三级**：供应商密钥解析顺序 = 凭据库该供应商凭据 → 供应商配置中的环境变量表 → 按供应商类型约定的系统环境变量；三级都无则按现状报「供应商无凭据」。配置文件中的密钥字段**从解析链中移除**——迁移（Epic E，含启动期自动重检）是它唯一的安全网。被否决备选：a) 字段层保留为链中一级（否——「配置文件可分享」建立在密钥不在其中，保留一级等于密钥可以回来）；b) 废除环境变量旁路只认凭据库（否——无头/CI 场景的既有用法不破坏）。
- **D-M4 值类型三选一**：凭据条目的值类型为 **key**（密钥本体）、**external**（外部引用）、**oauth**（平台登录令牌，保留槽位，随托管登录恢复时启用）；本批实现前两种。被否决备选：只做 key（否——云 CLI 引用是明确诉求）。
- **D-M7 每供应商一条凭据（SDR-004）**：砍除多密钥并存与激活切换——每供应商恰一条，添加即覆盖。被否决备选：a) 保留多密钥 + 标签 + 切换（否——真实使用从未出现该需求，而激活标记、接任规则、级联、标签唯一性、web/CLI 切换交互的复杂度全部由它派生，性价比不成立）；b) 保留存储多条、UI 只暴露一条（否——死数据面，违背 R5 可用性诚实）。真需求出现时按提案 P-5 重启。
- **D-M5 失效状态为运行时视图**：「需重新配置」不落盘——只存在于进程内的连接状态视图，凭据变更即重算。被否决备选：把失效写进凭据记录（否——重启后状态陈旧，且多进程写放大）。
- **D-M6 管理面共享一套语义（SDR-003 修订）**：**web 设置页是第一等管理面**——Epic G 全语义（状态 / 更新 / 移除）经服务端方法交付；命令行面重定位为辅助，保留三类不可替代场景：密钥回读（B.5，唯一明文出口）、无头 / 脚本、服务未运行时的直连管理。两者走同一服务层语义，不各自直改文件。TUI 面本批不做（既有 TUI 短期不维护，rust 内核 TUI 就绪后经同一服务层接入）。设置页「编辑密钥」（model-settings US-6）的目标态即写入凭据库。

## 10. 验收标准（汇总）

| # | 验收项（假如-当-那么） |
|---|---|
| V1 | **假如**供应商 S 已有凭据 A、**当**我添加凭据 B，**那么** B 立即替换 A（库里仍恰一条），**下一次模型调用**即使用 B（A.3/A.4） |
| V2 | **假如**供应商凭据被移除、**当**移除完成，**那么**供应商呈未配置态，调用报「无凭据」而非崩溃（A.5） |
| V3 | CLI 回读命令 → 终端输出该凭据完整明文；直连终端时先警示；列表命令 → 任何输出不含明文（B.1/B.5/F.2） |
| V4 | 密钥经环境变量供给 → 调用成功，界面显示来源为环境变量（A.6） |
| V5 | 登记外部引用 → 凭据库文件中无密钥本体字段；来源工具在场时调用成功；来源缺席 → 错误含该来源登录指引（C.1-C.3） |
| V6 | **假如**模型调用因密钥被拒、**当**失败定局，**那么**供应商状态即时变「需重新配置」+ 行动指引；换密钥后状态即恢复（D.1/D.2/D.5） |
| V7 | 存量配置文件含密钥 → 首启自动入库存档并从配置文件清除；重复执行不产生重复条目且清除最终完成；畸形条目跳过并告警；迁移后再手写密钥 → 下次启动自动补迁移（E.1-E.3/E.6） |
| V8 | 两进程同时写凭据库 → 后写者基于最新状态落盘，无半条记录；CLI 直写后 server 下一次解析即见新值（F.3） |
| V9 | 凭据库文件被人为写坏 → 服务正常启动、按空库告警（F.4） |
| V10 | 普通配置文件（迁移后）不再含密钥明文；其读取面维持既有脱敏（D-M1/F.2） |
| V11 | 删除供应商 → 其凭据条目一并消失；出现孤儿条目 → 读取跳过且诊断告警（A.5b） |
| V12 | 迁移预览命令输出 → 仅供应商标识，无密钥明文（E.5） |
| V13 | web 供应商详情 → 呈现凭据类型、健康状态与外部来源在场态，无密钥明文（G.1） |
| V14 | web 更新 / 移除凭据 → 语义与命令行完全一致（A.3/A.5），状态徽标即时刷新（G.2-G.4） |
| V15 | web 面任何展示与操作 → 不出现密钥明文；编辑已有密钥时表单留空不回显（G.5） |

## 11. SDR 记录

- **SDR-005（2026-10-28）**：401 自动上报的接线裁决（补 D.5）。背景：O-5 侦察确认——失败轮次在引擎侧可判 `provider.auth_error`，但**供应商归因在整条错误上抛链上都不可见**（模型适配器构造层知道 provider，却无任何回传面；事件与错误体均无 provider 字段）。决策：为模型适配器（`Llm` trait）增加 `provider_id()` 访问器（构造时注入，见架构 ADR-009），失败上抛时把 provider 归因随错误带出（经 `EngineError::ProviderAuthError` 的结构化字段）；embedded 在轮次失败的统一出水面（fire 事件发布点与 wait 模式错误返回点）识别该归因并调内部上报。被否决备选：a) `SessionEvent::TurnFailed` 加 provider_id 字段（否——wait 模式交互轮次不走 TurnFailed 事件而走 message.send 错误响应，只改事件漏掉主路径）；b) embedded 侧反查「model alias → provider」（否——错误上抛点没有 config 句柄，且 fire/cron/goal 各分支重复反查）。影响范围：D.5、V6、架构 §6/ADR-009、core 的 Llm trait 与错误结构。
- **SDR-004（2026-10-28）**：砍除多密钥并存与激活切换。背景：建域初稿采纳了竞品（opencode）的「每 integration 多凭据 + active 激活标记」模型；复审发现该能力对所有原始动机（密钥与配置分离、CLI 回读、外部引用、失效呈现、免重启换 key）均非必需，且激活切换、接任规则、标签唯一性、供应商删除级联、web/CLI 切换交互等近半数复杂度由它独自派生；用户确认长期使用中从未出现同供应商多账号切换需求（竞品 Claude Code / Codex / Cursor 同为单 key per provider）。决策：每供应商恰一条凭据，添加即覆盖（D-M7）；存储格式保持条目数组的形态（天然兼容未来放开多条，无需格式迁移）；真需求出现按提案 P-5 重启。被否决备选：保留多密钥（否——复杂度即时压在第一批实现上，后砍比先砍贵）；存储层保留多条但 UI 只暴露一条（否——死数据面）。影响范围：Epic A（重写）、B.2/B.3、G.1-G.5、C.2、F.5、V1/V2/V13/V14、架构 §1/§2/§3/§5.3/ADR-001、glossary PC2。
- **SDR-003（2026-10-28）**：管理面主次重定——web 优先。背景：既有 TUI 短期不维护，rust 内核 TUI 未就绪，产品 UI/UX 以 web（desktop 外壳）为主；原 D-M6 把 web 面限定为「写入方向、切换走 CLI」与管理体验诉求不符。决策：新增 Epic G（web 管理界面）为第一管理面——清单 / 添加 / 切换 / 移除 / 状态全语义；命令行面重定位为辅助（密钥回读、无头 / 脚本、服务未运行场景）；TUI 面本批不做，rust TUI 就绪后经同一服务层接入。被否决备选：a) 维持 web 仅写入方向（否——web 是当前唯一受维护 UI，切换都要回终端不成立）；b) web 管理交互整体归 model-settings 域（否——操作语义与数据契约是本域的，彼域只出界面容器）。影响范围：Epic B 定位、Epic G（新增）、D-M6、V13-V15、架构 §0/§5.3/映射表、ROADMAP 批次。
- **SDR-002（2026-10-28）**：明文存储、终端可回读（D-M2/F.1/B.5）。背景：调研建议「列表接口不回明文 + 系统钥匙串加密」；用户裁决：跨系统加密对接的测试成本高，本批不做；同时需要能通过命令行核对密钥内容。决策：凭据库明文存放，权限边界为本机文件权限；终端提供显式回读命令（唯一明文出口，F.2）；系统钥匙串列为未来增强提案，不在本批。被否决备选：a) 系统钥匙串为默认（否——用户裁决）；b) 只回脱敏尾缀（否——不满足核对诉求）。影响范围：F.1、F.2、B.5、D-M2。
- **SDR-001（2026-10-28）**：建域。背景：供应商密钥此前混存于普通配置文件，无法多密钥并存、无法即时切换；竞品调研（见 context §2）显示独立凭据库 + 激活标记 + 外部引用是成熟解法。决策：新建 provider-credential 域，采纳「独立凭据库 / 多凭据激活 / 外部引用 / 失效状态呈现 / 迁移兼容」五项能力为终态需求；运行目标为 Rust core + web/ACP，TS core 退役线不承载本域。被否决备选：在 model-settings 域内扩展（否——凭据生命周期与设置页交互是两层，且 auth-oauth 域已被托管登录退役钉死为历史基线）。影响范围：全部条目。

## 12. 未来增强提案（非本批能力）

- **P-1 系统钥匙串后端**：凭据库增加系统级加密存储选项，默认仍明文（SDR-002 显式保留的后续路径）。已预留的承接面：每条凭据的加密形态声明（F.1）——落地时按**操作系统选择后端**（macOS Keychain / Windows DPAPI / Linux libsecret，主密钥管理方式随之不同）、可选**加密算法**；滚动迁移期间明文与加密条目**混合并存**（逐条重写，非整库切换）；未知形态按损坏容错不猜测。
- **P-2 oauth 值类型启用**：托管账户登录恢复时（auth-oauth 域），其令牌落入凭据库的 oauth 类型槽位，与 key/external 同享更新、移除与即时生效语义（D-M4 预留）。
- **P-3 整库导出/导入**：跨机器搬移全部凭据（带 TTY 警示，语义同回读），供 P-5 之外的迁移场景。
- **P-4 更多外部来源**：gcloud / AWS SSO 等按 C.4 契约扩展。
- **P-5 多密钥并存重启**：SDR-004 砍除能力的重启路径——若真实用户反馈出现同供应商多账号切换需求，按「条目数组 + 激活标记」恢复（存储格式已兼容，无需迁移）。
