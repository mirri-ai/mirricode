# 用量可见性（usage-visibility）— 架构与实现机制

> 本文档描述用量与缓存命中率可视化的目标态机制、数据流与接口形状。现状代码证据（file:line）与参考产品（DeepSeek Harness）差异分析见 [usage-visibility-context.md](usage-visibility-context.md)。需求语义与裁决见 [usage-visibility-requirements.md](usage-visibility-requirements.md)（SDR-001/002/003）。动机仅以抽象问题陈述保留，不携带代码事实。

## 1. 总体结构

用量可见性由四层组成：

1. **计量层（rust 内核）**：每次模型请求完成时，每步用量（四桶：未缓存输入 / 输出 / 缓存读取 / 缓存写入）以排他口径（未缓存输入不含命中部分）写入会话记录（wire op），归一由各供应商适配器完成。
2. **聚合层**：两条同源路径——
   - **会话级**：wire 重放时的状态折叠把四桶累计进代理状态（持久，天然免疫历史裁剪与恢复）；活会话的实时累计由引擎内用量服务维护，两路在恢复时刻无缝衔接。
   - **回合级**：按「回合开始 → 下一回合开始」窗口内的已完成步用量求和，从 wire 折叠派生。
3. **服务层**：用量查询接口（`agent.getUsage`）输出 klient 方言的四桶累计 + 按模型分组 + 能力描述；会话用量更新事件向客户端推送增量。
4. **呈现层**：web 统计条（会话级）；web 回合用量胶囊 + 明细面板（回合级）。浏览器与桌面应用复用同一呈现面。

数据流向：

```
模型请求完成（供应商适配器归一四桶）
  → wire 用量记录（每步，持久，恢复即重放）
     ├─→ 状态折叠累计（会话级四桶总数，随恢复重建）
     │     └─→ agent.getUsage（klient 方言 + 按模型分组 + 能力位）
     │           └─→ SDK / 客户端
     ├─→ 引擎内用量服务（活会话实时累计；恢复时由折叠回填）
     └─→ 回合窗口折叠（回合级四桶求和）
           └─→ 用量更新事件（带回合归属）→ 客户端
呈现层：web 统计条（会话级）
        web 回合胶囊 + 明细面板（回合级）
```

### 设计动机（抽象）

- **会话记录即持久投影**：会话记录是 append-only、恢复即重放的事实源，重放折叠天然产出全程累计——不需要为「统计免疫裁剪」再造一层投影（参考产品为此专门造了持久投影单元，因其会话窗口可分页且压缩改写窗口；本产品重放机制已覆盖该需求）。
- **两条派生路径、一个口径**：会话级允许边流边累计（请求失败前的早期采样已入账），回合级在回合关闭后一次性折叠——可靠性策略不同，但分母与聚合单位完全一致，两侧数字可互相校验。

## 2. 指标计算

### 2.1 缓存命中率（SDR-001 的技术形态）

```
命中率 = 缓存读取 / 计费输入
计费输入 = 未缓存输入 + 缓存读取 + 缓存写入
```

- 三桶为排他口径（供应商适配器保证未缓存输入不含命中部分），直接相加无重复计价。
- 计费输入与引擎的上下文压力口径同源（压力 = 计费输入 + 输出；本域分母去掉输出），两套数字不打架。
- 无计费输入（分母为 0）→ 指标为空，呈现层不渲染。

### 2.2 反假全命中格式化

- 部分命中在目标精度下舍入到 100 时，精度逐级加深（整数 → 1 位 → 2 位……），保证显示值严格小于真实值；显示值与真实值的差构成诚实区间。
- 真实全命中（未缓存输入 = 0 且缓存写入 = 0）→ 显示 100。
- 计数两档：紧凑格式（`517 / 12.2K / 1.2M`，用于回合胶囊）与精确格式（千分位分组，不舍入，用于明细面板与会话级统计条的各段，见 ADR-004）。
- 会话级精度 2 位小数（SDR-004）；回合级 1 位（受本规则加深）。

### 2.3 缺报即省略

- 可选构成（缓存读取 / 缓存写入 / 推理子集 / 模型归属）在聚合结果中是**可选字段**：某次计费请求未上报 → 聚合结果中该字段不存在 → 呈现层省略对应行。不存在「显示 0」或「显示 N/A」的兜底路径。

### 2.4 冷启动后命中率（SDR-004）

- 展示层计算：`（缓存读取 − 首调缓存读取）/（计费输入 − 首调计费输入）`，分子分母同时剔除首调。
- 首调快照在内核 reducer 折叠 `usage.record` 时捕获（累计为零的首条），随会话状态持久化；恢复会话时回填用量服务的首调基线，刷新页面时由快照续算。
- 首调口径 = 主代理的首条模型调用（非全代理汇总）；未知或单次调用时省略该指标。

## 3. 聚合规则

### 3.1 会话级（累计）

- **替换式累计**：同一步的重复采样替换而非累加；重试产生新的采样行，按尝试累加。
- **活会话**：引擎内用量服务在每步用量回调处累计（含按模型分组、当前回合进行中累计）。
- **恢复**：重放折叠的累计值回填用量服务；恢复前后的累计无缝衔接。
- **聚合范围（SDR-002 终态）**：主代理 + 会话内全部子代理。子代理的会话记录在主记录的代理子目录中，会话级聚合读全量；呈现的「当前回合」只指主代理的当前回合。

### 3.2 回合级（窗口折叠）

- **窗口定义**：一个回合开始标记 → 下一个回合开始标记之间的全部**已完成步**。
- **求和单位是步**：每步的四桶相加得到回合四桶。已完成的步计入；中断留下的悬空开始标记不计入、不臆造。
- **全有或全无**：窗口内存在无法归属的步（跨回合混入、顺序错乱）时，该回合的明细整体降级——不渲染面板，而不是渲染部分真相。
- **归属**：回合记录自带代理标识，子代理回合归子代理；模型归属按步的模型字段聚合去重。

### 3.3 供应商能力（SDR-003 的技术形态）

| 供应商族 | 缓存读取 | 缓存写入 | 推理子集 |
|---|---|---|---|
| Anthropic 系（显式缓存） | 上报 | 上报 | 不适用 |
| OpenAI 兼容（含网关） | 上报 | 协议不存在 | 视上游 |
| Google 系 | 上报 | 协议不存在 | 视上游 |

- 「缓存写入」行只在 Anthropic 系渲染；族归属由供应商类型静态判定（配置期已知）。
- 用量查询接口携带能力描述（是否上报缓存写入），SDK 消费方无需自行试错。

## 4. 呈现层形态

### 4.1 会话级（浏览器与桌面应用同一呈现面）

- **组序**（`|` 分隔，阅读优先序）：`回合/步数计数` | `缓存命中率` | `冷启动后命中率` | `缓存读取` | `未缓存输入` | `缓存写入` | `输出`。
- **丢弃规则**（三套独立判定，不混用）：
  - *缺报*：某桶未被供应商上报 → 该段不存在（§2.3）。
  - *累计为零*：缓存写入为零 → 该段不存在（ADR-004 c）；缓存读取为零 → 该段显示 `0`（ADR-004 d）。
  - *宽度不足*：按价值从低到高舍弃——先舍回合/步数计数与冷启动后命中率，再舍输出段，再舍输入构成三段（缓存读取 → 未缓存输入 → 缓存写入）；`缓存命中率` 与 `未缓存输入` 恒保留。悬停始终可查看完整行。
- 输入构成按计价档位分段（ADR-004）：三个输入桶各自成段，不提供三桶合计的单一「输入」数字；输出独立成段。
- 会话级统计条各段计数采用精确千分位格式（ADR-004）；回合胶囊采用紧凑格式。
- 不与上下文占用合并（一个事实一个家）。终端呈现面重建时遵循同一组序与门槛。
- **Web 统计条**：输入区附近常驻；更新由会话用量更新事件驱动；悬停显示完整行。

### 4.2 回合级

- **胶囊**：回合尾部操作行的数据库图标 + 紧凑总量标签；点击弹出锚定面板（视口钳位、Escape/外点关闭、对话框语义）。
- **行清单与条件**：见需求 US2.2 的逐行表（恒有：标题/精确总量/未缓存输入/输出；条件：模型、命中率、缓存读取、缓存写入、推理附注）。
- **终端呈现面**：重建时经回合详情对话或斜杠命令查看（终端无点击交互，胶囊降级为命令输出中的回合摘要行）。

## 5. 架构决策记录（ADR）

### ADR-001（2026-09-17）不新建投影层：wire 重放折叠为会话级统计的唯一事实源

- **背景**：参考产品（DeepSeek Harness）为「统计免疫分页与压缩」专门实现了持久会话投影单元，因为其会话窗口可分页、压缩会改写窗口内容。
- **决策**：本产品会话记录 append-only 且恢复即重放，状态折叠的累计即持久投影——会话级统计**只从重放折叠与引擎内用量服务读取**，不为统计再造第三份状态。活会话的实时性由用量服务补足（恢复时由折叠回填）。
- **被否决的备选**：①照搬参考产品的独立投影层——双份真相、双份失效模式，重放机制已覆盖其全部诉求；②纯客户端现场累加——裁剪/翻页即失真，且每端各写一份。

### ADR-002（2026-09-17）回合级折叠锚定在步求和，而非回合边界事件

- **背景**：回合开始/完成的事件流存在已知缺口（归属字段缺失、事件族未收口），而每步用量记录在 wire 上是成对、带步标识、恢复可重放的。
- **决策**：回合窗口 = 回合开始标记到下一回合开始标记，求和单位是**已完成步**；悬空开始标记（中断遗留）不计入。窗口不完整（无法归属的步）时整个回合明细降级不渲染。
- **被否决的备选**：①依赖回合完成事件携带聚合——事件族先要收口，链路长；②容忍部分归属渲染部分数据——呈现不完整的回合账单违反诚实性。

### ADR-003（2026-09-17）供应商能力静态判定，不做运行时零值推断

- **背景**：「未上报」与「真实的 0」在传输数据上不可区分（字段缺省写 0）；但供应商类型在配置期已知。
- **决策**：「缓存写入」行的渲染条件、用量查询的能力描述，均由供应商类型静态判定（Anthropic 系 = 上报写入）。不引入「连续 N 次为 0 视为不报」之类的启发式。
- **被否决的备选**：①运行时启发式——不可靠且带状态；②统一显示——向隐式家族用户呈现不存在的概念（详见 SDR-003）。

### ADR-004（2026-11-01）会话级统计条按计价档位分桶，写入段以非零为显示门槛

- **背景**：会话级统计条把三桶输入合计成一个数字呈现。但三桶的计价档位相差一个数量级，合计值被便宜的那一档主导，用户无法从数字本身判断花在贵档还是便宜档；而命中率只知道比例、不知道绝对量。（动机详见 SDR-005。）
- **决策**：a) 会话级统计条的输入构成拆为三个独立分组（缓存读取 / 未缓存输入 / 缓存写入），三桶合计数字不再上屏；命中率分母与精度规则（§2.1、§2.2）完全不变，「计费输入」作为命中率分母的口径术语保留。b) 输出独立分组。c) **缓存写入段的显示门槛是会话累计值非零**——为零即整段省略。会话累计值单调不减（只经饱和累加、无回退路径），所以「为零」在语义上等价于「本会话从未发生过写入」，不存在先显示后消失。代价：显式缓存族在尚未发生写入时看不到 `写入 0`，与回合级明细按 ADR-003 静态家族判定的行为不同——本域接受这一差异，因为会话统计条没有逐桶明细分层可兜底，而回合面板有。d) 缓存读取段不设非零门槛：真实的零是「一次都没命中」的可断言事实，照常显示。e) 会话级各段（输入三桶、输出、回合/步数计数）采用精确千分位格式；回合胶囊维持紧凑格式。f) 分段投影是共享库里的纯函数（返回各桶数值与门槛判定，不含文案），组件只做 locale 映射——与回合胶囊的分层同构。g) 呈现面为 web 统计条（桌面壳复用同一界面）；终端呈现面重建时须遵循同一组序与门槛。
- **被否决的备选**：①新增「价码当量」单值——需要产品内维护按模型的计价倍率表，倍率漂移会让数字静默失真，违反本域不做金额保证性换算的边界；②只拆「命中 / 未命中」两段——把标准价与写入价混成一格，藏起冷启动瞬间金额最高的写入档；③合计与拆分并列——同一事实两个数字，窄屏下拆分反而先被截断；④为写入段立即引入「会话→供应商缓存族」映射——需要跨越内核传输边界新增会话级能力事实，超出本次呈现层改动的范围，非零门槛已能保证不撒谎（详见 SDR-005）。
