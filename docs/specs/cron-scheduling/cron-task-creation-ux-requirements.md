## 0. 定位与范围

**本文管什么**：用户在管理面**直接创建**工作区定时任务时的创建表单——表单的信息架构、字段清单、交互细节与验收。用户直建是阶段二 D.0c 裁决的路径（用户自己的产品面，自己的动作就是授权，**无需任何审批**）；本表单是该路径的产品落地。

**本文不管什么**：

- **Agent 发起的创建路径**：改善批次 C2 已下线「提议-审批」包装，改为高危操作审批直建（SDR-124 回写登记）；其审批面的呈现不在本文范围——本文只管用户直建；
- **会话内定时器**（Agent 的延时回调工具；改善批次 A7/C1 后无用户创建面）——不在本文范围；
- **任务列表、运行记录、通知等管理面其余部分**（阶段二 Epic C/E）——例外（本文只立口径、版式仍归阶段二）：任务列表/详情的「上次/下次/下下次三时刻常驻呈现」（§3.6，SDR-112）、表单版式与主操作锚点（§3.7，SDR-115/118）、列表卡片元信息聚拢（§3.8，SDR-119）、状态词集与终态语义区分（§3.9，SDR-120）；
- **编辑已有任务**（改日程/改指示/改环境）不在本文范围——创建表单只管「从无到有」，编辑属管理面扩展，留后续批次；唯一例外：编辑表单的「主操作常驻可见」锚点口径在 §3.7 定（SDR-118）；
- 表单字段到任务数据模型、执行链的**技术映射**（架构文档职责）。

**核心产品主张（SDR-107）**：新建定时任务 = **新建一次 Session 的完整配置 + 一个结构化日程**。用户在新开一个会话时能操作的选项，这个表单都应该给到——用户不应因为「这是定时任务」而被剥夺对执行环境的控制权。

**术语表**（域内规范名；「结构化日程」为跨域术语，已登记 glossary v36 / CS9）：

| 规范名 | 形态/示例 | 含义 | 禁止的叫法 |
|---|---|---|---|
| 创建表单 | 用户直建工作区任务时的配置面 | 一次填写即确定「任务是什么 / 什么时候跑 / 在哪里用什么身份跑」三组信息，提交即建任务（无审批） | ~~新建向导~~（单页表单不是多步向导） |

## 1. 用户与场景

本文服务的角色沿用阶段二文档 §1，动机最直接的两类：

- **P1 · 委托例行工作的用户**：「每天早上替我巡检一遍、有异常叫我」「每周自动 review 一遍攒下的 PR」「每天早上汇总科技新闻给我」——这类用户要么自己直建（本文的表单就是这条路径），要么批准 Agent 发起的高危创建审批（不在本文范围，SDR-124）。直建时他要能一次性讲清楚：做什么（指示）、多久做一次（日程）、用什么资源做（环境）。
- **P2 · 直接排定者**：我在工作区层面排定任务，期望表单给我的控制力与「新开一个 Session」同阶——我能选在哪个工作区、什么权限模式、哪个模型、多深的思考档位里跑——任务按所选工作区的默认目录运行（SDR-121）。

**表单的用户体验基线**：用户此前创建过 Session，就没学过任何新概念——字段名、选择器形态、默认值与 Session 创建面同款（SDR-107）；唯一的新面是「什么时候跑」的结构化日程（SDR-108）。**零 cron 知识假设**：任何用户在不见到一个技术表达式的情况下，能完整配置一个定时任务。

**功能闭环**（表单只占首环，其余引用阶段二）：

```
填写（三区块：任务是什么 / 什么时候跑 / 在哪里用什么身份跑）
  → 提交（校验就地反馈，时机为触犯之后——SDR-114；成功即建，无审批——D.0c）
  → 之后的一切（存活/调度/执行/留痕/收尾）全部沿用阶段二 Epic A-F
```

## 2. 表单信息架构

表单按用户心智分**三个区块**，自上而下回答三个问题。

### 2.1 区块一：任务是什么

- **标题**：任务的显示名。缺省「未命名定时任务」（用户不填则以此入库，管理面如实呈现）；标题用于任务列表、运行记录与通知中的识别，不做唯一性校验。
- **指示（Instructions）**：任务的完整提示词内容，多行文本。标签措辞为「指示」，不使用技术词「Prompt」（用户原话裁决：Label 不用「Prompt」（技术视角），用「Instructions/指示」）。内容即任务每次运行注入执行会话的首条消息，语义等同阶段二的「提示词」，仅呈现层措辞不同。
- 该区块与「循环执行（Recurring）」声明在布局上相互靠近——是否循环与日程属同品类信息（用户原话裁决），归区块二呈现（见下）。

### 2.2 区块二：什么时候跑

- **结构化日程（Schedule）**：任务重复规则的唯一配置入口（SDR-108）。空态只有一个「添加日程（Add Schedule）」按钮；点击展开预设档选择（每小时 / 每天 / 每个工作日 / 每周 / 每月 / 自定义），各档交互见 §3.1。
- **循环执行（Recurring）**：循环性声明与日程选择靠近放置。六档预设选择即隐含「循环执行」；自定义（Custom）档中通过「结束方式（Ends）」显式选择「永不结束 / 于某日期结束」（见 §3.2）。用户不需要单独理解 recurring 概念——日程选择的结果已完整表达循环语义（一次性任务 = 结束日期**恰为首次运行日**的自定义日程——该日在其日程时刻触发一次后即结束，是用户表达「只跑一次」的方式；表单不另设「一次性」开关，见 §3.5 校验口径）。
- **可读描述预览**：日程选择完成后，表单实时呈现一句人类可读的描述（如「GMT+9 Daily at 09:03」）；预览**必须与实际触发语义一致**（见 §3.4，引用既有「显示=实际」原则，R4）。
- **时区**：不是常设输入项（用户原话裁决：必要时才输入）。缺省 = 用户本地时区；该缺省值在预览中**可见**（预览自带时区前缀）；需要改时区的用户点击预览中的时区即可修改，修改后预览立即按新时区重述。时区语义遵循阶段二 D.5（显式值、按任务时区换算呈现，不歧义）。
- **运行时刻预览**：日程选择完成后，表单显示**确切时刻**让用户直观验证日程是否符合预期（见 §3.6，SDR-112/123）——理论过去时刻、下次运行、下下次运行三个推演时刻以一条时间轴呈现，各自带时区标注（与可读描述预览同一时区口径），整体明示「预测 · 基于当前日程推算」——它是推演，不是运行事实。

### 2.3 区块三：在哪里、用什么身份跑

以下四项 = Session 创建面同款的选择器与模式名（SDR-107：用户零学习成本；清单经 SDR-121/122 修订），选择结果**记录在任务上、每次运行时如实生效**（SDR-109）：

- **工作区（Workspace）**：任务归属的工作区，缺省为当前工作区；任务建成后即按阶段二 Epic A 归属该工作区独立存活。
- **权限模式（Mode）**：与新建会话**完全同款、同名、同文案**的三档——逐条确认 / 自动常规 / 自动通过（yolo）；不新增任何档位、不引入「无人值守」等新概念，默认档与新建会话一致（SDR-122）。任务运行按所选模式的规则执法——选了什么就是什么。
- **模型（Model）**：任务运行使用的模型，缺省 = **用户工作区配置的默认模型**（与 Session 创建面的默认同源）；缺省值在表单上**可见**（选择器如实显示当前默认模型名，不呈现空白——用户看得见将用什么跑）；选择器与 Session 创建面同源同款。
- **思考深度（Thinking Effort）**：所选模型的思考档位，随模型选择联动（不支持该能力的模型如实禁用该选项，不呈现可点但无效的控件，R5）。
- **工作目录不由用户配置**：任务按所选工作区的默认目录运行（SDR-121）——「在哪里跑」由工作区这一个选择完整回答。

## 3. 交互细节

### 3.1 结构化日程：六档预设

空态：Schedule 区块只呈现「+ 添加日程」按钮，不预置任何表达式或技术输入。点击后下拉呈现六个选项：

| 预设档 | 用户操作 | 预览示例（时区前缀随实际时区） |
|---|---|---|
| 每小时（Every hour） | 频率 + 「at minute」分钟选择器 | Every hour at :03 |
| 每天（Every day） | 频率 + 「at」时间选择器 | GMT+9 Daily at 09:03 |
| 每个工作日（Every weekday） | 频率 + 时间选择器 | GMT+9 Every weekday at 09:03 |
| 每周（Every week） | 频率 + 星期多选（可多选，如 Mon–Fri）+ 时间选择器 | GMT+9 Weekly on Mon, Tue, Wed, Thu, Fri at 09:03（编译示例：`0 9 * * 1-5`） |
| 每月（Every month） | 频率 + 「Day N」日期选择 + 时间选择器 | GMT+9 Monthly on day 1 at 09:03 |
| 自定义（Custom） | 选择即打开「自定义重复（Custom Repeat）」弹窗（改善批次 A8 裁决），见 §3.2 | 随弹窗配置生成 |

- 已选择日程后，区块标题旁呈现**移除按钮**（垃圾桶图标）——点击即清空日程回到空态（「+ 添加日程」重现），不做确认弹窗（可一键重选，破坏性低）。
- 六档之间的切换 = 重新选择预设档，各档已填的子选项在切换时不保留（避免跨档语义错位）。
- **时间选择器的分钟粒度（SDR-117）**：预设档与自定义弹窗内的时间选择器，分钟粒度为全集（每分钟皆可选，00–59），不设 15 分钟档位限制——想设 09:05 的用户全程停留在结构化路径内，无需绕道技术表达式；选择器的呈现形态（下拉/直接输入）归设计侧。
- 预设档覆盖不了的规则（如「每 3 周跑两周」「到某日为止」）进入 Custom；「每 N 天」类流逝间隔规则在 Custom 以「每 N 天」表达（SDR-113）——五档预设是 cron 可表达的规则，Custom 另承载流逝间隔类规则，两类语义并存于同一弹窗（见 §3.2）。

### 3.2 自定义（Custom）弹窗

选择「自定义」即打开「自定义重复（Custom Repeat）」弹窗——选择即表达意图、无中间确认步骤（改善批次 A8 裁决），弹窗内分两种表达模式（SDR-113）：

- **重复频率（流逝间隔模式）**：数字输入 + 单位下拉（天 / 周 / 月……，单位集随架构扩展）。数字与单位组合表达「每 N 个单位重复一次」——这是**流逝间隔**语义（从首次运行日起每 N 个单位一次），不是 cron 的字段枚举语义（每 N 天 ≠ 每月 N 号），由系统的结构化间隔字段承载（SDR-113），仅此模式可表达「每 2 天」「每 3 周」类规则；间隔数字为 1 时文案不照读——「每 1 天」呈现为「每天」、「每 1 周」呈现为「每周」（间隔 1 是各单位的最常见形态，照读数字生硬、徒增确认成本；语义与实际触发完全等价，SDR-116）。首次运行日 = 提交后日程的第一个计划时刻（表单以预览确认，见 §3.6）。
- **按字段重复（cron 可表达模式）**：每月几号 / 每周几 / 每天几点 / 每小时几分——即五档预设已覆盖的场景在 Custom 内的组合形态（跨预设组合规则时使用）。
- **结束方式（Ends）**：单选——「永不结束（Never ends）」为默认；选「结束（Ends）」时启用**日历选择器**（月历网格 + 月份翻页 + 底部日期 + 取消/确认），选定结束日期。**边界语义（含当日）**：结束日期当天仍执行最后一次——「最后运行在 X 日（含当日）」。该口径继承 #181 既有验收要求「时间语义不歧义」的裁决方向；阶段二 D-M 系列对 end date 边界无既有裁决，本文按「含当日」定（SDR-110），选择结束日期后预览明确呈现「最后运行在 X 日（含当日）」。结束方式对两种模式一致适用（结构化间隔任务同样可设结束日期——每 2 天跑到 X 日为止）。
- **一次性任务的表达（与 SDR-110 统一，勿引入第二种一次性表达）**：一次性 = 结束日期恰为首次运行日的日程（两种模式通用——间隔模式「每 1 天 + 结束日 = 首日」与字段模式的同口径推导等价）。该定义与 SDR-110 的「一次性 = 结束日期恰为首次运行日的自定义日程」完全一致；系统不另设「单次」档或一次性开关（SDR-108 已否决独立开关）。
- **取消 / 确认**：取消则弹窗内的一切改动作废、日程回到弹窗前的状态；确认则弹窗关闭、预览按新日程重述。
- **cron 表达式的位置**：结构化选择是唯一主入口；技术表达式（cron）**不向用户的主路径暴露**，仅作为自定义/高级处的技术形态存在（供确实掌握表达式的用户使用），且其存在不改变结构化选项的完整性（R5：高级入口不可用或残缺即缺陷）。cron 表达式只能表达字段枚举类规则，不能表达流逝间隔（SDR-113）——高级入口对间隔类规则不可用是**语义边界而非缺陷**，该处如实提示。

### 3.3 日历选择器

结束日期选择使用统一的日历选择器（月历网格、月份前后翻页、底部呈现当前所选日期、取消/确认）。它只承担「选一个日期」的职责；日期 + 主表单的时间选择共同构成完整触发时刻。

### 3.4 预览规则（显示 = 实际）

- 预览句式：`[时区] <重复规则> at <时间>`——随用户在六档/自定义中的每次选择**实时重述**。
- **一致性硬约束（R4，引用既有「显示=实际」原则）**：预览描述与任务的实际触发语义**逐字对应**——预览说「Every hour at :03」，任务就在每小时的第 3 分触发；预览说「GMT+9 Weekly on Mon, Fri at 09:03」，任务就在 GMT+9 的周一与周五 09:03 触发。任何用户在表单上读到的描述，都是运行时真实发生的事；不存在「预览这么说、实际那么跑」的缝隙。
- **「显示=实际」的口径边界（jitter 声明）**：预览描述的是**日程计划时刻**；实际触发时刻可能因调度器的防拥塞抖动轻微偏移——周期任务向后偏移最多为「周期的 10% 与 15 分钟中的较小值」，恰落在整点/半点的一次性时刻最多提前约 90 秒（jitter 语义沿用工具文档已公开的口径，cron 归后台任务域 SDR-005/006）。本口径与列表页既有标注同款（「理想时刻，实际投递有防拥塞抖动」）——表单在日程选择区下方以一行轻量说明呈现同款措辞，不在预览句中混入抖动数字。
- 时区改动后预览以新时区重述；后续触发时刻（如「下次运行」）按阶段二 D.5 口径换算到任务时区呈现。

### 3.5 校验与提交反馈

- **就地校验与时机（SDR-114）**：错误信息就地在对应字段呈现，不等到提交后弹全局错误；但时机是**触犯之后**——错误只在用户与字段发生交互之后出现，纯初始空态不显示任何错误。表单刚打开时的空白是「尚未填写」，不是「填错了」。校验时机分三类：a) **失焦校验**——已交互过的字段失焦时即校验（输入后清空、失焦仍为空都在此类）；b) **提交校验**——提交尝试时对全部可校验项（指示为空、自定义频率数字非法、结束日期早于首次可能触发日等）校验，未交互过的空字段此时才首次报错；c) **即时清除**——错误出现后用户修正为合法值，错误即时消失、不残留。
- **结束日期校验口径（与 §2.2 一次性定义统一）**：结束日期**早于**首次可能触发日 = 非法（就地报错「结束日期不能早于首次运行日」）；结束日期**恰等于**首次触发日 = **一次性任务**，合法——预览如实显示「将于 X 日 X 时执行一次后结束」，用户从预览即可看出这只会跑一次；晚于则按多次循环正常预览。**双端校验**：前端就地报错是第一道（体验），服务端创建时的权威校验是第二道（口径同文案）——两道同口径，绕过表单直连通道也无法建出结束日期已过的任务。
- **结束日期的存储与执法**：结束日期不是表单的展示约定——任务**存储该字段**并按其**调度收尾**（最后可触发日为结束日期当天，与含当日口径一致；最后一次触发后任务结束移除）；流失间隔任务同样受结束日期约束。技术承载见架构文档（B1）。
- **提交语义**：提交即建（D.0c，无审批）；成功后任务立即出现在管理面任务列表，标题、日程（预览句式）、时区、环境四项、来源（「用户」）如实呈现（阶段二 E.1 列表口径）。
- **环境生效语义（SDR-109，产品语言）**：任务必须**携带**用户选择的执行环境（工作区/权限模式/模型/思考深度），并在**每次运行时如实生效**——执行会话按所选模型与思考深度起跑、在所选工作区的默认目录中工作、按所选权限模式执法。列表中的环境信息与任务实际携带的一致，不出现「选了 A 跑了 B」。
- **权限模式同名同义**：表单的权限选择器即会话三档本身（SDR-122）——所选的名字与实际执行的规则之间不存在翻译层。

### 3.6 运行时刻预览（确切时刻验证）

用户配置日程的目的是「确认这个规则会在什么时刻触发」——可读描述（§3.4）回答「规则是什么」，**确切时刻**回答「具体哪天几点」。选好日程后，表单在日程区块内呈现基于当前日程的**理论推演**三时刻（SDR-112 立项，SDR-123 修订口径）：

- **理论过去时刻**：假设该日程已经存在，最近的一个理论触发点——它回答「这个规则的周期长什么样」，不回答「过去真的跑没跑」（后者是运行事实，归历史呈现）。过去部分以可区分的样式呈现并标注「理论值」，与未来时刻视觉区分。
- **下次运行（Next run）**：日程的下一个计划时刻。
- **下下次运行（Next next run）**：再下一个计划时刻。其产品意义是**验证周期规律**——用户看到「每周三 09:03」的规则，再看到下次是周三 X 日、下下次是周三 Y 日，即可直观确认「对，确实是每周三」，无需在脑中推算日历。
- **预测明示**：三时刻整体标注「预测 · 基于当前日程推算」——用户必须知道这是预测、不是运行事实。
- **呈现形态**：三个时刻以一条时间轴合并呈现（过去 → 下次 → 下下次）；高频档（如每小时）的过去时刻可省略或弱化（「一小时前」对决策没有信息量），下次与下下次保持完整。
- **一次性任务的如实降级**：一次性规则（结束日期恰为首次运行日，§2.2/§3.5/SDR-110）没有理论过去时刻——过去位呈现「—」，不虚构「已过去」的时点。
- **计算口径（与 §3.4 既有 jitter 口径一致，SDR-111）**：三时刻均为**日程计划时刻**（pre-jitter 理想值）——「显示=实际」原则在既有 jitter 声明边界内适用：显示的是计划时刻，抖动声明（日程选择区下方轻量说明）已告知用户实际投递有防拥塞偏移，不另立口径。
- **时区口径**：每个时刻带明确的时区标注，呈现时刻与所标时区严格对应——用户对「几点触发」的判断只依赖时刻旁的时区，不需要脑内换算；时区改动后三时刻随预览一并按新时区重述，换算遵循阶段二 D.5。
- **事实与预测的分界**：真实的运行历史（真正跑过的记录）只在任务详情的「历史」中呈现——预测不进历史、事实不进预测，两处不混。
- **常驻态（任务列表/详情，同一需求的管理面呈现）**：任务建成后，列表行与详情页同样呈现理论推演三时刻，与表单态同口径（预测明示、时区、计划时刻）；已结束任务的「下次/下下次」如实显示「—」（终态词集见 §3.9）。时刻验证不是表单的瞬时功能，而是任务全生命周期的常驻信息。列表/详情的具体版式归阶段二 Epic C/E 深化，本文只立「三时刻常驻呈现」的口径。

### 3.7 表单版式：主操作与配置控件的分区

- **新建表单底部（SDR-115）**：区块三的四个配置选择器（工作区 / 权限模式 / 模型 / 思考深度）与主操作按钮（「取消」「创建任务」）不得同行共处同一视觉分组——主操作必须独立成区（以间距、分组或位置分离实现，具体版式归设计侧）。语义标准：用户读到「创建任务」时的心智是「要不要建」，而不是「这个蓝色按钮是选什么的」。
- **编辑表单的操作锚点（SDR-118）**：详情页编辑表单较长时，主操作（「保存修改」）常驻可见（视口内吸附或等效手段，具体版式归设计侧）——用户改完任意字段即可提交，不需要先滚动到表单底部寻找按钮。本文范围原不含编辑面，本条只立「主操作锚点」这一条口径，编辑面的其余需求仍留后续批次。

### 3.8 列表卡片元信息聚拢（SDR-119）

- 任务卡片上同品类的元信息（频率描述、已运行次数、三时刻等「这个任务是什么状态」的信息）聚拢呈现——相邻排列、同一视觉分组；不把同类信息推到卡片两端、在中段留出大片空白。小视口与宽视口下同样聚拢。语义标准：用户扫一眼卡片能整体读到「多频繁 + 跑了没跑」，而不是左端一个孤立的频率词、右端一个孤立的次数。

### 3.9 状态词集与终态语义区分（SDR-120）

- **全域状态词集**：任务状态呈现使用统一词集——**进行中**（启用调度中）、**已暂停**（用户手动暂停，可恢复）、**已结束 · 按计划结束**（到达结束日期或触发次数上限自然收尾，含一次性任务完成其唯一一次运行；口径说明区分「到达结束日期」与「次数到达」）、**失败**（异常终止调度）。自然结束不使用泛化的「已完成」一词——用户从状态本身即可读出「这是设计好的结束」，不需要结合运行次数反推、更不需要猜「它是不是坏了」。
- **对既有措辞的取代**：阶段一 E.3 的「已完成（次数到达）」归入「已结束 · 按计划结束」；列表页状态筛选 Tab 的「已完成」档位按本词集同步（该两处的决策记录由所属文档按治理约定追加）。
- **运行次数如实随状态呈现**：已结束任务的元信息呈现累计运行次数；从未运行过的如实显示「未运行过」，不与「运行过 N 次后按计划结束」混同呈现。
- **已结束任务的时刻降级**：已结束任务的「下次/下下次」预测时刻如实显示「—」（§3.6 常驻态口径）。

| VU18 | **假如**任务已创建（如每周三 09:03）、**当**我在任务列表或详情查看，**那么**同样呈现理论推演的三时刻（与表单态同口径：预测明示、时区标注、计划时刻），我可以凭「下次周三 X 日、下下次周三 Y 日」直观确认周期规律；**假如**我想知道真实运行历史、**当**我打开「历史」，**那么**运行事实在那里如实可查——预测不进历史、事实不进预测（SDR-112/123） |
| VU19 | **假如**我打开新建表单、尚未与任何字段交互，**当**表单呈现，**那么**不存在任何红色错误（空指示、空数值字段均不报错）；**假如**我与某字段交互后使其非法（输入后清空、失焦仍为空）或直接提交，**当**该次交互发生，**那么**错误就地出现在对应字段；**假如**我修正为合法值，**当**修正完成，**那么**错误即时消失不残留（SDR-114）
| VU20 | **假如**我填写新建表单至底部、**当**底部呈现，**那么**「取消」「创建任务」主操作与四个配置选择器（工作区/权限模式/模型/思考深度）视觉分区——我能一眼指出哪个是主操作按钮，不存在「创建按钮像第五个选择器」的误读（SDR-115）
| VU21 | **假如**我配置流逝间隔为每 1 天 09:00、**当**预览呈现，**那么**预览读作「每天 09:00」而非「每 1 天的 09:00」，语义与实际触发完全一致；「每 N 天/周」类规则经自定义弹窗可达（SDR-116/113） |
| VU22 | **假如**我要设定 09:05 的运行时刻、**当**我在时间选择器操作，**那么**05 分可选——分钟粒度为全集（每分钟皆可选），全程无需接触技术表达式（SDR-117）
| VU23 | **假如**我在详情页编辑一个表单较长的任务、**当**我在视口内修改字段，**那么**「保存修改」主操作常驻可见（不因滚动离开视口），修改完成后无需滚动寻找即可提交（SDR-118）
| VU24 | **假如**我在任务列表查看卡片（小视口与宽视口均含）、**当**卡片呈现，**那么**频率与「已运行 N 次」等元信息聚拢呈现（相邻、同组），卡片中段不因信息被推到两端而出现大片空白（SDR-119）
| VU25 | **假如**一个任务按计划自然结束（到达结束日期收尾，含一次性任务完成其唯一一次运行）、**当**它在列表呈现，**那么**状态为「已结束 · 按计划结束」（口径说明区分「到达结束日期」与「次数到达」），与「已暂停」（用户手动暂停）、「失败」（异常终止）不共用状态词；累计运行次数随状态可见，从未运行过的如实显示「未运行过」——我能凭状态本身读出「这是设计好的结束」而非「它坏了」（SDR-120，终态词集见 §3.9）

## 6. SDR 记录（本文档）

- **SDR-107（2026-11-01，用户裁决）**：用户直建表单的执行环境 = Session 全套；呈现层复用 Session 同款模式名与选择器。背景：用户裁决「就跟新开一个 Session 用户能操作的选项，这个页面都应该给到」——此前创建面只给最小字段集（日程 + 提示词），用户对定时任务的执行环境（用什么模型、什么权限、哪个目录）没有控制权，与「用户拥有的产品面」定位（SDR-105）不匹配；且用户已会创建 Session，同款选择器是零学习成本。决策（§2.1-§2.3）：表单区块三提供工作区/权限模式/模型/思考深度/工作目录五项，选择器与命名与 Session 创建面同款；权限模式的呈现层用 Session 模式名映射到阶段二 D-M2 运行姿态三档（映射机制归架构文档）。被否决备选：a) 保持最小字段集（与用户裁决直接相悖，环境失控）；b) 为定时任务自创一套模式命名（学习成本，且制造同物异名）。影响范围：§2、VU1/VU10/VU15、架构文档（映射关系）。（2026-11-02 注：环境清单中的「工作目录」项与权限第四档已由 SDR-121/122 收敛——环境为四项、权限为会话三档，本条「Session 全套」主张不变。）
- **SDR-108（2026-11-01，用户裁决）**：结构化日程是日程配置的唯一入口，不向用户主路径暴露 cron 表达式。背景：现有创建面要求用户直接书写表达式——这假设用户懂 cron，对目标用户（PM 可读层面的产品用户）不成立（用户原话：「不假设用户懂 cron」）；同时时区、循环性等技术概念也不应作为常设输入压给用户。决策（§2.2/§3.1-§3.3）：六档预设 + 自定义组件（频率 + 结束方式）+ 清空按钮 + 可读描述预览；时区按需输入（缺省本地、预览可见、点击可改）；cron 表达式仅存在于自定义/高级处的技术形态，不作为主输入面。被否决备选：a) 表达式为主、结构化为辅（把学习成本转嫁给用户，本 SDR 的动机即其反面）；b) 自然语言输入日程（解析不可靠，且无法保证「显示=实际」的可验证性）；c) 不提供自定义档（预设外的真实需求如「每 2 天」无出口）。影响范围：§2.2、§3.1-§3.4、VU2-VU7、glossary CS9。
- **SDR-109（2026-11-01，用户裁决）**：任务必须携带用户选择的执行环境并在运行时生效；新增标题与指示字段。背景：任务若不携带执行环境，运行时无法按用户选择执行——用户在表单上做的选择若不能到达运行现场，「Session 全套」就是虚假承诺（R4/R5：表单承诺了选择权就必须兑现）。任务字段与执行链当前不承载这些信息，属于能力缺口而非产品争议；本文只立产品语义（携带 + 运行时生效 + 列表如实），数据模型与执行链的扩展形态归架构文档。决策（§2.1/§2.3/§3.5）：标题（缺省「未命名定时任务」）、指示（标签用「指示」不用「Prompt」）、环境五项随任务记录并在每次运行如实生效；列表呈现与任务实际携带一致。被否决备选：a) 任务继承「创建时所在会话」的环境（定时任务到点新建执行会话，彼时无「创建时会话」可用，语义悬空）；b) 环境仅记录不生效（呈现撒谎，直接违反「显示=实际」）。影响范围：§2.1/§2.3/§3.5、VU9/VU13/VU14、架构文档（字段扩展）、阶段二 E.1（列表呈现口径）。（2026-11-02 注：环境五项表述已由 SDR-121/122 修订为四项；「携带并运行时生效」语义不变。）
- **SDR-110（2026-11-01，评审裁决）**：Custom 结束日期的边界为**含当日**（结束日期当天仍执行最后一次），一次性任务定义为结束日期恰为首次运行日的自定义日程。背景：§2.2 原文「结束日期在首次运行日之前」与 §3.5「结束日期早于首次可能触发日即非法」自相矛盾，且「早于首次运行日」字面语义是零次运行；结束日期「当天算不算」无既有裁决（阶段二 D-M 系列未覆盖 end date 边界，#181 仅要求时间语义不歧义）。决策（§2.2/§3.2/§3.5/VU12）：结束日期 < 首次触发日 = 非法并就地提示；= 首次触发日 = 一次性任务，合法，预览如实显示「将在 X 日执行一次后结束」；> 则正常循环。边界统一按含当日，选择结束日期后预览明确「最后运行在 X 日（含当日）」。被否决备选：a) 不含当日（结束日期当天不跑）——「选了 X 日却在 X 日前就停」反直觉，且与日历控件的心智模型不符；b) 一次性由独立开关表达（如 recurring toggle）——与 SDR-108「日程选择即完整表达循环语义」相悖，多一个概念多一份学习成本。影响范围：§2.2/§3.2/§3.5、VU5/VU12。
- **SDR-111（2026-11-01，评审裁决）**：预览的「显示=实际」口径 = 日程计划时刻（不含防拥塞抖动），表单以一行轻量说明标注「理想时刻，实际投递有防拥塞抖动」，与列表页既有标注同款。背景：R4 硬约束若不声明 jitter 边界则与实际不符——实际触发时刻因调度器防拥塞抖动偏移（周期任务最多偏移 min(周期 10%, 15 分钟)、整/半点一次性时刻最多提前约 90 秒，语义已在工具文档公开，归属后台任务域 SDR-005/006）。决策（§3.4）：预览描述日程计划时刻；抖动以表单内一行轻说明呈现（选项 a），措辞与批 3 列表页既有「理想时刻」标注一致（选项 b），不在预览句中混入数字。被否决备选：a) 预览直接显示抖动后的时刻——抖动是运行时确定的，表单阶段无法如实显示，反而制造「显示=实际」的假承诺；b) 不做任何声明——预览承诺与实际触发出现分钟级缝隙，违反诚实性口径。影响范围：§3.4、VU16。
- **SDR-112（2026-11-01，用户裁决）**：表单显示确切的上次/下次/下下次运行时刻，作为「日程是否符合预期」的直观验证手段；任务列表/详情（常驻态）同样显示三时刻。背景（用户原话整理）：基于 schedule，表单要能显示确切的上次运行、下次运行、下下次运行时间——让用户能直观验证这个 schedule 是否符合自己的预期。可读描述只回答「规则是什么」（如「每周三 09:03」），用户仍需在脑中推算「那下次到底是哪天」；确切时刻把验证成本降为零——看到下次周三 X 日、下下次周三 Y 日，周期规律（「对，是每周」）一眼可确认。常驻态同理：任务建成后用户随时核对任务何时将跑、上次何时跑过。决策（§2.2/§3.6）：a) 表单态——选好日程即显示三行确切时刻（带时区，与预览同口径），新建无历史时「上次运行」如实显示「尚未运行」；b) 常驻态——列表行/详情页显示上次/下次/下下次三个确切时刻（下次/下下次为计划时刻，「上次」= 最近一次实际运行的开始时刻——真值承载为运行记录中最近一次非跳过运行的开始时刻，跳过/合并的运行不产生新值；**不由调度游标承载**：游标在到期检测时即推进、与该次运行是否被跳过无关，用作「上次运行」会把跳过伪装成运行过，违背显示=实际；版式归阶段二 Epic C/E 深化，本文立口径）；c) 计算口径 = 日程计划时刻（pre-jitter 理想值），引用 SDR-111 既有裁决，不另立口径，jitter 声明沿用 §3.4 轻量说明；d) 一次性任务只有「下次」有值，「下下次」显示「—」，如实降级。被否决备选：a) 只显示下次运行一个时刻——无法验证周期规律（下次与下下次的间隔才是规律的证据），用户仍需自行推算「隔一周还是隔两周」；b) 表单只做瞬时预览、不落常驻态——提交后用户在列表看不到任务何时将跑，验证手段消失，「显示=实际」在管理面缺一块；c) 「上次运行」行在新建表单中隐藏——与常驻态（有历史的任务三行齐备）呈现不一致，且「尚未运行」本身是如实的信息（任务确实还没跑过），显示它比隐藏它更诚实（R4 同源）。影响范围：§2.2/§3.6、VU17/VU18、阶段二 Epic C/E（列表/详情呈现口径）。（2026-11-02 注：本条「上次运行」口径——表单态显示「尚未运行」、常驻态取运行记录事实——已由 SDR-123 修订为理论推演口径；三时刻验证价值、计划时刻与时区口径不变。）
- **SDR-113（2026-11-01，评审裁决）**：Custom 的「每 N 天/周/月」是**流逝间隔**语义，以结构化间隔字段承载，不以 cron 表达式表达；同一任务 cron 与 interval 互斥二选一。背景：cron 5 字段的 dom/dow 是字段枚举语义（每月 N 号 / 每周几），表达不了「每 N 天」的流逝间隔（`*/N` in dom 跳过没有 N 号的月份、月底断链，非用户输入意图）；而 issue #181 原文明确要「repeat frequency (a number plus a unit, e.g. 1 day)」——缩窄 Custom 到 cron 可表达场景会砍掉用户点名要的规则。决策（§3.1/§3.2）：a) Custom 弹窗区分两种表达模式——流逝间隔模式（数字+单位，结构化 interval 字段）与按字段重复模式（cron 可表达的每月几号/每周几/每天几点/每小时几分组合）；b) 一次性任务 = 结束日期恰为首次运行日的日程（与 SDR-110 定义一致，两种模式通用，不引入第二种一次性表达）；c) cron 高级入口只服务字段枚举类规则，对间隔类规则如实提示语义边界（非缺陷）。被否决备选：a) 缩窄——Custom 只保留 cron 可表达场景、去掉「每 N 天」类（直接违背 issue #181 用户原文点名诉求，砍掉目标规则）；b) 前端把间隔编译为「最接近的 cron」伪表达（语义失真，「每 2 天」变成每月 2/4/6…号或跨月断链——违反「显示=实际」R4）。影响范围：§3.1/§3.2/§3.5、VU5/VU12、架构文档 ADR-016（CronSchedule 加 interval 变体、compileSchedule 分流）与求值内核扩展点、cron.preview 投影扩展。
- **SDR-114（2026-11-02，认知走查裁决）**：表单校验的时机 = 「触犯之后」——错误只在用户与字段发生交互之后出现，纯初始空态不显示任何错误。背景（2026-11-02 三人格认知走查，隔离环境实测；两个可核实现象）：a) 新建表单一打开，「请填写任务的指示内容」红色错误已常驻——空态被当作错误呈现；b) 编辑已有任务时，任务携带的历史值若不合法（如触发次数上限值不合法），表单一打开即报错——用户未做任何操作就被指责。用户原话：「我还没开始填，它就在骂我？」（初学委托者，情绪分 -2）。§3.5 既有「就地校验」只定了错误**在哪呈现**（就地、不等全局弹窗），未定**何时出现**——被读成入场即校验，空态被当作错误。决策（§3.5）：a) 失焦校验——已交互过的字段失焦时即校验；b) 提交校验——提交尝试时对全部可校验项校验，未交互过的空字段此时才首次报错；c) 即时清除——错误出现后用户修正为合法值，错误即时消失不残留；初始空态零错误（空白是「尚未填写」，不是「填错了」）；d) 编辑态预填非法值 = 「继承的触犯」——历史值不合法时打开即呈现错误属如实反馈，但须同时给出修复引导（指明哪个字段、为何不合法、可直接修正），而非只留纯报错。被否决备选：a) 维持入场即红（实测情绪分 -2，把空态当错误构成指责感）；b) 只在提交时一次性校验、不做失焦即时反馈（长表单中错误积累到提交才发现，返工成本高，且丢掉「就地即时反馈」的既有价值）。影响范围：§3.5、VU19。
- **SDR-115（2026-11-02，认知走查裁决）**：新建表单底部的主操作按钮与配置选择器必须视觉分区，不共用同一视觉分组。背景（同走查）：区块三的四个配置下拉（工作区/权限模式/模型/思考深度）与「取消」「创建任务」同行同组。用户原话：「最右边那个蓝色按钮是『创建』还是也是选什么的？」（情绪分 -2）——动作按钮与配置控件混在一组时，按钮被读成「第五个选择器」。决策（§3.7）：主操作（取消/创建任务）与配置控件以间距、分组或位置分离实现分区；本文只锁「分区」这一语义硬约束，不指定具体版式（版式自由度留给设计侧）。被否决备选：a) 维持同行同组（实测已证混淆，情绪分 -2）；b) 在需求中规定唯一版式（如「按钮必须独立成行」）——把版式细节写死会捆绑设计侧的手，语义约束（分区）已足够验收。影响范围：§3.7、VU20。
- **SDR-116（2026-11-02，认知走查裁决；同日评审修正——原「自定义直达弹窗」一项经核实为改善批次 A8 既有裁决的重复登记，移除，选择即开弹窗为既有事实）**：间隔为 1 时文案不照读数字；流逝间隔类规则本批**不**新增为预设档（记 P-CS9）。背景（同走查）：卡片预览「每 1 天的 09:00」读起来生硬（初学委托者，情绪分 -2）。决策（§3.2）：a) 间隔数字为 1 时不照读——「每 1 天」呈现为「每天 09:00」、「每 1 周」呈现为「每周」，语义与实际触发完全等价，不违反「显示=实际」；b) 「每 N 天/周」类规则维持经 Custom 弹窗的流逝间隔模式（SDR-113）可达，不增设第七预设档——预设面每增一档，初学用户的扫读成本增一分，而走查中无人因「找不到每 2 天」受阻；预设化收益待真实使用频次证据，记 P-CS9。被否决备选：a) 照读「每 1 天」（生硬，走查用户已指出）；b) 本批即把流逝间隔提为预设档（无频次证据，预设面扫读成本增加）。影响范围：§3.2、VU21、P-CS9。
- **SDR-117（2026-11-02，认知走查裁决）**：时间选择器的分钟粒度放开为每分钟可选（全集），不保留 15 分钟档位限制。背景（同走查）：时间下拉仅 00/15/30/45 分可选，想设 09:05 的用户必须绕道技术表达式（情绪分 -1）——这与本文「零 cron 知识假设」直接冲突：结构化路径覆盖不了的时刻，被迫走本应只服务高级用户的高级入口。决策（§3.1）：预设档与自定义弹窗内的时间选择器分钟粒度为全集（每分钟皆可选）；选择器的呈现形态（下拉/直接输入）归设计侧，需求只锁「每分钟可达」。防拥塞已由 SDR-111 的抖动声明口径承载，不需要用输入粒度做限流。被否决备选：a) 保留 15 分钟粒度（其唯一站得住的理由是「防用户设出过密时刻」，但用户自己的任务自己负责、偏移声明已存在——保护不成立，拦住的是 09:05 这类完全正当的时刻）；b) 放开粒度但默认仍只展示 15 分钟档（折中无意义：全集可选后多一档「展开更多」徒增一步）。影响范围：§3.1/§3.2、VU22。
- **SDR-118（2026-11-02，认知走查裁决）**：详情页编辑表单的主操作（「保存修改」）常驻可见。背景（同走查）：编辑表单较长、提交按钮在视口外，用户改完字段必须先滚到底部找「保存修改」（审查型管理员）——修改与提交被滚动分离，易改完就走、漏提交。决策（§3.7）：主操作以视口内吸附或等效手段常驻可见，具体版式归设计侧；本文范围原不含编辑面，本条只立「主操作锚点」口径（编辑面其余需求仍留后续批次，§0 例外已同步）。被否决备选：a) 维持现状（滚动分离已实测造成可达性成本）；b) 借本条把编辑面全部需求拉进本文（超出走查证据覆盖，扩张无据）。影响范围：§0/§3.7、VU23。
- **SDR-119（2026-11-02，认知走查裁决）**：任务卡片的元信息聚拢呈现，不推到卡片两端。背景（同走查）：卡片上频率信息与「已运行 N 次」被布局推到两端、中段大片空白，小视口（1280×700）与宽视口下更松散——同品类信息被拉散，用户扫一眼无法整体读到「多频繁 + 跑了没跑」。决策（§3.8）：频率、运行次数、三时刻等元信息相邻排列、同一视觉分组；本文只锁「信息分组」语义，不锁像素布局（版式归设计侧与阶段二 Epic C 深化）。被否决备选：a) 维持两端分布（实测松散、扫读断裂）；b) 规定固定间距/列宽（版式细节归设计侧，需求锁聚拢语义即可验收）。影响范围：§3.8、VU24、阶段二 Epic C（列表版式口径）。
- **SDR-120（2026-11-02，认知走查裁决；同日评审补全——终态词集与取代关系）**：终态语义区分与全域状态词集——自然结束以「已结束 · 按计划结束」口径呈现，不与其它终态共用「已完成」。背景（同走查）：一次性任务自然结束与周期任务停止调度在列表上同样显示「已完成」+「已运行 0 次」、并列于「全部」——用户无法区分「这是设计好的结束」还是「它坏了」（审查型管理员）；一个状态词承载多种语义，用户只能靠猜，「已完成 + 0 次」并列时更像故障而非收尾。决策（§3.9）：a) 全域状态词集——**进行中**（启用调度中）/ **已暂停**（用户手动暂停，可恢复）/ **已结束 · 按计划结束**（到达结束日期或触发次数上限自然收尾，含一次性任务完成其唯一一次运行；口径说明区分「到达结束日期」与「次数到达」）/ **失败**（异常终止调度）；自然结束不与手动暂停、异常终态共用状态词；b) 本词集取代阶段一 E.3 的「已完成（次数到达）」措辞（归入「已结束 · 按计划结束」），列表页状态筛选 Tab 的「已完成」档位按本词集同步（文案「已结束」）——彼两处文档的相应决策记录由各文档按治理约定追加，本文只立规范口径；c) 累计运行次数随状态可见，从未运行过的如实显示「未运行过」，不与「运行过 N 次后按计划结束」混同呈现。被否决备选：a) 维持单一「已完成」（一词多义，实测无法区分设计好的结束与故障）；b) 仅靠「已运行 0 次」等辅助信息让用户自己推断（把状态判断转嫁为用户的推理负担，且「已完成 + 0 次」并列反而更像故障信号）；c) 自然结束的任务从列表移除（违背阶段二留痕口径，且用户需要核对历史收尾）。影响范围：§3.9、VU25、阶段一 E.3（措辞取代）、阶段二 Epic C/E 与改善文档筛选 Tab（状态呈现口径）、架构侧依赖——调度体系须能区分「到达结束日期/次数上限的自然收尾」与「用户手动暂停」「异常终止」，状态词的区分才有真值承载（承载形态归架构文档）。
- **SDR-121（2026-11-02，对 cron-improvement 域 A3 裁决的回写登记）**：创建表单不提供「工作目录」项，任务按所选工作区的默认目录运行。背景（转述自改善文档 A3）：表单里的「工作目录」文本框让用户手工填写运行目录——与「任务属于某个工作区」的归属模型冲突（工作区已决定目录），且自由填写可能填出界外路径。决策（§2.3/§3.5）：执行环境由五项收敛为四项（工作区/权限模式/模型/思考深度）；「在哪里跑」由工作区这一个选择完整回答；引擎侧对越界目录拒绝执行的既有防线保留（引擎安全行为，不构成产品概念，产品面不呈现）。被否决备选（提炼自改善文档 A3）：a) 保留输入项并做界内校验（校验只是复刻引擎防线，产品面徒增一个技术项）；b) 保留输入不校验（界外路径风险直通）。影响范围：§1/§2.3/§3.5、术语表、VU1/VU10、SDR-107/109 的环境清单表述（本批同步）。
- **SDR-122（2026-11-02，对 cron-improvement 域 A4 裁决的回写登记）**：权限模式原样复用会话三档，删除「只读观察」第四档与「无人值守」概念。背景（转述自改善文档 A4）：此前表单为定时任务自造权限体系——三档映射加第四档「只读观察」，还引入「无人值守」概念；用户多学一套只有这里用的词汇，且「选的名字」与「实际执行的规则」之间隔着一层翻译。用户原话（转述自改善文档 A4）：「我们不需要为这个 scheduled task 重新设计任何会话内的权限控制模式。只提供当前我们已经支持的会话内的权限控制模式即可」「全凭用户自主」。决策（§2.3）：选择器只提供会话三档——逐条确认 / 自动常规 / 自动通过（yolo），与新建会话完全同款、同名、同文案；默认档与新建会话一致；无第四档、无「无人值守」字样、无呈现层映射。被否决备选（提炼自改善文档 A4）：a) 保留第四档「只读观察」（自造档位，学习成本与翻译层正是被否决的对象）；b) 保留「无人值守」概念包装（同属自造概念，一并拆除）。影响范围：§2.3/§3.5/§4、VU1/VU10/VU15、SDR-107 的环境项表述。
- **SDR-123（2026-11-02，对 cron-improvement 域 A5 裁决的回写登记）**：三时刻口径改为理论推演。背景（转述自改善文档 A5）：当前表单的「上次运行」行查询运行事实，没有记录就显示「尚未运行」——但用户配置日程时想回答的问题是「这个规则到底会在什么时刻触发」，不是「这个还不存在的任务过去跑没跑」——对着一个尚未创建的任务显示「尚未运行」，信息量为零。用户原话（转述自改善文档 A5）：「从来都不是让你去写事实，而是预测结果，而且用户也得知道这是预测结果」。决策（§2.2/§3.6）：a) 三时刻全部为理论推演——假设日程已存在，最近的理论触发点是什么、接下来两次是什么；b) 预测明示——整体标注「预测 · 基于当前日程推算」，过去部分样式可区分并标注「理论值」（B1 呈现细节），三个时刻以一条时间轴合并呈现，高频档过去时刻可省略或弱化；c) 一次性规则无理论过去，过去位「—」，不虚构；d) 事实与预测分界——真实运行历史只在「历史」中呈现，预测不进历史、事实不进预测；e) 每个时刻带时区标注，呈现时刻与所标时区严格对应（B2）；f) 本条修订 SDR-112 的「上次运行」口径（表单态「尚未运行」、常驻态取运行事实均不再适用），SDR-112 其余裁决（三时刻验证价值、计划时刻口径、时区口径）不变。被否决备选（提炼自改善文档 A5）：a) 上次运行查运行事实、无记录显示「尚未运行」（信息量为零，答非所问）；b) 表单态显示真实历史（新建任务无历史可显示）。影响范围：§2.2/§3.6、VU17/VU18、SDR-112（部分修订）。
- **SDR-124（2026-11-02，对 cron-improvement 域 C2 裁决的回写登记）**：Agent 创建定时任务的「提议-审批」包装下线，代之以高危操作审批直建。背景（转述自改善文档 C2）：此前 Agent 创建路径是「提议」包装——模型起草提案、系统把提案作为中间产物保存一段时间（72 小时有效）、用户再批准；创建被拆成两段、多出中间状态。用户原话（转述自改善文档 C2）：「从用户的角度，这个设计莫名其妙，很烦人。」决策：Agent 在会话内发起创建走高危操作审批——任意权限模式下一律触发系统既有的高危操作审批，批准即建、拒绝即无，不产生「提议」中间概念与中间产物；本文服务的用户直建路径（无需审批）不受影响，仍为独立入口。被否决备选（提炼自改善文档 C2）：a) 保留提议包装、仅缩短中间产物有效期（中间概念本身已被用户否定）。影响范围：§0/§1/§4、阶段二提议-审批系列裁决（由彼文档按治理约定回写）。

## 7. 未来增强提案（非本批）

- **P-CS7 表单草稿暂存**：长指示填写中途离开不丢失（本地草稿）；无明确诉求不做。
- **P-CS8 从既有 Session 一键转任务**：「把这个会话的配置变成一个每天跑的任务」——环境四项从会话预填；待用户诉求。
- **P-CS9 「每 N 天/周」类流逝间隔的预设直达性**：把流逝间隔类规则（「每 2 天」「每 3 周」）从 Custom 弹窗提升为预设档或预设面的快捷入口。SDR-116 裁决暂不做的依据：Custom 弹窗已可达该规则、预设面维持六档以控制扫读成本，且走查中无人因「找不到每 2 天」受阻——待该类规则的真实创建频次证明预设化收益后再做。
- **P-CS10 运行记录携带一行运行摘要**：历史记录在状态/时间/时长之外，呈现该次运行「干了什么、结果怎么样」的一行摘要（取自该次执行会话的产出收尾）。走查确认这是查看历史时用户最关心的信息；摘要需要执行侧产出并随运行记录留痕的架构支持，本批不强行落地，摘要口径与呈现形态另行裁决。
