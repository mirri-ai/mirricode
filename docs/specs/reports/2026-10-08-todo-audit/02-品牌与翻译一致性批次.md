# 02 · 品牌与翻译一致性批次

> **✅ 已完成（2026-10-12）**。旧品牌残留全量清理（TUI 登录标题、内置 skill 文档、OAuth 显示名与错误消息、v1 常驻提示副本），`/login-with-kimi` 收敛为 `/login`（别名保留，SDR-003），中文审批文案补齐，新增 TUI 与 builtin skill 文档两级品牌防回归扫描。详见 [ROADMAP.md](ROADMAP.md) 处置记录。以下为审计时点的原始记录，勾选状态不再维护。

## 背景

产品有过一次更名（旧名 → Mirri Code）。更名和国际化（中英文翻译）的扫尾没有完全做干净。2026 年 9 月 18 日的用户视角评测集中暴露了一批这类问题。

## 现状（2026-10-08 核验）

逐项在翻译文件和界面代码里查过，以下全部原样存在：

1. **旧品牌名残留**：登录页标题仍然是「Sign in to Kimi Code / 登录 Kimi Code」——用户现在登录的产品叫 Mirri Code。
2. **审批卡片的占位文案**：中文界面的审批卡片上写着「文件操作?」（带一个突兀的问号，像是翻译键没配对），以及大写英文「APPROVAL REQUIRED」直接混在中文界面里。
3. **斜杠命令描述前后不一**：`/login-with-kimi` 这个命令的名字里有旧品牌，描述却写「在浏览器中登录 Mirri」。

评测之后到现在，网页前端只有 1 个提交且与本议题无关——这批问题没有任何一项被处理。

## 问题与影响

- 品牌混乱让用户怀疑产品的成熟度：「我到底在用谁家的东西？」
- 中英混排和问号占位符在中文用户眼里就是「没做完」的直接信号。
- 这类问题单个都极小，但集中出现在首次使用的路径上（登录页、第一次写文件的审批卡片），恰是第一印象形成的地方。

## 期待的最终形态

- 全部界面文案只出现当前品牌名。
- 中文界面不出现未翻译的英文句子（专有名词除外）。
- 不存在带问号的占位键——每个翻译键都有对应词条。

## 大致要做的事

1. 做一次**全量文案扫描**：把中英文两套翻译文件里所有含旧品牌名的词条列成清单（不只是评测提到的三处，要主动扫全量，避免打地鼠）。
2. 修正「文件操作?」的翻译键问题（大概率是词条键名与实际使用不一致，或词条本身写错了）。
3. 「APPROVAL REQUIRED」这类状态标题补上中文词条。
4. 斜杠命令 `/login-with-kimi` 与其描述统一口径（如果登录功能暂不做，此命令的文案调整也不阻塞——只改字，不动功能）。
5. 补充一条防回归检查：在网页端的自动化测试里加一条「翻译文件中不得出现旧品牌名」的扫描断言，防止将来再次漏网。

## 规模与风险

小。纯文案改动，不动任何功能逻辑。主要工作量在「扫全量」确保不漏，以及中英两套词条同步更新。
