### 01 · 错误的密码环境变量提示 — 已完成（2026-10-09）

- **定性**：文案准确性缺陷。弹窗指引设置 `MIRRICODE_CODE_PASSWORD` 环境变量，但 v2 引擎实际读取 `MIRRICODE_PASSWORD`、v3 Rust 核心无任何密码环境变量——对两个引擎都不可用。
- **处置**：不引入密码环境变量能力（被否决备选：为 v3 加该变量对齐 v2——为一个文案笔误反向加功能，且固定密码弱于随机凭证）。弹窗文案改为仅指引启动时打印的凭证；补防回归测试（弹窗文案不得出现任何环境变量名）。
- **同步销账**：认证域开放项 O-3 关闭、提案 P-8 关闭（SDR-002，见 `docs/specs/auth-oauth-requirements.md` §14、`docs/specs/auth-oauth-ROADMAP.md`）。
- **提交**：`906106e8`（`fix(web): remove nonexistent password env var from server auth dialog`）。
- **遗留**：原计划将 01 并入 02 文案批次合并执行，实际提前单独修复；02 的其余项不受影响。

### 03 · 登录前的错误弹窗抢跑 — 已完成（2026-10-12）

- **定性**：启动序列缺陷——数据请求（模型清单）先于认证门发出，未认证的失败被全局错误提示渲染成红色 toast，抢在服务令牌弹窗之前出现。
- **处置**（`b2187b89` `fix(web): gate boot data fetches behind the first-load auth check`）：结构重排而非全局静默 flag——先读公开路由 `/meta`（其 `dangerousBypassAuth` 字段指明引擎有无认证门）；首载且引擎要求认证时，把 `/auth` 门提到并行数据请求**之前**，命中「需要服务令牌」即提前返回（不发模型清单/配置/工作区请求）。bypass 引擎与 `/meta` 不可达场景保持旧顺序（meta 故障绝不卡启动）。`connectTransport` 保持 eager（P11c 语义不变）。

- **提交**：`b2187b89`（squash 合入 `feat/latest`，含 `useWorkspaceState.ts` +31/−16 与测试 +51）。
