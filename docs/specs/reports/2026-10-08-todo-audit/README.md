# Rust 核心 + Web 待办事项审计报告（2026-10-08）

## 这份报告是什么

这是一次「盘点家底」的审计：把 Rust 核心 + Web 这条产品线上所有还没做完的事情，逐项写成一份份独立的说明文档。每份文档回答同样四个问题：

1. **背景**——这件事是从哪来的？为什么会被记录下来？
2. **现状**——今天打开代码看，它处于什么状态？
3. **问题与影响**——如果不做，用户或团队会感受到什么？
4. **期待的最终形态**——做完了应该是什么样子？

## 审计方法（可信度说明）

本报告不是照抄内部任务清单，而是「文档 + 代码 + 提交记录」三方对照后的结论：

- 以项目内部的执行状态台账为出发点（`docs/specs/rust-core-design/ROADMAP.md` 及各领域 ROADMAP）；
- 每一项都到代码里实地核验过（例如：翻译文件里的旧品牌文案是否还在、某个功能入口是否仍然是占位报错）；
- 对照最近三个月的提交记录，确认「有没有人后来修过但忘了销账」——审计中确实发现了这种情况，相关项已从待办中移除。

审计基准日：2026-10-08（仓库最后一次功能提交为 2026-10-07）。

## 审计过程中被移出待办的事项（避免重复立项）

这些项曾被记录为问题，但核验后确认**已解决或本来就不是问题**，特此说明，防止将来被重复翻出来：

- **会话自动命名的「提示泄漏」问题**（旧方案下模型会在回复正文里抱怨一个不存在的工具）：已随 2026-10-03 的新命名方案（旁路调用、缓存搭车，实测命中率 99.2%）彻底根治。
- **服务重启后「上下文水位圈」归零**：经用户实测确认已恢复正常，代码链路（重启后自动从引擎读取真实用量回填）也已核验。评测报告忘了销账，现予销账。
- **「隔离目录不彻底」中关于技能的部分**：通用技能目录（`~/.agents`）按设计就是用真实系统目录，代码里有明文注释，属于文档化的既定行为，不是缺陷。
