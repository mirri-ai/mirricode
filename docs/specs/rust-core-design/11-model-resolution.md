## 1. 需求

### 1.1 动机（抽象问题陈述）

模型是会话最重要的运行参数，但"这一次调用到底用了哪个模型"今天无法预期：

- 用户为会话切换模型后，委派出去的子代理仍在调用一个**既非用户配置、也非会话当前模型**的固定模型；该模型没有凭据时静默失败，用户看到的只是含糊的报错。
- 同一个子代理任务，按理有三个来源可以决定模型（派发时显式指定、子代理类型的默认模型、沿用派发者模型），实际生产中第三个来源结构性失效，第二个来源又与一个本不该存在的内建默认纠缠。
- 多个改模型的入口行为不一致：有的持久化、有的只影响一次请求且不留痕迹；恢复会话后模型与关闭前不一致。
- 系统内部存在一个未经用户配置的具体模型作为兜底，用户无从知晓、无法关闭。

期望终态：任何一次模型调用的模型决定都**可预期、可解释、被文档固定**；系统不替用户做任何未经配置的模型决定；每一次切换对用户可见。（现状证据见 [context.md](context.md) §8。）

### 1.2 需求项

- **R1 单一裁定链**：一次模型调用用哪个模型，由唯一一条有优先级的来源链裁定；不存在链外路径（环境变量回退、内建兜底、入口私有逻辑均废除）。
- **R2 切换即时生效**：回合进行中的切换，从**该回合的下一次模型请求**起生效（工具调用之间的下一步即用新模型）；已在途的请求不中断、不重发。发消息携带模型参数属"请求之前的切换"，本次请求即用新模型（与 R8 一致）。
- **R3 切换可见**：每次切换在对话消息区以**分割线**呈现（标注切换前后模型的显示名），用户可辨"从哪里开始换的"；分割线属转录（glossary S6）投影，恢复会话后仍在。
- **R4 零内建模型**：系统不携带任何内建的具体模型；主链解析不出时**明确报错**（附可行动指引，如"未配置默认模型，请先在设置中配置"），绝不静默回退到固定模型。报错为公开、**不可自动重试**——用户修正配置或参数后可重试。
- **R5 子代理继承与钉扎**：子代理未显式指定模型且其类型无默认模型时，**沿用派发者当前模型**；裁定在**派发时点**做出并钉扎到该执行流，会话其后切换不影响在途子代理；对子代理的续作沿用钉扎值。
- **R6 内建类型无固定模型**：随产品分发的内建子代理类型只声明职责、提示词与工具面，**不声明任何模型**。
- **R7 派发说明不硬编码模型名**：派发工具对模型的说明**不硬编码任何具体模型名**（M1 别名与 M2 原始模型名均不得）；可用模型清单段与用户配置**同源动态生成**（增删模型后随配置变化）——它保留 LLM 显式指定（A4）的信息路径，但内容永不来自硬编码。
- **R8 入口统一**：所有改模型的入口（界面切换、会话命令、发消息携带的模型参数）汇入**同一语义**：统一校验 → 持久化 → 事件通知 → 分割线 → 后续请求跟随。发消息携带模型参数不是"仅本次的临时覆盖"，而是一次标准切换（本次请求即用新模型）。
- **R9 恢复一致**：会话恢复后模型与关闭前一致（含中途切换过的会话）；会话无模型记录时的回退链与新建会话完全相同（配置默认模型 → 报错）。
- **R10 校验统一**：任何入口收到未配置的模型名，以**同一错误**拒绝（列出可用模型），不进入任何旁路解析。
- **R11 引擎内部轮次跟随**：定时任务、任务通知等引擎内部发起的轮次，主体为主 agent 时在**发起时**按主链解析（首个请求用发起时会话当前模型）；收件人为子代理时沿用其钉扎值（R5 的延展）。内部轮次自身的模型在发起时点解析后即钉扎到该轮次（轮次进行中的会话切换自下一个内部轮次生效）——主 agent 交互轮次的逐请求生效（R2）不因此弱化（ADR-007）。
- **R12 用量归因**：每条用量按**该次请求实际使用**的模型记账；回合内切换后，切换点之后的用量记入新模型。

### 1.3 非目标

- 不改 TS v2 引擎行为——本文件是 Rust 内核终态规格；TS 侧既有行为不因本文件构成回归，其消化随退役线（ROADMAP 1.3）走。
- 不做模型推荐、按任务自动选型或模型路由。
- 不新增模型设置界面——配置面归模型设置域（[model-settings-page-requirements.md](../model-settings-page-requirements.md)）。
- 不做"单个子代理在运行中单独换模型"——换模型是会话级语义，子代理模型钉扎在派发时点（R5）。
- 不动 provider 配置与凭证域——本文件裁定"用哪个模型"，provider 解析决定"怎么连上它"，两层正交。
- 不动 profile 供给面——类型目录的发现（项目根扫描）、热重载与设置页展示归 agent-profile 域；A5 验收以用户配置的类型经既有注册面可达为前提（供给面现状缺口见 context §8 末条）。

### 1.4 验收标准

| # | 验收项（Given-When-Then） |
|---|---|
| A1 | 回合进行中切换模型 → 该回合**下一次模型请求**（含工具调用后的下一步）使用新模型；在途请求不被中断 |
| A2 | 切换发生 → 消息区在切换点出现分割线（标注前后模型显示名）；恢复会话后分割线仍在转录中 |
| A3 | 子代理未指定模型且其类型无默认 → 使用**派发者当前模型**（含派发者刚切换后的新模型） |
| A4 | 派发显式指定模型 → 使用指定模型（校验口径同 R10；LLM 的合法别名信息源为与配置同源动态生成的清单段与 A11 错误反馈） |
| A5 | 用户配置的类型声明了默认模型 → 该类型子代理使用之；内建类型无默认模型可声明（A7 的前提） |
| A6 | 主链解析不出（会话无模型且配置无默认）→ **发消息**明确报错（附行动指引）；**子代理链三无**（无显式指定、类型无默认、派发者主链亦无解）→ 派发同样报错；主链解析不出但派发**显式指定了有效模型** → 按 A4 成功（子代理链不依赖派发者主链有解） |
| A7 | 全系统**源码与运行时装配结果**均不存在未经用户配置的具体模型名——扫描对象：rust 源码硬编码（含会话装配缺省值与**全部内建类型**的模型字段，实施用例逐一覆盖）与会话装配产物 |
| A8 | 派发工具的说明文本不含任何**未经用户配置**的具体模型名（M1 别名与 M2 原始模型名均无硬编码）；配置装配的可用模型清单段与配置同源动态生成（增删模型后描述随之变化） |
| A9 | 发消息携带模型参数 → 与显式切换同语义：**本次请求即按新模型发起**，持久化、事件、分割线、后续请求跟随（一次切换，不是单次覆盖） |
| A10 | 恢复会话 → 模型与关闭前一致（含中途切换过的会话；无记录时回退链与新建相同） |
| A11 | 任意入口传入未配置的模型名 → 同一错误并列出可用模型（无环境变量回退旁路） |
| A12 | 定时任务触发轮次 → 首个请求用触发时会话当前模型（发起后该轮次钉扎，见 ADR-007）；收件人为子代理的内部轮次（通知）→ 沿用其钉扎值 |
| A13 | 回合内切换 → 切换点之后的用量记入新模型（逐请求归因，非会话开头快照） |
| A14 | 在途子代理不因会话切换换模型；其后续作沿用派发时点的钉扎值 |
| A15 | 用户删除会话当前模型（或某子代理钉扎模型）指向的别名后 → 其后的模型请求按 R10 同一口径报错（列出可用模型），不回退配置默认、不静默换模型 |
| A16 | 撤销对话内容 → 当前模型与分割线不受影响（模型切换记录不属于撤销单元） |
| A17 | 多 agent 会话中切换 → 切换记录为会话级（无 agent 归属字段），恢复后当前模型 = 最后一条切换记录（现状的折叠错位由此消除）；会话内后续请求与派发跟随新模型，在途子代理钉扎不变（同 A14） |

## 2. 设计

### 2.1 总体机制

```
  ┌─ 切换入口（全部汇入单一切换路径）─────────────────────┐
  │  界面切换 / 会话命令 / 发消息携带的模型参数             │
  └───────────────────┬──────────────────────────┘
                      ▼
  ┌─ 会话模型状态（唯一持有，会话级）─────────────────────┐
  │  统一校验（已配置别名）→ 写入会话日志（可回放）        │
  │  → 广播既有会话元数据更新事件 → 展示端渲染分割线       │
  └───────────────────┬──────────────────────────┘
                      ▼   逐次模型请求解析（请求间不缓存）
  ┌─ 主链（每次 LLM 调用，含回合内的每一步）──────────────┐
  │  会话当前模型 → 配置默认模型 → 明确报错（零内建）      │
  │  （解析时校验：当前模型别名已被删 → 报错，见 ADR-005） │
  └───────────────────┬──────────────────────────┘
                      ▼
                每次 LLM 调用
                      ▲
  ┌─ 子代理链（派发时点裁定一次，钉扎到执行流）────────────┐
  │  显式指定 → 类型默认（仅用户配置的类型可声明）         │
  │  → 派发者当前模型 → 明确报错                          │
  │  （钉扎值别名已被删 → 报错，同 ADR-005）              │
  └──────────────────────────────────────────────┘
```

要点：**状态在会话级唯一持有，裁定在请求级逐次发生**。切换路径只有一条；主链与子代理链是两条消费同一状态的裁定链；呈现（分割线）是切换记录在转录上的投影，不占模型上下文。

### 2.2 会话模型状态与切换路径

- 会话域唯一持有"当前模型"；任何入口的切换都汇入单一路径，路径上依次做四件事：统一校验（接受规范形态与短名形态的**已配置别名**，口径同 M1/R10）、作为一条**模型切换记录**写入会话日志、广播既有会话元数据更新事件、由展示端渲染分割线与模型指示。
- **生效边界**：模型在每次发起模型请求时解析，不在请求之间缓存——回合内的下一步即读到新值（A1）；正在执行的请求不打断、不重发。
- **解析时校验（配置漂移）**：请求级解析发现会话当前模型（或子代理钉扎值）指向的别名已不在配置注册表 → 按 R10 同一口径报错并列出可用模型，**不回退配置默认**——该模型是用户显式选定过的，静默换模型违背 R1（A15，ADR-005）。
- 发消息携带的模型参数进入同一路径：一次参数携带 = 一次标准切换，**本次请求即按新模型发起**，同样落日志、发事件、出分割线，后续请求跟随（A9）。不存在"只影响这一次请求"的临时覆盖形态。
- **撤销边界**：撤销面向对话内容（成对的输入与回复），不回退运行参数——当前模型以会话日志中最后一条切换记录为准，撤销不穿越、不回退模型（A16）。

### 2.3 子代理裁定

- 三级链与 [subagent-requirements.md](../subagent-requirements.md) US1.2 一致：**显式指定 → 类型默认 → 派发者当前模型**；三者皆无则报错（A6）。与该需求文档的差异只有一处收紧：本文件废除内建兜底，"类型默认"仅用户配置的类型可声明（R6）。
- **派发时点钉扎**：裁定在派发动作发生时做出并固定到该子代理执行流——会话其后切换不影响在途子代理（A14）；对子代理的续作沿用钉扎值，不重新裁定。已派发出去的执行流中途换模型会破坏其上下文与记账的连续性，钉扎避免之。
- 钉扎值随子代理会话记录（glossary A8）持久化——会话恢复后的续作仍可用（A14）；钉扎值指向的别名被删后的请求级行为同 §2.2 解析时校验（A15）。
- 派发工具的模型参数说明不硬编码具体模型名，可用模型清单段与配置同源动态生成（R7/A8）——清单内容随配置漂移即自动纠正，硬编码转述才是现状缺陷之源。

### 2.4 恢复、内部轮次与记账

- **恢复**：会话日志重放，最后一条模型切换记录即当前模型（A10）；会话无任何模型记录时，回退链与新建会话相同——配置默认模型 → 报错（R9），不存在"恢复专属"的内建兜底。
- **多 agent 归属**：模型切换记录是**会话级**记录、无 agent 归属字段（ADR-006）——多 agent 会话恢复后当前模型 = 最后一条切换记录，现状的"折叠错位"由此消除（A17）；会话内后续请求与派发跟随新模型，在途子代理钉扎不变。
- **引擎内部轮次**：定时、通知等内部轮次在**发起时**按主链解析模型并钉扎到该轮次（首个请求用发起时会话当前模型，轮次内不随会话切换变化——ADR-007）；收件人为子代理的通知轮次沿用其钉扎值。内部轮次不携带私有模型来源。
- **用量记账**：逐请求按实际解析出的模型归因（A13）；用量视图的模型维度直接反映逐次请求的真实模型，不使用会话开头的快照。

### 2.5 契约与呈现

- **无新 RPC**：切换复用既有的模型设置方法与发消息参数；子代理模型复用派发工具的既有参数。
- **记录族**：会话日志的"模型切换记录"（携带切换前后模型与触发入口），随恢复重放；实现载体为既有 `WireOp::ConfigUpdate { model_alias }`（状态 fold）+ `ContextAppendMessage { origin: model_switched }`（转录投影）对，零新增 wire op（ADR-008）；它不属于任何撤销单元（§2.2 撤销边界，A16）。
- **呈现**：web 与 TUI 消费既有会话元数据更新事件渲染模型指示与分割线；分割线是转录投影（glossary S6 全量投影的一部分），不进模型上下文（A2）。子代理的模型在其子代理会话记录（glossary A8）的独立记录流中可见。
- **失败呈现**：主链解析不出的报错为公开、不可自动重试的错误，附用户行动指引（未配置默认模型 → 指向设置；别名不存在 → 列出可用模型；用户修正后可重试，见 R4）。
- **跨域影响**：子代理类型清单的展示口径（无默认模型时显示"无默认、沿用派发者"）由 subagent 域展示条目同步，不属本文件改动面。
- 仅影响 rust 引擎与两端展示（web/TUI 分割线）；TS 各引擎零改动（非目标）。

### 2.6 成本语义

- 零新增模型请求：本机制是纯裁定与记录，不产生任何探测、验证或推荐调用。
- 常驻开销为零：逐请求解析是对会话状态的读取，无额外缓存维护、无后台任务；分割线只在切换发生时各出现一次。
- 会话日志增量为每条切换一行记录（仅在用户/参数实际切换时写入）。

## 3. 备选方案与取舍

| 备选 | 取舍 | 结论 |
|---|---|---|
| 保留内建默认模型并文档化（而非报错） | 开箱即用；但用户为模型付费与选型的知情权被架空——一个用户未配置、可能无凭据的模型被静默使用，失败时不可解释 | 否决（ADR-001） |
| 内建默认作为"最后手段"，仅在解析不出时启用 | 表面兼容；但"最后手段"正是静默失败之源（现状证据：内建模型无凭据时报错与用户配置完全无关），且不可测试地与用户配置区分 | 否决（ADR-001） |
| 切换在回合结束后再生效（turn 级粘性） | 实现简单（回合装配时快照）；但用户在长回合中切换的意图被推迟数分钟生效，与"即时反馈"直觉相悖 | 否决（ADR-002） |
| 发消息模型参数维持"单次覆盖"（影响一次请求即回弹） | TS 引擎既有形态之一；但覆盖不落盘导致恢复不一致、用量归因分裂，且"回弹"对用户不可见 | 否决（ADR-002） |
| 子代理实时跟随会话模型（不钉扎） | 切换语义全局一致；但执行流中途换模型破坏上下文与记账连续性，且"这个子代理到底用了什么"不可回答 | 否决（ADR-003） |
| 未知名宽松解析（裸名尝试环境变量、目录名兜底） | 少一层配置门槛；但同名异义与环境依赖使"用了什么"依赖部署环境，报错口径分裂 | 否决（ADR-004） |
| 派发工具说明硬编码静态模型清单 | LLM 选型信息自足；但清单随配置漂移、与事实脱节是现状缺陷之源——清单段必须与配置同源动态生成，硬编码形态被否决 | 否决（ADR-001） |
| 彻底废除派发说明中的可用模型清单段 | 最大限度防漂移；但 LLM 失去显式指定（A4）的信息源，只能靠错误反馈回路试错，派发成功率受损 | 否决（ADR-001，评审 B-3 裁量保留动态清单） |

## 4. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 零内建后"开箱即用"受损（新装环境无默认模型） | R4 的报错附行动指引；安装/首启引导配置默认模型属配置域既有职责（非本文件范围） |
| 用户切到无凭据的模型，下一次请求才失败 | 可接受——失败即时报错且指向真实原因（该模型无凭据），优于现状的静默内建回退 |
| 用户删除在用别名导致请求报错（A15） | 按 R10 口径报错并列出可用模型，用户改配置或重新切换即恢复——诚实报错优于静默换模型（ADR-005） |
| 回合内换模型导致同回合上下文跨模型混合 | 逐请求生效本就允许混合（用户意图）；用量逐请求归因（A13）保证记账诚实 |
| 模型切换记录进入会话日志的恢复/撤销复杂度 | 记录族随既有重放机制走；撤销边界明确声明不回退模型（§2.2，A16），不与对话撤销耦合 |
| 子代理钉扎与用户直觉相悖（"我都换了怎么子代理没换"） | 分割线让会话级切换可见（A2）；后续派发即用新模型（A3），钉扎范围限于在途执行流 |
| 多 agent 会话中切换的归属歧义 | 切换记录为会话级、无 agent 归属字段，恢复取最后一条（A17 / ADR-006）——单一归属规则，无歧义空间 |
| A5 依赖的类型供给面（目录扫描、热重载）是现状短板 | 已声明为非目标（agent-profile 域）；A5 验收以类型经既有注册面可达为前提 |

## 5. 成功标准

- 1.4 全部验收项（A1-A17）以测试覆盖（Given-When-Then）：**rust 层**断言记录/事件/装配结果（含 A7 的源码与装配扫描），**web/TUI 渲染**（A2 分割线）走 UI 层测试；重点：切换即时生效（A1）、钉扎边界（A14）、零内建断言（A7——全链路扫描不存在未经配置的具体模型名，内建类型逐一覆盖）。
- rust workspace 测试全绿、clippy 零新增告警（Rust 内核域质量门禁）。
- 契约链变更最小：无新 RPC；记录族零新增（复用既有 `ConfigUpdate` + `ContextAppendMessage(origin: model_switched)` 对，ADR-008）；展示端仅消费既有事件。
- 与 subagent-requirements US1.2 的三级链一致性经交叉评审确认（差异仅 R6 的收紧项 + R5 的钉扎时序细化）。

## 附录 A. 决策记录

### SDR-001（需求变更：模型决定收敛为单一裁定链）

- **日期**：2026-09-14
- **上下文与动机**：模型决定散落多入口且互相矛盾——内建具体模型作为兜底被静默使用、子代理继承结构性失效、切换是否持久化因入口而异、恢复后模型漂移（现状证据：context.md §8，含真实会话取证 session-0b8117a4）。用户裁决：系统不替用户做任何未经配置的模型决定。
- **决策**：全部需求项（R1-R12）如 §1.2；核心是"单一裁定链 + 零内建 + 入口统一 + 切换可见"四根支柱。
- **被否决的备选**：修补式方案（逐个入口打补丁、保留内建但加告警）——不改变"模型决定不可预期"的本质，且每处补丁各自引入新的口径。
- **影响范围**：本文件 §1 全部需求项。

### ADR-001（设计决策：废除内建具体模型，解析不出即报错；派发说明不硬编码）

- **日期**：2026-09-14 · **评审修订**：2026-09-14（独立评审 B-3/M-1：派发说明的可用清单段改为"与配置同源动态生成、不得硬编码"；证据面修正为多个落点、两种具体模型名）
- **上下文与动机**：内建默认以多个落点存在于 rust 内核——会话装配缺省配置与四个内建子代理类型（agent / coder / explore / plan）的模型字段，涉及两种具体模型名——源自早期 squash 提交、无意图记录；TS 引擎无硬编码默认（解析不出即失败）。真实会话取证：主 agent 用自定义模型时，连续四次派发的子代理全部因内建模型无凭据静默失败，第五次显式传参才成功——内建默认是"既不开箱即用、又制造不可解释失败"的纯负债。
- **决策**：R4/R6/R7——内建子代理类型去模型化（只声明职责与工具面）；主链终点从"内建兜底"改为"明确报错 + 行动指引"；派发工具说明**不硬编码任何具体模型名**，可用模型清单段**与配置同源动态生成**（保留 LLM 显式指定的信息路径，清单内容永不来自硬编码）。开箱即用问题交还配置域（安装/首启引导默认模型）。
- **被否决的备选**：保留并文档化 / "最后手段"启用（见 §3 前两行）；彻底废除清单段（LLM 失去显式指定的信息源，见 §3 末行）。
- **影响范围**：§2.1 主链、§2.3 子代理链第 2 级；内建类型定义面、派发工具描述面、会话装配缺省值。

### ADR-002（设计决策：单一切换路径 + 逐请求生效，发消息参数并入）

- **日期**：2026-09-14 · **评审修订**：2026-09-14（独立评审 M-5/M-6：R2 补发消息参数时点语义；内部轮次与普通轮次统一为逐请求解析）
- **上下文与动机**：发消息携带模型参数在现状 rust 侧是一次性覆盖（不落日志、恢复丢失），与界面切换语义分裂；"回合中切换何时生效"无定义。用户裁决（2026-09-14 早期讨论）：期望回合执行中的切换直接反映到执行中的回合（至少下一个工具调用后的下一步）。
- **决策**：R2/R3/R8——所有切换入口汇入单一路径（校验 → 落日志 → 事件 → 分割线）；模型在每次请求发起时解析、请求间不缓存，回合内下一步即生效；发消息参数并入为一次标准切换（本次请求即用新模型）。撤销不回退模型（运行参数与对话内容分离）。引擎内部轮次与普通轮次同语义（逐请求解析）；收件人为子代理的通知轮次沿用钉扎值。
- **被否决的备选**：turn 级粘性（回合结束再生效）；单次覆盖维持（见 §3）。
- **影响范围**：§2.2、§2.4；切换路径面、发消息参数面、记录族新增、内部轮次发起面。

### ADR-003（设计决策：子代理模型派发时点钉扎）

- **日期**：2026-09-14 · **评审修订**：2026-09-14（独立评审 N-6：补钉扎值持久化载体）
- **上下文与动机**：子代理继承链的第三级（沿用派发者模型）在现状结构性不可达（类型解析要求必带模型，且内建类型自带模型），继承从未真实生效；同时需要回答"运行中会话切换，在途子代理怎么办"。
- **决策**：R5——三级链（显式 → 类型默认 → 派发者当前）在**派发时点**裁定一次并钉扎到执行流；续作沿用钉扎值（随子代理会话记录持久化，恢复后可用）；会话切换不影响在途子代理，但下一次派发即用新模型。
- **被否决的备选**：子代理实时跟随会话模型（见 §3）。
- **影响范围**：§2.3；子代理派发面、续作面。

### ADR-004（设计决策：模型名校验口径全入口统一）

- **日期**：2026-09-14
- **上下文与动机**：现状校验分裂——会话级设置只认登记表精确键、创建与发消息入口不校验、裸未知名可滑入环境变量回退，同一模型名在不同入口得到三种结果。
- **决策**：R10——所有入口只接受"已配置模型别名"（M1 规范形态与短名形态），未配置名以同一错误拒绝并列出可用模型；废除环境变量回退与裸名宽容解析。
- **被否决的备选**：宽松解析（见 §3）。
- **影响范围**：§2.2 切换路径校验步、§2.3 派发校验；全部模型名入口。

### ADR-005（设计决策：配置漂移时请求级报错，不回退）

- **日期**：2026-09-14（独立评审 B-2 引入）
- **上下文与动机**：会话当前模型（或子代理钉扎值）指向的别名可能在事后被用户删除——此时请求级解析的行为未定义过：报错、回退配置默认还是静默换模型，是实施必然要拍板的分叉。
- **决策**：请求级解析发现已选定的别名不在配置注册表 → 按 R10 同一口径报错（列出可用模型），**不回退配置默认**——该模型是用户显式选定过的，静默替换违背 R1"可预期"；用户重新切换或恢复配置即恢复（A15）。
- **被否决的备选**：a) 回退配置默认模型——静默换模型，用户不知情；b) 调用时报 provider 错误——错误与真实原因（别名已删）隔了一层，不可行动。
- **影响范围**：§2.2 解析时校验、§2.3 钉扎值漂移；主链与子代理链的请求级解析面。

### ADR-006（设计决策：切换记录为会话级单一状态，无 agent 归属）

- **日期**：2026-09-14（独立评审 M-4 引入）
- **上下文与动机**：现状模型变更记录无 agent 归属字段，多 agent 会话恢复后模型状态折叠错位（context §8）；本文件的应答若只藏在风险表，该缺陷是否被消化不可审计。
- **决策**：模型切换记录是**会话级**记录、无 agent 归属字段——会话当前模型是全单一状态；多 agent 会话恢复后当前模型 = 最后一条切换记录（A17），归属规则唯一、无折叠歧义。
- **被否决的备选**：a) 切换记录带 agent 归属、按 agent 各自裁定——与"会话模型状态唯一持有"（§2.1）矛盾，且多 agent 会话中"会话用哪个模型"无法回答；b) 维持现状不定义——折叠错位不可审计。
- **影响范围**：§2.4 多 agent 归属；记录族字段定义。

### ADR-007（设计决策：内部轮次模型在发起时点钉扎）

- **日期**：2026-09-15（实施 T7 时发现语义缺口引入）
- **上下文与动机**：内部轮次（cron/通知）现实现为发起时从目标 agent 活 config 解析一次模型（R11 核心语义成立，A12 钉子已测试），但轮次进行中的会话切换不会传导进已在跑的内部轮次——评审修复时写入 R11 的"轮次内切换同样即时生效"对内部轮次属过度扩写：主 agent 交互轮次的逐请求生效（R2/A1）由 config-aware resolver 承担，内部轮次为一次性构建（FixedLlmResolver 形态），为极罕见边缘（用户在自动触发的短轮次进行中切换）引入逐请求重建不具成本正当性。
- **决策**：内部轮次的模型在**发起时点**按主链解析并钉扎到该轮次；轮次进行中的会话切换自下一个内部轮次生效（A12 措辞已同步）。主 agent 交互轮次的 R2 即时性不受影响。
- **被否决的备选**：a) 内部轮次也改 config-aware 逐请求 resolver——边缘场景成本不成比例，且 cron/通知轮次的可预测性（触发时点模型恒定）本身是运维友好属性；b) 维持 R11 原文不改实现——把现状语义分歧留给下一次审计发现，违背"语义不因实施便利静默偏离"。
- **影响范围**：§1.2 R11、§1.4 A12；cron/通知轮次的 LLM 构建面（现状零改动，语义经 ADR 固化）。**已知边界（实施 T8 时裁定，最终评审 F3 扩为双披露）**：在途轮次（无论内部钉扎轮次还是交互轮次）期间发生会话切换，其后续 step 的内存 by_model 记**切换时刻**的 key（与 wire 逐请求别名存在该窗口内的细微差异；wire 记录恒按实际请求模型，为对账的权威口径）——窗口窄（单步请求在途期），接受不修。

### ADR-008（设计澄清：模型切换记录的实现载体为既有 wire 对，零新增记录族）

- **日期**：2026-09-15（实施 T10 收口时引入）
- **上下文与动机**：§2.5 记录族原文写"会话日志**新增**'模型切换记录'"，实施时未引入新的 wire 记录类型——若不澄清，读者会预期一个不存在的专用 op，且"新增记录族一个"（§5）将无法对账。
- **决策**："模型切换记录"由既有 `WireOp::ConfigUpdate { model_alias }`（状态 fold，恢复重放后当前模型 = 最后一条）与 `ContextAppendMessage { origin: model_switched }`（转录投影，分割线渲染源）**这对既有载体**承载：前者满足 R9/A10（恢复一致），后者满足 R3/A2（分割线随恢复仍在）。属实现映射澄清，**非语义变更**——§2.5 的需求语义（随恢复重放、不属于撤销单元、携带前后模型显示信息）逐条仍成立。
- **被否决的备选**：a) 新增专用 `ModelSwitched` wire op——多一个需要版本化与全端实现的记录类型，与"契约链变更最小"（§5）冲突，且信息严格是既有对的子集；b) 不写澄清——留下"计划与实现不符"的审计缺口。
- **影响范围**：§2.5 记录族、§5 契约链变更计数（修正为"新增记录族零个，复用既有 op 一个"）；无代码影响。
