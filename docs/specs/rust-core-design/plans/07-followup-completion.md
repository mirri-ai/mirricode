## T1: MCP 运行池热更新（reconcile）

**优先级**：P0 ｜ **涉及面**：rust（mirri-embedded / mirri-mcp）+ web（MCP 面板验证）

**背景**（2026-09-07 核验修正）：配置写侧不 reconcile 运行池，但缺口比原 ROADMAP 表述**收窄**——实测：`mcp.config.set/remove/setToolFilter` 落文件后直接 ack，完全不触碰运行池（`mcp_config_handlers.rs:157-179`，`upsert_server_entry` 后即 `ack()`）；`mirri serve` 宿主（mirri-cli）已有 hot-reload watcher 监听三层 mcp.json 并 reconcile **workspace 池**（`mirri-cli/src/watcher.rs:511 reload_mcp_servers`），但 **user 池无任何 watcher 覆盖**；**嵌入式宿主（NAPI / ACP / desktop spawn）两侧均不 reconcile**——这些路径上增删改/启停确实下次启动才生效。MCP spec §4.3 已定义终态事件链（配置落盘 → diff → 池增量操作 → `event.mcp.serverChanged`）——本任务就是把设计落地到引擎层，取代宿主侧 watcher 补丁。

**Goal**：配置写侧按 MCP spec §4.3 落地引擎级 reconcile——enable/disable 即时生效（断开/重连）、新增 server 后台连接进池、移除即断连清理，全程无需重启进程；user 池与 workspace 池同语义；宿主 watcher 降级为兜底。

**验收标准**：
- [x] e2e：serve 运行中 `mcp.config.update` 将某 server disable → 该 server 工具从 live agent 工具表消失（`mcp.list` 状态翻转、工具注销），不重启进程；re-enable 后恢复
- [x] 新增 server：写入配置 → 后台连接完成进池（`mcp.list` 报 Connected，工具可调用）
- [x] 移除 server：连接断开、工具注销、句柄释放（无孤儿连接）
- [x] user 池与 workspace 池各验证一遍（懒连接语义不回退——见 T8 核验结论）
- [x] mutation 红线：删 reconcile 触发点即红（至少 1 处引擎级）
- [x] 门禁：workspace 全绿 + clippy 零告警 + web MCP 面板 Playwright 操作链（enable→工具消失→disable 除外）

**落地记录**（2026-09-07，`513fe257`）：引擎级 reconcile 落地于 mirri-embedded `mcp_config_handlers`（写侧 `mcp.config.set/remove/setToolFilter` 落盘后后台 spawn 池增量操作，`Arc<tokio::sync::Mutex>` 串行化），diff 纯函数在 mirri-mcp 新 `reconcile.rs`（`diff_pool_ops(old, new) -> Vec<PoolOp>`：Connect/Disconnect{unregister}/Reconnect/RefreshToolFilter，9 条纯函数测试）；池增量 API 补齐（`registered_configs`/`update_server_config`/`wait_for_idle` + `call_tool` 在途计数与撕断重映射）；R2 采"等在途完成、10s 强断、报错含 server 名"；事件复用既有 `mcp.server.status`（`SessionEvent::McpServerStatus`，池 listener 翻译发布到所有 live session——不新增 `event.mcp.serverChanged`，契约链零变更）；bootstrap 空配置也挂池（add 路径需目标池）；`status_listeners` 换 std RwLock 修静默丢弃。e2e 经 in-test mock HTTP MCP server（首个真实 Connected 测试基建）：workspace 池 disable→Disabled 翻转+工具注销+re-enable 恢复、user 池 disable+remove、add→Connected+工具可调、setToolFilter 不断连刷新、R2 等待/强断两臂。mutation：三个写触发点逐一删除→对应 e2e 各自红（3/3）。门禁：`cargo test --workspace` 全绿（mirri-embedded lib 421/0、mirri-mcp 207/0）+ clippy `--workspace --all-targets -D warnings` 零告警；契约链无变更 → TS 面免测（用户重定门禁替代 Playwright 项）。已知限制（热加遮蔽快照、跨引擎 user 池通知）记 brief followup 候选。

## T3: steer 语义族对齐（F-P7-10..13）

**优先级**：P1 ｜ **涉及面**：rust（mirri-core turn_flow / session manager）

**背景**：P7 评审（agent-110）登记的四件 steer 语义缺口：**F-P7-10** 驻留 steer 逻辑零测试覆盖（删掉后 355/0 无红）；**F-P7-11** 驻留 steer 不随 close/resume 丢弃——TS `finishResume()` 显式清空 steerBuffer，rust 复用同 key 旧 buffer；**F-P7-12** `message.steer` 不写 wire log——TS 记 `turn.steer` record 且 restore 恢复，rust 驻留 steer 重启即丢，触及契约 #2（steer 是否算 durable 状态域待裁决）；**F-P7-13** 无 turn 时 steer 不开新 turn——TS `steer()` 无 active turn 直接 `launch()`，rust 仅驻留（空闲会话 steer 用户无任何响应）。评审建议四件作为一组优先排期。

**Goal**：steer 语义与 TS 全对齐：驻留有测试钉住、随会话生命周期正确清理/恢复、durable 化按裁决落地、空闲 steer 即时开 turn。

**裁决点（批前立项，推荐默认已注）**：steer 是否 durable——**推荐 durable**（落 `turn.steer` op，重启恢复驻留 buffer；理由：用户 steer 一条指令后重启丢掉，感知为"吞消息"，比 TS 更差的静默行为）。
**核验状态**：本轮未逐条复验（来源 P7 评审 agent-110 证据链）——批前 brief 先复核四项现状。

**验收标准**：
- [x] e2e：驻留语义钉住——F-P7-13 落地后存续的驻留路径是 abort-turn 上的 steer（自然结束恒消费）：gated fire turn → steer → abort → `message.send` → 首个 LLM 请求含 steer+新 prompt（`should_flush_resident_steer_into_next_turn_first_request_when_turn_aborted_after_steer`）
- [x] F-P7-13：空闲会话 steer 直接开新 turn（fire-mode launch，LLM 即调、TurnStarted/Completed 可见、请求体含 steer 文本）
- [x] F-P7-11：durable 裁决——close→resume（含进程重启，双 server 同目录模拟）驻留 steer 恢复，clear-then-park 幂等，出现恰好一次断言
- [x] F-P7-12：wire `turn.steer` record 写侧（write-before-mutate + blob offload）+ resume 恢复 + `turn.steer_flushed {count}` 消费标记（reducer `steer_pending` FIFO pop）双红线
