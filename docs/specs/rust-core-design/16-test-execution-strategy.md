# 16 — 测试执行策略与并行安全（Testing Execution Strategy & Parallel Safety）

> 状态：设计文档（终态）。现状证据与摸底快照见 `context.md` §16（2026-11-02 调研）。
> 变更记录：SDR-016.1（2026-11-02，初版：确立测试分层、隔离契约、并行安全规则与速度预算）。编号作用域：本文件内自增（与同目录其他编号文档的 SDR 空间相互独立）。

## 1. 范围

### IN

- rust workspace 的**测试执行策略**：分层定义、并行安全规则、隔离契约、速度预算、验收度量。
- 为满足上述契约而进行的**非测试代码可测试性重构**（环境注入化、共享测试设施下沉）。
- 面向 agent 与人的**测试落地标准**（写入 `rust/AGENTS.md` 的硬规则）。

### OUT

- 不改变任何生产功能语义（wire 协议、事件投影、RPC 方法面均不动）。
- 不引入新测试框架迁移（不换 test harness 本体）；不改变 TS 侧测试。
- 不优化 rust 编译速度本身以外的 CI 流水线结构。

## 2. 目标与非目标

**目标**

1. 全量 `cargo test --workspace`（含编译）在标准开发机上 ≤ 7 分钟，且结果可复现（连续两次全绿且均在预算内）。
2. 测试**可并行**：任意两个测试并发执行不因共享进程级状态（环境变量、HOME、端口、锁文件）互相干扰。
3. 测试**稳定**：无随机失败（flake）——不依赖真实墙钟等待的时序假设、不依赖执行顺序、不依赖外部网络。
4. 测试**有效且不冗余**：每层各有明确职责，同层内不重复覆盖。
5. 测试**隔离**：每个测试的文件系统足迹限制在其私有临时目录内。

**非目标**

- 不追求零 flake 的形式化证明；以「连续两次全量全绿」为验收线。
- 不追求把每个 sleep 都虚拟化——仅处理结构性慢因（见 §7 P2）。
- 不改变 `#[ignore]` 真实网络 e2e 的存在形态。

## 3. 上下文与动机

- 团队以 agent 协作开发为主，测试执行的「快、稳、可并行」直接决定 agent 迭代速度与门禁可信度。测试若慢或随机红，agent 会被迫反复跑全量或误改正确代码。
- 现状中测试对进程级状态（环境变量、真实 HOME）的依赖分散在多个测试二进制中，各自持有互不相识的锁，形成隐性竞态窗口（证据清单见 `context.md` §16.1）。
- 集成测试文件数量多、各自独立成二进制，导致全量测试的编译体积成为总耗时主导项（证据清单见 `context.md` §16.4）。
- 项目缺少一份让所有 agent 统一遵循的测试落地标准，不同批次贡献的测试风格漂移（有的隔离、有的依赖真实等待、有的持锁贯穿全程），是策略不清晰与执行不稳定的根源。

## 4. 提案：四层测试模型与硬规则

### 4.1 测试分层（唯一允许的层级定义）

**命名裁决（SDR-016.2）**：为避免与 TUI 规范的 L1–L4 分层（`docs/specs/tui-architecture.md`）撞名，本域测试层级统一使用 **T0–T3** 前缀。任何文档或 AGENTS 规则中提到「测试层级 T2」均指本表语义，与 TUI 分层无关。

| 层 | 名称 | 位置 | 职责 | 并行安全 | 速度预算 |
|---|---|---|---|---|---|
| T0 | 单元测试 | `src/` 内 `#[cfg(test)]` | 纯逻辑：reducer、解析、纯函数。禁止 IO、禁止真实时间、禁止环境变量读写 | 天然可并行 | 单测 ≤5s |
| T1 | 组件集成测试 | `tests/` 目录 | 单 crate 内组件协作，使用注入的假件（Fake FS / 暂停时钟 / MockLlm） | 必须可并行 | 单测 ≤5s |
| T2 | 服务级集成测试 | `tests/` 目录（server/embedded 等） | 起真实服务实例（随机端口 + 私有 HOME），验证协议行为 | 必须可并行 | 单测 ≤30s |
| T3 | 真实二进制 e2e | `#[ignore]` gated 或独立命令 | 真实网络/真实 LLM/真实子进程链路 | 显式串行/手动触发 | 不设预算（不进全量门禁） |

**层级判定规则**：一个测试属于哪层，取决于它**需要什么真实资源**。需要假件即可覆盖的归 T0/T1；需要真实进程/端口的归 T2；需要真实外部网络的归 T3。T3 不参与 `cargo test --workspace` 默认门禁，仅 `--ignored` 或专用命令触发。

**层级声明机制**：每个测试模块（`mod` 或文件）头部必须携带 `// layer: T<n>` 注释标签（如 `// layer: T1`）。该标签是评审与后续机械扫描的判据（扫描器实现见 §4.5 第 7 条），未声明层级的测试不得进入评审。

**与既有规则的衔接**：本模型与 mirri-core zero-IO 架构裁决（Z1）同构——IO 经 trait 注入使 T0/T1 成为可能；测试侧是同一哲学的验收面。

### 4.2 隔离契约（每个测试的硬性义务）

1. **环境变量**：T0/T1 禁止读写进程环境变量。需要环境语义的代码必须经注入式解析（`resolve_*_from` 模式），测试传值而非改环境。T2 如确需设置环境变量（如真子进程需要），必须：(a) 只作用于自己 spawn 的子进程命令（`Command::env`），(b) 若必须 `set_var`，则使用**全 workspace 唯一**的 `env::lock()` 守卫并覆盖最小变量集合。
2. **HOME / 目录**：所有测试的文件足迹必须落在 `tempfile::tempdir()`（或等价一次性目录）内。禁止读写真实 `~` 下任何路径。需要 HOME 语义的，注入 `home_dir` 参数或使用隔离的 fake home 目录。
3. **端口**：一切监听必须 `127.0.0.1:0` 随机分配，禁止硬编码端口。客户端侧对端口冲突需有重试容忍。
4. **时间**：T0/T1 禁止真实等待（`thread::sleep` / 固定 `tokio::time::sleep`）。异步测试默认 `start_paused`；需要推进时间用 `tokio::time::advance`。轮询等待一律用带 deadline 的 `wait_for_*` helper（禁止对象是测试代码内的**裸固定 sleep**，helper 内部 ≤50ms 步进机制除外），禁止裸固定 sleep 充当同步原语。
5. **网络**：默认门禁测试禁止真实外网。HTTP 一律 wiremock / 本地 listener。
6. **数据库 / 锁**：测试用 db 文件与锁文件必须在 tempdir 内。
7. **工作目录**：测试不得假设 CWD 可写；不得在真实 CWD 下留痕。
8. **锁与异步**：`env::lock()` 为同步 Mutex，**禁止跨 `.await` 持锁**（多线程 runtime 下线程饥饿死锁风险）。需要异步上下文内改环境的，在进入异步块前完成 set/restore，或改为子进程级注入（`Command::env`）。

### 4.3 公共测试设施（唯一提供点）

新建 **`mirri-test-support`**（workspace 内 dev-only 公共 crate，无生产依赖方），提供：

- `env::lock()` — workspace 级唯一环境变量互斥守卫（Lazy 静态 Mutex），配套 `EnvGuard`（保存/恢复被改变量）。
- `home::temp_home()` — 创建一次性 fake HOME（tempdir + 标准子结构），返回路径与守卫。
- `wait_for` 模板 — 带步进与 deadline 的条件轮询 helper 家族（`wait_for_eq / wait_for_some / wait_for_cond`）。
- `port::ephemeral_listener()` — `127.0.0.1:0` 绑定 + 端口提取。

**放置裁决**：设施放在独立 crate 而非塞进 `mirri-test-harness`（后者是 wire 层黑盒设施，职责不同，见 `context.md` §16.2）。`mirri-test-harness` 与 `mirri-test-support` 职责边界：前者面向「跨端契约黑盒客户端」，后者面向「crate 内并行安全基础设施」。

**终态**：全 workspace 唯一的环境变量互斥锁提供点是 `mirri-test-support::env::lock()`（同步 Mutex，配合 `EnvGuard` 保存/恢复被改变量）；唯一的 fake HOME 构造点是 `mirri-test-support::home::temp_home()`。任何 crate 不得再自建静态 ENV 锁。

**生产代码 HOME 读取注入化的范围判据**：凡**被任何 lib 测试目标并发路径可达**的进程级 HOME 读取（含 env 直读与 home_dir 回退链），必须提供注入式变体（`resolve_*_from` 模式）供测试使用；仅被子进程型测试触达的入口（每进程独立 env）可豁免。完整现状清单见 `context.md` §16.1。

### 4.4 测试二进制收敛（编译预算的主要杠杆）

- **规则**：一个 crate 的 `tests/` 目录默认收敛为**少量二进制**（目标 1–3 个），通过共享 `tests/common/` 模块复用搭建代码。全 workspace 集成测试二进制总数收敛到 ≤30。
- 收敛以集成测试文件最多的 crate 为首要对象，方式为**纯移动合并**（不改测试逻辑，只共享 setup），分批执行降低风险。域组数量超过 3 个的 crate，将相近域再归并（如 `tools/` 吸收 `scope/`），保证二进制数不超规则。
- **测试命名与可发现性不受影响**：`cargo test --test <name>` 语义保留（合并后的二进制名即模块组名）。
- **原则**：合并只做「文件→模块」的机械搬运（原文件以 `mod 文件名 {}` 包裹进组二进制，import 不整理），任何逻辑改动走独立批（防止纯移动批夹带行为变化）。
- **static 状态前置扫描**：合并进同一二进制前，必须确认各文件无跨文件依赖的 static 可变状态；有依赖的文件保持独立二进制或最后处理。

### 4.5 测试落地标准（写入 `rust/AGENTS.md` 的硬规则）

> 该节内容将逐字落入 `rust/AGENTS.md`「测试铁律」章节（新增），违反 = 返工。

1. 新测试必须声明层级（`// layer: T<n>` 模块头标签），按 §4.1 判定。T3 必须 `#[ignore]`。
2. 新测试必须满足 §4.2 全部八条隔离契约，方可进入评审。
3. 需要环境变量语义 → 注入式优先；确需 `set_var` → `mirri-test-support::env::lock()` + 最小集合 + 不跨 await。
4. 存量测试不满足隔离契约的，按 ROADMAP 分批迁移，不阻塞新贡献。
5. 速度预算：单测试 ≤5s（T0/T1）/ ≤30s（T2）；全量 workspace ≤7min（热缓存口径）。超预算的测试须拆分或降层（改用假件）。
6. 每个测试 crate 维护共享 `tests/common/` 模块；新增测试搭建代码必须进 common，不得在各测试文件内重复。
7. **机械守卫**：`thread::sleep` 与裸 `std::env::set_var` 在测试代码（test cfg）中列入 clippy `disallowed-methods`（豁免须注释说明理由），使「禁裸 sleep / 禁裸 set_var」成为可扫描判据而非人工约定；`// layer:` 标签缺失由扫描脚本报告（与 check-zero-io.mjs 同级别门禁，落地批定义其具体形态）。（SDR-016.3，2026-11-02：主门禁落地为 node 扫描脚本 `rust/scripts/check-test-hygiene.mjs` + baseline 白名单 `rust/scripts/test-hygiene-baseline.json`——test cfg 的精确识别与存量容忍（R2/R4 迁移前的 584 处存量）需要脚本级控制，clippy `disallowed-methods` 的全局作用域无法限定 test cfg、会误伤生产代码中合法的 `set_var`（子进程注入准备等），故记为 ROADMAP 增量项而非主门禁。）

### 4.6 执行器与门禁

- 保持 `cargo test`（libtest）为门禁执行器，不引入 nextest 作为门禁依赖（见 §5 拒绝项）。
- CI 与本地同构：单条 `cargo test --workspace --locked` 为唯一全量门禁命令。
- 全量验证用「连续两次全绿」标准（消缓存后第一次不计入）。

## 5. 被拒绝的方案（trade-offs）

| 方案 | 描述 | 拒绝原因 |
|---|---|---|
| cargo-nextest | 现代执行器，进程级隔离+重试标记 | 引入门禁工具链依赖（RustSec 审计面+CI 变更+agent 使用成本）；libtest 的并行问题本设计已从源头消除；收益不抵迁移成本 |
| 全部测试强制单文件单二进制 | 最大化编译收敛 | 与域分组冲突；单二进制过大会造成 link 慢与 CI 分片不便 |
| serial_test crate | `#[serial]` 注解串行化 env 敏感测试 | 治标：让竞态测试串行而非消除竞态；与「可并行」目标相反 |
| 每个测试独立进程沙箱 | 绝对隔离 | macOS 无低成本进程沙箱原语；开销与复杂度不成比例 |
| 修改 libtest 线程数 | `RUST_TEST_THREADS` 调优 | 不消除竞态，只降低概率 |
| 单独测试专用 CI runner | 更快机器 | 掩盖问题，成本递增，不解决本地开发体验 |
| `[profile.test]` 激进调优（debug=0 等） | 压缩编译产物体积 | 牺牲测试失败时的调试体验（无符号/无法断点）；二进制收敛已足够达成预算；保留为超预算时的后备杠杆 |
| T2 服务级测试全部 `#[ignore]` 化 | 立即压缩门禁耗时 | 门禁覆盖面缩水：协议行为回归只能在手动/CI 专属步骤发现，违背「门禁可信」目标 |

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 大规模文件移动引入路径/引用错误 | 纯移动批零逻辑改动；每批后跑受影响 crate 测试；分批小步 |
| `env::lock()` 粗粒度锁造成新的串行瓶颈 | 仅 T2 少数测试需 set_var；T0/T1 注入化后锁需求趋零；锁为 workspace 级单一同步 Mutex（变量集合可由 EnvGuard 记录，但互斥域全局——串行面仅限确需 set_var 的测试） |
| `start_paused` 与真实 tokio runtime 特性不兼容（如某些 spawn 的任务依赖真实 IO 完成） | 仅对纯异步调度类测试启用 paused；IO 等待类保留 wait_for 轮询 |
| 合并二进制后同二进制内测试间出现意外耦合（static 状态） | 合并前扫描各文件的 static 状态使用；有 static 依赖的文件最后合并或保持独立二进制 |
| 编译收敛反而降低单测试迭代速度（改一个文件重编译整个组） | 增量编译下代价可接受；域组划分保持功能聚合，热路径（mirri-core 单 crate 测试）仍可用 `--test <name>` 单独跑 |
| 7 分钟预算依赖机器性能 | 预算定义为热缓存口径（编译产物已在本地 target 缓存；冷缓存与 CI 首跑不在此预算内）；「标准开发机」= 维护者日常开发机（与 CI runner 不同属，CI 时间不承诺 7 分钟）；预算超额时先归因（编译 vs 执行）再动用后备杠杆（§5 profile.test 条目） |

## 7. 成功标准（验收度量）

1. **速度**：热缓存口径下 `cargo test --workspace --locked` 单次总耗时 ≤ 7:00（含增量编译）；验收流程 = 消缓存后跑一次（不计入）+ 连续两次全绿且均 ≤7:00。
2. **并行安全**：全 workspace 环境变量互斥锁收敛到唯一 `mirri-test-support::env::lock()`（workspace 内其他静态 env 锁定义清零）；无裸 `set_var` 无锁调用残留（扫描命令零命中）。
3. **稳定**：连续两次全量全绿；对曾持锁/裸 set_var 的测试目标以 5× 重复运行或随机顺序（`-Z unstable-options --randomize`）作附加验证无红。
4. **标准落地**：`rust/AGENTS.md` 增补「测试铁律」章节；`docs/specs/glossary.md` 不新增跨域术语（T0–T3 为本域内命名，已与 TUI 分层显式消歧）。
5. **可维护**：每 crate `tests/` 二进制数 ≤3；全 workspace 集成测试二进制总数 ≤30。
6. **不冗余**：合并后无同一行为被两个二进制重复覆盖（人工审查 + reviewer 校验）。

## 8. 执行切分（顺序裁决）

批次顺序为设计裁决：**先立标准与设施，再除竞态，后收编译，末治 sleep**（R2 必须先于 R3——二进制合并会让原本被进程边界隔离的文件进入同一进程并发，竞态必须先清；R4 依赖 R1 的 wait_for helper）。各批内容、任务分解与验收节奏见 `plans/` 对应 plan 文件；批次状态记录于 `rust-core-design/ROADMAP.md`。合并节奏由用户决定。
