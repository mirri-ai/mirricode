## 1. 需求

### 1.1 动机（抽象问题陈述）

新会话在会话列表中靠首条消息的原始文本片段充当标题：文本长、口语化、词不达意，同一意图的不同措辞产生面目迥异的标题，用户从列表里认不出"这条会话是干什么的"。期望标题能概括会话意图、保持简短、一致可读；同时命名不得污染主会话上下文、不得扰动主对话请求的前缀稳定性——命名自身的模型成本由一次骑乘 provider 输入缓存的旁路调用承担。（现状盘点见 [context.md](context.md) §7。）

### 1.2 需求项

- **R-A 自动命名**：新会话首个用户轮次内**第一个 LLM 响应落地后**（SDR-016 前移；原为首个用户轮次成功结束后），引擎以一次**旁路 LLM 调用**依据对话内容（用户意图与助手响应）生成一个简短、概括性的标题，经既有自动命名守卫写入（会话列表等处展示），用户无需任何手动操作。长任务的单轮多步执行不再阻塞命名——首个响应落地即触发。
- **R-B 手动优先**：用户手动设置过标题的会话，任何自动命名的尝试都不得改动它——最后一次手动设置的标题永久生效。
- **R-C 一次生效**：已自动命名的会话不再重复命名；后续消息不再影响标题。
- **R-D 标题恒存在（兜底）**：旁路调用未触发（轮次错误结束、硬中止、未配置模型）或未成功（调用失败 / 超时 / 响应不可用）时，自动退回"用户消息文本截取"命名规则，保证会话始终有一个可读标题。
- **R-E 敏感信息防护**：标题的写入与展示均不得携带密钥、令牌、口令等敏感内容（脱敏后仍可表达意图）。
- **R-F 实时生效**：标题写入后立即同步到 web 与 TUI 展示端，无需刷新、重连或重启。ACP 端标题不实时刷新是**既有边界**（ACP v1 官方 schema 无标题更新类型），非本方案回归。
- **R-G 默认可用**：功能默认启用，无需任何配置。
- **R-H 缓存骑乘的旁路调用**：命名经由**一次**旁路 LLM 调用完成——该调用逐字节复用主循环的请求前缀（provider 输入缓存近乎全量命中）、不进入主会话上下文、不记入 wire log；主会话各轮请求中与命名相关的增量**严格为零**。

### 1.3 非目标

- 不重写历史会话的既有标题（含旧规则派生的标题）——只对"尚未命名"的会话生效。
- 不提供"标题生成中"的中间 UI 状态。
- 不做标题的语言本地化或个性化定制。
- 子 agent（subagent）轮次不参与命名——标题是会话级语义，仅主 agent 的用户轮次触发旁路调用。
- 不新增"标题专用小模型"配置面——旁路调用使用与会话主循环相同的模型解析；未来如需切换模型别名属独立裁决，届时须重评前缀缓存损失。
- 不为 fork 会话自动命名——fork 未显式给标题时沿用 fork 默认标题（该标题不视为占位，自动命名对其不生效，与既有 fork 语义一致）。
- 不为 ACP 端新增标题实时推送（见 R-F 边界声明）。

### 1.4 验收标准

| # | 验收项（Given-When-Then） |
|---|---|
| A1 | 新会话首个用户轮次内首个响应落地后触发一次旁路调用，生成概括性标题（明显区别于消息原文的截取），web/TUI 展示端实时刷新 |
| A2 | 用户手动改名后，旁路调用的标题写入被守卫拒绝，标题保持用户所改内容 |
| A3 | 用户改名与旁路写入同时到达 → 以先写入者为准，后到者被守卫丢弃（无部分写入） |
| A4 | 旁路调用未被触发（轮次错误结束 / 硬中止 / 未配置模型）或未成功（调用失败 / 超时 / 响应清洗后不可用）→ 标题退化为用户消息文本截取，会话仍可命名 |
| A5 | 旁路调用返回的标题经脱敏（与规则式同一实现，不允许两套脱敏规则）与长度校验后写入（≤200 字符、无敏感原文） |
| A6 | 首条用户消息无文本（纯图片等）→ 旁路调用仍可基于多模态内容命名；兜底规则无文本可截取时保持未命名，待后续用户轮次重试 |
| A7 | 主会话的任何轮次请求中**不出现**命名指令、标题工具或工具表变更提醒——与命名相关的注入增量严格为零 |
| A8 | 旁路调用不记入 wire log；标题的崩溃恢复以既有会话状态持久化为准——崩溃窗口内标题未落盘时，恢复后会话回到未命名，下一用户轮次重新触发旁路调用（自愈语义） |
| A9 | 轮内首响应触发失败（调用失败 / 超时 / 响应不可用）时**不得**立即走规则式兜底——须保持未命名并释放 claim，由该轮次的 settle 站点重试旁路调用；settle 重试仍失败才退回规则式兜底（标题不得从 LLM 版跳回截取版） |
| A10 | 首个用户轮次被取消（cancelled）→ 轮次仍经成功结束路径：轮内已触发且成功的标题保持；轮内未触发（取消早于首个响应）或轮内失败时，settle 站点照常重试旁路调用；重试失败 → 兜底照常执行 |
| A11 | steer（用户在轮次进行中追发消息）不改变本轮触发决策；steer 作为会话首个用户轮次（无在途轮次的 steer）时与普通首条消息同语义 |
| A12 | 旁路调用请求与主循环请求**前缀逐字节对齐**：工具定义全量同一、消息序列为主循环投影的严格扩展（仅末尾追加一条标题指令消息）——以自动化请求对比测试固化；轮内触发时点快照的投影仅含首步响应前缀，同样满足严格扩展语义 |

**触发时点（轮内首响应落地）的依据**（SDR-016，取代原 settle 触发论证）：

- **意图已足够**：首个用户轮次的第一个响应落地时，上下文已有用户消息 + 助手首步响应——标题的意图信号主要来自用户消息本身，settle 时点多出的几十轮工具结果对标题质量增益极小；
- **缓存同样热**：旁路调用的缓存骑乘依赖"前缀刚被主循环请求写入缓存"——首个 step 的请求刚完成，此刻快照的前缀正是刚写入缓存的内容，与 settle 时点（距最后请求数秒）相比等价甚至更热；
- **并发安全复用**：旁路调用只读投影、不写上下文、不记 wire log、不进 in-flight 注册表——与主循环后续 step 并发执行的安全性论证与原 §4 风险表"旁路调用与下一用户轮次并发"完全同构，只是并发对象从下一轮次变为本 turns 内后续 step；
- **用户感知**：大任务（单轮多步、耗时长的工具调用循环）在旧时序下全程显示占位标题，新时序下首个响应落地即命名，占位期缩至首个 LLM 响应的延迟。

**时序契约**：旁路调用的首选触发时机是首个用户轮次内第一个响应落地（`TurnStepCompleted` 的 step 1）；轮内触发失败时**不**立即走规则式兜底——释放 claim 保持未命名，等该轮次 settle 站点重试（A9）；settle 重试仍失败才退回规则式兜底（R-D）。轮次错误 settle 与硬中止 settle（未经轮内触发或轮内触发未成功）直接走规则式兜底。唯一例外不变：未配置模型（无 LLM 工厂）的消息派发路径——轮次不存在，派发时点直接执行规则式命名（该消息仍计为有效对话输入：会话物化、标题恒存在；RPC 本身照常报错）。

**被取消轮次的语义**：取消（cancelled）的轮次经成功 settle 路径收尾——若轮内已触发且成功，标题已落地；若轮内未触发（取消发生在首个响应前）或轮内触发失败，settle 站点照常重试旁路调用；重试失败由规则式兜底收尾。

### 2.2 命名守卫（终态语义）

命名（无论旁路写入还是兜底写入）仅在以下条件同时成立时生效：

1. 该会话标题不是**用户手动设置**的（`is_custom_title == false`）；
2. 该会话标题仍是**占位标题**（未命名 / 未派生）。

守卫在**写入的原子闭包内**检查——用户手动改名（`session.rename` 同样经原子元数据更新）与旁路写入无论以何种顺序到达，先写入者生效，后到者被丢弃，不存在部分写入（A2/A3）。

### 2.3 降级链（终态语义）

| 情形 | 行为 |
|---|---|
| 首个用户轮次内首响应落地（wait / fire / steer），会话未命名 | 触发旁路调用（首选时点）；成功 → LLM 标题 |
| 轮内触发失败 / 超时（30s）/ 响应无文本 / 清洗后为空 | 释放 claim、保持未命名（**不**走规则式兜底，A9），等本轮次 settle 站点重试 |
| 该轮次成功 settle（含被取消轮次），仍未命名（轮内未触发或失败） | settle 站点重试旁路调用；成功 → LLM 标题；失败 → 规则式兜底（用户消息文本截取）；无文本可截取时保持未命名，下一用户轮次可重试 |
| 轮次错误 settle（wait / fire / steer） | 直接规则式兜底，不重试旁路调用——轮次失败通常意味着 provider 异常，旁路调用大概率同样失败，且错误轮次的消息尾部可能残缺 |
| 硬中止（abort）settle | 规则式兜底（锁无关路径） |
| 未配置模型（无 LLM 工厂） | 轮次不存在，消息派发时点直接执行规则式命名（该消息仍计为有效对话输入：会话物化、标题恒存在；RPC 本身照常报错） |
| 兜底规则无文本可截取（纯图片消息） | 保持未命名，释放 claim，下一用户轮次重试旁路调用 |
| 非用户发起的轮次（cron / task 等引擎内部轮次） | 不参与命名：不触发旁路调用、不兜底（标题仅从**用户消息文本**派生；触发订阅按派发方自己铸造的 wire turn id 过滤，天然排除） |

### 2.4 数据与契约

- 复用既有标题字段与 `is_custom_title` 标志（`session.rename` 已有"手动改名即置位"语义）；自动命名（旁路与兜底）写入标题时**不**置 `is_custom_title`——"用户手动"与"系统自动"可区分，两者都满足"不再次覆盖"（条件 2）。
- 标题长度上限沿用既有约束（200 字符）；脱敏复用规则式同一实现（A5）。
- **不新增任何工具**：命名不占用内置工具面——主 agent 与子 agent 的工具列表与命名无关，主循环请求的工具定义序列不含任何命名相关条目。
- **wire log**：旁路调用不向 wire log 记录任何操作——旁路标题写入不构成需要跨重启审计回放的会话状态变更，持久化由 `state.json` + 索引写通承担（写穿机制不变）；崩溃窗口的自愈语义见 A8。会话恢复对转录中的任意工具调用帧按普通消息内容恢复，不重新执行。
- **契约链变更最小**：不新增 RPC、不新增工具、不新增事件类型；标题写入复用既有元数据更新事件（web/TUI/SDK 已消费；ACP 端落既有 catch-all 分支，行为与现状一致）。
- 仅影响 rust 引擎；TS 各端零改动。

### 2.5 成本语义

- **主会话成本严格为零**：主循环任何轮次的请求中不含命名指令、标题工具或工具表变更提醒（A7）——命名对主对话的上下文占用与请求前缀的扰动为零。
- **旁路调用缓存骑乘**：请求前缀与主循环最后请求逐字节对齐——同一 LLM 解析构造（同 provider / 模型 / system prompt）、同一工具定义序列、同一消息投影（normal 投影 + 同一 media pipeline），仅在末尾追加一条标题指令消息（A12）。
- **缓存命中分析**（显式断点的 provider）：system 断点与 tools 断点的内容与主循环完全相同 → 全量命中（system 是最大的静态块）；消息断点落在追加的指令消息上（新内容，按缓存写计价），其前的消息段为未缓存输入——首个用户轮次后该段仅一条用户消息 + 一条助手响应（约数百 token）。隐式服务端前缀缓存的 provider（OpenAI / Google / Kimi）：旁路请求前缀是主请求前缀的严格超集，消息段同样命中。
- **旁路调用不写缓存**：不追加上下文、不记 wire 操作——不会进入后续主循环请求的前缀，主循环缓存不受影响。
- **总量**：旁路调用输入 ≈ 全量缓存读（约 0.1x 单价）+ 数百 token 新输入 + 极短输出；并以 usage 三桶（未缓存输入 / 缓存读 / 缓存写）日志提供运行时成本观测。

## 3. 备选方案与取舍

| 备选 | 取舍 | 结论 |
|---|---|---|
| 首条用户消息派发时点（轮次开始前）调用旁路 | ① 意图只有用户消息、无助手响应佐证，清晰度差；② 主循环请求尚未发出，provider 缓存未写入，缓存冷 | 否决（与 SDR-016 的"轮内首响应"区分：后者已有响应佐证、缓存已写入，两条否决理由均不适用） |
| 用独立小模型调用 | 前缀与主会话不匹配，缓存零命中，输入全额计费且慢；且需新增模型配置面 | 否决（未来可作可选配置，见 §1.3 非目标） |
| 主循环内注入指令、模型以文本输出标题 | 指令与响应进入主会话上下文与缓存前缀，污染主对话（违背 R-H） | 否决 |
| 工具机制（模型在既有响应流中调用标题工具写入） | "零额外请求"表象下的隐性成本：工具 schema 常驻每个请求、提醒注入与 tool-call 帧进入缓存上下文、占用内置工具面——高于一次缓存骑乘的旁路调用（演进与论证见附录 A） | 否决（ADR-020） |
| 保留工具作兜底、旁路作主路径 | 两套机制并存：工具 schema 常驻成本仍在，守卫与降级双写 | 否决 |
| 轮次错误（failed）settle 时也触发旁路调用 | 轮次失败通常意味着 provider 异常，旁路调用大概率同样失败；错误轮次的消息尾部可能残缺 | 否决——错误 settle 直接走规则式兜底（保持 R-D） |
| 规则式派生保留在派发时点、LLM 事后精化 | 派发即"已派生"，旁路守卫恒拒绝精化；标题二次跳动 | 否决（时序互斥） |
| 默认关闭、配置开启 | 新增配置面与文档成本 | 否决（默认开启已裁决） |
| 短消息特判（过短不触发） | 复杂化；垃圾输入的兜底标题与截取规则持平 | 否决 |
| cron/task 轮次也参与命名 | 引擎内部 prompt 会污染标题语义 | 否决（仅用户消息文本可派生标题） |

## 4. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 轮内触发失败被误判为终态 | 时序契约（§2.1）：轮内失败仅释放 claim 不兜底，settle 站点重试，A9 验收固化 |
| 旁路调用与主循环后续 step 并发执行 | 旁路只读投影快照、不写上下文、不记 wire 操作、不进 in-flight 注册表——对主循环前缀稳定性零影响；写入侧由守卫先到先得 |
| 旁路调用与主循环在途请求并发打 provider | 输入几乎全为缓存读、请求轻量；30s 超时限制暴露窗口 |
| 旁路调用失败 / 超时 / 响应不可用（轮内触发） | 30s 超时；失败仅释放 claim、保持未命名——标题不跳到截取版（A9），等该轮次 settle 站点重试 |
| 旁路调用失败 / 超时 / 响应不可用（settle 重试） | 退回规则式兜底，标题恒存在（A4）；最坏情况 = 截取规则质量 |
| wait / fire / steer 并发 settle 重复触发旁路调用 | 会话级一次性 claim（进程内原子 CAS）：每进程生命周期内至多一次成功触发；失败释放后下一用户轮次可重试 |
| 用户在旁路调用在途时手动改名 | `set_auto_title` 写入守卫在原子闭包内拒绝，用户标题胜出（A2/A3） |
| 轮次中标题被提前派生，触发前提失效 | 守卫在写入闭包内复核（仍占位 + 非手动）；轮内触发与 settle 重试由一次性 claim 串行化 |
| 旁路请求与主循环请求前缀漂移（缓存全失效） | 前缀逐字节对齐为验收项（A12：工具定义全量同一 + 消息前缀严格扩展的自动化请求对比）；usage 三桶日志提供运行时观测 |
| 缓存遥测误读：旁路调用缓存读桶偏低被误判为前缀未对齐 | 三桶解读须知：provider 缓存 TTL 过期（分钟级）、隐式服务端缓存未回报、首个轮次前缀尚短，以及旁路调用在 spawn 时点读取的投影可能已含紧随派发的下一用户轮次消息（良性前缀超集，仅影响遥测解读）等都会压低缓存读——缓存未命中不必然是设计缺陷；前缀对齐的正确判据是 A12 的逐字节对比，真实 provider 的三桶实测作为补充证据 |
| 旁路调用与下一用户轮次并发执行 | 旁路只读投影、不写上下文、不记 wire 操作、不进 in-flight 注册表——对主循环前缀稳定性零影响；写入侧由守卫先到先得 |
| 轮内首响应为纯 tool-call（无文本），标题质量信号偏少 | 用户消息本身承载主要意图；首步 tool-call 序列亦是信号；settle 重试兜底仍在（R-D） |
| 敏感信息经标题泄露 | 旁路响应与兜底路径统一脱敏实现（A5） |
| 崩溃窗口内标题未落盘 | 恢复后自愈：回到未命名、下一用户轮次成功 settle 重新触发（A8） |
| 标题出现时间移到首个轮次结束之后 | 已由 SDR-016 消除：轮内首响应即触发，占位期缩至首个 LLM 响应的延迟 |

## 5. 成功标准

- 1.4 全部验收项（A1-A12）以自动化测试覆盖（Given-When-Then），含守卫竞态（A3）、降级链（A4）、时序前提（A9）、主会话零增量（A7）与前缀对齐（A12）路径。
- rust workspace 测试全绿、clippy 零告警（Rust 内核域质量门禁）。
- 契约链变更最小化：无新 RPC、无新工具、无新事件类型；标题写入复用既有元数据更新事件。
- 成本验证：主循环请求中命名增量严格为零（A7）；旁路请求前缀与主循环逐字节对齐（A12 自动化断言）。

## 附录 A. 决策记录

### SDR-014（需求变更：自动标题升级为 LLM 生成）

- **日期**：2026-09-13
- **上下文与动机**：会话自动标题目前由首条消息的文本截取充当，长而口语化、无法概括意图（现状盘点：context.md §7）。产品要求标题反映用户意图、简短可读、且不打扰手动设置。
- **决策**：自动标题由模型依据首条用户消息的意图生成；规则式截取降级为兜底仅保证标题恒存在；用户手动设置（`is_custom_title`）后永不覆盖；功能默认开启。命名机制本身属设计层，现行决策见 ADR-020。
- **被否决的备选**：turn 结束后独立生成（成本+延迟）；agent 自由改名无守卫（可覆盖手动标题）；占位后精化（标题二次跳动）；默认关闭（保护成本 vs 开箱即用，选后者）。
- **影响范围**：本文件 §1 全部需求项。

### SDR-015（需求变更：R-H 由"零额外调用"改为"一次缓存骑乘的旁路调用"）

- **日期**：2026-10-02
- **上下文与动机**：与 SDR-014 同期确立的"命名不产生独立的模型请求"（R-H 零额外调用）裁决，其前提是额外请求的输入按未缓存单价全额计费。provider 输入前缀缓存复用改变了该前提：与主循环同模型、同前缀的旁路调用，输入几乎全为缓存读（约 0.1x 单价）——独立调用的成本论据不再成立。而承担"零额外请求"的工具机制自身持有更高隐性成本（工具 schema 常驻、提醒注入、tool-call 帧进入缓存上下文、占用内置工具面，见 ADR-020 动机）。
- **决策**：R-H 改为——命名经由一次缓存骑乘的旁路调用完成，不进入主会话上下文与 wire log；主会话各轮请求中与命名相关的增量严格为零。R-A 的触发语义细化为"首个用户轮次成功结束后"。
- **被否决的备选**：维持"零额外调用"约束（工具机制隐性成本更高且污染主循环）；旁路调用配独立小模型（缓存零命中，见 §3 备选表）。
- **影响范围**：本文件 §1.1 / §1.2（R-A、R-H）、§1.4（A1/A7/A8/A12）；本裁决取代 2026-09-13 的"零额外调用"成本裁决。

### SDR-016（需求变更：R-A 触发时点由"轮次 settle 后"前移到"轮内首响应落地"）

- **日期**：2026-10-13
- **上下文与动机**：ADR-020 的 settle 触发时点在"带明确指示的大任务"场景暴露体验缺陷——大任务是单个长轮次（多步工具调用循环），settle 前标题恒为占位符，用户在列表里长时间看到 "Untitled Session"。原 §3 备选表否决"派发时点"的两条理由（无响应佐证、缓存冷）对"轮内首响应落地"时点均不成立：首步响应已落地（意图佐证存在），首个主循环请求刚完成（缓存刚写入、最热）。
- **决策**：R-A 触发时点前移——首个用户轮次内第一个响应落地（`TurnStepCompleted` step 1，按派发方自己铸造的 wire turn id 过滤，天然排除子 agent / cron / task 轮次）即触发旁路调用；轮内触发失败仅释放 claim、保持未命名，等该轮次 settle 站点重试（A9 语义重定义）；settle 重试仍失败才走规则式兜底。settle 站点由"唯一触发点"变为"重试点"。原 A9"轮次进行中标题保持占位"废止——它只是 ADR-020 时代的可测性手段，非用户需求。
- **被否决的备选**：① 截取→LLM 精化（派发时先写首条消息截取、settle 后精化）——标题二次跳动，且中间态质量低；② UI 本地回退（占位时显示首条消息预览）——列表排序仍按占位标题、跨客户端不一致；③ 等首个含文本的响应——大任务前几步常为纯 tool-call，又回到久等占位的问题；④ 维持 settle 时点——长任务体验缺陷即本 SDR 动机。
- **影响范围**：本文件 §1.2（R-A）、§1.4（A1/A9/A12）、§2.1 / §2.3 / §4；rust 引擎 embedded 层（新增轮内触发站点、`SideTitleContext` 触发阶段语义）、t9 测试面（占位保持用例改为轮内触发语义）。

### ADR-016（已废弃 — superseded by ADR-017；其成本否决理由后被 ADR-020 推翻）

- **日期**：2026-09-13 · **废弃日期**：2026-09-13（当日被否决，未实施）
- **原决策**：首条消息到达即后台异步发起**独立的**小请求调用模型生成标题；限时返回；失败降级规则式。
- **废弃原因**：每个新会话多一次完整模型请求，成本不可接受（用户裁决 2026-09-13）。命名指令与工具随既有轮次注入即可达成同一需求，零额外请求（ADR-017）。
- **保留价值**：其守卫复核、降级链、脱敏与契约复用等子决策被 ADR-017 继承。
- **后续修订（2026-10-02）**：本条"每个新会话多一次完整模型请求，成本不可接受"的裁决被 ADR-020 的前缀复用论证推翻——彼时未考虑 provider 输入前缀缓存复用；同模型、同前缀的旁路调用输入几乎全为缓存读（约 0.1x 单价）。独立调用方向经 ADR-020 以"settle 触发 + 前缀逐字节对齐"的形态转正。

### ADR-017（设计决策：轮次内注入 + 标题工具 + 守卫兜底 · 已由 ADR-020 取代）

> **（本条已由 ADR-020 取代：注入 + 工具机制随机制退役整体移除；其守卫、降级链、脱敏与契约复用语义被继承。）**

- **日期**：2026-09-13（替代 ADR-016）· **评审修订**：2026-09-13（评审人 agent-29，REJECT→修复：B1 时序契约、M1 工具启停机制、M2 状态读取约束、M3 origin 限定、M4 ACP 边界）· **取代日期**：2026-10-02（ADR-020）
- **上下文与动机**：命名不得增加独立模型调用（成本裁决）；模型行为存在不确定性（可能不调用、重复调用、越权调用），且必须不阻塞对话主流程。
- **决策**：
  1. **注入**：会话未命名时（非手动设置 + 占位标题），向该用户轮次注入系统提示片段，指令模型基于用户意图在本轮调用标题工具写入精简标题；命名后注入消失（增量归零，A7）；
  2. **时序契约**：LLM 路径下规则式派生不在消息派发时点执行——轮次开始前标题保持占位（A9）；规则式派生的唯一时机是首个用户轮次结束的兜底；未配置模型的派发路径例外，直接派发时点规则式命名；
  3. **工具启停**：标题工具注册为内置工具（默认停用），由消息派发宿主按"未命名"状态为本轮主 agent 启用、命名后停用（注册与激活分离，工具管理面）；子 agent 的同名注册保持停用；**（本条已由 ADR-019 修订：工具改为常驻，不再逐轮启停）**；
  4. **状态读取**：注入决策在消息派发的异步上下文读取元数据后做出，轮次内静态生效；
  5. **工具执行守卫**：工具写入在原子元数据更新闭包内检查——`is_custom_title == false` 且标题为占位；不满足则静默跳过；与 `session.rename` 先到先得、无部分写入（A2/A3）；
  6. **兜底**：首个**用户发起**的轮次结束（completed/failed/cancelled）仍未命名 → 规则式截取（仅从用户消息文本派生；无文本保持未命名）；cron/task 等引擎内部轮次不参与命名；仍未命名的后续用户消息继续注入；steer 作为会话首个用户轮次时与普通首条消息同语义（A11）；
  7. **清洗**：工具参数标题经脱敏（与规则式同一实现）与 ≤200 字符校验后写入；非法视同未调用走兜底；
  8. **契约**：新增内置工具（主 agent、免审批、wire log 记录）；复用既有元数据更新事件；不新增 RPC；ACP 端标题不实时为既有边界（非回归）；
  9. **默认开启**，无配置开关（用户裁决 2026-09-13）。
- **被否决的备选**：见 §3 表格（含被本决策取代的 ADR-016 独立调用方案）。
- **影响范围**：本文件 §2 设计各节；rust 引擎的消息派发宿主层（注入决策、工具启用、兜底站点）、注入器面、工具注册面。

### ADR-018（设计决策：注入器中途熄灭——修订 ADR-017 第 4 条 · 已由 ADR-020 取代）

> **（本条已由 ADR-020 取代：提醒注入器随机制退役整体移除，不再存在轮内注入。）**

- **日期**：2026-09-14 · **取代日期**：2026-10-02（ADR-020）
- **上下文与动机**：会话审计 session-30c0d8bb（P1-1）证实 ADR-017 第 4 条"注入决策轮次内静态生效"的代价：模型在 step 1 调用 SetSessionTitle 成功后，reminder 仍在其后每个 step 前重复注入（同一 turn 内 6 次，每次约 120 token），文案与事实矛盾（"还没有标题"），并诱导低遵从模型重复调用工具覆盖标题——A7"命名后注入消失（增量归零）"在轮内被违反。
- **决策**：注入器从无状态改为**观察同步熄灭标志**：`SessionMetaHandle` 增设原子标志（`set_auto_title` 成功写入、`session.rename` 命名、`session.update` 的 title 写入（复审补强）、会话恢复时装载到非占位标题时置位）；`TitleInjector` 持有 handle 克隆，`inject` 时同步检查——标志置位即返回 `None`（不再注入）。派发时点的挂载判定（非手动标题 + 占位标题才挂载）不变，ADR-017 第 4 条的"决策时点"部分保留，仅"轮次内静态生效"修订为"轮内可被命名事实熄灭"。
- **被否决的备选**：a) 把 `Injector::inject` 改为异步读元数据——破坏 Injector trait 的同步契约，牵连全部注入器；b) SetSessionTitle 工具成功后从工具内部清除 turn_flow 的注入器——turn 运行中 flow 被异步锁持有，工具层跨锁层级写入有死锁风险；c) 维持现状（每步重复注入）——上下文浪费且提示与事实矛盾。
- **影响范围**：本文件 §2.1；注入器面（TitleInjector 携状态）、元数据句柄面（SessionMetaHandle 标志位）、工具面（SetSessionTitle 成功路径）、派发宿主（挂载点构造）；t9 测试中"轮内每步重复注入"的既有断言按新语义更新。

### ADR-019（设计决策：标题工具常驻——修订 ADR-017 第 3 条 · 已由 ADR-020 取代）

> **（本条已由 ADR-020 取代：工具整体退役；本条的前缀缓存发现构成 ADR-020 的论证基础。）**

- **日期**：2026-09-17 · **取代日期**：2026-10-02（ADR-020）
- **上下文与动机**：会话审计 session-8e06060e（前缀缓存）证实 ADR-017 第 3 条"逐轮启停"的代价：`SetSessionTitle` 在标题落定后被移出 tools 列表，而 tools 区位于序列化请求的最前端（OpenAI 兼容协议下先于全部消息），前缀缓存在 tools 区分叉点失效——一个 ~50k token 会话的命中率从 99.6%（49,472 命中）跌到 14.5%（7,232 命中），42.8k 已缓存内容重新按未缓存输入计费。逐轮启停本要保护的"工具列表最小化"收益（一个 schema 约一两百 token，且骑在稳定前缀上走缓存读）与之完全不成比例。
- **决策**：
  1. `SetSessionTitle` 在主 agent 上**注册即激活、全轮次类型常驻**（用户轮次、cron 轮次、通知轮次、steer 轮次一律不切换启停）——序列化工具列表跨请求字节恒定，前缀缓存稳定；cron/notification 驱动的 F-1a 清理收窄为仅清理提醒注入器，不再触碰工具；
  2. 命名指令（提示注入）保持逐轮挂载 + ADR-018 熄灭语义不变——注入是尾部追加，其出现/消失不影响已缓存前缀；
  3. 工具结果文本极简化：成功返回 `OK.`，守卫拒绝（手动/已派生标题）返回空输出——工具结果持久进上下文并成为后续缓存前缀的一部分；
  4. 子 agent 仍不注册（无元数据句柄，spec §2.4 不变）。
- **被否决的备选**：a) 维持逐轮启停——每次启停是一次全量前缀失效，成本不可接受（本 ADR 动机）；b) 仅用户轮次启用、cron 轮次停用——user→cron→user 每次交替破坏前缀两次，比现状更糟，工具存在性必须跨轮次恒定；c) 命名后以"空壳工具"保留 schema——复杂化且守卫已提供同等保护。
- **接受的残余风险**：cron/通知轮次（引擎内部轮次）现在也能看到该工具——模型可能自发调用并以引擎内部语境命名一个未命名会话。缓解：该路径上无命名指令（模型缺乏动机）、命名守卫与用户路径同一实现、真实会话中 cron 轮次几乎总是晚于首个用户轮次（兜底已保证标题存在）。红线 3 的"引擎内部轮次不参与命名"由此收窄为"不注入、不兜底、不覆盖"。
- **影响范围**：本文件 §2.1/§2.5；rust 工具注册面（`tools/mod.rs`）、消息派发宿主（启停站点移除）、cron/notification 驱动（F-1a 收窄）、工具本体（结果文本）；t9 测试中"settled 后工具停用"的既有断言按新语义更新。

### ADR-020（设计决策：settle 触发的缓存骑乘旁路调用）

- **日期**：2026-10-02（取代 ADR-017 / ADR-018 / ADR-019；推翻 ADR-016 的成本否决理由）
- **上下文与动机**：工具机制（模型在既有响应流中调用标题工具）的三重痛点——① 工具 schema 常驻每个请求（ADR-019 确立的交换代价）；② 提醒注入与 tool-call 帧进入缓存上下文（ADR-018 的轮内注入成本）；③ 占用内置工具面。工具路径的"零额外请求"收益可被旁路调用的 provider 前缀缓存命中替代：同模型、同前缀的旁路调用输入几乎全为缓存读（约 0.1x 单价），总量低于工具机制的常驻成本，且完全不占主循环。
- **决策**：
  1. **触发**：主 agent 用户轮次的三个成功 settle 站点（wait / fire / steer），会话未命名（非手动 + 占位）且进程内一次性 claim 成功时，spawn 后台旁路调用；被取消（Aborted）的轮次仍经成功 settle 路径，照常触发；轮次错误 settle、硬中止 settle、未配置 provider 的派发分支不触发（直接规则式兜底，保持 R-D）；
  2. **请求构造**：与主循环同一 LLM 解析构造（同 provider / 模型 / system prompt）、同工具定义序列（含多媒体能力过滤）、同消息投影（normal 投影 + 同一 media pipeline），仅末尾追加一条标题指令 user 消息；全新取消令牌 + 30s 超时；不进 in-flight 注册表、不可取消、不记 wire log；
  3. **写入与降级**：成功经 `set_auto_title` 原子守卫（非手动 + 仍占位 + 共享脱敏 / 200 字符截断）写入 → 发布既有元数据更新事件 → 写穿 `state.json` 与索引（settle 的写通先于标题落地，须再写一次）；失败 / 超时 / 响应无文本 / 清洗后为空 → 释放 claim → 规则式兜底；
  4. **并发与生命周期**：会话级一次性 claim（进程内 CAS 原子，不持久化——重启后未命名会话在下一用户轮次 settle 重试，即 A8 自愈）；用户改名经写入守卫原子胜出；usage 三桶（未缓存输入 / 缓存读 / 缓存写）日志观测；
  5. **移除**：标题工具（文件 / 注册 / 目录）、提醒注入器、TurnFlow 注入器挂载、挂载 / 卸载 / 清理接线、元数据句柄的标题接线与已命名标志全量退役——正文 §2 各节为不含这些面的终态。
- **被否决的备选**：见 §3 表格（派发时点触发、独立小模型、主循环内文本输出、保留工具作兜底、错误 settle 触发）。
- **supersede 关系**：ADR-016 的"独立调用成本不可接受"裁决被缓存骑乘论证推翻（推翻理由：彼时未考虑前缀复用）；ADR-017 的注入 + 工具机制、ADR-018 的注入器熄灭、ADR-019 的工具常驻全部随机制移除而失效——三者的守卫、降级链与脱敏语义由本决策继承。
- **影响范围**：本文件 §1.2 / §1.4 / §2 全部；rust 引擎的消息派发宿主（settle 站点）、会话元数据句柄（一次性 claim）、旁路调用编排层；t9 测试面按新语义更新。
