# Mirri Desktop Lite — 需求定义（Requirements）

- 域：desktop-lite（桌面轻量壳）
- 状态：R1–R9 评审通过（见文末 SDR 记录）
- 架构文档：`desktop-lite-architecture.md`
- 现状盘点：`desktop-lite-context.md`

## 1. 背景与动机

Mirri Code 目前只有一个桌面壳（第一壳）。它功能完整，但安装包体积大（百 MB 级）、内存占用高。用户希望在保留现有壳的前提下，增加一个**轻量第二壳**用于日常试用对比：

- 一个用户可并行安装、并行运行的第二桌面应用，与现有应用**互不干扰**
- 壳与界面的能力契约保持一致：界面代码不需要为第二个壳做任何修改
- 某些系统增强能力（图标角标、开机自启等）在第二壳上**允许暂时缺失**，缺失时界面自动降级、不得报错
- 启动更快、安装包与内存显著更小（十 MB 级 vs 百 MB 级）

**动机的抽象问题陈述**：单一壳绑定了特定技术栈的全部重量，用户没有"轻量使用"的选择；同时壳技术栈的替换成本未知，需要一个并存的第二实现来对冲。

## 2. 目标用户与场景

- **用户**：Mirri Code 的现有桌面用户（自己），想在日常使用中对比两种壳的体验差异（启动速度、内存、稳定性）
- **核心场景**：打开轻量壳 → 连接同一个本地服务 → 进行会话对话 → 打开/查看文件 → 收到系统通知
- **明确非目标**：不追求功能对等；不做自动更新；暂不做 Windows/Linux

## 3. 需求

### 3.1 双壳并存（R1）

产品必须支持两个桌面应用同时安装在用户机器上：
- 应用名称、图标、系统标识互不相同，用户在程序坞/启动台中能一眼区分
- 两个应用可以同时运行，连接**同一个**本地服务实例（不重复启动服务）
- 任一应用的安装、升级、卸载不影响另一个

**验收**：同一机器上两个应用并存、同时运行、共用服务，互不干扰。

### 3.2 核心使用流完整（R2）

轻量壳必须覆盖以下完整使用流，缺一不可：
1. 启动应用 → 自动连接本地服务（服务未运行时自动拉起并等待就绪）
2. 浏览会话列表、打开会话、发送消息并收到回复
3. 会话内文件引用：用系统文件管理器定位、用指定编辑器打开
4. "在应用中打开"：对文件选择预设应用（如编辑器、终端）打开
5. 收到系统通知（消息到达、权限请求等场景）

**验收**：上述 5 项在轻量壳中全部可用（人工逐项走通）。

### 3.3 能力缺失时优雅降级（R3）

以下增强能力在轻量壳上**第一阶段允许缺失**：
- 应用图标角标（未读数）
- 程序坞图标弹跳提醒
- 开机自启设置
- 点击深链唤起已运行的应用

缺失时的表现要求：
- 界面上对应功能自动隐藏或退化为浏览器等价物，**不得**出现报错弹窗、红点、异常提示
- 调用方拿到的"未执行"信号真实反映能力缺失（不得假装成功）

**验收**：缺失能力被调用时，界面无异常表现且后续流程不受影响。

### 3.4 界面零改动（R4）

轻量壳必须直接加载与现有壳**同一份**界面程序（不做任何分支、条件编译或单独构建），界面通过运行时的能力探测区分环境。

**验收**：界面代码仓库在轻量壳上线前后零提交。

### 3.5 窗口体验一致（R5）

轻量壳的主窗口观感与现有壳一致：
- 隐藏系统标题栏、交通灯按钮内嵌（macOS 隐藏式标题栏形态）
- 界面标题区可拖动窗口
- 窗口尺寸不小于最小可用尺寸

**验收**：与现有壳并排对比，标题栏形态与拖拽行为一致。

### 3.6 开发与分发形态（R6）

- 开发态：一条命令从源码启动（热改代码快速试用）
- 分发态：能构建出独立命名的安装应用包（可放进应用程序目录、可双击启动），构建产物与现有应用不冲突
- 打包产物暂时不做代码签名与公证（本地试用）

**验收**：`命令启动`（开发态）与 `构建应用包 + 启动`（分发态）两条路径均可用；未签名的应用包允许通过系统提示的方式首次打开（本地试用约定）。

### 3.7 工程边界（R7）

- 轻量壳作为仓库内一个新应用目录，遵循仓库工作区规范
- 不修改：现有壳、界面应用、引擎核心
- 桥的能力契约以**界面侧已存在的契约为唯一事实源**，轻量壳作为实现方接入（不新建第二份契约）

**验收**：新目录加入后，仓库既有检查全部维持通过；桥契约只有一份定义。

### 3.8 服务生命周期共用（R8）

轻量壳的服务连接逻辑与现有壳**语义一致**：
- 服务已在运行 → 直接复用
- 服务未运行 → 自动启动并等待健康
- 两个壳**同时冷启动**时，不得出现服务被拉起两次、或状态互相覆盖导致的异常
- 应用退出时**不得**杀死仍被另一个壳使用的服务；只允许清理**自己拉起的**服务实例

**验收**：两个壳交替或同时启动/退出，服务进程始终存活且只此一份（除非全部退出）。

### 3.9 试用可观测（R9）

轻量壳启动过程的关键事件（服务复用/启动、桥注入结果、能力探测）在开发者日志中可见，便于试用期排查问题。

**验收**：启动日志能明确回答"服务从哪来、桥有没有注入成功"两个问题。

## 4. 术语

| 术语 | 定义 |
|---|---|
| 壳（Shell） | 包裹界面并提供系统能力的桌面应用容器 |
| 桥（Bridge） | 界面与壳之间的能力调用层（约定的一组方法与事件） |
| 服务（daemon） | 本地运行的后端进程，提供界面所需的全部业务能力 |
| 深链（Deep Link） | 通过外部链接（如网页里的特定地址）点击唤起应用 |
| 现有壳 / 轻量壳 | 第一壳（当前主桌面应用）/ 本需求的第二壳 |
