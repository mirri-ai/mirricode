# 对话渲染 — 架构设计

> 状态：v1 基线 · 2026-09-12 · 待需求评审后校准 ·
> 本文是对话渲染域设计侧的唯一事实源（内部规格文档，不进文档站构建，中文单语）。
> 需求契约：见 [conversation-rendering-requirements.md](conversation-rendering-requirements.md)（本设计的验收依据）；现状证据（TS 参照机制、Rust 差距）见 [conversation-rendering-context.md](conversation-rendering-context.md)；执行状态见 [conversation-rendering-ROADMAP.md](conversation-rendering-ROADMAP.md)。
> 术语规范：会话快照（R1）、在途回合（R2）、易失事件（R3）、事件游标（R4）、会话日志（S5）、转录（S6）见 [glossary.md](glossary.md)。
> 本文描述的机制以 TS v2 现行实现为参照基线（带代码事实的现状证据一律在 context 文档），并给出 Rust 内核对齐的终态形状；Rust 侧尚未兑现的部分在 ROADMAP 排期，不在此展开。

## 1. 目标与设计原则

本域的架构问题只有一句话：**如何把一份只增不改的记录流水，投影成界面上一份既忠实又连续的对话视图**——实时（正在追加）与恢复（重开/重连）两条路径收敛到同一结果。

设计原则（对应需求编号）：

1. **记录是唯一事实，视图是投影**（ADR-001）：界面上的一切内容要么直接来自记录，要么是记录追加前的易失先行流（R3，由快照在途回合补偿）——不存在第三份"界面自己的历史"。
2. **同步是 IM 式的**（ADR-002）：打开 = 原子快照（带水位）；之后 = 从水位续订事件；对不上 = 明确要求重新对表。
3. **双轨事件**（ADR-003）：持久事件逐条有游标（可重放、可补齐）；易失流（流式分片、进度）不落盘、不可重放，其恢复由快照的在途回合承载。
4. **消息身份由读面统一供给**（ADR-004）：快照与历史分页返回的是同一投影的同一行形状，身份与时间来自单一推导/铸造点，消费端不自造。
5. **归因随事件走**（ADR-005）：每条会话事件携带会话与身份标识，消费端不猜。
6. **消费端只做收敛，不做纠错**（ADR-006）：界面侧的投影器/合并器/去重器的职责是"把两条路径的内容收敛成一条"，不是"修复服务端给错的东西"；凡是需要客户端打补丁绕过的服务端缺陷，都回推到读面修复。

## 2. TS 参照架构（v2 全链路）

### 2.1 记录层：事件溯源的会话日志

- 每条身份（主/子代理/btw 分支）一份独立追加日志（wire.jsonl），每行一条记录；记录 = 扁平化操作（判别字段 `type`），首行为协议版本头。
- 对话内容的记录族：回合括号（`turn.prompt`/`turn.steer`/`turn.cancel`/`turn.ended`，闭括号带结局与时长）、用户/注入消息（`context.append_message`，携带来源 origin）、助手回合流（`context.append_loop_event`：`step.begin` / `content.part`（文本/思考/媒体分片，**step 粒度**而非流式 delta）/ `tool.call` / `tool.result`（含输出与失败标记）/ `step.end`（含用量与时延））、压缩整理（`context.apply_compaction` + `full_compaction.*`）、撤销（`context.undo`）、用量（`usage.record`）、人机交互（`interaction.request`/`resolved`）。
- **追加即双发**：一条记录 live 派发时先折叠进模型状态（reducer）→ 追加日志 → 发布总线事件；恢复时只重放折叠（silent，不发事件）。**实时折叠与恢复折叠是同一个折叠函数**——这是"两条路径收敛"的根基。

### 2.2 实时事件面：三条通道

- **回合生命周期**：`turn.started`（携带用户输入文本——消息记录本身不是事件，输入文本借此上浮）、`turn.step.*`（开始/完成（用量+时延）/重试/中断）、`turn.ended`（结局 + 原因 + 时长）。
- **易失流**（R3，只走总线不落日志）：`assistant.delta` / `thinking.delta` / `tool.call.delta`（参数增量）；响应完成后才批量落 `content.part` 记录，中断时把已积累的非空分片落盘。
- **工具面**：`tool.call.started`（名称+完整参数+展示提示）、`tool.progress`（易失）、`tool.result`（输出+失败标记+名称归位）。
- **聚合视图**：`agent.activity.updated`——每身份一份可丢弃重建的活动折叠（阶段/活跃工具/待审批/重试）。
- 顺序保证：单身份内事件顺序 = 日志追加顺序 = 折叠顺序（同步串行派发）。

### 2.3 恢复投影：三条读路径，一个原则

| 路径 | 消费方 | 机制 |
|---|---|---|
| 模型视图 | 引擎内部（续聊上下文） | 恢复重放折叠后的当前上下文（压缩后坍缩视图） |
| 全量转录（REST） | web 历史读面 | 流式读日志 + 转录折叠器：**保留压缩前全部历史**（压缩落位为标记消息而非删减）、重放撤销/清空、合并内存未落盘尾部（live tail） |
| 回放记录 | TUI 重开 | 日志 → 回放折叠器 → 回放记录流（消息/压缩/目标/计划等），按最近回合上限截取，渲染层与实时同构 |

三条路径的折叠器是**多份实现、一套语义**（压缩标记行为、中断工具合成为带失败标记的合成结果、未闭合工具调用的兜底输出），语义对齐靠"磁盘形状跨引擎逐字节兼容"的约束与共享谓词维护——这是 TS 侧最大的结构性脆弱点，Rust 对齐时的改进方向见 ADR-004 的影响评估。

### 2.4 服务器契约（kap-server `/api/v1`）

- **快照（R1）**：`GET /sessions/{sid}/snapshot` → `{ as_of_seq, epoch, session, messages（升序最近一段，带 has_more）, in_flight_turn, subagents, pending_approvals, pending_questions }`；在途回合（R2）= `{ turn_id, assistant_text, thinking_text, running_tools[], current_prompt_id }`。
- **历史分页**：`GET /sessions/{sid}/messages`——方向游标（before/after）+ 每页上限 + 角色过滤，newest-first；单条获取 `GET .../messages/{mid}`。
- **事件订阅（WS）**：协议带能力协商；订阅携带每会话游标 `{seq, epoch}`（seq = 持久事件日志位点，epoch = 日志世代）；持久事件逐条有 seq，超窗/世代变更时服务端发**重同步信号**（要求客户端重新快照）而非默默丢；易失帧不推进 seq、携带回合内偏移（供续流对齐）；心跳保活；服务端可声明事件批处理/压缩能力。
- **事件缓冲**：每会话内存环形尾部 + 磁盘持久事件日志双级——重放先内存后磁盘。

### 2.5 消费端（web）投影管线

原始事件 → 客户端投影器（事件 → 应用事件，含在途回合播种）→ 帧级批处理器（分片合并、后台标签定时兜底）→ 纯 reducer（状态收敛）→ 视图模型折叠（消息 → 回合/卡片树）→ 渲染。
合并/去重的三个层次：乐观回声去重（身份/内容三级匹配）、流式副本 vs 正式副本的内容签名子集覆盖、快照安装保留旧页防闪。订阅容量有上限（LRU 退订，被退订者重开走全量快照）。

### 2.6 TUI 参照管线

实时：本地回显用户消息 → 事件流 → 节流合并控制器 → 组件树。恢复：回放记录流 → **复用同一套渲染钩子**（仅数据源不同），收尾清理后与实时无痕衔接。转录窗口有保留上限（旧回合按策略淡出，图片内存回收）——界面态的修剪不影响记录。

## 3. 终态形状（Rust 对齐设计）

### 3.1 同步模型对齐（ADR-002 的兑现）

快照的六要素（水位、会话视图、升序消息页、在途回合、子代理、待交互）与历史分页的行形状统一为**同一投影**：快照是"分页读面 + 在途状态"的复合，消息行在两个入口间逐字段一致。消息身份与时间由读面单点供给（ADR-004），分页游标以消息身份为锚。

### 3.2 事件面补强（ADR-003/005 的兑现）

- 工具结果事件携带**输出内容**与失败标记（对齐工具调用域 T4 的结果定义：输出是结果的本体，不是可选装饰）。
- 回合/工具/压缩/后台任务等事件族统一携带身份归因（会话 + 身份），成功与失败终态对称。
- 状态聚合事件以结构化负载呈现（阶段/上下文水位/用量切片），不以调试串占位。
- 易失帧保持双轨语义：不落盘、带回合内偏移、不推进游标——其恢复完全由快照在途回合承载（R2）。

### 3.3 在途回合的捕获

引擎侧维护"当前回合的易失影子状态"（已流出文本/思考的累计、运行中工具的最近进度）——它是**派生缓存**（可随时丢弃重建，对齐聚合视图的定位），快照请求时一次性读取。影子状态不属于记录（不落日志），但它的**输入**（易失流）与它的**快照出口**（R2）构成闭环：流式内容落盘前的一切可见性都由这条链路保证。

### 3.4 消费端收敛职责（ADR-006 的兑现）

客户端投影器/reducer/去重层的职责边界：**收敛两条路径的重复**（乐观回声、流式副本），**不修复读面缺陷**（缺输出、缺归因、缺时间——这些回推读面）。凡服务端读面补齐后，客户端的对应补丁代码应被移除而非并存。

## 4. 关键机制的动机（抽象问题陈述）

1. **为什么快照要原子 + 水位**：打开会话时"边收事件边拼首屏"会出现半新半旧拼接；原子快照给一个一致起点，水位给后续事件的续接锚——起点一致 + 续接有锚 = 不重不漏。
2. **为什么易失流不落盘**：流式分片的量级（每 token 级）远超记录价值（step 粒度足够忠实）；落盘成本与写入放大不成立。代价（崩溃窗口内容不保证）由"中断时尽力落盘已积累分片"兜底。
3. **为什么需要重同步信号而不是尽力补**：补齐能力有限（缓冲窗、世代变更）时，静默截断的补齐比明确报"对不上"更有害——客户端会基于缺洞状态继续错下去。明确信号 + 客户端照做重新快照，是唯一诚实路径。
4. **为什么消息身份要稳定**：身份承担三个职责（翻页锚、去重键、单条定位）；随重启漂移的身份会让翻页锚失效、去重失效——要么数据状态内稳定，要么在历史改变时显式宣告对表。
5. **为什么折叠器必须单一语义**：转录（S6）的承诺是"全量投影"——如果实时折叠与恢复折叠对中断工具、压缩标记、未闭合调用各有各的兜底，同一个会话重开前后会呈现不同内容。

## 5. 决策记录（ADR）

### ADR-001 会话日志是唯一事实源，对话视图是其投影

- **背景与动机**：界面呈现的内容若存在第二份真相（界面自存历史），断线/重开/多端立刻分叉。记录追加与事件发布的时序错位（先折叠、后追加、再发布）要求一切视图可从记录重放得出。
- **决策**：界面视图 = 记录投影（持久路径）+ 易失先行流（实时路径，由快照在途回合补偿）；实时折叠与恢复折叠共用同一折叠语义；转录投影保留压缩前全量（全量投影，与模型视图的压缩坍缩有意分叉——两套视图各有契约）。
- **否决的替代**：界面自存历史（多端/重开必然分叉）；事件流即真相（易失事件不可重放，撑不起恢复路径）。
- **影响面**：全部恢复读面；US1.1、US5.1。

### ADR-002 同步模型采用"原子快照 + 水位游标 + 订阅重放"（IM 式）

- **背景与动机**：打开会话需要一致起点；后续需要增量续接；异常需要明确对表信号。
- **决策**：快照携带水位（as_of + 世代）；订阅从水位重放持久事件；缓冲溢出/世代变更 → 明确的重同步信号（客户端重新快照）。快照重开（而非游标续订）用于一切"易失内容可能已丢"的场景（重开进行中会话、退订后的重进）——因为易失流不可重放，只有快照在途回合能补齐。
- **否决的替代**：纯事件重放式打开（首屏不原子、易失内容无解）；纯拉取轮询（实时性不成立）。
- **影响面**：US1.1、US3.1、US4.1；服务器事件面契约。

### ADR-003 事件双轨：持久事件带游标，易失流带回合内偏移

- **背景与动机**：持久事件要可重放（断线补齐），易失流要低延迟不可重放；两者混在同一游标轨道会让"补齐"语义崩溃（易失帧没有"错过"可言——它们只对当下有效）。
- **决策**：持久事件逐条推进游标（seq，附世代）；易失帧不推进游标、携带回合内累计偏移（供快照播种后续流对齐去重）；易失内容的恢复由快照在途回合承载（影子状态一次性读取）。
- **否决的替代**：全部事件持久化（流式分片写入放大不可接受）；易失帧也占游标（重放语义无法定义）。
- **影响面**：US2.1、US3.1、US4.1；影子状态的设计（§3.3）。

### ADR-004 消息身份与时间由读面单点供给

- **背景与动机**：快照、历史分页、单条读取三个入口若各自给行形状/身份/时间，消费端去重与翻页锚必然漂移。TS 现状的身份是从记录位置推导的（历史改变时随迁，靠重新对表兜住），存在对表成本。
- **决策**：读面提供**统一的消息行投影**（身份、时间、角色、内容分片、来源标注）；Rust 对齐时身份在"数据状态内稳定"的前提下供给（推导身份可接受的前提是历史改变事件显式触发对表；升级为铸造式持久身份属 §7 提案 P3，裁决前不预设）。快照与分页的消息行**逐字段同形**。
- **否决的替代**：消费端自造身份（多端漂移）；快照与分页两套行形状（TS 读面现状的教训——两个入口各自演化已经开始分叉）。
- **影响面**：US1.2、US1.3；服务器读面契约。

### ADR-005 归因随事件走，成功与失败对称

- **背景与动机**：多身份会话（子代理、后台任务、btw）中，事件缺归因会把子身份的活动误折叠进主对话；失败带归因、成功不带的不对称会让"顺利的子活动"全部归错人。
- **决策**：全部会话事件携带会话标识与身份归因；同类事件的成败两态携带对称的归因字段集。
- **否决的替代**：消费端按事件顺序猜测归属（顺序在重放/批处理后不可靠）。
- **影响面**：US5.4；事件面契约全集。

### ADR-006 消费端只收敛、不纠错

- **背景与动机**：客户端为服务端读面缺陷打的每个补丁（缺失字段的兜底、缺失归因的猜测）都会与后续服务端修复并存成双份逻辑，漂移不可控。
- **决策**：客户端投影层的合法职责限定为收敛两条路径的重复（乐观回声、流式副本覆盖）与呈现批处理；读面缺陷（缺输出/缺时间/缺归因）一律回推服务端修复，修复落地后移除客户端补丁。
- **否决的替代**：客户端长期持有服务端缺陷的兼容层（维护面翻倍且掩盖缺陷）。
- **影响面**：§3.4；web 投影器/reducer 的演进纪律。

### ADR-007 消息读面投影到 TS 协议 content part 形状（2026-09-13）

- **背景与动机**：快照与历史分页产出的消息行若直接沿用引擎内部内容表示的序列化拼写（判别符与字段名为持久化方言，而非消费端契约），消费端必须逐内容类型打补丁才能渲染；补丁与契约一旦漂移，工具调用关联、思考块、媒体分片在重渲染路径逐类丢失，同一会话 live 与重开呈现不同内容（现状证据见 [conversation-rendering-context.md](conversation-rendering-context.md) §4.2 G15/G16）。
- **决策**：消息读面产出的 content 数组统一投影为 TS 协议消息契约的判别符与字段形状——assistant 工具调用 = `tool_use{tool_call_id, tool_name, input}`；工具结果行 = `tool_result{tool_call_id, output, is_error}`（纯文本输出为字符串、分片为数组）；思考 = `thinking{thinking}`；图片 = `image{source{kind, ...}}`；文件 = `file{fileId, name, mediaType, size}`。纯文本行保持字符串形态（不包裹为数组）。投影只发生在 rpc 序列化边界；磁盘日志（wire.jsonl）记录拼写不变——持久化契约不随读面形状调整。
- **否决的替代**：渲染侧直接消费 wire 日志内部格式——①把内部记录格式冻结为公共契约，写侧演进被锁死；②需跨语言各实现一份基于内部格式的折叠/重放逻辑，双实现语义漂移（与折叠器多实现的脆弱性同构放大）；③易失性内容（流式分片、进度）本就不落日志，快照在读面上仍旧残缺，覆盖不了 live 路径。
- **影响面**：快照与历史分页读面契约；web 快照路径映射；schema 契约测试。

### ADR-008 双路收敛点 = 协议契约 + App 内容类型（2026-09-13）

- **背景与动机**：live（事件投影）与重渲染（快照映射）若各自维护内容形状规则，两条路径必然漂移；快照路径以"改动最小"为由只实现局部映射，正是重开丢失内容的直接成因（现状证据见 context.md §4.2 G17）。
- **决策**：live 事件投影与快照重渲染收敛到同一对锚点——上游是 TS 协议消息契约（content part 判别符与字段），下游是 web 的同一套 App 消息内容类型（toolUse/toolResult/thinking/image/file 等）；快照路径的映射范围与 live 投影一致，禁止"只映射 text"的局部实现；任一方向的形状变更必须同时修改两侧映射并触发契约测试。收敛不止形状，也含顺序：wire 记录的 part 顺序必须与 live 投影渲染一致——按 provider 惯例的桶序（think 桶先于 text 桶，`finalize_step` 落地，G19）；引擎流式收集是分桶的，交织流的真实到达序不保留（provider 惯例 reasoning 先于 content，桶序即到达序的准确近似）。
- **否决的替代**：快照路径维持简化映射、依赖 live 后续事件补全（等于重渲染时重放 live，引擎需重放事件流，易失内容不可重放，补不全）；双路径各自维护一套映射（分叉后漂移不可控）；顺序按"记录侧自定义"而非到达序（重渲染与 live 显示颠倒，浏览器验收证实用户可感知）。
- **影响面**：web 投影器/映射器与快照映射；协议契约；渲染接线测试。

### ADR-009 渲染接线三层测试保障（2026-09-13）

- **背景与动机**：读面投影与消费端映射的断裂（输出形状过不了消费端契约）若没有自动防线，只会在用户重开会话时暴露；单层测试（单侧手写 mock）与真实输出无对账，双侧契约漂移依旧漏网（现状证据见 context.md §4.2 G18）。
- **决策**：渲染接线段落以三层测试作为持续保障——①读面消息行构造的单元测试（锁住投影形状，含纯文本行保持字符串的护栏断言）；②wire 重放等价不变量：同一会话 live 快照与冷恢复快照逐字段恒等（防 replay/reducer 折叠漂移）；③schema 驱动契约 e2e：真实 serve 输出经共享协议快照 schema（`sessionSnapshotResponseSchema`）校验（防双侧断裂，为形状的最终裁判）。已知豁免：在途回合 `turn_id` 的 string/number 偏差登记为既知偏差（TS 契约声明 number、rust 读面发字符串，见 context.md 已裁决后续项），契约测试对该字段放宽校验，类型统一记入后续项。
- **否决的替代**：仅靠单侧渲染单测（手写 mock 与真实输出无对账，正是该断裂此前漏过的原因）；仅靠服务端形状快照（无消费端 schema 裁判，两侧各自漂移）。
- **影响面**：测试基建（单测/不变量/e2e）；rpc 行构造；web 快照映射。

### ADR-010 插话身份标记与回合内折叠渲染（2026-10-13）

- **背景与动机**：插话消息折入运行中回合后，其来源标注与回合开启消息完全相同（同属"用户"家族），读面无法区分两者——消费端只能按"用户消息即回合边界"的通则切割，运行中的回合被渲染成两片（需求 US2.3 / SDR-001 的动机）。来源标注是读面单点供给的既有职责（ADR-004），缺的只是"插话"这一个可辨识身份，而非新投影机制。
- **决策**：来源标识体系（与回合调度域共享的来源家族枚举）新增**插话专属变体**，形状与既有变体同构（判别标签 + 无载荷）：
  - **打标点在准入侧**：插话折入运行中回合（park 进插话缓冲）时即打插话标识，随缓冲冲刷原样落进上下文与记录——冲刷路径不需要理解插话语义，身份在准入时一次确定。引擎消费方按"真实用户输入"家族对待它（压缩保留、撤销可达），与"用户"同待遇。
  - **插话在无运行中回合时自行开起新回合的路径不打此标**（维持"用户"标识）——该消息在语义上就是下一回合的开启消息，正常回合边界。
  - **消费端折叠规则**：读面消息行携带插话标识时，渲染为**完整用户气泡**（含附件解析、时间戳、"插话"角标）但折叠进当前回合块序（不触发回合边界切分、不占回合序号）；实时路径的本地先行消息（乐观回显）携带同一标识，进行中与历史回放收敛到同一呈现。无待折叠回合时（插话在回合结束后才被消化）退化为普通用户回合，语义上正确。
  - **网关/投影枚举对齐**：协议契约的类型联合与消费端本地类型同步补齐该变体；外围适配层（ACP 等）按既有默认分支处理，不外发插话语义（插话是会话内呈现语义）。
- **否决的替代**：a) 消费端结构推断（夹在同一回合两段输出之间的用户消息即插话）——时序竞态与缺回合归属场景误判不可控，违反 ADR-006 的"只收敛不纠错"；b) 插话标识携带回合号载荷——渲染只需身份，回合超出本次需求，冲刷本身已有记录。
- **影响面**：来源标识枚举（引擎、协议契约、消费端本地类型）；读面消息行（来源标注随行，无新字段）；消费端回合折叠规则与气泡渲染；实时路径的乐观回显标记；回合调度域 §5 契约表；ROADMAP 批次 CR13。
