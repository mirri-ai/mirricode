# 工具调用域需求文档（User Stories）

> 状态：v1 基线 · 2026-09-10 ·
> 本文是工具调用域需求侧的唯一事实源（内部规格文档，不进文档站构建，中文单语）。
> 产品愿景：**模型想用的工具随手可用，执行过程全程透明，结果可信可查**——用户对"agent 正在做什么、做成没做成、为什么失败"始终有准确、一致的认知。
> 基线说明：本域为**新建域**。本文描述工具调用域引擎应支持的**终态行为**，作为 **Rust 内核的对齐基线（parity baseline）**——这是 Rust 需要对齐的**底线**，不是 Rust 被限制的天花板；Rust 可以（且应当）做得更好，文中不设上限。TS 引擎当前实现现状（含实现归属与差距）与代码事实见 [tool-calling-context.md](tool-calling-context.md)，机制与数据流见 [tool-calling-architecture.md](tool-calling-architecture.md)。
> 术语：工具（T1）、工具调用（T2）、工具输入展示（T3）、工具结果（T4）的唯一定义见 [glossary.md](glossary.md)；本文件只使用这些规范叫法。
> 范围边界：审批与权限流 UX 归 approval 域（本域只保证「调用在截获点被强制拦截/放行」这一强制面）；MCP 服务器管理与配置归 mcp 域；执行原语（终端/文件/进程抽象）归 execution-environment 域；技能系统归 skills 域；后台任务与子代理管理归 background-tasks 域；目标/计划/定时任务的服务语义归各自域；旁路投递（顺带问）的投递机制归会话管理域（G4），本域只保证工具结果可携带该投递通道。本域覆盖：工具的定义与可用面、调用执行与取消、结果与更新流、内建工具集的行为契约、用户自定义工具、工具选择与策略、重复调用抑制、非功能与可观测性。

## 0. 角色定义（Personas）

| 角色 | 场景 | 核心诉求 |
|---|---|---|
| **单人开发者**（TUI 主，单工作区） | 终端里让 agent 读写文件、跑命令 | 工具干活看得见、能随时叫停；命令/文件操作的结果一目了然 |
| **多端/网页用户**（desktop/web） | 网页上观察 agent 完成长任务 | 工具调用的状态永远清楚（进行中/成功/失败/为什么失败）；大输出不淹没对话 |
| **高级配置用户**（角色工具面、全局配置） | 约束 agent 能用什么、不能用什么 | 工具面声明即生效；禁用严进严出——绕过清单直接调用也被拦 |
| **宿主集成者**（把引擎嵌进自己产品的开发者） | 在引擎外实现工具能力 | 注册一个工具就能被模型调用；调用/取消/结果可靠往返；重启不丢 |
| **模型侧使用者**（理解性角色，非人） | 决定何时调用哪个工具 | 工具描述、参数契约、结果与错误反馈清晰可执行，不产生歧义 |

## 1. Epic E1：工具可用面 — 定义、注册与激活

> 解决"模型到底能调哪些工具"。工具的**定义**（名称、描述、参数契约）、**归属与命名**、哪些工具进入当前会话的可用集合。

### US1.1 暴露给模型的工具元信息（P0）

作为模型侧使用者，我想对会话中可用的每个工具看到其名称、人类可读的描述与参数契约，以便正确地决定调用。

验收：
- Given 会话可用工具集非空，When 引擎向模型提供工具列表，Then 每个工具携带名称、描述、JSON Schema 参数契约（缺省参数仍为可选）
- Given 工具参数契约声明了字段集合，When 模型提交契约外的未知参数，Then 该调用在参数校验阶段被拒（未知字段不接受）

### US1.2 工具名解析唯一性与同名覆盖（P0）

作为宿主集成者，我想让注册的工具名可预期，以便模型调用不会命中错乱的工具。

验收：
- Given 两个工具以完全相同的名称先后注册，When 第二个注册完成，Then 可用集合与调用均解析到后注册者（先注册者被替换）——任一时刻一个名称只解析到一个工具
- Given MCP 服务器提供的工具，When 其进入可用集合，Then 名称带服务器前缀以区分不同服务器（多服务器同名工具不会互相覆盖，冲突时按 mcp 域规则跳过并记录）

### US1.3 角色工具面与实时激活（P0）

作为高级配置用户，我想让会话绑定角色的工具面（允许列表/禁用列表）决定模型可见与可调用的工具，以便角色语义完整生效。

验收：
- Given 会话绑定某角色，When 会话启动，Then 该角色的允许列表、禁用列表与工作区级、全局级工具约束共同决定激活集合（任一来源禁用即不可见不可调用）
- Given 会话运行中切换角色，When 新角色允许更多工具，Then 新允许的工具**不重启会话**即进入可用集合
- Given 会话切换角色收紧工具面，When 收紧生效，Then 被移出集合的工具从模型视野移除，对它的**新调用**被拦截；历史中的既有调用按转录规则全量保留（动态工具的历史整形见 US6.3）

## 2. Epic E2：工具调用与执行

> 解决"一次工具调用从模型发起到结果回传的完整旅程"。参数校验、并发、流式进展、取消、超时、回合控制。

### US2.1 单次调用生命周期（P0）

作为模型侧使用者，我想发起一次工具调用并在同一回合内获得其结果，以便继续推进任务。

验收：
- Given 模型发起一次参数合法的工具调用，When 该工具在当前集合内，Then 工具被执行，其结果作为该调用的回复回传模型（结果含错误标记时模型明确感知失败）
- Given 同一批多个调用，When 执行，Then 模型等待本批全部结果回传后才继续（批内并发、批间阻塞）；模型需要在结果就绪前继续推进时，可显式选择后台化路径（US2.6 / US2.11）
- Given 调用进入执行，When 用户在界面上观察，Then 界面呈现 进行中 → 成功/失败 的明确状态变化（工具卡片：`Using …` → `Used …`；失败带红色标记且错误文本不以单行摘要折叠）
- Given 一次调用完成，When 界面呈现结果，Then 工具卡片保留头部与结果；运行中与完成后卡片高度稳定不塌缩

### US2.2 参数校验与坏文本（P0）

作为模型侧使用者，我想让参数错误在**执行前**被抓住，以便不产生副作用。

验收：
- Given 调用缺少必填参数、携带未知参数或参数值不符合契约，When 校验，Then 工具**不执行**，模型收到含具体错误明细（如"缺少必填属性 X"）的失败结果，界面显示失败
- Given 模型提交无法解析的参数文本，When 解析，Then 按空参数处理并走常规校验（校验失败则按上条输出失败），不因解析问题静默吞掉
- Given 无法解析的参数文本被归一为空参数、且该工具的全部参数均为可选（校验通过），When 调用到达执行，Then 调用**仍会执行**——引擎不因坏文本直接拒绝（有副作用的调用由审批面另行把关；此为基线行为，实现者无需在此追加拒绝逻辑）
- Given 参数问题导致拒绝，When 模型收到结果，Then 失败信息可定位到是参数问题（区别于执行失败）

### US2.3 并发调用与资源冲突（P0）

作为单人开发者，我想让模型在同一批发起多个工具调用时尽快完成，而不必串行等待。

验收：
- Given 同一批多个调用的资源访问互不冲突（如分别读不同文件），When 执行，Then 各调用**并行**执行，结果各自成条按完成序回传，界面可同时看到多个进行中状态
- Given 同一批某两个调用的资源访问存在写冲突（任一方向同一文件/目录树写入），When 执行，Then 二者**串行**执行（按提交序排队，后到者等先到者完成，不并发写同一处）
- Given 工具未声明资源访问范围，When 执行，Then 按"与所有并发调用冲突"的最保守策略处置，不并发

### US2.4 流式进展可见性（P0）

作为多端/网页用户，我想在工具长时间执行时看到过程，以便判断它是活着还是在卡死。

验收：
- Given 执行中的工具产生过程输出，When 输出到达，Then 用户在界面上**实时**看到：命令类工具的标准输出/错误输出尾窗（保留最近若干行、超限截断标记）、状态行（如"连接断开，正在重连…"）、或数值进度
- Given 工具发出带授权地址的状态更新，When 展示，Then 地址可点击打开（终端内转为可点击链接）
- Given 执行结束，When 结果落地，Then 界面实时过程输出被最终结果取代（不残留过期过程内容）

### US2.5 用户中断（P0）

作为单人开发者，我想随时叫停正在执行的工具，以便误操作或长任务失控时立即止血。

验收：
- Given 工具执行中，When 用户发出中断（终端 Esc / Ctrl+C；网页 Esc），Then 执行被中止，**当前回合内全部在途的工具执行**一并中止（不限于同一批；已后台化的任务不受影响，由任务停止工具管理）
- Given 因用户主动中断而中止，When 结果回传模型，Then 模型收到明确说明：这是用户的有意动作（非系统错误、非超时、非容量限制），**不得自动重试或猜测原因**，等待用户下一步指示
- Given 因非用户原因（系统错误/流中断）中止，When 结果回传，Then 模型收到"工具被中止"的区分性说明
- Given 用户中断后界面反馈，When 处理完成，Then 界面显示"已由用户中断"状态，而非报错

### US2.6 超时与后台化（P0）

作为单人开发者，我想让长命令不被简单杀死，以便不丢失正在进行的计算。

验收：
- Given 后台化的适用面，When 模型查看可用工具，Then 仅 命令执行、子代理派发、后台问询 三族支持模型主动后台化——其余工具均同步执行（同步工具在同批内仍可与不冲突调用并行）
- Given 命令类工具（Bash）前台执行超时，When 超时发生，Then **默认转入后台继续运行**（用户可配置为超时杀灭），用户获知任务已进入后台及其任务号
- Given 后台化被配置关闭，When 命令超时，Then 命令被终止，模型收到含退出原因的失败结果，界面显示失败
- Given 命令前台执行，When 时长上限被查看或调整，Then 上限存在且配置可调（默认前台上限显著短于后台上限；基线值见 US8.1）
- Given 前台命令或子代理派发运行超过短暂提示阈值（命令约 10 秒），When 运行中，Then 终端显示"按快捷键转后台继续运行"的提示（提示随结果落地消失）；用户可随时主动将前台执行转为后台

### US2.7 回合内停止指令（停止整批 / 停止回合）（P1）

作为单人开发者，我想让某些工具在结果中标记"本回合到此为止"，以便回合在合适的边界收尾、不做无意义的空转。

两种停止标记均由工具在结果中向引擎发出（引擎内部循环控制提示，不是模型可用的参数），语义不同、不可互换。

验收：
- Given 某工具结果带"停止整批"标记，When 同批仍有未执行的其他调用，Then 未执行调用不再执行，模型收到"因前一调用停止而被跳过"的说明
- Given 某工具执行结果带"停止回合"标记，When 同批其他调用仍在执行或排队，Then 这些调用照常执行，不被跳过；本批收尾后回合正常结束，不再进入后续工具调用循环
- Given "停止整批"标记出现在直接失败的结果上，When 收尾，Then 按"停止回合"语义收尾（机制见架构 §4）

### US2.8 MCP 服务器断连的调用恢复 `[mcp-集成]`（P0）

作为单人开发者，我想让与 MCP 服务器的偶发断连不直接毁掉一次调用，以便获得基本韧性。

验收：
- Given 调用期间与 MCP 服务器连接中断，When 执行失败可归因于模糊错误，Then 引擎尝试探活/重连并重试；传输级断连尝试重连一次后再试
- Given 重试仍失败，When 结果回传，Then 模型收到"该工具已加载但其 MCP 服务器当前断连、不要立即重试"的说明，界面显示失败
- Given 恢复重试的执行语义，When 实现与调用有副作用的远端工具，Then 重试为**尽力而为、不保证恰好一次**——同一调用可能被远端执行多次（副作用防护由审批面与工具自身幂等承担）；重试上限明确：模糊错误探活后重试一次，传输级断连重连一次后再试

### US2.9 流中断导致未执行的调用（P1）

作为多端/网页用户，我想让因对话流中断而未执行的调用被明确标记，以便不会误以为它们执行过。

验收：
- Given 模型生成参数过程中达到输出上限，When 该调用的参数被截断，Then 该调用**不会被执行**，界面卡片头部显示截断状态并提示"参数因输出上限被截断、调用未执行"，同时给出会话级提示
- Given 对话流因暂停/过载/输出上限等原因中断，When 同批存在其他未执行调用，Then 全部不执行，模型逐个收到"未执行"的合成失败说明，聊天记录中如实呈现合成结果

### US2.10 数字形态参数值宽容（P1）

作为模型侧使用者，我想让对数字字段提交数字形态字符串的调用被按数值接受，以便不因类型书写习惯被白白拒绝（某些模型确实容易把数字以字符串形态写出）。

验收：
- Given 工具参数契约声明某字段为数字（整数或小数），When 模型提交该字段的值为数字形态的字符串（如 `"42"`、`"3.14"`），Then 引擎按数值接收该参数并照常执行（不因类型拒绝）
- Given 提交的字符串无法按数字解读（如 `"abc"`、空串），When 调用，Then 仍按常规参数校验拒绝，不静默吞掉
- Given 字段契约声明为非数字类型，When 提交数字字符串，Then 不适用本宽容，按常规校验处理
- Given 数字字符串被接收，When 后续校验，Then 其余契约规则（必填、取值范围等）照常生效

### US2.11 后台任务的自动通知与再开（P0）

作为模型侧使用者，我想在后台任务到达终态时被自动告知，以便不轮询、不等待，继续当前工作。

验收：
- Given 后台任务（命令或子代理）到达终态（完成/失败/中止），When 通知构建，Then 引擎把完成通知作为用户侧消息自动注入对话：含任务标识、终态、摘要与输出快照（全量可得时携带全量，否则尾部约 3,000 字节）；完成为普通级、失败/中止为警示级
- Given 通知到达时模型正在执行回合，When 注入，Then 通知并入后续步骤送达（不打断当前步骤）
- Given 通知到达时无活动回合（空闲），When 注入，Then 引擎自动开启新回合驱动模型继续（无需用户输入）
- Given 同一任务同一终态，When 重复触发或会话恢复，Then 只通知一次（已投递的不重复补发；恢复时对未投递的终态任务补发）
- Given 工具的结果说明面，When 模型选择后台运行，Then 指引明确告知"完成将自动通知——勿等待、勿轮询、勿主动查询；仅必要时停止任务"
- Given 前台（非后台）任务，When 到达终态，Then 不在通知面（结果按同步路径回传）
- Given 前台任务因超时转入后台（US2.6），When 到达终态，Then 同样进入通知面（转入后台即为后台任务）
- Given 通知被显式抑制，When 任务终态，Then 不注入（模型仍可经任务查询工具获知）
- 同族再开路径：定时任务的注入与后台问询的答案到达同样驱动模型继续（服务语义归各自域）

## 3. Epic E3：工具结果

> 解决"工具结果如何呈现给模型与用户"。形态、错误、截断、摘要、合成结果。

### US3.1 结果形态与空/非文本（P0）

作为模型侧使用者，我想让结果形态可预期，以便正确处理。

验收：
- Given 工具返回文本输出，When 结果回传，Then 文本原样进入对话并按界面规则呈现
- Given 工具返回空输出，When 结果回传，Then 模型收到"输出为空"的明确提示（不静默）
- Given 工具仅返回媒体内容（图片/视频/音频），When 结果回传，Then 文本面提示"返回了非文本内容"，界面按媒体形态呈现

### US3.2 错误结果（P0）

作为多端/网页用户，我想让失败的工具调用与成功明确区分，以便知道 agent 哪一步磕绊了。

验收：
- Given 工具执行失败（非零退出码/异常/被拒），When 结果呈现，Then 界面以错误样式呈现（红色标记、错误文本不以单行摘要折叠、以错误色完整可展开）；模型侧结果带"失败"标记
- Given Bash 命令以非零退出码结束，When 结果回传，Then 附带退出码说明（如"以退出码 N 失败"）

### US3.3 大输出截断与落盘（P0）

作为多端/网页用户，我想让超大的工具输出不淹没对话，又不丢失可读性。

验收：
- Given 单次工具文本输出超过 5 万字符，When 结果回传模型，Then 模型只看到超限头部说明、2 千字符预览和读取指引（含唯一输出路径），**完整内容已落盘**且可经读取工具按指引取回
- Given 已落盘的工具结果文件，When 会话长期使用，Then 文件长期保留、随会话数据一并处置，不设自动清理（清理策略跟踪见 ROADMAP F-11）
- Given 单条输出行超过长度上限，When 呈现，Then 行尾被截断标记
- Given 工具结果落地界面，When 默认呈现，Then 折叠为前 3 行预览 + "共 N 行，展开查看"提示，可一键展开/折叠（终端 Ctrl+O 全局切换；网页点击卡片）
- Given 错误结果被截断呈现，When 展示，Then 错误文本不以单行摘要折叠（错误色、可展开查看全文）

### US3.4 数字摘要（P1）

作为多端/网页用户，我想在工具卡片头部一眼看到结果规模，以便快速扫读。

验收：
- Given 文件/搜索类工具成功返回，When 卡片头部展示，Then 显示数字摘要：读取=N 行、内容搜索=N 行结果（含提示行；无匹配显示"无匹配"）、模式匹配=N 个文件、编辑=+N −M、写入=N 行、网页抓取=按字节规模、网页搜索=N 条结果
- Given 工具执行完成，When 卡片头部展示，Then 显示本次执行耗时（各端一致）
- Given 结果失败，When 卡片头部展示，Then 摘要整体转红

### US3.5 中断/未记录调用的合成结果（P1）

作为多端/网页用户，我想让会话恢复后不出现"假装完成"的工具调用，以便对事实有准确认知。

验收：
- Given 会话恢复时存在执行被中断、结果未记录的工具调用，When 恢复完成，Then 模型收到明确说明（"执行被中断、其结果未记录、不要假定成功"），转录中如实呈现

### US3.6 重复调用抑制（P1）

作为高级配置用户，我想让模型同批重复提交完全相同的调用时只执行一次，以便避免重复副作用。

验收：
- Given 同批内模型提交完全重复的调用（相同工具名、参数内容一致——字段书写顺序无关），When 第二次到达，Then 拒绝执行，模型收到重复说明（合成占位结果，真实结果来自第一次执行）
- Given 跨批出现相同调用，When 重复发生，Then 不静默执行，而是向模型注入递进的提醒（第一次轻提醒，持续重复升级措辞）
- Given 重复持续升级，When 连击达到上限（第 12 次），Then 引擎强制结束回合，不再继续重复循环

### US3.7 错误反馈的自我修正闭环（P1）

作为模型侧使用者，我想让每次失败的错误信息告诉我出了什么错、能不能修、怎么修，以便不依赖用户干预地自我修正，或明确知道该停下来。

验收：
- Given 任意一次失败（参数校验 / 预检拦截 / 执行失败 / 中止），When 错误回传模型，Then 错误信息包含**失败类别定位**与**具体原因**——同类失败形态一致、不同类别可区分（模型能分辨"是我的输入错了"还是"环境/权限/用户中止了"）
- Given 失败源于模型可修正的输入（参数错、路径错、前置条件未满足），When 错误回传，Then 指引指向**具体修正动作**（如：先读取再编辑、先加载再调用、提供绝对路径、换用媒体读取工具、按落盘路径取回全量输出）
- Given 失败不可通过重试解决（用户中断 / 连接断开 / 策略禁用），When 错误回传，Then 明示**勿重试或勿猜测原因**，并指引替代行为或等待指示
- Given 同一失败原因重复出现，When 生成错误信息，Then 文案确定性一致（同因同文案，不随机措辞）
- Given 模型的修正进入无效循环（同样的调用反复失败），When 重复持续，Then 由重复调用抑制递进提醒并在上限强制结束（US3.6——闭环的终止保护）

## 4. Epic E4：内建工具集

> 解决"引擎开箱即用的工具各保证什么行为"。以下每个工具/工具族的语义都是基线验收项；服务语义（目标、计划、任务后台等）的深层规则归各自域。

### US4.1 文件读取 `Read`（P0）

作为单人开发者，我想可靠地读取文本文件，以便查看源码与产物。

验收：
- Given 读取路径合法，When 调用，Then 返回按行编号的内容；输出上限（行数/行长/字节数）适用于全部读取
- Given 提供行偏移，When 调用，Then 从指定行开始读取；超大文件可分段读；负偏移从文件尾部读
- Given 目标是二进制或图片，When 调用，Then 拒绝并以媒体读取工具指引替代
- Given 提供的是相对路径且目标解析到受限工作区外，When 调用，Then 拒绝并要求提供绝对路径
- Given 目标命中敏感文件清单（环境变量文件/凭据/SSH 私钥类），When 调用，Then 拒绝并说明命中的敏感类别（env / credential / SSH key）；**读取、写入与编辑工具同受此保护**（见 US4.2）
- Given 敏感文件保护与工作区越界守卫，When 默认运行，Then 两者独立生效、默认均开启；各自存在配置级逃生门（高级用户可分别关闭敏感检查、关闭越界守卫），关闭只影响对应检查、两开关互不联动（越界守卫关闭后，工作区外路径不再区分相对/绝对放行）

### US4.2 文件写入 `Write`（P0）

作为单人开发者，我想创建或覆写文件，以便产出代码与文档。

验收：
- Given 目标文件不存在，When 写入，Then 自动创建其父目录并写入
- Given 提供覆盖模式，When 写入，Then 整体替换文件内容；提供追加模式时在文件尾追加且不加多余换行
- Given 写入路径解析到工作区外，When 调用，Then 按工作区路径规则处理（绝对路径放行并交由审批面裁决；相对路径越界拒绝，见 US4.1 与 approval 域）
- Given 目标命中敏感文件清单，When 写入，Then 拒绝（与读取/编辑同受敏感文件保护，US4.1）

### US4.3 精确编辑 `Edit`（P0）

作为单人开发者，我想对小范围修改做精确替换，以便不重写整个文件。

验收：
- Given 声明唯一的前后文本串，When 替换，Then 精确替换且保持文件行尾风格原样（LF 文件仍 LF）
- Given 声明替换串不唯一且未启用全局替换，When 调用，Then 拒绝并说明歧义，避免误改
- Given 启用全局替换，When 调用，Then 替换全部出现处

### US4.4 模式搜索 `Grep`（P0）

作为 LLM，我想在代码库中按模式搜索内容并直接得到可读的代码块，从而一次调用完成"定位 + 顺带看清周边"，无需再链式跟读。

验收：
- Given content 模式下相邻命中的上下文窗口重叠或相邻，When 调用，Then 合并为一个块——块头 `path:startLine-endLine` 行号范围、正文逐行 `行号│内容`、命中行尾 `← match` 标记（US-G1）
- Given `-n: false`，When content 输出，Then 行内无行号前缀但块头行号范围保留（定位能力不丢）
- Given multiline 命中载荷内含换行，When 渲染，Then 按多行命中渲染为块内连续行、行号按命中起始行计
- Given `path` 为 2~32 个文件/目录路径的数组，When 调用，Then 一次搜索覆盖全部路径且结果按数组顺序分组（offset 翻页可复现）；数组超 32 项或任一元素不存在时拒绝并点名（US-G2）
- Given `path` 数组任一元素构成词法逃逸，When 调用，Then 整体拒绝；工作区外干净绝对路径逐一进权限链裁决（与单路径语义对称）
- Given `exclude_line_pattern` 非空，When 调用，Then 命中行被丢弃且其独占的上下文行随之消失，全模式生效（files/count 模式文件命中全被排除则文件不出现）；非法正则报错不静默回退；滤光全部命中时返回 `No non-sensitive matches found`（与"本来无命中"同文案）；已传但零效果时（`excluded_matches == 0`、未截断、结果非空）note 通道附无效果提示行（US-G3）
- Given content 模式且未传 `head_limit`，When 输出，Then 默认上限 30 个命中（`0` 不限）；输出累计字节超 4,096B 软预算时在最后一个完整块边界截断并附 `Results truncated at N of T entries (byte budget reached). Use offset=... to see more.`；`head_limit: 0` 时字节预算不适用（US-G4）
- Given 搜索范围包含忽略文件或敏感文件，When 调用，Then 默认跳过 ignore 文件（可显式包含）、任意模式照旧过滤敏感文件（US-G5）
- 界面呈现（消费端参考，非引擎对齐项）：块状格式下 glance 从块头提取路径、chip 计数 = 命中数（US-G6）

### US4.5 文件模式匹配 `Glob`（P0）

作为 LLM，我想按文件名模式找文件并对结果做二次过滤与限量，从而替代 `rg --files | rg | head` 管道。

验收：
- Given `filter` 参数，When 调用，Then 对匹配路径做不区分大小写的二次过滤——纯文本按子串、含正则元字符（`\ + * ? ( ) [ ] { } | ^ $`，刻意不含 `.`）按正则（编译失败回退子串不报错）、`!` 前缀取反；匹配对象为显示路径（US-GL1）
- Given `filter` 滤光全部匹配，When 调用，Then 输出完整计数头 `0 matches (of M matching before filtering, 0 after filter) — most recent first`（与"模式无匹配"的 `No matches found` 区分）
- Given 未传 `limit`，When 调用，Then 默认上限 200（原 100）；`0` 不限但受双硬上限约束（10,000 条 / 1 MiB 相对路径字节）；计数头恒在——未传 filter 时 `N matches — most recent first`，传了时 `N matches (of M matching before filtering, K after filter) — most recent first`；截断时附 `[Results truncated at N of K — refine pattern or filter, or pass limit]`（US-GL2）
- Given 多个匹配，When 排序，Then mtime 降序、同 mtime 按显示路径字典序为次级键；过滤发生在 limit 截断之前（"过滤后的最新 N 条"）（US-GL3）
- Given 仍传已废弃的 `include_dirs`，When 调用，Then 参数校验拒绝（现状确认；历史会话回放不受影响）（US-GL4）
- Given 匹配包含敏感文件或搜索根越出沙箱，When 调用，Then 照旧过滤/沿用既有路径守卫拒绝文案——filter 不能"捞回"被滤敏感文件（US-GL5）
- 界面呈现（消费端参考，非引擎对齐项）：chip 计数 = 实际返回的路径行数（不含计数头与截断行）（US-GL6）

### US4.6 命令执行 `Bash`（P0）

作为单人开发者，我想让 agent 执行终端命令，以便完成构建、测试与运行。

验收：
- Given 提供命令文本（可带工作目录、超时、描述、后台运行、禁用超时），When 执行，Then 标准输出与错误输出汇总后返回；执行过程实时流式可见（见 US2.4）
- Given 命令非零退出，When 完成，Then 结果带失败标记与退出码（US3.2）
- Given 命令转入后台或直接后台运行，When 启动完成，Then 返回任务号并告知完成将自动通知（勿等待、勿轮询；完整输出已落盘、可按需读取），不阻塞前台
- Given 命令主体内容，When 界面展示，Then 以命令形式呈现（`$ 命令`），区别于输出文本

### US4.7 网络抓取 `FetchURL`（P0）

作为单人开发者，我想让 agent 读取网页内容，以便获取文档与资料。

验收：
- Given 合法的公开 URL，When 调用，Then 返回页面正文（或明确失败）；仅支持公开 HTTP(S) 地址

### US4.8 网页搜索 `WebSearch`（P0）

作为单人开发者，我想让 agent 搜索网页，以便获取最新信息。

验收：
- Given 提供查询词，When 调用，Then 返回搜索结果列表；搜索后端由宿主注入

### US4.9 结构化提问 `AskUserQuestion`（P0）

作为单人开发者，我想让 agent 用选项问我问题，以便快速给出决策而不用打长句。

验收：
- Given 需要用户决策，When 提问，Then 呈现 1–4 个问题、每个 2–4 个选项（支持多选的问题允许多选）；用户也可自行输入
- Given 选择后台问询变体，When 提问，Then 不阻塞 agent 执行（答案到达后继续）
- Given 用户关闭提问（不回答），When 结果回传，Then 当前回合终止、输入权归还用户，模型收到「用户已关闭问询且未说明原因」及行为指引（不得基于猜测继续；终态语义见 approval 域 SDR-005，工具契约侧不重复定义）
- Given 界面展示，When 提问/收答/失败，Then 三种状态文案区分（等待输入/已收集/未能收集）

### US4.10 子代理派发 `Agent`（P0）

作为单人开发者，我想让 agent 派发子代理处理可并行的独立任务，以便主流程不被一个长任务拖死。子代理生命周期语义见 background-tasks 域。

验收：
- Given 提供任务描述，When 派发，Then 子代理执行并返回结果与用量；派发可选子代理类型
- Given 选择前台执行，When 派发，Then 主 agent 等待其完成；选择后台执行时立即返回，可由任务管理面跟踪，完成时经自动通知送达（US2.11）
- Given 提供子代理标识（续作），When 派发，Then 沿用其既有对话与记忆继续执行
- Given 子代理运行，When 界面展示，Then 呈现专用卡片（运行状态、工具数、耗时、token 数、最新活动），完成后高度不塌缩；多个并发子代理聚合为组
- Given 后台子代理异常终止，When 状态呈现，Then 明确区分丢失/被杀/超时/失败

### US4.11 批量派发 `AgentSwarm`（P0）

作为单人开发者，我想让 agent 用模板一次派发多个子代理，以便批量并行处理。

验收：
- Given 提供模板（含条目占位符）与条目清单，When 派发，Then 每个条目一个子代理，全部完成后聚合返回
- Given 条目少于 2 个，When 派发，Then 拒绝（批量派发要求至少两个条目或提供续作名单）
- Given 重复的任务条目，When 派发，Then 拒绝（成员必须可区分）
- Given 条目数量超上限，When 派发，Then 拒绝
- Given 界面展示，When 运行中，Then 默认展开呈现每个成员的实时状态；有成员失败/中止时聚合状态为失败/中止

### US4.12 技能调用 `Skill`（P1）

作为单人开发者，我想让 agent 调用技能获取指导，以便按既有方法论干活。技能系统自身归 skills 域。

### US4.13 任务清单 `TodoList`（P1）

- Given 清单已提交，When 界面展示，Then 清单在专用面板呈现（工具卡片只留标题，不重复正文）

### US4.14 后台任务管理 `TaskList` / `TaskOutput` / `TaskStop`（P0）

作为单人开发者，我想查询/读取/停止后台任务，以便管理并行执行。

验收：
- Given 查询任务，When 调用，Then 返回任务列表（可只看进行中、可限量）
- Given 提供任务号读取输出，When 调用，Then 返回该任务日志
- Given 停止任务，When 调用，Then 任务停止并返回状态（可选原因）

### US4.15 目标管理 `CreateGoal` / `GetGoal` / `UpdateGoal` / `SetGoalBudget`（P1）

作为单人开发者，我想让 agent 建立并维护一个可验证完成条件的目标，以便长任务聚焦。目标域语义见 goal 域。

验收：
- Given 提供目标与完成条件，When 创建，Then 目标建立（已有目标时替换需显式声明）；预算经 SetGoalBudget 另行设置
- Given 查询目标，When 调用，Then 返回目标、完成条件、状态与预算用量
- Given 更新目标状态，When 调用，Then 状态在 活跃/暂停/完成/受阻 之间流转（暂停由用户/宿主置入，模型经"活跃"恢复它）；完成由模型声明（引擎不强制验证完成条件，完成即结束本回合并产出完成摘要——服务语义与提示词引导归 goal 域）
- Given 设置预算，When 调用，Then 目标的回合/令牌/时间预算被限制并持续执法

### US4.16 计划模式 `EnterPlanMode` / `ExitPlanMode`（P1）

作为单人开发者，我想让 agent 先出计划再动手，以便复杂改动有可控的审批点。计划域语义见 plan 域。

- Given 计划就绪请求退出，When 调用，Then 可携带最多 3 个备选方案呈现给用户选择；批准后按所选方案执行；获批方案在界面回显

### US4.18 媒体读取 `ReadMediaFile`（P1）

作为单人开发者，我想让 agent 读取图片/视频，以便理解视觉内容。媒体处理机制见 media 域边界。

验收：
- Given 提供媒体路径，When 调用，Then 返回可被模型理解的媒体内容（图片/视频）
- Given 提供区域裁剪或全分辨率选项，When 调用，Then 按选项返回
- Given 文件超过体积上限（100 MB），When 调用，Then 拒绝

### US4.19 工具选择 `select_tools`（P1）

见 E6（渐进披露）。模型通过本工具显式加载未加载的动态工具。

### US4.20 MCP 认证合成工具 `[mcp-集成]`（P1）

作为单人开发者，我想让需要授权才能连接的 MCP 服务器在对话流内完成授权，以便连接与调用顺畅衔接。

验收：
- Given 服务器需要授权（OAuth）而尚未获得令牌，When 其工具被调用或需要连接，Then 引擎在会话内注入认证工具，用户经授权链接完成授权（链接在界面可点击，状态行实时呈现授权阶段）
- Given 授权完成，When 回调到达，Then 认证工具被真实工具替换，后续调用走正常路径
- Given 授权等待期间用户未完成授权，When 等待超时（最长达 15 分钟），Then 按失败收尾并给出说明

## 5. Epic E5：用户自定义工具

> 解决"引擎外的宿主如何把自己的能力变成模型可调用的工具"。宿主集成者是主消费方。

### US5.1 注册/注销/查询与同名覆盖（P0）

作为宿主集成者，我想注册一个带名称/描述/参数契约的工具，以便模型能调用宿主的内部能力。

验收：
- Given 宿主注册工具，When 注册完成，Then 该工具立即进入当前会话的可用集合、模型可见可调用（未显式禁用时）
- Given 宿主再次注册同名工具，When 注册完成，Then 旧工具被替换
- Given 宿主注销工具，When 注销完成，Then 该工具从可用集合移除
- Given 查询，When 调用，Then 返回全部已注册的用户工具与启用状态

### US5.2 会话恢复后仍可用（P1）

作为宿主集成者，我想让注册的工具在会话重启后仍在，以便不需要重新注册。

验收：
- Given 会话包含宿主注册的工具，When 会话恢复，Then 工具注册重建（名称/描述/参数/披露配置恢复），可继续调用

### US5.3 子代理继承（P0）

作为宿主集成者，我想让派生的子代理也能调用宿主工具，以便子任务继承能力。

验收：
- Given 主 agent 注册了用户工具，When 派发子代理（不含显式覆盖），Then 子代理继承该用户工具并可直接调用

### US5.4 调用往返与取消（P0）

作为宿主集成者，我想让工具调用转发到宿主执行、结果可靠回传，以便实现真正的宿主侧行为。

验收：
- Given 模型调用用户工具，When 执行，Then 调用参数转发给宿主、宿主结果原样回传（失败标记保留）
- Given 用户中断该调用，When 取消，Then 宿主收到取消信号；工具未响应时结果按"已中止"回传
- Given 宿主返回异常（空结果/非结果对象/缺输出字段），When 回传，Then 模型收到确定性的兜底说明（如"未返回结果"），不静默

## 6. Epic E6：工具选择与渐进披露

> 解决"工具很多时如何不让模型被淹没"——不是自动选择（模型始终自行决定），而是**显式加载 + 历史整形的披露管理**。

### US6.1 动态工具显式加载（P1）

作为模型侧使用者，我想在工具清单里只看到当前活跃的工具、需要时再加载更多，以便注意力不被成百个工具稀释。

验收：
- Given 工具被标记为"动态加载"（MCP 工具或延迟披露工具），When 工具列表请求，Then 未加载的动态工具**不进入**模型视野；模型可用 `select_tools` 显式加载
- Given 模型调用 `select_tools` 并给出工具名，When 加载，Then 成功加载的逐个确认（`Loaded: …`）；已在集合的返回"已可用"提示；未知名称明确提示从最新公告清单中挑选
- Given 一次加载请求既未加载到新工具、也无任何已可用项（名称全部未知），When 结果回传，Then 视为失败结果

### US6.2 加载公告（P1）

作为模型侧使用者，我想在每回合开始被明确告知工具集合的变化，以便不持有过期的工具面认知。

验收：
- Given 一回合开始（或压缩边界）时工具集合相对上回合有增删，When 回合内第一步提示，Then 模型收到增量公告（新增/移除清单，形态见架构 §7），无变化时零成本不发

### US6.3 历史整形防幻觉（P1）

作为模型侧使用者，我想让已移出集合的动态工具从历史上下文里也消失，以便不产生"旧工具仍可用"的幻觉。

验收：
- Given 动态工具曾出现在历史消息中，When 其已从当前集合移除，Then 模型请求的历史消息中该工具的参数契约被剥离（旧调用行为不误导）
- Given 模型调用未加载的动态工具，When 拦截，Then 模型收到明确指引（"该工具可用但未加载，先调用 select_tools 加载再调用"）
- Given 模型调用已加载但被策略关闭的工具，When 拦截，Then 模型收到"已加载但不再活跃，请询问用户启用后再调用"的说明

### US6.4 实验开关（P1）

作为高级配置用户，我想让渐进披露默认关闭、可显式开启，以便默认行为稳定。

验收：
- Given 未开启实验开关，When 会话启动，Then 渐进披露能力不生效（无公告、无历史整形），全部可用工具直接可见
- Given 开启实验开关，When 会话启动，Then US6.1–US6.3 生效

## 7. Epic E7：工具可用性策略

> 解决"谁能用、谁不能用"的强制面——**独立于审批流**：策略决定工具是否在集合内（建模层强制），审批决定单次调用是否放行（approval 域）。本域只保证策略的强制点与语义。

### US7.1 多层叠加与优先级（P0）

作为高级配置用户，我想让多个来源的工具约束按确定优先级叠加，以便治理面可预期。

验收：
- Given 同一工具被多个来源同时约束，When 激活集合计算，Then 按 工作区级禁用（最高）→ 角色工具面（允许/禁用）→ 全局工具配置 → 会话级禁用 的序叠加，任一来源禁用即整体禁用

### US7.2 强制拦截（P0）

作为高级配置用户，我想让被禁用的工具调用在**执行之前**被硬拦截，以便"禁用"不是摆设。

验收：
- Given 工具被任一层禁用但模型仍发起调用（绕过清单直连），When 调用到达执行器，Then 在预检阶段被拒（工具不执行、不产生副作用），模型收到"被当前工具策略禁用"的明确原因，界面显示失败
- Given 工具已从集合移除，When 模型仍调用，Then 以"工具不存在"拒绝，并按场景给出区分性指引（动态工具未加载的指引加载、已禁用的指引询问用户，见 US6.3），不静默

### US7.3 通配匹配范围与误配检测（P1）

作为高级配置用户，我想让通配规则只作用于允许的命名空间，以便不会误禁全部工具。

验收：
- Given 配置把带通配符的规则用于非 MCP 工具，When 配置生效，Then 该规则被识别为永远匹配不到的误配并提示（此类误配在允许列表场景会把全部工具都禁掉，绝不可静默采纳）
- Given 为 MCP 工具配置通配规则，When 生效，Then 按模式匹配服务器前缀的工具
- Given 配置里出现残缺的 MCP 工具名或指向未知工具的规则，When 配置生效，Then 与通配误配同被静态检测并提示

### US7.4 会话级禁用前置（P1）

作为高级配置用户，我想让会话级工具禁用有清晰的启用前提，以便不会在错误状态下报错操作。

验收：
- Given 会话尚未绑定角色，When 设置会话级禁用工具，Then 请求失败并说明需先绑定角色

## 8. Epic E8：非功能与可观测性

> 工具的运行时质量面：上限、性能、事件流、跨端一致性。

### US8.1 资源上限清单（P0）

作为多端/网页用户，我想让所有界面呈现都有明确上限，以便超限行为可预期，不会无限占用。

验收（上限清单，均为基线值；工具级完整上限以内建工具规格为准——见 [tool-calling-builtin-tools.md](tool-calling-builtin-tools.md)）：
- 单次工具文本结果：50,000 字符内原样；超过则 US3.3（预览 + 落盘）
- 单行输出：2,000 字符截断标记
- 界面实时过程输出：保留最近 3 行 + "共 N 行更早"提示；累计 50,000 字符截断；状态行最多 24 行、超出滚动丢弃旧行
- 文件读取：1,000 行 / 每行 2,000 字符 / 100 KB
- 模式匹配：最多 100 个文件
- 模式搜索输出：单次默认 250 行（可调）
- 命令执行：前台默认 60 秒、上限 300 秒；后台默认 10 分钟、上限 24 小时
- 批量派发：条目上限 128（且 ≥2）
- 媒体读取：文件 ≤100 MB
- 定时任务：每会话 ≤50 个，注入文本 ≤8 KiB
- 重复调用连击：连续重复在第 3/5/8 次递进提醒，第 12 次强制结束回合
- 后台任务通知快照：全量可得时携带全量，否则尾部约 3,000 字节
- 中止宽限：用户取消后工具有短暂响应窗口（约 2 秒），超时按中止处理（不无限等待停止）

### US8.2 性能与响应性（P0）

作为单人开发者，我想让工具调用不拖慢对话，以便交互顺畅。

验收：
- Given 模型在流式生成参数（终端界面），When 参数陆续到达，Then 界面呈现已解析部分（命令先行显示、文件内容边写边显示）；网页端参数在调用开始事件中全量到达（流式参数形态为可选增强、非本基线要求，见 [tool-calling-ROADMAP.md](tool-calling-ROADMAP.md) F-2）
- Given 工具 schema 反复使用，When 编译，Then 复用缓存，不在每次调用重复开销
- Given 超大结果截断，When 处理，Then 只截断展示，不阻塞会话后续

### US8.3 事件流与跨端一致（P0）

作为多端/网页用户，我想让工具调用的全程事件在任意端呈现一致，以便换端观察不糊涂。

验收：
- Given 一次工具调用，When 事件流消费，Then 依次呈现：调用开始（含参数与展示提示）→ 参数流增量 → 过程更新 → 结果（含输出、失败标记、合成标记），四种事件类型完整
- Given 工具运行中网页刷新/重连，When 恢复，Then 运行中工具的状态与最近进展从快照重建，不显示为"从未发生"
- Given 会话历史回放，When 查看，Then 每次工具调用的开始与结果如实呈现（转录全量，见 session-persistence 域）
- Given 事件流消费端，When 收到工具集合变化事件（如 MCP 工具增删），Then 按各自端规则处理或显式忽略，不误报
- Given 工具结果缺失（如回合被中断），When 呈现，Then 该调用收敛为明确的终态（如实反映中断，不悬空、不虚报成功），且各端终态语义一致（端差异跟踪见 [tool-calling-ROADMAP.md](tool-calling-ROADMAP.md) F-10）

### US8.4 钩子扩展面（P1）

作为宿主集成者，我想让工具调用前后可挂宿主钩子，以便接入治理与观测。钩子系统自身归 hooks 域。

验收：
- Given 配置了"调用前"钩子，When 工具即将执行，Then 钩子先行裁决（可拒绝并给出模型可见原因、可改写参数、可附加上下文）；参数被改写时按改写后参数执行
- Given 配置了"调用后"钩子，When 工具执行结束，Then 钩子收到结果（输出在交付钩子前截断至 2,000 字符）；失败与成功均触发对应钩子
- Given 钩子执行中抛出错误，When 执行链处理，Then 工具按中止处理并给出明确说明，不静默

## 9. 未来增强提案（超出基线范围）

> 本节内容**不构成基线承诺**——均为候选提案，不是引擎当前保证的行为，不要求 Rust 对其对齐；是否采纳由产品决策。与提案相关的实现现状事实见 [tool-calling-context.md](tool-calling-context.md) §2。

### P-1 参数名笔误宽容（提案；残余兜底已采纳）

作为模型侧使用者，我想让参数**名**的常见笔误也有尽可能低的失败率，以便命名规约之外的残余幻觉不白白浪费一轮调用。

提案要点：
- **治本路径（已作为设计约束落位）**：工具公开参数遵循「领域直觉命名」规约（见 [tool-calling-architecture.md](tool-calling-architecture.md) §1.1），从源头消除反直觉命名引发的参数名幻觉；别名表类运行时容错不作为 TS 基线引入
- **残余兜底（2026-09-10 裁决采纳）**：按"仅当笔误名不是合法参数、且映射目标确为该工具合法参数"的无歧义归位原则宽容处理；存在歧义时一律按常规校验拒绝（US2.2），不静默吞掉——该原则已升格为**参数名别名机制**（见 P-2 / 架构 ADR-1，独立设计决策，覆盖改名过渡与实证幻觉两类来源）
- 数字形态参数值宽容已由 US2.10 定义为基线需求，不在本节重复

### P-2 参数名别名机制（已裁决的 Rust 设计增强，超出 TS 基线）

> 裁决于 2026-09-10：Rust 内核执行，别名为**独立设计决策**（非改名附属）。TS 现行契约仍为各参数现名（基线事实见 builtin-tools 规格）；本条为刻意增强，非 TS 现状。完整裁决与护栏见架构文档 ADR-1。

作为模型侧使用者，我想让命中已知等价名的旧参数名/幻觉参数名被静默兼容，以便单项迁移的历史内容、既有提示词与模型的参数名书写习惯不因命名变化而白白失败一轮调用。

验收：
- Given 参数已按命名规约改名（新名为直觉命名、且已在参数契约中发布），When 模型提交该参数的旧名（旧名不在任何契约/描述/公告中出现），Then 引擎按别名映射后照常执行，模型无感知
- Given 模型提交的参数名不在契约中、但命中实证幻觉类别名（该别名有遥测或历史实证支撑），When 调用，Then 同样静默映射后执行
- Given 模型同时提交权威名与任一别名，When 校验，Then 拒绝并给出明确的参数冲突说明（不静默取舍）
- Given 模型提交别名清单之外的未知参数名，When 校验，Then 仍按常规参数校验严格拒绝（US2.2 语义不松动——别名源必须不是该工具合法参数、映射目标唯一合法，无歧义归位）
- Given 别名被命中，When 调用执行，Then 命中可观测（遥测计数）；改名类别名以迁移潮结束为移除参考，幻觉类别名以命中率衰减为移除参考

首例（已裁决范围）：Read 的行数参数 `n_lines` 改名 `limit`（与 TaskList 的"取多少"语义统一）；旧名 `n_lines` 作为改名过渡类别名。实证幻觉类首例：`Read.offset → Read.line_offset`（2026-09-10 裁决——v1 历史实证 + TS 侧实录报错；`line_offset` 保持权威名，名称中的 "line" 为模型提供单位语义，幻觉 `offset` 时模型意图亦为行）。

## 10. 决策记录（SDR）

> 补录于 2026-09-10（历史追加，不改写正文；后续需求变更在此追加编号记录）。

### SDR-001 数字形态参数值宽容定为基线需求（2026-09-10）

- **背景**：部分模型易把数字字段写成字符串形态；TS 主引擎无此机制（仅 legacy 路径有），原基线未覆盖。
- **决策**：新增 US2.10 为基线需求（Rust 需实现；TS 侧由 legacy 机制承载）。
- **被否决备选**：不做宽容、严格按类型拒绝——实测模型确实易犯此错，白白浪费一轮调用。
- **影响范围**：US2.10、architecture §2（加工链顺序）、context §5 差异矩阵。

### SDR-002 后台任务自动通知补录与措辞修正（2026-09-10）

- **背景**：机制在代码中完整存在，但原基线以"读取指引"措辞记载为拉模式，与真实机制（自动通知、勿轮询）相反。
- **决策**：新增 US2.11 如实补录自动通知闭环（注入/幂等/恢复补发/勿轮询指引）。
- **被否决备选**：维持拉模式措辞——与代码事实相反，属失真。
- **影响范围**：US2.11、architecture §5、context §1.11。

### SDR-003 参数名别名机制升格为独立设计决策（2026-09-10）

- **背景**：同日两次裁决——先初判"笔误宽容不引入"，随后改判：别名本身合理（参数幻觉场景下兼容不出问题），升格为独立设计决策，同时承担单项迁移兼容。
- **决策**：采纳 P-1 残余兜底的无歧义归位原则，落为 P-2 参数名别名机制（两类来源：改名过渡 + 实证幻觉）；首例 Read `n_lines` 改名 `limit`。治本仍为命名规约。
- **被否决备选**：维持不引入——幻觉容错与迁移兼容的价值经裁决压过"拒绝得明确"；公开双名——违反单一权威名。
- **影响范围**：P-1/P-2、architecture §1.1+ADR-1、builtin-tools §1.1、ROADMAP F-6/F-13。
