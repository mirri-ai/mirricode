> 本文件收录**横跨多个域**的术语的唯一规范定义，**仅限术语**：条目只有规范名、形态与示例、定义、出现面、禁止的叫法、同名异义警示。不含代码、不含实现机制、不含裁决（那些归域内 spec 与架构文档）。

## 收录与使用规则

1. **收录条件**（满足其一即应收录）：术语出现在两个及以上域的 spec 中；或出现在共享面——持久化配置、传输契约、用户可见文案。
2. **单一事实源**：收录后，任何域 spec 的术语表只是它的**域内视图**（可裁剪、可补充域内语境与代码事实），两者冲突时以本文件为准。
3. **同批变更**：引入或修改跨域术语的 spec 变更，必须同批更新本文件，不允许"先改 spec、术语表以后再说"。
4. **条目格式**：规范名 / 形态与示例 / 定义 / 出现在哪里 / 禁止的叫法 / 同名异义警示。禁用自造同义词；含 "id" 的表述必须能唯一归位到某个条目。
5. 域内私有术语（只在一个域内出现）不收录，留在该域自己的术语节。

## M. 模型域标识符

首批条目，来自 model 设置域（其域内视图含 config.toml 对应位置与代码事实：[model-settings-page-requirements.md](model-settings-page-requirements.md) §2.1）；M5 来自 rust 内核域（[rust-core-design/11-model-resolution.md](rust-core-design/11-model-resolution.md) 同批登记）。

### M1 模型别名（短称"别名"）

- **形态**：**规范形态** `provider-id/model-id`（如 `github-copilot/claude-opus-4.8`）；**短名形态**（如 `sonnet`）为容忍形态。
- **定义**：全系统指称"哪个模型"的唯一方式——别名本身就是标识符，没有另外一个"id"。
- **出现在哪里**：持久化配置中模型登记表的键；默认模型指针的取值；会话当前模型；agent 工具模型参数的唯一合法值；模型选择界面的条目。
- **禁止的叫法**：~~别名 id~~、~~modelId~~、~~模型 id~~。
- **同名异义警示**："model" 作为参数值时指模型别名（本条目）；作为数据行中的模型字段时指原始模型名（M2）。

### M2 原始模型名（raw model name）

- **形态**：规范形态别名的斜杠右侧部分，如 `claude-opus-4.8`；短名形态别名没有斜杠，其原始模型名只存在于模型登记表的模型字段。
- **定义**：调用供应商时实际发送的模型名。
- **出现在哪里**：持久化配置中模型登记表的模型字段；模型数据行的模型字段；设置表单中名为 "model id" 的输入框。
- **禁止的叫法**：~~原始 id~~、~~raw model id~~、~~原始 model id~~。

### M3 provider id

- **形态**：规范形态别名的斜杠左侧部分，如 `github-copilot`。
- **定义**：模型供应商的唯一标识。
- **出现在哪里**：持久化配置中供应商登记表的键；供应商列表的条目标识；模型数据行的 provider 字段。

### M4 显示名（display name）

- **形态**：任意人类可读文本，如 "Claude Opus 4.8"。
- **定义**：名称解析链（显式显示名 → 目录名 → 原始模型名）的产物，供人阅读。**不是标识符，不能作为模型参数的值**。
- **出现在哪里**：持久化配置中模型登记表的名称字段；模型数据行的名称字段；所有展示模型名的界面。

### M5 模型裁定链（model resolution chain）

- **形态**：两条有优先级的来源链——主链（会话当前模型 → 配置默认模型 → 明确报错）与子代理链（派发显式指定 → 类型默认模型 → 派发者当前模型 → 明确报错）；链的终点一律是报错，不存在内建兜底。
- **定义**：决定"这一次模型调用用哪个模型"的唯一规则——链上每一级都是来源（用户/会话/类型默认的声明），系统自身不贡献任何模型决定；子代理链在派发时点裁定一次并钉扎到该执行流。
- **出现在哪里**：rust 内核域设计（spec 11）；后台任务与子代理域（US1.2 三级裁定规则）；模型设置域（默认模型指针是主链的一级）；用量统计（按逐次裁定结果归因）；web/TUI 模型切换呈现（分割线对应一次裁定变化）。
- **禁止的叫法**：~~模型选择优先级~~（口语泛称）、~~fallback 链~~（回退只描述链的后段，且链终点是报错不是回退）。
- **同名异义警示**：与 provider 解析（别名 → 供应商与凭证，M3/AU 域）不同层——裁定链决定"用哪个模型"，provider 解析决定"怎么连上它"；与「模型切换」（裁定链上会话当前模型这一级的一次变化，用户动作）是链与链上事件的关系，不得互推。

### 同名异义警示：catalog（跨域词）

「catalog」一词两义，出现时必须先归位：

- **已配置模型注册表**（engine model catalog）：引擎内、由持久化配置的模型别名装配的注册表，是运行时解析与 LLM 感知面的数据源。引擎代码与图示中的 `ModelCatalog` 一律指它。
- **目录数据**（models.dev catalog）：从外部公开模型目录拉取并缓存的数据，仅用于名称兜底与导入素材。目录浏览 / 导入相关接口与方法名中的 catalog 一律属它。

两义的成因：注册表的惯用英文名与目录浏览 / 导入接口的命名共用同一词根，且分别出现在类名层与方法名层。各域 spec 可在域内视图补充代码级对应（类名 / 方法名），唯一定义以本文件为准。

## MI. 多模态输入域

首批条目，来自多模态输入域（MI1 产品语义见 [multimodal-input-requirements.md](multimodal-input-requirements.md) §3、机制见 [multimodal-input-architecture.md](multimodal-input-architecture.md) §4；MI2 见需求 E8/SDR-002/SDR-003 与架构 §5.5 + ADR-005）。

### MI1 模型模态能力（model modality capability）

- **形态**：每个模型一条输入模态布尔记录，图片/视频/音频三键，纯布尔无第三态（配置与目录数据中写作能力字符串数组，如 `image_in`、`video_in`、`audio_in`；目录数据形态由 `modalities.input` 数组换算）。ADR-003 修订后不再有**未知态**：模型未被任何来源收录且用户未声明时，记录为全 false——未定义一律按不支持处理（见 SDR-006）。
- **定义**：判定"这一次模型请求能否携带某模态内容"的唯一依据；按优先级制解析（ADR-003 修订）：用户显式声明为王（勾选 = 支持、未勾选 = 不支持）> 外部目录（models.dev 显式 boolean）> 名字推断（仅无声明时兜底）；未定义的模态一律按不支持处理。
- **出现在哪里**：持久化配置中模型条目的能力数组；模型目录数据；web/TUI 模型选择与编辑界面的能力徽章/预置选项；读媒体工具的注册门控与说明裁剪；会话标题派生之外的媒体适配、降级、剥离等全部请求投影判定。
- **禁止的叫法**：~~vision 能力~~（vision 只是 image_in 的展示标签之一）、~~多模态标志~~（不区分具体模态的泛称）、~~模型支持图片~~（口语，未说明来源——现语义下"支持"必须由声明或推断显式成立，未定义一律按不支持处理）。
- **同名异义警示**：与 M5 模型裁定链不同层——裁定链决定"用哪个模型"，模态能力决定"该模型吃得下什么内容"；与工具能力（工具调用域的工具声明能力）不同物——前者是模型输入面，后者是工具自身的执行面，两者只在"按能力门控注册工具"处相邻。

### MI2 媒体在场（media residency）

- **形态**：媒体内容在传递给模型的请求中的持续参与状态。域内原则四要素（SDR-003 修订）：**随压缩衰减**（退场发生在摘要压缩边界，不逐轮滚动）、**缓存友好**（两次压缩之间历史不因媒体而改写，前缀缓存不失效）、**有界**（单图体积由入口压缩限定，请求总量由 413 反应式降级约束）、**可恢复**（退场文本化携带留档路径，可由读媒体工具重读）。
- **定义**：衡量"用户提交的媒体在多大程度上持续参与每次模型请求"的域概念；与**会话历史中的永久留存**是两个层面——历史与人类视图永不因退场而丢失媒体本体。
- **出现在哪里**：摘要压缩边界的媒体文本化退场（目标机制，architecture §5.5 + ADR-005）；压缩触发的媒体固定估值计价（现状：每媒体 2000 token）；观测中的请求媒体体量标记（`size_bytes` 形态，现状已有）与请求级媒体数量/字节记录（目标机制）。
- **禁止的叫法**：~~上下文驻留~~（未区分"历史留存"与"请求在场"两个层面）、~~图片缓存~~（那是服务商侧的 prompt 缓存机制，不是引擎侧的在场管理）、~~媒体瘦身~~（口语，未表达退场时机与可恢复性）。
- **同名异义警示**：与 MI1 模型模态能力正交——模态能力决定"模型吃得下什么内容"，媒体在场决定"媒体在请求中待到什么时候、以什么形态"；与压缩域的"模型视图是投影"不变量同族但作用点不同——压缩域投影管全部历史内容，媒体在场只管媒体部件的退场时机与恢复句柄。

## W. 工作区与 MCP 配置来源层

来自 MCP 域（与该域规格修订同批登记；域内视图含代码事实与裁决：[mcp-requirements.md](mcp-requirements.md) §0、[mcp-architecture.md](mcp-architecture.md) §4.1）。

### W1 工作区（workspace）

- **形态**：一个打开的项目目录及其运行上下文（例：桌面端同时打开两个项目 = 两个工作区）。
- **定义**：系统按它划分运行时资产（配置、连接、会话）边界的单位。
- **出现在哪里**：MCP 域与 rust 内核域的规格文档；桌面/网页/TUI 的界面文案；配置与接口中带"工作区"的参数与字段。
- **禁止的叫法**：~~项目上下文~~（与"项目"混淆）、~~工作目录~~（只是路径，不是运行上下文）。
- **同名异义警示（核心）**：**MCP 配置接口的作用域取值 "workspace"** 指"项目根层 + 项目本地层的合并配置"，**不含**用户全局层——与"工作区"作为运行上下文的概念同形不同义。读到"工作区级配置"时指后者（该工作区内生效的全部层），读到作用域参数 "workspace" 时指前者，两者不得互推。

### W2 MCP 配置来源层（四层）

- **形态**：四个规范名——**用户全局层**（user）、**项目根层**（project-root）、**项目本地层**（project）、**插件层**（plugin）。
- **定义**：MCP 服务器配置的四种来源——用户全局层随个人（个人全部工作区可用）；项目根层由 git 仓库团队共享（例：行业标准文件 `.mcp.json`）；项目本地层仅本机本项目（不进 git）；插件层由插件自带（随插件分发，用户不可改写其定义）。
- **出现在哪里**：设置页的来源标注与说明文案；配置查询/写入接口的来源字段；MCP 域规格文档。
- **禁止的叫法**：~~全局配置~~（单数泛称，无法区分层）、~~项目配置~~（不区分项目根层/项目本地层）。
- **同名异义警示**：页面"配置作用域选择"中的"某个项目"语义对应**项目本地层**——项目根层是团队共享资产、永远只读，不可被选为写入目标；层间覆盖规则属域内设计（见 MCP 域架构文档），不在本条目重复。

### W3 工作区注册表（workspace registry）

- **形态**：数据根下的一份跨引擎共享文件（`workspaces.json`），记录全部已注册工作区（编号 → 根路径、名称、时间戳）与删除标记列表。
- **定义**：工作区身份的唯一事实源——新旧引擎读写同一份文件，互相认可对方的注册与删除。
- **出现在哪里**：工作区管理域规格；rust 内核域多工作区设计（并发写策略）；跨引擎排查场景。
- **禁止的叫法**：~~工作区列表~~（是读取面不是事实源）、~~workspace 缓存~~（会话索引才是可丢缓存，注册表不可）。
- **同名异义警示**：注册表**不承载**排序（排序真相文档归会话管理域）与信任（独立文档）——它只有身份与删除标记。

### W4 工作区信任（workspace trust）

- **形态**：一个按工作区身份独立成档的标记（文档存在 = 信任；删除 = 撤销；缺失 = 未信任，默认态）。
- **定义**：新注册工作区的项目级配置（团队共享层/本机项目层 MCP 配置；Rust 侧含项目说明注入）是否生效的开关——未信任即不加载，信任后加载，撤销即断开。
- **出现在哪里**：工作区管理域规格（门控语义与入口）；MCP 域（项目层加载的开关消费方）；添加/信任确认的界面文案。
- **禁止的叫法**：~~授权~~（与 OAuth 登录授权混淆）、~~安全模式~~（不是运行模式，是配置加载开关）。

### W5 别名集（alias set)

- **形态**：同一个根目录因历史拼写差异产生的全部工作区编号的集合（含规范派生的代表编号）。
- **定义**：身份折叠单位——集合内全部编号在工作区过滤、计数、刷新时视为一个工作区；对外身份取规范派生编号。
- **出现在哪里**：工作区管理域规格（折叠语义）；会话持久化域开放项；跨引擎存量数据排查。
- **禁止的叫法**：~~重复工作区~~（是同一工作区的多种拼写，不是两个工作区）、~~桶合并~~（桶是存储形态，别名集是身份语义）。

## A. 角色域

来自 agent profile 域（配置面与使用域两份规格修订同批登记；域内视图见 [agent-profile-settings-page-requirements.md](agent-profile-settings-page-requirements.md) §1）。A5（v8 修订）与 A9–A11 来自后台任务与子代理域（2026-09-12 扩域修订同批登记；域内视图见 [subagent-requirements.md](subagent-requirements.md) E9–E12 与 [subagent-architecture.md](subagent-architecture.md) ADR-003~005）。A12/A13 来自等待语义裁决批次（2026-09-13，SDR-011/ADR-008）。A15 来自重启孤儿治理批次（2026-10-14，SDR-013/ADR-012）。

### A1 角色

- **形态**：一份具名的角色定义（名称、描述、行为提示词、工具面、默认模型等），文件形态为 Markdown（头部配置区 + 正文）。
- **定义**：agent profile 的用户侧统一称谓——一套可复用的人格与能力包，被装配为主 agent 或子 agent 后生效。
- **出现在哪里**：设置页与终端的角色列表；配置与接口中 agent profile 相关的字段；角色域与协作域规格。
- **禁止的叫法**：~~agent profile~~（用户文案层）、~~人设~~。
- **同名异义警示**：协作域「角色」= agent profile 的团队用法（在提示词正文中声明职责与产出契约），见 collaboration spec——两域同源，协作域单向依赖本域。

### A2 主 agent

- **形态**：会话中唯一对用户直接负责的 agent，由某个角色装配而来。
- **定义**：直接面向用户、可派发子 agent 的会话主体；未选择专用角色时由内置缺省角色兜底。
- **出现在哪里**：会话创建入口（终端参数 / 页面）；角色域与使用域规格；会话历史。
- **禁止的叫法**：~~主智能体~~、~~默认 agent~~（后者指内置缺省角色这一具体兜底项，不是本条目）。

### A3 子 agent

- **形态**：由主 agent 经派发工具创建的 agent，由某个角色装配而来。
- **定义**：执行主 agent 所派发子任务的会话内 agent；用量归因到其角色。
- **出现在哪里**：派发工具的候选列表；会话历史与用量视图；角色域规格。
- **禁止的叫法**：~~子智能体~~、~~副手~~。

### A4 可派发子角色

- **形态**：角色声明中的一份子角色名单（缺省 = 全部启用角色）。
- **定义**：限定「该角色能派发哪些子角色」的清单；名单外的显式指定被拒绝并说明可用集合。
- **出现在哪里**：角色详情与编辑页；派发白名单的运行时校验；使用域规格（派发边界）。
- **禁止的叫法**：~~可委托子角色~~（本次修订前使用域的旧叫法，已统一）。
- **同名异义警示**：与「用途标记」（主 agent / 子 agent / 两者皆可）不同——本条目约束「我能派谁」，用途标记声明「我能被当作什么用」。

### A5 后台任务

- **形态**：脱离发起者原地等待而产生的执行单元，带任务号标识（例：`task-xxx`）；任务面板承载**三类**（以 subagent 域文档为准）：**子代理**（后台派发的子代理执行流）、**后台进程**（命令后台执行）、**后台提问**（等用户作答的问题）。
- **定义**：脱离发起者等待、由任务管理面（查询进度与输出、停止、终态通知）管控的执行单元——三类共用同一套任务号、状态词与停止/超时/丢失终态语义；与之相对的是前台执行（发起者原地等待到终态）。
- **出现在哪里**：派发工具的后台运行选项；任务管理工具的条目与停止动作；终态通知（A11）；TUI/网页的任务面板与「后台」标记（任务类型分类为用户可见文案）。
- **禁止的叫法**：~~后台 agent~~、~~fire-and-forget~~（英文内部叫法，用户面不用）。
- **同名异义警示**：「后台任务」是三类的统称；狭义指某一类时点名类型（后台子代理 / 后台进程 / 后台提问）——「后台进程」专指命令形态，不与统称互推。

### A6 续作（resume）

- **形态**：一个子代理标识 + 一条新指令（「接着上次的活继续干」）。
- **定义**：对既有子代理（完成 / 失败 / 中断 / 超时 / 丢失均可）发起新的执行流，沿用其既有对话与记忆；续作不更换子代理类型，也没有一并选择类型的选项。
- **出现在哪里**：派发工具的续作参数；工具结果中的续作指引（失败/超时/中断后的恢复提示）；会话重启后的丢失恢复路径；界面「继续」入口。
- **禁止的叫法**：~~恢复~~（与会话恢复混淆）、~~重开~~（重开会丢记忆）。
- **同名异义警示**：与「会话恢复」不同——续作是子代理级的、对话保留的继续；会话恢复是进程重启后的会话重建。「续作」与「同时指定子代理类型」互斥（续作保持既有类型，见 subagent 域需求 US4.6）。

### A7 派发工具

- **形态**：两个具名入口——单一派发（每次一个子代理）与批量派发（模板 + 条目一次多个，条目含占位符）；显示名分别沿用产品既有名 `Agent` / `AgentSwarm`。
- **定义**：主代理经其创建并派发子代理的入口；批量派发要求至少两个条目（或提供续作名单）且成员可区分（重复任务内容被拒绝）。
- **出现在哪里**：派发者的工具清单；工具描述面的可用子代理类型与可用型号清单；子代理状态事件的父工具标识。
- **禁止的叫法**：~~子代理工具~~（不是子代理使用的工具）、~~协作工具~~（协作域另有其义）。
- **同名异义警示**：与协作域「协作工具」（团队消息 / 任务板等团队内部设施）不同——本条目是派发侧入口；协作域工具是团队建立后的内部设施。

### A8 子代理会话记录

- **形态**：每个子代理身份一份独立的记录流，自派发起累积其完整对话与事件；主会话记录中只保留派发镜像与摘要引用（例：回放主会话看到"某子代理被派出、何时、结果如何"，完整对话在子代理自身记录流）。
- **定义**：子代理自创建以来的完整对话与事件记录，按身份独立组织，是续作记忆、回放查询与用量归因的记录依据。
- **出现在哪里**：会话历史与回放视图；用量归因展示；续作与恢复机制；subagent 域需求与架构文档。
- **禁止的叫法**：~~子会话~~（子代理不是独立会话）、~~子代理日志~~（与任务输出日志混淆）。
- **同名异义警示**：与「主会话记录」不同——两者分离存储，经派发镜像与引用关联；「会话记录」单独出现时按语境归位（指主会话记录或子代理会话记录，不得混用）。

### A9 定时任务（cron 任务）

- **形态**：一条计划（标准 5 字段表达式，本地时区）+ 一段提示词；到点把提示词作为一条合成用户消息注入所属会话（消息带可辨识信封：任务标识、计划、是否循环、合并计数、过期标记与提示词全文）。
- **定义**：归属创建它的会话的按计划自动注入提示的机制——一次性任务触发即自删；循环任务存活有上限，超期最后一次投递带过期标记后自删；会话忙时触发挂起、空闲后投递，错过的触发合并为一次注入。
- **出现在哪里**：后台任务域全套规格（E11/E12）；会话管理域（复制会话的资产裁决：fork 不携带定时任务，SDR-007）；会话持久化域（会话资产：删除会话级联清除）；模型可见的任务创建/查询/删除工具；TUI/网页的定时触发消息呈现（对话渲染域消费）。
- **禁止的叫法**：~~提醒任务~~（口语可用，规格不用）。
- **同名异义警示**：与「目标（goal）」不同——目标是长程自治任务，定时任务是按时刻注入提示的机制；一次触发驱动的是回合（S7），不是另一个定时任务。**fork 边界口径（已裁决）**：fork（G2）一律**不携带**定时任务——会话管理域 SDR-007、会话持久化域 SDR-002、后台任务域 SDR-006 三方一致裁决；后台任务域 2026-09-12 增量中曾出现的「克隆」表述已由其 SDR-006 修订作废（与 TS 参照行为相悖，属有意的设计增强：避免新旧会话双触发）。

### A10 后台提问

- **形态**：任务面板三类后台任务之一（子代理 / 进程 / 提问）：以「向用户提问」发起、后台化后在任务面板呈现为等用户作答的问题；作答后定局为「已完成」且答案作为通知（A11）送达发起者。
- **定义**：提问的后台化任务形态——「问」的界面交互（何时呈现、如何作答、关闭语义）归 approval 域的问询闭环，后台化的生命周期（排队、状态、停止、通知）归后台任务域（按生命周期归属切分，subagent 域 SDR-003）。
- **出现在哪里**：后台任务域规格（E9/E10、裁决点 Q7）；任务面板的任务类型标注（用户可见文案）；approval 域问询交互的归属边界（交叉引用）。
- **禁止的叫法**：~~后台问询~~（易与 approval 域「问询」这一交互闭环单义混用——问询是交互，本条目是任务形态）。
- **同名异义警示**：与「问询（AskUserQuestion 类交互）」不同——问询是"问—答—回传"的交互闭环，本条目是后台化的任务形态；与其他两类后台任务（A5）共用面板语义。

### A11 任务通知（合成 user 消息投递）

- **形态**：后台任务定局（完成/失败/超时/被停止/丢失）时投递给发起者的一条**合成用户消息**：含任务号、类型、终态与原因（子代理失败类另附可行动恢复指引）；发起者忙则并入当前回合、闲则自起新回合消化。
- **定义**：后台任务定局结果到达模型（发起者）本身的投递机制——不是界面弹窗、不要求轮询；同一任务同一终态至多送达一次，与对话撤销对账、重开补录、压缩后的"后台任务仍在跑"提醒重注入配套成立。
- **出现在哪里**：后台任务域全套规格（E10）；会话管理域（撤销的对账边界）；上下文压缩域（压缩后提醒的重注入）；TUI/网页对话流的后台状态播报（对话渲染域消费）。
- **禁止的叫法**：~~完成弹窗~~（不是界面弹窗）、~~回调~~（那是集成方的事件订阅面，不是给模型的消息）。
- **同名异义警示**：与「集成方生命周期回调」（程序方订阅的开始/结束回调）不同——回调给程序方、通知给模型；与「合成结果」（T4 的子类，未执行调用的占位结果）不同——本条目是用户角色的对话消息。

### A12 阻塞等待入口

- **形态**：任务输出查询工具上的一个显式「等待」选项（缺省关闭）+ 声明的时长上限；例：对运行中的后台任务选择「等它定局」，一次等待替代反复查询确认。
- **定义**：派发者显式选择的「原地等一个后台任务到定局」的能力——等待持续到定局或时长上限；到期诚实返回部分输出与「仍在运行」标注并劝退连续等待；等待命中定局时其自动通知被抑制（等待的返回即应答）；未就绪的普通查询附「完成将自动送达、勿重复查询」的动态提示。
- **出现在哪里**：后台任务域规格（E13/US13.1）；任务输出查询工具的参数与结果；工具调用域的逐工具接口规格。
- **禁止的叫法**：~~轮询~~（轮询是被本入口取代的反模式）、~~sleep~~（与任务无绑定的自由等待，被否决形态）。
- **同名异义警示**：与 A13 等待挂起不同——阻塞等待发生在**回合内**（一次工具调用的占位），等待挂起发生在**回合间**（目标循环暂停发续航提示）；两者互补共存，分工见 subagent 域 SDR-011。

### A13 等待挂起

- **形态**：自治目标模式下，续航回合无实际工作（无工具调用）且存在进行中后台任务时，目标循环暂停发起新续航提示；任一后台任务定局通知（或用户插话、看门狗到期）唤醒。
- **定义**：目标循环的「合法等待」语义——把「回合结束即强制续航」的结构改为「有等待信号则挂起、事件驱动唤醒」；挂起期不计回合预算，看门狗兜底防止永久沉睡。
- **出现在哪里**：后台任务域规格（E13/US13.3 的协同契约）；目标（goal）域 E5（等待挂起的产品语义正式落点，机制切分见 goal-architecture §4；落地排期见 goal-ROADMAP O2）。
- **禁止的叫法**：~~暂停目标~~（目标本身未暂停，只是循环不发续航提示）、~~休眠~~（与会话/进程休眠混淆）。
- **同名异义警示**：与无界面模式「接力驱动」同构（等待由引擎侧事件承担）但语境不同——接力驱动是无界面单次运行的退出策略，本条目是交互式目标模式的循环语义；与 A12 阻塞等待的分工见 A12 警示句。

### A14 成员挂起（member suspension）

- **形态**：委托成员执行中的「暂停推进、等待外部输入」状态；挂起原因三分类——等待用户审批（approval）/ 等待用户作答（question）/ 限流退避（rate_limit）；例：蜂群某成员发起权限审批，成员状态由「进行中」变为「等待审批中」，决议后同身份续跑。
- **定义**：成员执行流的挂起语义——进展、上下文与身份保留，原因解除后同身份续跑；**不是终态**。等待用户期间成员时长预算停表、并发槽让渡；挂起/恢复经成员状态事件发布（原因结构化，非自由文本）。
- **出现在哪里**：subagent 域规格（ADR-011：调度器挂起原语与事件面）；督导域规格（SDR-008 / US5.4：成员状态呈现「等待审批中 / 等待作答中」）；wire 契约（成员状态事件的结构化原因字段）。
- **禁止的叫法**：~~暂停~~（与督导域用户主动的「暂停/恢复」提案（proposals P-025）混淆——本条目是引擎侧因等待外部输入的被动挂起；用户主动暂停若落地将复用同一原语，但语义入口不同）。
- **同名异义警示**：与 A13 等待挂起（目标循环回合间的续航暂停）不同——本条目是**成员执行流**的挂起，发生在被委托 agent 的执行中；与 A12 阻塞等待（回合内工具调用占位）也不同——A12 是派发者的主动查询行为，本条目是被派发成员的执行状态。

### A15 进程身份指纹（process identity fingerprint）

- **形态**：三元组——进程号、进程组号、该进程的启动时刻（操作系统记录的进程创建时点）；例：`pid=8808, pgid=8808, started=2026-10-14T23:11:07`。命令文本作为旁证展示信息，不参与判定。
- **定义**：跨服务代际唯一标识一个后台进程的方法——进程号会被操作系统复用，但「进程号 + 启动时刻」共同构成的身份在同一台机器上至多属于一个进程实例；档案中的指纹与当前系统状态比对即可回答「这个任务对应的进程还在不在、是不是它」，是重启孤儿普查（subagent 域 Epic E14）的判定基础。
- **出现在哪里**：subagent 域规格（SDR-013 / ADR-012：指纹三元组与启动普查）；进程类后台任务的持久化档案；孤儿普查结果报告。
- **禁止的叫法**：~~进程 ID~~（进程号单独不构成身份——复用场景下会误伤）、~~PID 校验~~（同上，且 PID 是实现词）。
- **同名异义警示**：「身份指纹」判定的是**进程**，不是任务——任务（A5）是管理面概念，同一任务的档案在进程死后仍存在；指纹回答的只是「档案指向的那个进程如今是否仍活着且是它」。与执行环境域的「进程组终止」（整组发信号）是两个面：一个管身份判定，一个管终止执行。

## L. 回合调度域

来自回合调度域（与该域规格基线同批登记；域内视图见 [turn-scheduling-requirements.md](turn-scheduling-requirements.md)）。

### L1 异步唤醒源（wake source）

- **形态**：任何"晚到的、要以消息形态送达模型"的来源——任务终态通知、定时触发、目标续航提示、用户插话、重试等；接入统一入口并声明准入类别与来源标识。
- **定义**：能驱动或注入回合的异步消息来源；其接入契约（准入类别、来源标识、合并规则、挂起联动、撤销对账五要素）由回合调度域统一定义——任何新异步源不得发明旁路调度。
- **出现在哪里**：回合调度域全套规格；后台任务域（任务通知/定时注入两个既有实例）；目标域（续航提示）；wire 的来源标识家族（PromptOrigin）。
- **禁止的叫法**：~~事件源~~（与界面事件混淆）、~~回调~~（那是程序方订阅面，消息给模型/回调给程序）。
- **同名异义警示**：唤醒源是"进入对话的消息来源"，不是引擎事件总线的 event（后者是观测面，不驱动回合）。

### L2 准入策略（admission）

- **形态**：四类封闭集——立即开新回合 / 忙则折入·闲则自起 / 等待下一回合 / 仅活动回合。
- **定义**：一个步骤请求进入回合的路径规则；新异步源接入时必须从四类中选择，不发明第五类。
- **出现在哪里**：回合调度域全套规格（E2）；各异步源的接入点。
- **禁止的叫法**：~~路由~~。
- **同名异义警示**：与权限审批（approval 域的放行/拦截）无关——准入管"何时进入回合"，审批管"能不能执行"。

### L3 回合结局（turn outcome）

- **形态**：wire `turn.ended` 的 reason 枚举与对外呈现的对应词族——已完成（completed：正常结束/未知原因/输出截断/暂停）、已失败（failed：错误/步数上限/引擎硬丢弃）、已过滤（filtered）、已取消（cancelled）、已停滞（stalled：系统判定无进展且回合协作收场的终止）、已阻塞（blocked：钩子阻断）。
- **定义**：回合定局时对外报告的终态词汇，用户面与 wire 契约一一对应——**词汇即归因**：每个非"已完成"结局都能让用户不查日志就说出"为什么停"。取消来源（用户取消/系统中止）是"已取消"结局的原因细分字段，不另立结局词；系统判定无进展的终止是独立结局"已停滞"（协作收场；不协作的硬丢弃归"已失败"族），不得记为"已取消"。
- **出现在哪里**：回合调度域全套规格（E1/E5，ADR-004 词汇拆分）；wire 契约 turn.ended；会话列表/对话渲染域的终态呈现；审批往返结论（approved/rejected/cancelled）是另一套词汇（见 A6 同名异义）。
- **禁止的叫法**：~~Stopped~~（不区分原因的笼统词，正是 ADR-004 修复的目标形态）。
- **同名异义警示**：审批往返的 cancelled（用户对一次审批的取消）与回合结局的 cancelled（用户对整个回合的取消）同名不同物；wire 层以所属事件区分，产品文案层按上下文呈现。

### L4 等待类别（WaitKind）

- **形态**：封闭枚举——模型流式响应中 / 等模型首响应 / 前台工具执行中 / 等后台任务 / 等子代理 / 等用户决策 / 未登记（Unknown）；嵌套/并发等待登记为等待集合。
- **定义**：回合执行循环中每个等待点的类别登记（经等待框架语法登记，不靠各等待点自觉）——僵死看门狗按类别决定判据路径（向哪类 owner 查询、适用哪类窗口）。扩枚举必须走 ADR。
- **出现在哪里**：回合调度域 ADR-006（看门狗三代架构）；mirri-core 回合执行循环的等待框架。
- **禁止的叫法**：~~等待类型~~（与任务类型 task kind 混淆）。
- **同名异义警示**：与任务类型（后台任务域的任务行分类）无关——WaitKind 是回合侧等待点的分类，不是被等待对象自身的分类。

### L5 owner（等待对象事实源）

- **形态**：每类等待所依赖的资源或登记处——模型响应 → HTTP 连接（读空闲超时）；后台任务 → 任务生命周期；子代理 → 子代理宿主；用户决策 → 门未决登记；前台工具 → 工具超时参数。
- **定义**：拉模式看门狗查询活体事实的对象——持有该等待的精确活体判定（"仍在推进"），看门狗按登记的等待类别向其查询（四态返回：推进中 / 已结算 / 推进停滞 / 查询失败）。
- **出现在哪里**：回合调度域 ADR-006；后台任务域（任务生命周期）、代理监督域（子代理宿主）作为 owner 的归属域。
- **禁止的叫法**：~~心跳源~~（推模型词汇——拉模型下 owner 不再"喂"任何信号）。
- **同名异义警示**：无。

### L6 推进（advancing）

- **形态**：owner 侧活体事实的判定标准——"资源存在/运行态为 Running"不是活体，"仍在推进"才是（任务心跳推进、子代理活动钟推进、门登记存在）。
- **定义**：判"活"的语义基准，继承自 ADR-004 的活动信号判据——拉模式架构下由 owner 侧持有与判定，方向从"等待点推送"反转为"看门狗查询"，判定标准本身不降级（前台静默工具类例外——该类无推进事实源，维持存在性保活）。
- **出现在哪里**：回合调度域 ADR-006/US5.5；后台任务域（任务心跳）、代理监督域（子代理活动钟）。
- **禁止的叫法**：~~存活~~（裸用——存在性存活与推进性存活是两个判定，前者不是看门狗认的活体）。
- **同名异义警示**：与任务心跳（后台任务域的设施）不同——心跳是推进判定的载体之一，不是推进本身。

### L7 类静默窗（per-kind stall window）

- **形态**：按等待类别适用的僵死计时窗口——owner 查询报"推进停滞"的等待与前台静默工具的存在性保活走该窗（数量级即历史静默窗口）；与第三层兜底长窗（兜底窗口，量级分钟到小时级）并列，两窗不串联。
- **定义**：资源保护窗口——被等待对象"资源存在但推进失守"时的终止计时；超窗走两级收尾（协作取消 → 硬丢弃）。
- **出现在哪里**：回合调度域 ADR-006 双窗结构；看门狗实现。
- **禁止的叫法**：~~静默超时（裸用，不区分是哪个窗）~~。
- **同名异义警示**：与兜底窗口（第三层长窗）是两个窗两个用途——类静默窗回收"推进失守"的资源，兜底窗口兜"引擎侧死锁/未知等待"的底。

## O. 目标域

来自目标域（与该域规格基线同批登记；域内视图见 [goal-requirements.md](goal-requirements.md)）。

### O1 目标（goal）

- **形态**：一段目标描述（≤4000 字符）+ 可选验收标准 + 三种预算（回合/token/时间，可不设）；四态：进行中/已暂停/已阻塞/已完成（瞬态，总结后即清）。
- **定义**：用户委托的长程自治任务——建立后引擎自动续航（回合结束即继续）直到终态（完成/阻塞）、预算闸门或用户干预；同一会话同一时刻至多一个（多目标靠消费端队列接力）。
- **出现在哪里**：goal 域全套规格；后台任务域（A9 定时任务的异义警示引用）；TUI `/goal` 命令族、web 目标条、无界面模式退出码（0/3/6）。
- **禁止的叫法**：~~任务~~（与后台任务 A5 混淆）、~~待办~~（TodoList 与目标零耦合）。
- **同名异义警示**：与定时任务（A9）不同——目标是长程自治（续航驱动），定时任务是按时刻注入提示；与后台任务（A5）不同——目标不是被任务面板管控的执行单元。**fork 边界**：fork 一律不携带目标（清除并补发提醒）。

### O2 续航提示（continuation prompt）

- **形态**：目标进行中、回合计结束时注入的合成用户消息（系统触发来源）——要求继续朝目标工作或当回合报终态；步数上限变体换"接续进度"文案。
- **定义**：目标自治循环的驱动消息——经"立即开新回合"准入同步入队；等待挂起（A13）期间暂停发放。
- **出现在哪里**：goal 域 E4；回合调度域（异步唤醒源之一）；turn.ended 事件消费方中唯一的新回合投递者。
- **禁止的叫法**：~~续作~~（A6 是子代理的 resume）。
- **同名异义警示**：与子代理续作（A6）无关——续航提示是回合驱动消息，续作是子代理执行流的恢复。

## S. 会话域

来自会话持久化域（与该域规格基线同批登记；域内视图见 [session-persistence-requirements.md](session-persistence-requirements.md) §10）。

### S1 会话恢复（resume）

- **形态**：对一条已收起的会话执行"重新打开"，从磁盘数据重建为可继续使用的运行态会话。
- **定义**：进程重启或会话收起后的会话重建路径——历史对话完整保留、从上次冻结点继续。
- **出现在哪里**：终端/网页的会话历史列表与「恢复」入口；引擎的会话生命周期接口；会话持久化域规格。
- **禁止的叫法**：~~加载会话~~、~~重开会话~~（重开暗示丢记忆）。
- **同名异义警示**：与 A6「续作」不同——续作是子代理级的新执行流；会话恢复是进程级的会话重建。两者都保留记忆，作用层级不同。

### S2 归档会话（archived session）

- **形态**：会话的一个可逆标记状态：置标记（归档）↔ 清标记（恢复归档，非 S1 的恢复）。
- **定义**：把会话移出默认视野的收纳动作——数据完整保留、随时可取回；默认列表在数据读取层排除归档会话。
- **出现在哪里**：网页/终端侧边栏的归档动作与设置页的归档列表；会话列表查询的包含归档参数；会话持久化域规格。
- **禁止的叫法**：~~删除~~（归档不删数据）、~~隐藏~~（界面隐藏是另一层，读取层排除才是语义本体）。
- **同名异义警示**：「恢复归档的会话」指清标记取回；「S1 会话恢复」指进程级重建——对已归档会话取回时两者接连发生（先清标记再重建），但概念独立。

### S3 工作区桶（workspace bucket）

- **形态**：会话数据根下的一个目录，名为工作区键（`wd_<slug>_<hash12>` 形态，例：`wd_mirricode_1a2b3c4d5e6f`），内含该工作区的全部会话目录。
- **定义**：会话按所属工作区的目录归置单位——同一工作区的会话聚在一处，目录名由工作区路径确定性派生（跨引擎一致）。
- **出现在哪里**：会话数据根目录结构；会话持久化域与工作区管理相关规格；数据备份/排查场景。
- **禁止的叫法**：~~工作区文件夹~~（泛称，无法指认派生规则）、~~wd id~~（是键的构造片段，不是条目名）。
- **同名异义警示**：桶名与「工作区 id」同源同值——W1 工作区在本域存储面的键即桶名；本条目只定义目录形态与派生规则，工作区运行时概念见 W1。

### S4 会话索引（session index）

- **形态**：一份可整体丢弃重建的只读清单缓存（本机数据库文件），行内容为各会话的摘要（名称、时间、归档标记、归属）。
- **定义**：磁盘会话数据的加速读模型——目录枚举仍发现事实，索引只加速摘要读取；与磁盘不一致时以磁盘为准并自愈。
- **出现在哪里**：会话列表/计数/工作区列表的读取路径；会话持久化域规格；性能问题排查场景。
- **禁止的叫法**：~~会话数据库~~（暗示是事实源——索引是缓存，删了不丢数据）、~~会话存储~~（存储指磁盘数据本体）。
- **同名异义警示**：两代内核各持一份索引文件（位置不同、互为黑盒）——读到"索引损坏/重建"时先归位是哪一侧的文件；TS 与 Rust 的索引文件**不共享**。

### S5 会话日志（wire journal）

- **形态**：会话（或会话内单条身份记录流）目录下的一份只增不改的事件流水文件（wire.jsonl）；每行一条记录。
- **定义**：会话对话历史的**唯一真相**——转录、模型视图、用量统计都由它重放投影得出；记录族的语义与字段 schema 由产出域（压缩、子代理等）所有，存储布局与版本链由会话持久化域管辖。
- **出现在哪里**：会话持久化域规格（存储布局、版本链）；上下文压缩域规格（日志唯一真相）；会话恢复/导出的输入。
- **禁止的叫法**：~~会话存储~~（存储指磁盘数据整体）、~~操作日志~~（口头缩写易与系统日志混淆）。
- **同名异义警示**：与「子代理会话记录」（A8）的关系——子代理的记录流是**各自独立的一份会话日志**（同格式、不同流），不是主日志的分区。

### S6 转录（transcript）

- **形态**：用户在界面看到的会话对话呈现（终端或网页的对话区），由会话日志投影得出。
- **定义**：**全量投影**——转录保留全部原始对话，不因压缩（C1）而删减；压缩在转录中只表现为一条可展开的整理记录（分隔条）。上下文压缩域称"人类视图"，与"模型视图"（压缩后投影）相对。
- **出现在哪里**：终端/网页的对话区；会话恢复后的回放呈现；上下文压缩域规格（人类视图全量）。
- **禁止的叫法**：~~聊天记录~~（口语可用，规格中不用）、~~历史~~（过泛，与"会话历史"混淆）。
- **同名异义警示**：「转录」永远全量；「模型可见历史」可能被压缩——同一个会话日志投影出两套视图，读到"历史被压缩"时指模型视图，不是转录。

### S7 回合（turn）

- **形态**：一次用户输入到该轮交互完整结束的执行单元（含其间全部模型请求与工具执行）。
- **定义**：会话交互的原子计费/中断单元——回合内包含多次模型请求（每称"一步"），回合结束后才接受下一个用户输入的回应开始。
- **出现在哪里**：会话管理域规格（回合原子性、轮次终点分叉）；上下文压缩域规格（检查点语义：压缩判定在步骤边界、回合只停等不中止）；用量统计。
- **禁止的叫法**：~~轮次~~（规格中作为同义词保留但正文优先用"回合"）、~~一次对话~~（过泛）。
- **同名异义警示**：管理域的"轮次终点"指**回合终点**（用户可分叉的边界点）；压缩域的"轮间隙"亦指**步骤/回合边界**——两处语义一致，但「一步」（单次模型请求）是回合内子单元，不得与回合混用。

## SC. 会话一致性域

来自会话一致性域建域批次（2026-10-13 同批登记；域内视图见 [session-consistency-requirements.md](session-consistency-requirements.md)）。

### SC1 另一入口（another entry）

- **形态**：与本服务进程共享同一份个人数据目录的另一个服务进程（网页服务入口或桌面服务入口，同一可执行文件的多个实例）。
- **定义**：会话一致性域的协调对象——两个入口各自独立运行、互不发现，仅通过共享的磁盘会话数据间接交互；"发现数据变化"在语义上归因于它。
- **出现在哪里**：会话一致性域全部规格；冲突提示的用户可见文案（"该会话可能正在被另一入口使用或已被修改"）。
- **禁止的叫法**：~~另一个用户~~（多入口是同一个人的两个程序实例）、~~另一个服务~~（口语可用，规格中用"入口"）、~~对方实例~~。
- **同名异义警示**：入口指**进程级**的服务形态，不是界面级——网页界面和桌面界面连的是不同的入口进程；"发现另一入口的写入"不区分成因（也可能是其崩溃前的最后写入），提示文案必须保持中性。

### SC2 并发修改冲突（concurrent modification conflict）

- **形态**：本地已知版本与磁盘当前版本不一致这一事实；触发于提交动作或回合执行中的版本检查点。
- **定义**：会话一致性域的核心判定事件——出现即拦截（提交前）或中止（回合中），浏览路径出现只刷新不拦截。
- **出现在哪里**：会话一致性域规格；提交围栏与回合监视的行为定义。
- **禁止的叫法**：~~锁冲突~~（本域无锁）、~~版本冲突（裸用）~~（须带"并发修改"限定）。
- **同名异义警示**：与上下文压缩域的检查点语义无关；与任何数据库/传输层错误码不同名不同义——这是域语义概念，不是错误码。

### SC3 本地已知版本（known version）

- **形态**：`(字节数, 修改时刻)` 二元组，一个入口进程对一个会话各持一份。
- **定义**：该入口已同步到的会话日志版本锚点——自己落盘或吸收另一入口写入后前进；与磁盘当前版本比对即得 SC2 判定。
- **出现在哪里**：会话一致性域架构文档（版本探测器/增量吸收器/提交围栏的共用锚点）。
- **禁止的叫法**：~~本地版本号~~（缺"已知"限定）、~~检查点~~（与压缩域检查点撞名）。
- **同名异义警示**：与压缩域的"检查点"（收起时的快照冻结）完全不同——本条目是跨进程一致性锚点，不落盘、不快照。

## G. 会话管理域

来自会话管理域（与该域规格基线同批登记；域内视图见 [session-management-requirements.md](session-management-requirements.md) §9）。

### G1 置顶（pin）

- **形态**：会话的一个布尔标记状态，配对操作为置顶/取消置顶；置顶的会话在其工作区分组顶部的**置顶区**呈现。
- **定义**：用户显式声明的会话优先级——不是智能推荐，顺序权只属于用户的显式操作。
- **出现在哪里**：网页侧边栏的置顶动作与置顶区；终端会话列表的呈现顺序；会话管理域规格；会话列表契约的 pinned 字段。
- **禁止的叫法**：~~收藏~~（无收纳语义）、~~标星~~（无评分语义）、~~固定~~（与界面固定面板混淆）。
- **同名异义警示**：与「置顶区」不同——本条目是会话级标记，「置顶区」是列表中置顶会话的呈现分组；拖动会话进置顶区等价于执行置顶（会话管理域 US2.3）。归档压过置顶：已归档的会话不因置顶回到默认列表（S2 归档语义优先）。

### G2 复制会话（fork）

- **形态**：一个动作 + 一个新会话：新会话携带源会话至复制时刻的完整历史继续，默认命名「Fork of 源会话名」（SDR-012 裁决形态）。
- **定义**：基于既有会话的完整复制——产出**完全独立的会话**（列表/归档/删除/置顶全规则适用），源会话不受任何影响。
- **出现在哪里**：网页/终端的会话菜单与复制入口；会话生命周期契约的 fork 方法；会话管理域规格（US5.1）。
- **禁止的叫法**：~~克隆~~、~~备份会话~~（备份是导出语义）。
- **同名异义警示**：与「顺带问」（G4）不同——顺带问不产生新会话；与「续作」（A6）不同——续作是子代理级继续，fork 是会话级复制；fork 不携带运行中资产（如定时任务，见 A9 的 fork 边界口径）。

### G3 子会话（child session）

- **形态**：带父子溯源关系的派生会话：由某会话派生（fork + 父标识），默认命名「Child: 源会话名」。
- **定义**：程序化派生产生的独立会话——**溯源不等于所有权**：父会话删除后子会话保留，列表可按父会话过滤（childOf）。
- **出现在哪里**：派生入口与会话列表的父子过滤；会话元数据的父标识字段；会话管理域规格（US5.2）。
- **禁止的叫法**：~~子代理会话~~（子代理不是会话，见 A3）、~~从属会话~~（无所有权语义）。
- **同名异义警示（核心）**：「子会话」**不是**子代理的记录流——子代理在会话内的按身份分片记录（持久化域 ADR-006）有时被口头称作"子会话载体"，那是**记录流**不是会话；读到"子会话"一律指本条目（带父标识的独立会话）。

### G4 顺带问（btw）

- **形态**：会话内的旁路问答分支：继承主对话上下文、**工具全禁用**、仅文本作答；追问复用同一分支。
- **定义**：不打断主对话的临时提问通道——它是**会话内的分支，不是独立会话**：不进会话列表，随宿主会话持久化与恢复。
- **出现在哪里**：网页/终端的"顺带问"入口；btw 契约（`btw.start`）；会话管理域规格（US5.3）。
- **禁止的叫法**：~~临时会话~~（不是会话）、~~侧边栏提问~~（与界面区域混淆）。
- **同名异义警示**：与「子会话」（G3）和「复制会话」（G2）都不同——顺带问不产生任何新会话；与「续作」（A6）不同——无需标识续作，追问自动同分支。

### G5 撤销（undo）

- **形态**：一个动作 + 一个回退点：把会话内最近的若干轮对话（用户的输入与对方的回复成对）从当前对话中移除，会话从该点继续；默认整轮原子。
- **定义**：用户对**自己会话内对话历史**的显式回退操作——被撤销的内容从会话的后续状态（对话呈现、模型可见历史）中消失，且经收起/重开保持消失（持久生效，不是临时画面效果）；遇压缩摘要（C3）即停，不穿越压缩。
- **出现在哪里**：终端的 `/undo` 命令与撤销选择器；会话管理域规格（Epic U）；wire 契约的撤销方法与会话日志的撤销记录；上下文压缩域的边界条款（C1/C3 警示）。
- **禁止的叫法**：~~回滚~~（泛指，与存储层回滚混淆）、~~删除消息~~（不是删除操作，是历史回退）、~~Ctrl-Z~~（快捷键不是概念名）。
- **同名异义警示**：与「压缩」（C1）不同——压缩是系统对模型可见历史的整理，撤销是用户对对话历史的回退，且压缩不是可撤销的编辑（C1 已警示）；与文本编辑器的撤销不同——本条目只指会话对话历史的回退；与「复制会话」（G2）不同——撤销原地回退本会话，不产生新会话。撤销的粒度细节与深度上限属会话管理域开放项（其 ROADMAP），本条目不预设。

### G6 服务方费用优惠身份（conversation cache identity）

- **形态**：模型请求上携带的"这段对话属于谁"的标识（一个字符串，如某会话的标识值 `session_a1b2c3`）；每个会话独立持有自己的标识，分叉出的会话持有自己的新标识（不沿袭，SDR-010）。
- **定义**：模型服务方对已读对话前缀给予计费优惠时的归属依据——服务方据此把"同一来源的连续请求"算作一段对话连续计费。引擎侧只保证该标识的确定性（一个会话一个稳定标识），命中与否是服务方行为。
- **出现在哪里**：模型请求配线（服务方各异的前缀路由键/归属元数据字段）；会话管理域规格（US5.5/SDR-010）与架构（ADR-007）。
- **禁止的叫法**：~~缓存 key~~（技术实现名，各服务方字段名不一）、~~会话身份~~（会话身份是列表/权限的归属主体，本条目是计费归属——两者恰好同值但语义不同，未来可能分离）。
- **同名异义警示**：与「会话标识」目前同值但概念不同——会话标识是列表/权限的归属主体，本条目是计费归属；与「缓存命中」（用量可见性域）不同——命中是结果事件，本条目是引擎可控的归属输入。

### G7 运行状态（session work facts）

- **形态**：会话的一个正交四元组快照：聚合忙碌（busy）、主对话回合是否活跃（mainTurnActive）、挂起交互类型（none/approval/question）、最近回合结局（completed/cancelled/failed）；经列表行、会话快照与状态变化事件（`event.session.work_changed`）暴露。
- **定义**：会话"正在做什么"的权威事实——**侧边栏"运行中"标记的判定口径是主对话回合未收尾**（后台任务与子代理回合点亮聚合忙碌但不点亮标记）。状态由服务端持有与重建，刷新/换端不变形；引擎进程死亡即清零（运行态是进程内事实，不跨重启复活）。
- **出现在哪里**：网页/终端会话列表的运行中标记与停止按钮；会话列表契约的状态字段；会话状态事件；会话管理域规格（US4.4/SDR-013）。
- **禁止的叫法**：~~会话状态~~（歧义——v1 的五值状态**事件枚举**已被本四元组取代，但列表行/详情的 `status` 字段与状态查询接口仍独立存在，指代不同面）、~~在线状态~~（不是连接状态）。
- **同名异义警示**：与「在途回合」（R2，对话渲染域）不同——在途回合是对话呈现的概念（正在生成中的那个回合的续看与补齐），运行状态是列表/通知的概念（哪些会话还在干活的信号灯）；两者判定同源（回合收尾与否）但消费面与投影不同。与「聚合忙碌」不同——忙碌含后台与子代理工作，运行中标记只看主对话回合。与列表行的 `status` 字段（live/closed/archived 的生命周期态）不同——status 说"这个会话处在什么生命周期"，本条目说"这个会话现在是否在干活"，正交并存。

## C. 上下文压缩域

### C1 压缩（compaction）

- **形态**：把旧历史替换为摘要、腾出模型上下文空间的整套操作；含触发判定、修剪、摘要生成、落位、失败恢复。
- **定义**：只影响**模型可见历史**的整理机制——原始记录物理永不删除，用户可见转录全量保留（双视图）。
- **出现在哪里**：loop 控制配置段；会话日志的压缩记录族；终端 `/compact` 命令与网页压缩入口；上下文压缩域全套规格。
- **禁止的叫法**：~~清理会话~~（不删任何用户数据）、~~裁剪~~（与投影修剪 C4 混淆）。
- **同名异义警示**：与「归档」（S2）无关——归档是会话列表的收纳动作，压缩是模型上下文的整理，二者正交；与「撤销」（undo）不同——压缩不是用户可撤销的编辑操作（压缩是撤销的边界，见 C3）。

### C2 保留尾（retention tail）

- **形态**：压缩时按预算（模型窗口容量的比例，或绝对 token 值）从最新内容往回收的一段**完整对话**（用户消息、助手回复、工具调用与结果成对）。
- **定义**：压缩的手术边界——**不参与摘要、逐字节原样保留**的最近对话；预算语义为"最少保留"，切线只向更老方向修正。
- **出现在哪里**：上下文压缩域规格（保留尾切线、落位形态）；会话日志压缩记录的保留计数字段。
- **禁止的叫法**：~~最近消息窗口~~（暗示按条数，口径错误）、~~上下文窗口~~（那是模型容量，不是保留策略）。
- **同名异义警示**：与「上下文窗口」不同——窗口是模型能看到的总量上限，保留尾是压缩时的保留策略；与旧的"仅保留用户消息"机制不同——保留尾是完整对话（含助手与工具交互），用户消息独立预算已被其吸收。

### C3 压缩摘要（compaction summary）

- **形态**：一条带固定前缀的整理记录消息（第一人称交接笔记 + 附带任务清单），落位时**替换**被压缩旧段的原位。
- **定义**：旧历史的浓缩投影——它是模型视图对旧历史的唯一呈现，也是撤销回退的边界（撤销遇摘要即停，不穿越压缩考古）。
- **出现在哪里**：会话日志的压缩落位记录；用户转录中的压缩分隔条（可展开计量与摘要文本）；压缩遥测。
- **禁止的叫法**：~~备份~~（原文在日志里，无需备份）、~~总结报告~~（是交接笔记不是交付物）。
- **同名异义警示**：与「续作摘要」类概念不同——压缩摘要由模型在压缩时自写、随会话演进会被后续压缩再折叠；「摘要」在本仓库各域中如无 C1 限定词，一律先按本条目核对。

### C4 投影修剪（projection trimming）

- **形态**：把较早的、超长的工具输出在**模型视图**中替换为占位说明（原文留在日志，可按需取回）；只在压缩条件已成立时发生。
- **定义**：不花模型调用成本的免费腾空间手段——只改投影不改内存与日志；是压缩判定流程中先于摘要调用的第一道手段。与**追加时的单条工具输出预算**（工具结果落盘时常驻的单条上限，与空间压力无关）是两层独立机制，互不替代。
- **出现在哪里**：上下文压缩域规格（修剪优先）；模型视图投影管线。
- **禁止的叫法**：~~微压缩~~（历史叫法，机制同名但易与完整压缩混淆）、~~删除工具输出~~（原文永不删）、~~裁剪~~（泛指重试丢弃等动作时与本条混淆）。
- **同名异义警示**：与「压缩」（C1）不同——修剪不生成摘要、不重排历史，只是请求投影里的占位化；修剪后压力缓解时压缩流程到此为止。

## T. 工具调用域

来自工具调用域（与该域规格基线同批登记；域内视图含代码事实与机制：[tool-calling-requirements.md](tool-calling-requirements.md)、[tool-calling-architecture.md](tool-calling-architecture.md)、[tool-calling-context.md](tool-calling-context.md)、[tool-calling-builtin-tools.md](tool-calling-builtin-tools.md)）。

### T1 工具（tool）

- **形态**：一个具名的可调用能力（名称、描述、参数契约；可选来源与披露方式），例：命令执行工具、文件读取工具、网页搜索工具。
- **定义**：引擎暴露给模型、由模型按参数契约发起执行的能力单元——一次工具调用就是一个工具在其参数契约下的一次执行请求。
- **出现在哪里**：模型可见的工具列表与调用（wire 事件 `tool.call.*`）；角色/配置中的工具面（允许/禁用清单）；终端与网页的工具卡片与文案（"Using …"）；配置文件的工具段（`[tools]`）。
- **禁止的叫法**：~~函数调用~~（指 T2 工具调用，英文内部说法 function calling 在用户面不用）、~~能力~~（过泛，与能力标签混淆）。
- **同名异义警示**：MCP 工具、用户自定义工具、内建工具都是本条目（按来源 T1 的子类）；「技能」（skill）不是工具——技能是携带说明文档的方法封装，其调用入口是一个名为 Skill 的工具，域内详见 [skills-requirements.md](skills-requirements.md)（来源层级与激活见本表 SK1–SK3）；agent-profile 域「工具面」= 角色声明的工具可用性约束，不是工具本体。

### T2 工具调用（tool call）

- **形态**：一次执行请求单元：工具名 + 参数（JSON）+ 该次调用的唯一标识，直到结果回传结束。
- **定义**：模型发出、引擎执行、结果回传的完整单元——每次调用有进行中/成功/失败三态，失败带错误标记；调用与结果在会话记录中成对出现。
- **出现在哪里**：wire 事件（`tool.call.started/delta/progress/result`）；终端工具卡片头部状态动词（Using/Used/Truncated）；网页工具行状态指示；会话记录与转录；上下文压缩域"工具调用与结果成对"的保留尾语义。
- **禁止的叫法**：~~函数调用~~（口头英文对话可用，规格中不用）、~~工具执行~~（是调用的执行阶段，不是调用本身）。
- **同名异义警示**：与「工具」（T1）不同——T1 是能力本体，T2 是一次执行请求；「被跳过的调用」（同批中因前一调用停止回合而未执行）仍是调用，只是未执行。

### T3 工具输入展示（tool input display）

- **形态**：一次工具调用的**结构化展示提示**，按十余种类别区分呈现方式，例：命令执行（含命令文本）、文件读写（含路径与操作）、差异（含路径）、搜索、抓取、子代理派发、技能调用、计划评审、目标启动等；类别之外的调用落入通用形态。
- **定义**：附着在工具调用上、供界面与审批面板结构化渲染该次调用的提示信息——**提示**而非数据源：界面渲染工具卡片时仍以工具名与参数为准，展示提示只决定"怎么更好地呈现"。
- **出现在哪里**：wire 调用事件的展示字段；审批面板（approval 域）的结构化渲染；协议包的类型定义。
- **禁止的叫法**：~~显示信息~~（过泛）、~~input display~~（英文内部口径，规格中一致用本中文条目）。
- **同名异义警示**：与「工具结果展示」（tool result display，结果侧的结构化呈现提示）相对——T3 是输入侧、结果展示是输出侧，两者共用协议族但语义不同；展示提示不改变参数本身，界面按参数渲染是底线行为。

### T4 工具结果（tool result）

- **形态**：一次工具调用的返回体：输出内容 + 成功/失败标记（失败标记必带，供模型明确感知失败）+ 可选截断/停止标记。
- **定义**：工具调用完成后回传模型、并同时呈现给用户的返回体——成功结果与失败结果同构呈现；失败结果不走单行摘要（错误色、可展开）。
- **出现在哪里**：wire 事件（`tool.result`）；模型视图中的工具角色消息（错误带失败标记）；终端/网页工具卡片的结果区；上下文压缩域保留尾"工具调用与结果成对"。
- **禁止的叫法**：~~工具输出~~（是结果的内容部分，不是结果整体；规格中"输出"指内容时用输出）。
- **同名异义警示**：与「工具输入展示」（T3）不同——T4 是输出侧；"合成结果"（未执行的调用/中断恢复生成的占位结果，明确标记为未执行）是 T4 的子类，不是真实执行产物。

### T5 MCP 工具名规约（`mcp__` 前缀）

- **形态**：`mcp__<server>__<tool>`——双下划线分段：前缀 + 服务器名 + 工具名。
- **定义**：MCP 来源工具的注册与调用名规范——服务器前缀隔离不同服务器的同名工具；工具策略与审批规则对该命名空间可用通配匹配（非 MCP 工具不可用通配）。
- **出现在哪里**：模型可见工具列表与调用；工具策略配置；审批规则；tool-calling / mcp / agent-profile / rust-core-design 域的 spec。
- **禁止的叫法**：~~`mcp:<server>:<tool>`~~（单冒号——仅存在于已退役的旧服务层，live 路径均为双下划线）。
- **同名异义警示**：前缀 `mcp__` 修饰的是**工具名**，与 MCP 服务器连接状态无关（断连时工具仍在集合内，调用被拦截并提示勿立即重试）。

### T6 渐进披露（progressive disclosure / 动态加载）

- **形态**：deferred（延迟披露）标记 + `select_tools` 显式加载 + 每回合集合变化公告 + 历史整形。
- **定义**：对工具可用面的披露管理——模型始终只看到当前活跃工具，MCP 与 deferred 工具未加载时不在视野内，模型按名显式加载后其契约进入上下文；引擎不做自动选择。整套能力受实验开关控制（默认关：全部直接可见、无公告、无整形）。
- **出现在哪里**：模型可见工具列表；tool-calling 域全套规格；compaction（压缩边界公告）；session-management；rust-core-design。
- **禁止的叫法**：~~工具自动选择~~（模型始终自行决定，引擎只管理披露）。
- **同名异义警示**：与角色工具面（agent-profile 域，静态配置层的允许/禁用）不同——渐进披露是运行时的视野管理；两者叠加生效。

## H. 历史读回域

来自历史读回域（与该域规格基线同批登记；域内视图见 [history-readback-requirements.md](history-readback-requirements.md) / [history-readback-architecture.md](history-readback-architecture.md)——该域为设计提案，尚未实现）。

### H1 读回（read-back）

- **形态**：按条目编号区间取回被压缩覆盖的对话原文（例：读取"第 60 至 70 条"），取回的内容作为当轮普通工具结果回到模型上下文。
- **定义**：模型在压缩发生后把已不在其可见历史中的旧原文按编号取回的翻旧账能力——原文取自完整会话记录，读回**不改变**模型可见历史的既有结构（不是撤销压缩，读回内容只在本轮生效）。
- **出现在哪里**：上下文压缩域的 P-E1 提案（未来增强）；历史读回域规格；模型的工具清单（提案落地后）。
- **禁止的叫法**：~~回放~~（与转录/重放的呈现语义混淆）、~~恢复~~（与 S1 会话恢复、A6 续作混淆——读回不重建任何执行状态）。
- **同名异义警示**：与投影修剪占位说明里的"可取回"口头表述不同——那是对超长工具输出的占位化说明；本条目是被压缩历史的按编号取回。用户侧转录本就全量可见（S6），读回解决的是**模型侧**可达性。

### H2 目录卡片（TOC card）

- **形态**：一张描述某段被压缩内容的导航卡片：被覆盖段落的编号区间 + 段内条目的简短摘要行（每行带编号）。
- **定义**：被压缩旧历史的目录页——每段旧历史一张、追加生成、永不改写；模型据此定位要读回（H1）的编号区间。卡片只导航，不承载转述。
- **出现在哪里**：上下文压缩域的 P-E1 提案；历史读回域规格（与现状卡 H3 成对）。
- **禁止的叫法**：~~摘要~~（与 C3 压缩摘要混淆——C3 是交接笔记，本条目是编号目录）、~~索引~~（与 S4 会话索引混淆——那是列表加速缓存）。
- **同名异义警示**：与「现状卡」相对——目录卡片每段一张且永不改写，现状卡全会话一张且每次整理重写；两者对同一段落的描述同源一致。

### H3 现状卡（context-state card）

- **形态**：一张描述"当前窗口外还压着什么"的全貌卡片：被压缩段落的数量、各自的编号区间与一句话概要、合计规模。
- **定义**：会话压缩现状的鸟瞰图——每次整理时重写为最新状态；模型据此知道有哪些旧段、各自在哪，翻旧账有的放矢。
- **出现在哪里**：上下文压缩域的 P-E1 提案；历史读回域规格（与目录卡片 H2 成对）。
- **禁止的叫法**：~~状态栏~~（界面组件，不是上下文内容）、~~上下文摘要~~（与 C3 混淆）。
- **同名异义警示**：见 H2——现状卡重写、目录卡片不改写；会话未压缩时现状卡不存在（无"空目录"占位）。

### H4 按编号寻址（entry-seq addressing）

- **形态**：以会话内累计的条目编号指称历史内容——编号随会话单调递增，压缩与撤销都不回收（例："第 60 至 70 条"为闭区间）。
- **定义**：读回与历史检索的定位方式——编号在压缩前后稳定，是被压缩内容唯一可靠的逻辑坐标；编号本身由上下文压缩域产生与标注（ADR-007），读回域只消费。
- **出现在哪里**：上下文压缩域规格（编号产生、区间与丢弃标注、摘要指令的编号引用约定）；历史读回域规格（读回/检索/卡片的寻址）；会话日志压缩记录的区间字段。
- **禁止的叫法**：~~行号~~（那是存储布局里的位置，导入导出/换格式即作废）、~~消息索引~~（压缩后会漂移，编号不漂移）、~~序号~~（过泛）。
- **同名异义警示**：与「wire 行号」「槽位索引」不同——后两者随重排/压缩漂移，本条目永不回收；「编号」在本仓库他域中另有所指时（如任务号）以前缀或语境归位，指历史条目时一律用本条目。

## R. 对话渲染域

来自对话渲染域（与该域规格基线同批登记；域内视图见 [conversation-rendering-requirements.md](conversation-rendering-requirements.md) §1–§4）。

### R1 会话快照（session snapshot）

- **形态**：打开会话时一次性返回的原子数据包——切片时刻的水位（R4 对应进度）、会话视图、最近一段升序消息（带"还有更早"标记）、在途回合（R2）、子代理名册、待人工交互项。
- **定义**：对话视图的**一致起点**——同一时刻的完整切片，界面据此首屏呈现并从水位续接后续事件；历史改变或缓冲失效后，重新快照是唯一正确的重新对表方式。
- **出现在哪里**：网页/终端打开会话与重开进行中会话的读取路径；断线重连的重同步动作；对话渲染域规格（E1/E3/E4）。
- **禁止的叫法**：~~检查点~~（那是收起时的引擎状态冻结，见会话持久化域）、~~全量历史~~（快照只带最近一段，更早靠分页）。
- **同名异义警示**：与持久化域「检查点（snapshot.json）」**词形相近但完全不同**——检查点是引擎恢复加速的落盘物，快照是对话视图的读取面；读到"快照"在引擎恢复语境中时先归位是不是指检查点。

### R2 在途回合（in-flight turn）

- **形态**：一个回合进行到一半时的状态包——已流出的文本与思考累计、正在执行的各工具（标识/名称/参数/最近进度）、当前回合标识。
- **定义**：易失内容（R3）的**快照侧补偿物**——流式分片不落记录，重开进行中的会话时由快照携带在途回合，界面据此呈现"半成品"回复并从断点续流。
- **出现在哪里**：快照的在途回合字段；对话渲染域规格（E3）；引擎侧易失影子状态的读取出口。
- **禁止的叫法**：~~进行中回复~~（只是其中文本部分，不含工具）、~~当前状态~~（过泛）。
- **同名异义警示**：在途回合是**派生缓存**（可丢弃重建），不是记录的一部分——它与 S5 会话日志的关系是"日志落定前的先行可见性"，落定后以记录为准。

### R3 易失事件（volatile event）

- **形态**：不进入会话日志、不占事件游标、只对当下订阅者有效的事件——流式文本/思考分片、工具参数增量、工具进度；携带回合内累计偏移供续流对齐。
- **定义**：延迟优化通道——内容最终形态由持久事件/记录承载，易失事件只负责"正在发生"的实时呈现；错过即错过（不可重放），其恢复由 R2 承担。
- **出现在哪里**：事件订阅协议的易失帧标记；对话渲染域规格（US2.1/US3.1/US4.1 的续流与补齐语义）；架构文档的双轨事件决策。
- **禁止的叫法**：~~临时事件~~（口语可用，规格不用）、~~流式事件~~（部分持久事件也流式到达，词面混淆）。
- **同名异义警示**：与「持久事件」相对——持久事件带游标、可重放补齐；两者同走一条连接但语义分层，读到"补齐/重放"时只对持久事件成立。

### R4 事件游标（event cursor）

- **形态**：一对值（位点 + 世代）：位点标记"已收到第几条持久事件"，世代标记"事件日志的第几代"（会话重建等使旧位点作废的时刻递增）。
- **定义**：断线重连与快照续接的**水位**——订阅携带游标则从其后补齐；世代不符或超出缓冲能力时服务端要求重新对表（重新快照）。
- **出现在哪里**：事件订阅协议的订阅/续订帧；快照的切片时刻标记；对话渲染域规格（US1.1/US4.1）。
- **禁止的叫法**：~~偏移量~~（特指易失帧的回合内对齐值，是另一个概念）、~~序号~~（过泛，与 H4 编号混淆）。
- **同名异义警示**：游标的**位点**与 R3 的**回合内偏移**是两个维度——前者是持久事件流的全局水位，后者是单回合内易失流的字符/分片对齐；两者不得互换使用。

### R5 内容块（content block）

- **形态**：一次代理响应内的有序呈现单元，种类至少含：推理（thinking）、富文本（text）、工具卡（tool）。示例：`[推理块, 富文本块, 工具卡, 富文本块]`。
- **定义**：主会话转录与成员叙事共用的**呈现内容模型**——按真实发生顺序线性排列；是渲染组件族的输入契约，不是引擎持久化格式。
- **出现在哪里**：对话渲染域的转录渲染；督导域叙事区（ADR-009，消费方）。
- **禁止的叫法**：~~消息~~（持久化与传输单位，粒度大于内容块）、~~事件~~（引擎侧时序事实，含 status/error 等非呈现内容）。
- **同名异义警示**：部分协议用 "content block" 指消息内容的原始分片（未经呈现归一化）——本文义为**呈现归一化后**的单元；引用协议原始分片时须显式限定，不得裸用。

### R6 工具卡（tool card）

- **形态**：一个工具调用在界面上的卡片呈现：图标 + 调用名 + 参数人读摘要 + 状态 + 结果输出区（可折叠）。
- **定义**：内容块中 tool 种类的渲染形态；参数/结果折叠、差异交互入口的样式与行为以对话渲染域组件为权威实现。
- **出现在哪里**：主会话转录的工具块；督导域叙事区的工具块（ADR-009，消费方）。
- **禁止的叫法**：~~调用行~~（督导域改造前的单行文本降级形态）、~~工具事件~~（引擎侧时序事实，非呈现单元）。
- **同名异义警示**：无。

## E. 执行环境域

来自执行环境域（与该域四件套基线同批登记；域内视图见 [execution-environment-requirements.md](execution-environment-requirements.md) / [execution-environment-architecture.md](execution-environment-architecture.md)）。

### E1 执行环境（execution environment）

- **形态**：agent 执行的底层环境层的统一抽象——文件、命令、终端原语面向的同一接口；实现可以是本机、远程机器或宿主桥接，上层无感知（例：把执行环境指向远程机器后，文件读写与命令执行全部发生在远程）。
- **定义**：承载 agent 全部文件系统访问、进程创建与终端仿真的运行底座——"agent 在哪台机器上干活"的答案；工作目录与运行上下文按它隔离。
- **出现在哪里**：执行环境域全套规格；工作区管理域规格（工作区运行上下文的引用）；工具调用域（工具执行原语的落点引用）；rust 内核域设计。
- **禁止的叫法**：~~运行时~~（过泛，与引擎运行时混淆）、~~宿主环境~~（宿主桥接只是其一种实现形态）。
- **同名异义警示**：与「工作区」（W1）不同——工作区是身份与资产边界的单位，执行环境是执行落点；两者常伴生但概念独立，不得互推。与「宿主集成者」语境中的"宿主"（把引擎嵌入自己产品的开发者）不同层。

### E2 附加目录集（additional dirs）

- **形态**：主工作区根之外被显式纳入允许访问范围的目录集合（工作区本地配置文件持久声明，或仅本次进程内声明）；与主根合并构成共享的允许目录集（主根 ∪ 附加目录集）。
- **定义**：路径约束的放宽机制——附加目录内的文件访问对文件类界面（文件树/读取/列举/监视/终端）与 agent 文件工具一致放行；同一工作区内全部会话共享，集合变化对已存在会话即时生效。
- **出现在哪里**：执行环境域规格（沙箱面）；工具调用域（文件工具路径守卫的"工作区边界判定"——执行环境域规格声明两侧共享同一允许目录集数据）；approval 域（工作树内写放行的判定范围——"工作区含附加目录"）；工作区管理域（域边界互引：文件沙箱归执行环境域）。
- **禁止的叫法**：~~额外目录~~（与技能域「额外目录」来源层级撞名）。
- **同名异义警示**：「允许目录集」是"主工作区根 ∪ 附加目录集"的**合并概念**（执行环境域沙箱面的正式域内名词）——本条目只是主根之外的增量部分，不得用合并概念称呼本条目；与技能域「额外目录」来源层级（SK1 的 Extra 层）不同形不同义——本条目是文件访问允许范围，那是技能发现来源，两者不得互推。命令级访问不受此目录集约束（执行沙箱面的诚实边界，见该域规格）。

## CO. 协作域

来自协作域（与该域规格修订同批登记；域内视图见 [collaboration-requirements.md](collaboration-requirements.md) §12/SDR-003 与 [collaboration-architecture.md](collaboration-architecture.md)）。

### CO1 蜂群模式（swarm 模式）

- **形态**：会话级模式开关：网页模式菜单的 Swarm 开关 / 终端 `/swarm` 命令族；手动开启后主代理收到"先探索拆解、再并行派发"的工作法指引（因批量派发进入的不注入该指引，见协作域 US8.1），界面以标签/徽标/状态面板可见。
- **定义**：让主代理以"先探索拆解、再批量派发子代理、任务尽量细分、避免成员间重复冲突"方式工作的会话姿态——手动开启跨回合保持；因单任务命令或批量派发进入的，回合结束自动退出；该模式下批量派发独占一次调用批次。
- **出现在哪里**：协作域规格（E8）；approval 域（手动权限下的蜂群启动确认、yolo/auto 的免确认差异）；后台任务域（蜂群派发的语境引用）；网页模式菜单、终端 `/swarm` 命令与状态栏徽标（用户可见文案）；会话持久化（模式状态随会话回读）。
- **禁止的叫法**：~~群体模式~~、~~swarm agent~~。
- **同名异义警示**：与「协作模式」（CO2）不同——蜂群是单用户主从派发的并行姿态（TS 已支持基线），协作模式是多 agent 团队模型的前置入口；与「批量派发」（A7 中显示名为 AgentSwarm 的工具入口）不同——蜂群是模式、批量派发是入口，批量派发可在蜂群模式外独立使用，两者不得因英文名同根互推。蜂群不改变权限语义（非权限豁免）。

### CO2 协作模式（collaboration 模式）

- **形态**：会话级模式：经显式入口（网页模式选择区的 Collaboration 开关 / 服务端的进入-退出调用对）开启；进入时整组协作工具对模型暴露，退出时收回；不持久化，重启回到隐藏态。
- **定义**：多 agent 团队协作能力的前置开关——协作工具组在成熟前默认对模型隐藏，经本模式显式 opt-in 暴露（协作域 SDR-003）；模式为会话级。
- **出现在哪里**：协作域规格（SDR-003、E5.1 的入口前提）；网页模式选择区（与 plan/goal/swarm 并列的用户可见文案）；服务端调用面（进入/退出方法）。
- **禁止的叫法**：~~团队模式~~（团队是协作域设计目标的概念；进入本模式不等于团队已组建）。
- **同名异义警示**：「协作域」指整个多 agent 团队协作领域，本条目只是其模式开关——读到"进入协作模式"指本条目；与「蜂群模式」（CO1）并列但不同（见 CO1 警示）。

## AP. 权限与审批域

来自权限与审批域（与该域基线同批登记；域内视图见 [approval-requirements.md](approval-requirements.md) / [approval-architecture.md](approval-architecture.md)；AP3 的生成语义由工具调用域文档化并拥有）。

### AP1 权限模式（permission mode）

- **形态**：三档规范名——**manual（手动）**、**auto（自动）**、**yolo**；IDE 客户端（ACP）呈现为四档（Default / Plan / Auto / YOLO——其中 Plan 同时进入计划模式并保持 manual 姿态）。
- **定义**：会话级的审批姿态档位——manual：只读与编排类内建工具自动放行、其余弹审批；auto：除用户显式 deny 外全部放行，且问询被禁用（模型被要求自行决策）；yolo：全部放行但三类仍打断（用户 ask 规则、敏感文件、git 控制路径）。模式对同会话子代理同步生效（广播）。「配置默认权限模式」不是本条目的运行时状态——它仅为新会话的初始姿态与界面初始显示（种子），运行时以会话实时模式为唯一决策源（approval 域 SDR-004）。
- **出现在哪里**：approval 域全套规格；CLI 启动参数与配置默认值；TUI 命令（/auto、/yolo、/permission）；ACP 模式列表与切换；协作域（蜂群/目标启动的模式切换选项）；后台任务域（子代理沿用派发者模式）。
- **禁止的叫法**：~~审批模式~~（审批是动作，模式是姿态档位）、~~安全模式~~（与 W4 的禁止叫法撞名）。
- **同名异义警示**：与「计划模式」不同——计划模式是只读规划的工作姿态，权限模式是放行姿态（两者可组合，见 ACP 的 Plan 档）；与「蜂群模式/协作模式」（CO 域）不同——那两个不改权限语义，本条目直接决定放行行为。

### AP2 会话级批准（session-scoped approval）

- **形态**：审批面板选项之一「Approve for this session（本会话内均批准）」；批准后为该调用的审批刻面（AP3）记录一条会话级放行记忆。
- **定义**：一次批准的放大范围——此后同刻面调用自动放行不再弹面板；记忆随会话恢复重建、**会话内跨代理共享**（子代理的调用同受覆盖）、会话结束即消亡（不跨会话留存）。
- **出现在哪里**：TUI/web/ACP 三端审批文案（Approve for this session）；approval 域规格；SDK 审批处理器的返回值之一；排队请求的自动继承语义。
- **禁止的叫法**：~~始终允许~~（那是升级为用户级规则的未来提案语义，当前不存在）、~~记住批准~~（口语）。
- **同名异义警示**：与「用户权限规则」（[permission] 配置中跨会话持久的用户级声明）不同——本条目只活一个会话；与「工作树内写放行」（manual 下的自动放行面）不同——那不需要任何用户批准动作。

### AP3 审批刻面（approval rule pattern）

- **形态**：一次工具调用被归一化后的可匹配规则串——「工具名(参数模式)」形态（例：`Bash(git*)`）；工具名支持通配，非 MCP 工具不可用通配的约束以 T5 为准。
- **定义**：权限规则匹配与批准记忆的最小单位——同刻面即同规则串；各工具如何归一自己的调用（生成语义）由工具调用域文档化并拥有，approval 域消费。
- **出现在哪里**：工具调用域（刻面生成语义与逐工具的刻面声明）；approval 域（用户规则匹配、会话级批准记忆的去重键）；用户配置的 permission 规则。
- **禁止的叫法**：~~审批签名~~、~~规则键~~。
- **同名异义警示**：「刻面」与「工具名」不同——刻面含参数主体（命令文本、路径、pattern 等），用户规则只写工具名时不做参数级匹配（任何参数都命中）。

### AP4 权限决定（permission decision）

- **形态**：一次裁决的三值——**放行（approve）/ 拒绝（deny）/ 问询（ask）**；用户规则的声明值与裁决结论共用此枚举。
- **定义**：一次工具调用在执行前的裁决结果——由固定优先序的裁决面链（模式姿态、用户规则、会话记忆、敏感路径、兜底问询）取第一个命中面得出；每次裁决产生决策遥测。
- **出现在哪里**：approval 域规格（裁决优先序）；用户配置的规则三值；引擎裁决链；工具调用域（执行前裁决链的结论）。
- **禁止的叫法**：~~审批结果~~（指审批往返的用户面结论，形态比本条目更细，不同层）。
- **同名异义警示**：与「审批往返结论」（approved / rejected / cancelled 等用户面终态）不同——本条目是规则与姿态层面的三值枚举；往返结论含取消、错误等终态，超出本条目。

### AP5 问询关闭（question dismissal）

- **形态**：问询面板的关闭动作（Esc / 关闭按钮）及其终态——回传给模型的工具结果标注「用户关闭了问询且未说明原因」（附原因输入时携带原因），回合随之终止。
- **定义**：用户对一次问询的意图不明的拒绝（可能是稍后再说 / 问得不对 / 想自己打字 / 误触），因此**不构成任何授权**——引擎终止回合、归还输入权，模型不得基于猜测继续（approval 域 SDR-005/ADR-007）。「别问了你自己定」的委托只经 auto 模式显式表达。语义是「暂不回答」而非「永久拒绝」——后续可换方式重问，禁止原样重问。后台问询被关闭时任务取消定局、通知送达，发起代理停止依赖该答案的决策但不打断无关工作。
- **出现在哪里**：approval 域规格（US8/US10/SDR-005）；architecture ADR-007；工具调用域（问询工具的结果契约）；TUI/web/桌面端的问询面板关闭交互。
- **禁止的叫法**：~~跳过~~（skip 是逐题跳过、部分作答仍回传已答部分，关闭是整次问询作废）、~~拒绝回答~~（拒绝指向具体选项的否定选择）。
- **同名异义警示**：与「逐题跳过」（某题不出现在答案记录，问询整体仍完成）不同——关闭是整次问询交互的终结；与「auto 模式问询拒绝」（引擎策略拒绝，模型被指引自行决策）不同——那是显式委托，本条目恰恰不构成委托。

## SK. 技能域

来自技能域（与该域基线同批登记；域内视图见 [skills-requirements.md](skills-requirements.md) 与 [skills-architecture.md](skills-architecture.md)）。

### SK1 技能来源层级

- **形态**：模型可见技能清单的分组层名——**项目级（Project）/ 用户级（User）/ 额外目录（Extra）/ 内置（Built-in）** 四层；发现优先级为 项目 > 用户 > 额外 > 插件 > 内置（插件托管技能在清单中归入「额外」层展示），同名冲突取更具体来源。
- **定义**：技能的发现来源分层——按作用域从"仅本项目"到"随产品分发"递减特异性；模型据清单分组向用户解释同名技能的来源与消歧。
- **出现在哪里**：系统提示词的技能清单（模型可见文案，按 Project/User/Extra/Built-in 分组）；配置文件的技能目录声明；网页设置开关；技能域全套规格。
- **禁止的叫法**：~~作用域~~（泛）、~~技能目录层级~~（目录是数据结构，层级是来源语义）。
- **同名异义警示**：与 MCP 域「配置来源层」（W2，用户全局/项目根/项目本地/插件四层）是平行的两套分层——一个分层技能来源、一个分层 MCP 服务器配置来源，层名不同、不得互推；「额外目录」（Extra）与执行环境域「附加目录集」（E2）不同义（见 E2 警示）。

### SK2 技能激活（skill activation）

- **形态**：一次激活 = 技能全文以统一「技能已加载」包裹块注入对话 + 一条激活事实（技能名、触发方式、类型、路径、来源、参数）；触发方式四态：用户斜杠 / 用户消息内联 / 模型工具 / 嵌套。
- **定义**：技能全文进入模型上下文的唯一路径——常驻的只有清单，全文按需在激活时注入；激活事实是会话记录中的一等记录，回放重建激活卡片而不重复触发副作用。
- **出现在哪里**：技能域全套规格；传输契约的激活记录族与激活事件；TUI/web 的激活卡片与斜杠命令；会话管理域（激活是撤销锚点——与其后对话构成可撤销单元）；对话渲染域（激活卡片投影）；工具调用域（Skill 工具与技能调用展示类别）。
- **禁止的叫法**：~~技能调用~~（口语可用；规格中指模型经 Skill 工具发起这一种触发方式）、~~加载技能~~（无主语，分不清入口）。
- **同名异义警示**：与「插件会话启动注入」不同——那是引擎在会话装配时的注入（不经用户或模型主动发起，也不计为激活事实的触发方式四态）；「技能调用遥测」只记真实激活，回放不重复。

### SK3 插件（plugin）与 marketplace

- **形态**：插件 = 一个可安装、可信任、可升级的单元（一份 manifest 声明其全部贡献面：技能、斜杠命令、MCP 服务器声明、hooks 声明、角色目录、系统提示词段）；marketplace = 插件目录（一份 JSON 清单，官方/精选/第三方分级）。
- **定义**：技能与指令的主要分发宿主——安装后从托管副本运行；停用即全部贡献面失效、重新启用恢复；marketplace 是发现与一键安装的目录面。
- **出现在哪里**：技能域全套规格（插件系统 Epic）；MCP 域（插件对 MCP 服务器的声明与启停管理）；角色域（插件托管的角色目录来源）；TUI/web 的插件管理面板、信任徽章与更新徽章。
- **禁止的叫法**：~~扩展~~（泛）、~~addon~~。
- **同名异义警示**：「插件层」在 MCP 域指配置来源层之一（W2）——插件自带的 MCP 服务器声明落在该层；本条目是插件单元本体，两者是"物"与"其配置落点"的关系，不得混用。

### SK4 技能启停（user-level skill enablement）

- **形态**：用户级配置键 `disabled_skills`（TOML 顶层字符串数组，只记**禁用**名，缺省/空 = 全启用）+ 管理写面 `skill.setEnabled`（逐名启停，未知名答 `registered:false` 不写配置）。
- **定义**：用户对单个技能的逐项停用——被停用技能仍出现在目录与管理列表（状态可见），但模型侧（Skill 工具）、用户侧（斜杠激活）与清单消费面全部拒绝调用；跨 workspace 生效（用户级，不是会话级）。
- **出现在哪里**：技能域全套规格（B8 管理面）；rust 引擎 config.toml 顶层键与 config wire `disabledSkills`；`skill.list` 行的 `enabled` 字段；web 设置技能页的开关。
- **禁止的叫法**：~~技能开关持久化进会话~~（不是会话状态域）、~~删除技能~~（禁用不是卸载）。
- **同名异义警示**：与「工具面管理」`tool.setUserToolEnabled`（会话级、写 session wire log）不同——本条目是用户配置（rust 侧不进 wire log，恢复路径 = 装配种子 + config 写后 resync）；与插件域「插件停用」（整个插件全部贡献面失效）粒度不同，本条目精确到单个技能名。

### SK5 插件限定名（plugin-qualified skill name）

- **形态**：`插件id:技能名`（单冒号两段，例 `superpowers:subagent-driven-development`）——技能调用引用（Skill 工具参数、程序接口激活技能名）的容错形态（解析语义见技能域 ADR-001）。
- **定义**：携带插件归属的技能引用写法，供插件技能文档交叉引用（生态惯例）——使按文档指引的调用不因命名形态而失败；与清单裸名调用等效，非主名（清单与呈现始终用裸名）。
- **出现在哪里**：技能域规格（US4.2/US3.3、ADR-001）；工具调用域 Skill 工具参数契约（名称解析说明）；插件技能文档与从其他生态导入的技能正文（外部引用面）；插件命令的同构命名 `/插件id:命令名`（US6.6）。
- **禁止的叫法**：~~带命名空间的技能名~~、~~限定技能引用~~、~~插件前缀技能~~（同一概念多叫法易漂移，规格内统一「插件限定名」）。
- **同名异义警示**：与 MCP 工具的单冒号旧形态 `mcp:<server>:<tool>` 无关（T5 已明确该形态属已退役旧服务层，技能域不使用 `mcp:` 前缀）；与插件命令 `/插件id:命令名` 是**同构不同面**——一个限定技能引用、一个限定斜杠命令名，形态相同但作用面不同，不得互推；与用户斜杠的 `skill:` 命令前缀（`/skill:技能名`）完全不同——那是命令入口前缀，不是命名空间。

### SK6 技能触发符（skill trigger symbol）

- **形态**：`$`（及其全角等价 `¥` / `￥`）置于光标所在的词首位置（输入串首位，或紧随空白字符之后）且尚未出现空格——唤起**纯技能候选**菜单的输入约定；选中后依输入框状态回填：为空时回填规范斜杠命令（`/skill:技能名 ` 等）供追加参数，已有内容时在光标处插入技能引用链接（SK7）的芯片；触发符本身不构成执行语法（`$` 开头文本直接发送 = 普通消息）。
- **定义**：输入框中直达技能候选的专用唤起符，与 `/`（全部可操作选项：命令 + 技能，分组呈现）互补；全角等价为中文输入法免切换英文态而设计；词内位置不触发（防代码/路径中的 `$` 误弹）。
- **出现在哪里**：技能域规格（US3.4、US3.6、SDR-003/SDR-005）；网页与终端输入框的触发判定与候选菜单；用户输入本身。
- **禁止的叫法**：~~技能命令前缀~~（与命令命名语法 `skill:` 混淆）、~~美元前缀~~。
- **同名异义警示**：技能正文中的 `$` 参数占位符（`$ARGUMENTS` / `$1` / `$<参数名>`，技能域 US1.3）是技能体内文本展开语法，与本条目（输入框触发符）无关；命令执行语义中 `$` 不参与任何解析——触发符只作用于输入候选的唤起，不进入消息解析路径。

### SK7 技能引用链接（skill reference link）

- **形态**：消息正文中的行内链接，链接文字以触发符前缀 + 技能/命令展示名（如 `[$brandkit](/Users/…/brandkit/SKILL.md)`）——消息内联引用技能或斜杠命令的唯一底层载体；输入中与发送后由客户端渲染为内联芯片（统一技能图标 + 名称，技能域 US3.5/US3.6）。
- **定义**：用户在一条消息中激活多个技能/命令的引用单元——消息正文自身即唯一事实源（不依赖独立的结构化字段）；解析与激活判定的规格见技能域 US3.6 与架构文档 ADR-004（正文中的普通 markdown 链接不是本条目）。
- **出现在哪里**：技能域规格（US3.6、SDR-005）；网页输入框的芯片渲染与消息气泡呈现；会话历史持久化与回放（其他客户端降级为普通链接文本）。
- **禁止的叫法**：~~内联技能标记~~、~~技能 mention~~（同一概念多叫法易漂移，规格内统一「技能引用链接」；「内联引用块」是其在输入框/消息层的呈现侧口语，指同一载体）。
- **同名异义警示**：与普通文档链接不同——本条目是被引擎解析的执行单元，普通 markdown 链接是纯文本；与 SK6 技能触发符不同——触发符是输入框唤起候选的辅助符（不进入消息解析路径），本条目是消息文本内的载体本身。


## NF. 非功能域

来自非功能域（与该域基线同批登记；域内视图见 [non-functional-requirements.md](non-functional-requirements.md) 与 [non-functional-architecture.md](non-functional-architecture.md)）。

### NF1 遥测事件（telemetry event）

- **形态**：一条事件 = 事件名 + 数值/字符串/布尔基础类型属性 + 匿名身份（设备标识、会话标识）+ 环境上下文；非基础类型属性静默丢弃；每事件有全局唯一编号。
- **定义**：产品方对使用情况的匿名观测单元——不含对话内容、代码内容、文件路径等业务数据；遥测关闭即不采集、不缓冲、不发送。
- **出现在哪里**：非功能域全套规格（遥测与隐私 Epic）；各业务域的域内遥测面（审批决策、技能激活、登录/刷新、压缩、子代理、工具耗时等事件族——各域只定义"哪些事件必须可观测"，命名与上报归遥测面）；遥测上报请求与暂存。
- **禁止的叫法**：~~埋点~~（口语；且"埋点位置"易与代码事实混淆）、~~追踪事件~~（tracking 暗示用户级追踪，与匿名原则相悖）。
- **同名异义警示**：与「会话日志（wire journal）」正交——遥测外发给产品方、会话日志本地留存；与各域产品内"事件"（wire 事件、状态事件）不同——本条目专指匿名上报的观测事件。

### NF2 设备标识（device id）

- **形态**：首次使用时随机生成并本地持久保存的匿名标识（文件权限仅限本人）；与每次会话新生成的会话标识配对，构成遥测仅有的两个身份标识。
- **定义**：遥测的匿名设备级身份——不采集姓名、邮箱、IP 等个人身份信息。
- **出现在哪里**：非功能域规格（匿名身份条目）；遥测上报请求的携带字段。
- **禁止的叫法**：~~设备指纹~~（暗示可追踪识别，与匿名原则相悖）、~~机器码~~。
- **同名异义警示**：认证域另有「设备 ID / 设备身份」——那是授权请求携带的设备身份头族（设备名、型号、系统版本等，见 auth-oauth 域），用途与归属不同；读到"设备 ID"先按语境归位（遥测语境 → 本条目；登录授权语境 → 认证域）。

### NF3 步级重试（step retry）

- **形态**：模型请求级的自动重试——按退避策略（默认最多 10 次尝试、等待指数翻倍封顶、带随机抖动），仅对临时性错误（限流、服务端 5xx、超时类、可降级的过大请求）生效。
- **定义**：「一步」（回合内单次模型请求，S7）失败后的恢复机制——临时故障自动重试不打扰用户，不可重试类（配额耗尽、鉴权失效）立即失败；模型流中断没有流级自动重连，恢复统一走本条目。
- **出现在哪里**：非功能域规格（临时故障自动重试条目）；会话管理域（「一步」的回合内子单元定义，S7）；模型错误遥测的可重试性标记。
- **禁止的叫法**：~~自动重连~~（那是连接层恢复，模型流不走）、~~指数退避~~（那是策略细节，不是本条目名）。
- **同名异义警示**：与「断线自动重连」（网页连接层恢复）不同——本条目只在模型请求级；与「批量派发的限流重试」（后台任务域，按任务成员排队重试）不同层——那个按成员，本条目按模型请求。

### NF4 转录滑动窗口（transcript window）

- **形态**：界面保留最近 N 个回合（默认 15，附迟滞余量防抖动）+ 回合内较早步骤合并为摘要 + 最近若干回合可展开——超窗内容整块从界面释放。
- **定义**：用户界面（转录呈现侧）内存与节点占用的有界机制——只影响界面常驻呈现，不影响会话记录与模型可见历史（两者另有各自的留存与投影规则）。
- **出现在哪里**：非功能域规格（长会话资源有界条目与全局等待/上限索引——呈现语义归对话渲染域）；对话渲染域（转录 S6 的呈现面）；终端与网页界面。
- **禁止的叫法**：~~上下文窗口~~（那是模型容量，C2 警示）、~~消息分页~~（分页是滚动取回更早历史，窗口是界面侧有界保留）。
- **同名异义警示**：与「保留尾」（C2，压缩时的模型侧保留策略）不同——本条目只修剪界面呈现；与 S6「转录」的全量承诺不矛盾——转录数据全量（记录与回放可取回），界面常驻窗口有界。

## AU. 认证域

来自认证域（与该域基线同批登记；域内视图见 [auth-oauth-requirements.md](auth-oauth-requirements.md) §0 术语表与 [auth-oauth-architecture.md](auth-oauth-architecture.md)——授权页地址、失效墓碑等其余术语为域内私有，不入本表）。

### AU1 托管账户登录（managed:mirri-code）

- **形态**：平台 OAuth 账户登录的规范名；配置中 provider 以 `managed:mirri-code` 标识，令牌由客户端保管。
- **定义**：经平台 OAuth（设备码流）完成的用户身份登录——与直接使用平台 API key 的认证方式互斥并存；登录成功触发托管 provider 与模型目录的装配。
- **出现在哪里**：认证域全套规格；持久化配置的 providers 键（共享面）；REST 契约；TUI/web 登录文案（用户可见层允许品牌名，规格内部统一用本规范名）；模型设置域（登录后装配的消费方）。
- **禁止的叫法**：~~Mirri OAuth 登录~~、~~kimi 登录~~（规格内部；用户可见文案允许品牌名）。
- **同名异义警示**：与 MCP 服务器的 OAuth 授权（mcp 域，远程服务器自身的授权流）协议与生命周期互不相干——本条目是平台账户登录；与服务访问鉴权（本地守护进程自身的访问凭证）不同层。

### AU2 OAuthRef（凭证槽引用）

- **形态**：配置中 provider/模型条目引用一份登录凭证的声明——指向一个凭证槽（存储方式 + 槽键，可选授权主机）；槽键形态如 `oauth/mirri-code`。
- **定义**：配置与凭证存储之间的解耦引用——登录写入哪个槽、运行时读哪个槽，由同一推导规则得出（写入的槽永远等于读取的槽）；不同环境（授权主机 + 服务地址组合）各占一个槽，互不串用。
- **出现在哪里**：认证域全套规格；持久化配置 provider/model 条目的 oauth 字段（共享面）；传输契约。
- **禁止的叫法**：~~账户~~（一个账户可在多环境各有一槽）、~~profile~~（与 agent-profile 域撞名）。
- **同名异义警示**：「凭证槽」是存储位置本体（认证域域内术语），本条目是配置中指向它的引用——读到"oauth 引用"指本条目，读到"槽"按该域语境归位。

### AU3 设备码（device code）

- **形态**：授权服务器发放的一次性用户码（形如 `ABCD-1234`），用户在另一设备的授权页输入以完成授权；配对一个已内嵌码的授权页地址。
- **定义**：设备码授权流（RFC 8628）的人机接力点——无浏览器一侧展示码与地址，有浏览器一侧输入码完成登录。
- **出现在哪里**：认证域全套规格（登录发起与设备码协议 Epic）；CLI/TUI/web 登录界面的用户可见文案；REST 契约的登录流字段。
- **禁止的叫法**：~~验证码~~（易与 2FA 混淆）。
- **同名异义警示**：授权页地址（已内嵌设备码、打开即免手动输入的链接）是配套物，不是本条目；认证域域内另有完整术语表（授权页地址、失效墓碑等域内私有术语见该域 spec §0）。

### AU4 认证就绪门（auth readiness gate）

- **形态**：发起会话/请求前的就绪判定：至少一个 provider + 默认模型可解析到 provider +（若存在托管 provider）其凭证未被判失效；三类失败分别对应三个可行动错误。
- **定义**：引擎级的认证就绪校验——不通则不发起模型调用；错误公开、不可重试、附用户行动建议（如指引登录命令）。
- **出现在哪里**：认证域规格（状态呈现与就绪门 Epic）；就绪快照接口与 web 首屏登录门（共享面）；TUI 欢迎页提示。
- **禁止的叫法**：~~登录墙~~（web 登录门禁是本条目在 web 端的整页呈现，不是门本身）、~~鉴权中间件~~。
- **同名异义警示**：与「服务访问鉴权」（守护进程自身的 bearer token / 密码）不同——本条目校验用户身份就绪，不校验服务访问凭证。

### AU5 终端认证（terminal-auth）

- **形态**：ACP 协议发现面的一等认证方法名（名称 `Login with Mirri account`）——IDE 宿主经协议发现后即可在终端拉起设备码登录；另保留传统描述供旧宿主回退。
- **定义**：IDE 宿主复用 CLI 终端登录入口的协议面——宿主不需要自带登录界面。
- **出现在哪里**：认证域规格（ACP 宿主登录条目）；ACP 协议的认证方法发现（共享面）。
- **禁止的叫法**：~~终端登录协议~~（不是独立协议，是 ACP 协议内的方法）。
- **同名异义警示**：与「CLI 子命令登录」（终端 `mirri login`）是同一登录流的两个入口形态——本条目是宿主经协议发现拉起的那个入口的规范名。

## SV. 督导域

来自督导域 v1 基线（2026-09-14 同批登记；域内视图见 [agent-supervision-requirements.md](agent-supervision-requirements.md) §1 与 SDR-001/002）。

### SV1 委托（delegation）

- **形态**：主 agent 把一段工作交给子 agent（A3）执行的行为的统称——涵盖单个派发工具调用与蜂群模板批量派发；界面呈现为同一种委托卡片（N=1 或 N 成员）。
- **定义**：用户视角的"把活交出去"心智单元：委托在对话区占一行摘要卡片，过程细节在详情面板（渐进披露的起点）。
- **出现在哪里**：督导域规格全部条目；conversation-rendering 域（工具卡片呈现）；subagent 域（派发语义，本条目不重定义派发——委托是派发的用户界面心智名）。
- **禁止的叫法**：~~外包~~、~~派任务~~（口语）；~~子任务~~（指被派发的工作本身，不是这个行为）。
- **同名异义警示**：与 A6「续作」区分——续作是对既有委托的继续，不是新委托。

### SV2 督导（supervision）

- **形态**：用户对被委托/自主运行的 agent 的三类活动的统称：观测（实时查看 + 事后回看）、控制（停止/暂停/审批）、干预（定向指令）。
- **定义**：本仓库督导域的域名与能力坐标轴——三轴与呈现三层（摘要/聚焦/深挖）正交。
- **出现在哪里**：督导域规格；collaboration 域 E5（团队观测）的界面承接关系；后续 subagent 域呈现条目。
- **禁止的叫法**：~~监控~~（只覆盖观测轴，丢失控制与干预）、~~管理~~（与配置管理混淆）。
- **同名异义警示**：不指引擎内部的资源管理（并发上限/超时等生命周期语义归 subagent 域）——督导只描述用户侧的看/管/介入。

## CI. 上下文注入域

来自上下文注入域 TS 能力基线（2026-09-16 同批登记；域内视图见 [context-injection-requirements.md](context-injection-requirements.md)）。

### CI1 系统提醒（system reminder）

- **形态**：一条追加在对话末尾的补充消息，正文包裹在 `<system-reminder>` 权威指令标记中，以用户侧消息角色投递但绝不冒充用户原话；模型收到的系统提示中已声明该标记为必须遵守的系统指令。
- **定义**：引擎向模型传达运行时状态与权威指令的统一旁路通道——区别于驱动回合的"异步唤醒源"（L1，消息要参与回合准入调度）与静态系统提示（画像域一次性组装）；系统提醒只需"在场"，不驱动调度。
- **出现在哪里**：上下文注入域全套规格；goal/approval/skills/multimodal/subagent/collaboration/tool-calling 各域的变体注入均经此通道；wire 会话记录中带注入来源标识的消息。
- **禁止的叫法**：~~系统消息~~（易与消息角色 system 混淆——信封内容以用户侧角色投递）、~~提示注入~~（安全语境下指对模型的攻击手法，语义完全相反）、~~唤醒~~（那是 L1 的调度语义）。
- **同名异义警示**：与工具侧 `<system>` 补充标记（嵌在工具结果内的次级信息）不同——系统提醒是权威指令信封，`<system>` 是工具侧补充说明；两者构成"权威/补充"双信封体系。

### CI2 注入变体（injection variant）

- **形态**：注入来源标识中"注入"这一类别的细分名（如目标提醒、计划模式提醒、待办列表提醒各是一个变体）；一个变体名对应一类可重复注入的内容。
- **定义**：注入物的去重、节流与位置记账的最小单位——框架按变体名记账历史注入位置，提供者按变体决定"本步是否再注入"。
- **出现在哪里**：上下文注入域（框架契约）；各业务域声明自己的变体并拥有其内容语义。
- **禁止的叫法**：~~注入类型~~（与消息角色类型混淆）、~~提醒类型~~（变体覆盖非提醒形态的注入，如裸消息注入）。
- **同名异义警示**：变体是来源的细分，不是内容的版本号——同一变体多次注入内容可以不同（如待办列表当前值）。



## UV. 用量可见性域

来自用量可见性域建域批次（2026-09-17 同批登记；域内视图见 [usage-visibility-requirements.md](usage-visibility-requirements.md)）。

### UV1 缓存命中率（cache hit rate）

- **形态**：百分比，会话级整数精度、回合级一位小数；部分命中在目标精度下会舍入到 100 时自动加深精度（如 `99.9%`），真实全命中才显示 `100%`。
- **定义**：一个统计范围（会话或单回合）的**计费输入（UV2）中享受缓存折扣的比例**——分子是缓存读取，分母是计费输入；输出不进分母。它回答"输入账单打折了多少"，与"上下文还剩多少"（占用率）是两个指标两个家。
- **出现在哪里**：web 会话统计条与回合用量明细；TUI footer 统计段；用量可见性域全部规格。
- **禁止的叫法**：~~缓存利用率~~（暗示容量资源视角，与账单视角混淆）、~~命中率（无"缓存"前缀的裸用）~~（与检索/匹配类命中率混淆）。
- **同名异义警示**：与上下文占用率（当前上下文规模相对窗口上限）完全不同——占用率回答空间余量，命中率回答账单折扣；两者禁止合并进同一展示组。

### UV2 计费输入（billed input）

- **形态**：三个互斥构成之和：未缓存输入 + 缓存读取 + 缓存写入；展示为精确或紧凑 token 计数。
- **定义**：一个统计范围内 prompt 侧实际被计价的全部 token——缓存命中率（UV1）的分母；与上下文压缩域的压力口径同源（压力 = 计费输入 + 输出）。
- **出现在哪里**：web/TUI 用量展示的"输入"数字；用量可见性域规格；上下文压缩域的压力计算。
- **禁止的叫法**：~~输入 token（作为总量使用）~~（与三桶中"未缓存输入"这一构成同名冲突——裸"输入"在用量语境下必须能归位到本条目，指构成时必须带限定词"未缓存"）。
- **同名异义警示**：传输契约上"未缓存输入"字段（三构成之一）与日常说的"输入"（本条目总量）是包含关系，不是同义词——统计条上显示的"输入 N tok"是本条目总量。
