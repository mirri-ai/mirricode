## 1. 服务与职责分层（TS v2 基线）

工作区能力在 App 层组织为一组协作服务，全部围绕单一持久化文件（工作区注册表）：

| 服务 | 职责 |
|---|---|
| **工作区目录服务** | 注册表的业务面：列出（含会话数投影）、注册/触摸（幂等，校验路径存在且为目录）、改名（仅显示名）、移除（软删 + 删除标记） |
| **注册表持久化** | 读写磁盘上的跨引擎名单文件（原子写、损坏容错降级、删除标记往返保留） |
| **别名解析服务** | 把一个工作区编号展开为同根目录的全部拼写编号集合（供过滤/计数/刷新折叠） |
| **工作区会话服务** | 按工作区取会话计数（非归档）与最近会话（有上限） |
| **信任服务** | 读取/翻转一个工作区的信任状态（存储在工作区数据之外、按身份键独立成档） |
| **生命周期服务** | 把一个工作区引用物化为运行时句柄（幂等并发收敛；句柄随 App 存续，不单独关闭） |

设计要点（动机抽象）：
- **注册表是唯一身份源**：会话索引只是读模型；索引可丢弃重建，重建不改变身份与计数口径。
- **写路径串行化**：目录服务的全部写操作经进程内互斥队列串行，避免同进程交错写坏名单。
- **一次性历史对账**：进程首次操作时与旧版会话清单文件对账（无可用于名单则按会话工作目录重建；有则只并入未知目录），此后依赖手动刷新观察外部写入者。
- **信任是独立文档**：信任状态不写入注册表（注册表是跨引擎共享的身份文件，不承载单引擎语义）；文档存在即信任、删除即撤销、缺失/读失败按未信任处理。

## 2. 身份派生（跨引擎一致性）

工作区编号由根路径**确定性派生**，不依赖注册顺序或注册方。派生采用**双键结构**——编号键与比较键职责分离，二者不得混用：

- **编号键（身份铸造）**：路径仅做两类词法归一——反斜杠归一为正斜杠、去尾斜杠——随后对**大小写保留**的路径做哈希，得 `wd_<路径 slug>_<哈希前 12 位>`。编号铸造**不折叠 Windows 大小写**：`C:\Foo` 与 `c:\foo` 会得到**两个不同编号**。
- **比较键（同目录判定）**：在编号键的归一之上，对 **Windows 形态（盘符/UNC）整体小写**；用于"是否同一目录"的一切判定——注册复用（重复添加时找回既有条目）、重建去重、别名折叠的代表选择。比较键只参与判定，**永不改写已铸造的编号**。
- **别名的成因与折叠**：正因编号键不折叠 Windows 大小写（以及历史符号链接等形态），同一目录可在名单与索引中存在多个编号拼写——Windows 盘符大小写是现网别名分叉的主要成因。别名集 = 从注册表 + 旧版会话清单两处收集到的、同根目录的全部编号拼写（同目录判定用比较键）；折叠时取规范派生编号为代表（显示/对外身份），集合内全部编号参与查询展开。

> Rust 实现警示（对齐红线）：若在编号派生阶段提前折叠 Windows 大小写，将与全部既有 TS 侧名单行/存储桶/索引行**编号不兼容**——恰恰制造出第二套身份，违反 §7 的同名同义约束。

## 3. 注册表文件形状

```
<数据根>/workspaces.json
{ "version": 1,
  "workspaces":   { "<编号>": { root, name, created_at, last_opened_at } },
  "deleted_workspace_ids": [ "<编号>", ... ] }
```

- 读写经原子文档存储（临时写 + 原子替换）；损坏/缺失时按"无可用于名单"降级（触发重建），不阻断启动。
- `deleted_workspace_ids`（删除标记）是删除语义的一部分：写侧保留（不被后续写冲掉）、读侧过滤（已删行不出现）。
- **并发边界（SDR-005）**：TS 侧写法为整文档替换、无跨进程锁、不合并——与本引擎（Rust）交错时存在残余覆盖窗口（详见 rust-core-design §2.3 与需求 US6.1 的声明）。

## 4. REST 契约（基线 + 本域裁决扩展）

| 方法 | 语义 | 备注 |
|---|---|---|
| `GET /workspaces` | 全注册表 + 每行会话数（折叠别名集）；**返回序 = 注册表插入序**（现网无排序语义——"最近使用在前"为 Rust 目标语义见 §7；网页端现自行按最近使用排序） | 基线 |
| `POST /workspaces` | 注册/触摸：路径必须存在且为目录；幂等（同根触摸不重建、名称保留、删除标记清除） | 基线；隐式注册路径复用同一语义 |
| `PATCH /workspaces/{id}` | 改显示名 | 基线 |
| `DELETE /workspaces/{id}` | 从注册表移除（软删：删除标记 + 数据保留） | 基线 = "仅移除"模式 |
| `DELETE /workspaces/{id}`（**模式参数：purge**） | **物理删除**：会话目录 + 索引条目清除，不可恢复 | 〔设计增强 · SDR-001〕：删除调用携带模式参数（`purge` / `remove`），两模式共用软删的标记语义 |
| `POST /workspaces/{id}/refresh` | 重扫磁盘会话入索引：先失效服务缓存（外部写入者可见），别名集展开后逐桶收敛 | 基线 |
| `GET /workspaces/{id}/trust` | 读信任状态 | 基线（网页端入口缺失，见需求 US4.2） |
| `POST /workspaces/{id}/trust` / `untrust` | 翻转信任 | 基线；翻转触发项目层配置热重载 |

会话面（消费关系，形状归会话域）：`GET /sessions?workspace_id=` 按持久化的会话归属列匹配，查询前先做别名集展开；`POST /sessions` 显式指定工作区时校验存在且与目录一致，未注册目录隐式注册。

## 5. 信任门控点（gate 位置）

信任检查发生在**配置加载阶段**，不是连接复用阶段：

- 项目层 MCP 配置的两个加载点（初始化 / 文件或信任翻转触发的热重载）以信任状态为开关：未信任 → 跳过团队共享层与本机项目层两个文件，用户全局层与插件层不受影响。
- 项目层配置的**写入口**同样被门控：未信任时对项目层配置的写入请求被拒绝。
- 〔设计增强 · SDR-002〕Rust 侧门控范围扩大：项目说明注入（AGENTS.md 项目段）同样受门控——TS 现网无此门。
- 撤销信任与授予对称：撤销后热重载即断开项目层连接（不等待重启）。

## 6. 会话归属与派生展示

- **归属确立**：会话创建时持久化其工作区编号（由工作目录派生）；跨重启以持久化列为准。
- **列表过滤**：`workspace_id` 参数经别名集展开后做集合匹配。
- **客户端分组兜底**：界面分组优先按"注册工作区根 = 会话工作目录"匹配，其次会话自带归属，最后以工作目录本身派生（派生工作区）——保证索引/注册表缺失时列表仍可用。
- **派生工作区的隐藏**：移除工作区时界面记录隐藏集合（按根路径），防止派生逻辑让已移除工作区复活；隐藏是**浏览器本地**语义（不同浏览器各自记忆），服务端删除标记是全局语义，两层独立生效。

## 7. 多工作区运行时（Rust 目标，消费关系声明）

一进程多工作区、注册先行 + 惰性构建、宿主钉扎、会话寻址路由、注册表写并发策略、注册表之上的工作区 CRUD——完整设计见 [rust-core-design/08-multi-workspace.md](rust-core-design/08-multi-workspace.md)（ADR D1-D8，2026-09-11 全部裁决）。本域架构与其关系：

- 身份派生（§2）与注册表文件形状（§3）与该设计共享同一规范——两侧实现必须同名同义，不允许第二套身份。
- 本域契约表（§4）即该设计契约语义的域内投影；执行计划见 [rust-core-design/plans/08-multi-workspace.md](rust-core-design/plans/08-multi-workspace.md)（W1-W9），状态在 [rust-core-design/ROADMAP.md](rust-core-design/ROADMAP.md) 1.8。

## 8. 边界与邻域

| 邻域 | 边界 |
|---|---|
| 会话管理域 | 工作区**排序/置顶/拖拽固化**（含顺序文档与列表分层返回）归该域；本域只提供身份与计数 |
| 会话持久化域 | 注册表文件的存储原语、桶布局、索引读写模型归该域；本域定义其上的业务语义 |
| MCP 域 | 三池架构、连接生命周期归该域；本域只定义信任门对项目层的开关 |
| 执行环境域 | 文件沙箱/路径校验归该域；本域只提供"工作区根"作为沙箱锚点 |
| rust 内核域 | 引擎内部结构（管理器组织、路由缝）归 rust-core-design；本域不重复 |
