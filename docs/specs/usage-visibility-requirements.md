# 用量可见性（usage-visibility）— 需求规格

> 2026-09-17 建域。随批登记三条需求裁决：SDR-001（缓存命中率口径）、SDR-002（会话级统计聚合范围含子代理）、SDR-003（缓存写入行的展示条件）。
> 参考设计：DeepSeek Harness 的双展示面（会话统计条 + 回合用量明细）调研，现状证据与差异分析见 [usage-visibility-context.md](usage-visibility-context.md)。

## 1. 范围与边界

**本域覆盖**（用量与缓存命中率的「看得见」闭环）：

1. **会话级用量统计的常驻展示**：会话进行中，用户随时能在输入区附近看到一组不随内容滚动、不受历史裁剪影响的累计数字（缓存命中率、按计价档位拆分的输入构成、输出 token、回合/步数计数）。
2. **回合级用量明细的按需展示**：单个回合结束后，用户能查看该回合的精确用量（各输入构成、输出、模型归属、命中率）。
3. **缓存命中率与用量构成的指标语义**：每个数字回答什么问题、怎么计算、精度与诚实性规则（何时出现、何时必须消失、何时不许四舍五入）。
4. **可编程消费面**：SDK / 客户端开发者通过用量查询接口拿到同样口径的分组累计数据。

**本域不覆盖**（引用相邻域，防重叠）：

| 相邻主题 | 归属 | 本域引用方式 |
|---|---|---|
| 上下文占用率（当前上下文规模相对窗口上限）的展示 | 各宿主既有展示位 | 本域**不占用、不合并**该事实——「一个事实只有一个家」：占用率回答「窗口还剩多少」，命中率回答「输入账单打折了多少」，是两个指标两个家 |
| 上下文压缩的触发与决策 | 上下文压缩域 | 本域的命中率分母与压缩压力口径**同源**（同一组输入构成），但用途是计费展示，不是压缩决策 |
| 用量数据的产生与传输 | rust 内核域（传输契约） | 本域消费既有的每步用量上报，不改动其形状 |
| 回合的渲染结构（回合块、操作行） | 对话渲染域 | 本域的回合级入口（胶囊）挂在其渲染结构上，不改变回合本身的呈现 |
| 货币换算 / 成本金额展示 | — | 本域只展示 token 量与比率，不做任何「约 $\$X$」的换算（价格表与汇率不在职责内，避免呈现不保证的数字） |
| 用量上报的采集机制（各供应商怎么报数） | rust 内核域 | 见 SDR-003：本域只消费「该供应商报不报某个桶」这一事实，并在展示层如实区别对待 |

## 2. 用户画像

- **P1 终端用户**：在终端里跑长会话；关心「这个会话烧了多少 token」「我的缓存策略有没有生效」，展示空间窄、无点击交互。终端呈现面重建时沿用本域的口径与组序。
- **P2 网页用户（web）**：通过网页客户端使用；可以接受更丰富的按需交互（胶囊 + 弹窗）。
- **P3 SDK / 客户端开发者**：以 SDK 内嵌引擎或自建客户端；需要编程拿到与界面同口径的用量数据。

## 3. 用户故事与验收标准

### US1 会话级统计常驻展示

**US1.1 显示内容与位置**

- 假如 一个会话内已有至少一次模型请求成功完成，当 用户查看输入区附近的常驻统计条，那么 能看到按 `|` 分隔的分组：回合/步数计数、**缓存命中率 X%**、**冷启动后命中率 X%**（条件出现，见 SDR-004）、**按计价档位拆分的输入构成**（缓存读取 / 未缓存输入 / 缓存写入，各自独立成段）、**输出 M tok**。
- 输入构成以三段呈现，**不提供三桶合计的单一「输入」数字**（见 SDR-005）；命中率百分比仍是那三段之和上的比率。
- 统计条中的各项计数一律采用精确千分位（如 `1,193,119`），不舍入为 `1.2M`：这些数字的用途是判断花在哪个计价档位，近似值会让用户误判金额量级。回合胶囊采用紧凑格式（那里是入口标签，一步可达逐桶明细）。
- 一段完整的统计条形如：`3 回合 · 12 步 | 缓存命中 93.92% | 冷启动后 97.21% | 缓存读取 1,120,576 | 未缓存输入 72,543 | 输出 38,210`（该会话累计写入为零，故写入段不出现）。
- 假如 统计条宽度不足以完整显示，那么 按价值从低到高逐组丢弃：先舍回合/步数计数与冷启动后命中率，再舍输出段，再舍输入构成三段（顺序为缓存读取 → 未缓存输入 → 缓存写入）；「缓存命中率」与「未缓存输入」两组始终保留——前者回答折扣比例，后者是全额计费的真实成本。任何情况下都提供查看完整内容的途径（web：悬停提示）。

**US1.2 显示条件（出现与消失对称）**

- 假如 会话刚开始、尚无任何模型请求完成，那么 统计条整体不出现。
- 假如 会话内全部请求都失败（没有任何计费输入），那么 计数分组照常显示，**命中率、输入构成各段与输出段整组消失**——一个「每次都失败」的会话不显示 `0%` 命中率，也不显示各桶的 `0`（0% 是一个有数据的断言，此处并无数据）。此条优先于下面关于单段显示的条件。
- 假如 计费输入为零但输出大于零，那么 输出段仍显示（输出是真实计费事实）。
- 假如 会话累计的缓存写入为零，那么 **缓存写入段整段消失**，不显示 `写入 0`。会话累计值只增不减，因此「为零」等价于「本会话从未发生过写入」；省略段本身即携带这一信号（见 ADR-004 c）。
- 假如 会话已有成功的计费请求、缓存读取已上报且累计为零，那么 缓存读取段照常显示真实的 `0`——「一次都没命中」是可断言的真实事实，与「尚未发生写入」不同。

**US1.3 数字存活（不受窗口影响）**

- 假如 会话经历了历史裁剪或翻页，When 用户查看统计条，那么 数字与裁剪前完全一致（统计骑在会话全程记录上，不是「当前屏幕上有什么」的口径）。
- 假如 会话被关闭后恢复，那么 统计条从恢复时刻起继续累计，且恢复前的累计值不丢失。

### US2 回合级用量明细

**US2.1 胶囊入口**

- 假如 一个已完成的回合，When 用户查看该回合尾部，那么 看到一个数据库图标的用量胶囊，标签为该回合的紧凑总量（如 `用量 15.8K tok`）。
- 假如 用户处于无点击交互的终端环境，那么 回合级明细经回合详情对话或斜杠命令进入，胶囊入口的等价物是命令输出中的回合摘要行。

**US2.2 明细内容与逐行显示条件**

- **恒有行**（有回合用量即显示）：标题与精确总量（千分位不舍入）、未缓存输入、输出。
- **条件行**（数据缺报则整行消失，**不显示 0、不显示 N/A**）：

| 行 | 显示条件 |
|---|---|
| 模型（供应商/模型名） | 该回合每次计费请求都有模型归属 |
| 缓存命中 X% | 该回合有缓存读取数据 |
| 缓存读取 | 同上 |
| 缓存写入 | 该回合的模型属于**显式缓存家族**（见 SDR-003） |
| 输出附注「其中推理 N」 | 供应商单独上报了推理 token |

- 假如 回合生命周期不完整（被中断、用量未结算），那么 已结算部分照常显示，未结算部分不臆造。

**US2.3 交互（web）**

- 假如 用户点击胶囊，那么 弹出锚定在胶囊上方的明细面板，视口边缘自动钳位不越界；Escape 或点击面板外关闭；面板有对话框语义（无障碍标注）。

### US3 命中率的指标语义与诚实性

**US3.1 语义（见 SDR-001）**

- 命中率回答的是：「这个统计范围（会话或单回合）的**输入账单**中，有多少比例的输入享受了缓存折扣」。输出 token 不可缓存，不进入分母——命中率不随回答长短失真。

**US3.2 反假全命中**

- 假如 部分命中的会话/回合，按显示精度舍入会得到 100%，那么 自动加深一位精度（`99.9%`、`99.99%`……），保证显示值严格小于真实值加一个诚实区间——**宁可显示 99.9%，不显示假的 100%**。
- 假如 真实的全命中（输入全部来自缓存读取、且无写入），那么 显示 `100%`。
- 假如 无计费输入，那么 命中率不渲染（返回空，而不是 0%）。

**US3.3 精度两档**

- 会话级：两位小数百分比；回合级：一位小数（受反假全命中规则可加深）。
- 「冷启动后命中率」仅在会话首条调用的用量已知、且会话不止一次调用时展示（见 SDR-004）。

### US4 会话级统计的聚合范围（见 SDR-002）

- 假如 会话派出子代理完成工作，When 用户查看会话级统计，那么 主代理与子代理的消耗**合并计入**（口径 = 用户真实支付的账单）。
- 假如 用户查看回合级明细，When 该回合由子代理执行，那么 明细归属到该子代理自己的回合（回合级按回合归位，不跨回合合并）。
- **首批落地允许**先只聚合主代理，但必须在该数值的展示中标注口径范围；终态为全聚合（见 SDR-002）。

### US5 缓存写入行的展示条件（见 SDR-003）

- 假如 回合的模型属于**显式缓存家族**（写入单独计价、单独上报），When 用户打开明细，那么 看到「缓存写入」行——它有真实金额含义（写入按高于普通输入的单价计费）。
- 假如 模型属于**隐式缓存家族**（写入免费且不上报），那么 「缓存写入」行**永不出现**（该供应商没有这个概念，显示 0 是撒谎）。
- 假如 显式缓存家族发生了全命中、无过期、无写入，那么 该行显示 `0`（这是真实的 0，不是缺报）。

### US6 可编程消费面

- 假如 SDK 开发者接入一个活跃会话，那么 通过用量查询接口能拿到四项构成（未缓存输入、输出、缓存读取、缓存写入）的累计值，以及按模型分组的明细；当前回合的进行中累计可查询。
- 假如 会话未恢复（刚创建），那么 查询返回真实累计而非全零（活会话与恢复会话同口径）。
- 假如 开发者想知道「某供应商是否上报缓存写入」，那么 能从查询结果的能力描述中得知，无需自行试错。

## 4. 需求决策记录（SDR）

### SDR-001（2026-09-17）缓存命中率的口径：输入账单中享受缓存折扣的比例

- **背景与动机**：接入的模型供应商分两类缓存机制——显式缓存（写入单独计价、单独上报）与隐式缓存（写入免费、只上报命中）。同一个「命中率」若各家口径不一（是否含写入、是否含输出、按请求次数还是按 token 量），用户在供应商之间无法比较，也无法用同一把尺子诊断「我的会话为什么贵」。此外部分命中的会话按整数精度会舍入到 100%，向用户呈现并未达到的完美缓存。
- **决策**：a) 命中率的分母是**全部计费输入** = 未缓存输入 + 缓存读取 + 缓存写入三桶之和；分子是缓存读取。b) 输出 token 不进分母（不可缓存，混入只稀释指标）。c) 按 token 量加权而非按请求次数（用户按 token 付费，一次大请求全命中比十次小请求部分命中更值得 100%）。d) 反假全命中：部分命中在目标精度下会舍入到 100 时自动加深精度，显示值严格小于真实值加诚实区间；真实全命中才显示 100；无计费输入不渲染该指标。e) 会话级整数精度、回合级一位小数。
- **被否决的备选**：①分母只含「未缓存输入 + 缓存读取」（不含写入）——对显式缓存家族，写入是真实付费的输入，剔除后全命中会话的命中率低于 100%，指标失真；②按请求次数的命中率——与用户付费方式脱钩；③分母含输出——回答长短直接污染指标；④缺报时显示 0%——0 是有数据的断言，缺报时显示它是撒谎。
- **影响范围**：US1.1/US1.2/US3 全部；术语表 UV1（同批登记）；架构文档的分母公式与格式化规则。

### SDR-002（2026-09-17）会话级统计聚合范围：主代理与子代理合并（口径 = 真实账单）

- **背景与动机**：本产品会话会派出子代理（探索、蜂群），子代理的消耗是用户真实支付的一部分。若会话级统计只算主代理，数字系统性偏低，用户拿着一个「打了折的账单」去判断缓存策略是否生效，会得出错误结论。参考产品（DeepSeek Harness）为单代理会话模型，无此维度可借鉴，须自行裁决。
- **决策**：a) 会话级统计的终态口径 = **主代理 + 会话内全部子代理的合计**——它就是用户支付的账单。b) 回合级明细按回合归位（子代理的回合就是子代理的回合，明细里能看到模型与归属）。c) 分批落地：首批允许只聚合主代理，但必须标注口径；全聚合落地后撤标注。d) 不提供「主/子代理拆分」的会话级开关——拆分需求由回合级明细的自然归位满足，不再造第二套切片。
- **被否决的备选**：①永久只算主代理——系统性偏低，且两套口径并存教坏用户；②会话级即提供主/子拆分开关——先造切片再找需求，超出本域最小闭环；③子代理消耗单独出「子代理账单」概念——多一个用户要理解的概念，回合归位已够。
- **影响范围**：US4；上下文压缩域的压力口径不受影响（那是引擎内部决策，不消费本域的展示聚合）；ROADMAP 分批记录。

### SDR-003（2026-09-17）缓存写入行的展示条件：按供应商缓存家族静态决定

- **背景与动机**：「缓存写入」对显式缓存家族（Anthropic 系）是一个有金额含义的事实（写入按约 1.25 倍输入单价计费，缓存过期与前缀改写都会重新产生写入）；对隐式缓存家族（OpenAI 兼容、Google 系）该概念在协议中不存在——写入免费且不上报，字段恒为零。若统一显示，隐式家族的用户会看到一个永远的 0，误以为自己的缓存「一直在写但从不命中」或相反；若按「零值即省略」，显式家族「全命中无写入」这一健康状态又会被误判为缺报。
- **决策**：「缓存写入」行**只在显式缓存家族的用量中渲染**；家族归属是配置期已知的事实（供应商类型），静态判定，不做运行时零值推断。显式家族中真实的 0 照常显示。
- **被否决的备选**：①统一显示（隐式家族永远 0）——向用户呈现供应商并不存在的概念；②零值即省略——把显式家族的健康状态（全命中无写入）误判为缺报；③运行时探测「连续 N 次为 0 则视为不报」——启发式不可靠且引入状态。
- **影响范围**：US2.2 条件行表、US5；US6 的能力描述（查询结果携带「是否上报缓存写入」的能力位）；架构文档的供应商能力矩阵。

### SDR-004（2026-10-07）冷启动后命中率与精度统一：会话级两位小数

- **背景与动机**：缓存命中率把会话第一次调用的「冷启动惩罚」（整段提示词未命中、还要写入缓存）摊进了整段会话的数字，用户无法看出「缓存热起来之后」的真实命中率——而后者才是缓存策略是否生效的判断依据。同时，会话级整数精度与回合级一位小数并存，同一会话两个入口的数字对不上，用户无从判断哪个更准。
- **决策**：a) 会话级统计条在缓存命中率之外，追加展示「冷启动后命中率」一组——分子与分母同时剔除会话首条模型调用的用量。b) 会话级精度统一为两位小数（替代 SDR-001 e) 的会话级整数精度；回合级维持一位小数不变。c) 首调用量未知（旧会话历史、或引擎未上报）或会话只有一次调用时，省略「冷启动后」一组，不显示臆造数字。d) 首调用量以会话首条模型调用为准（主代理的首调，不是全代理汇总），随会话状态持久化，刷新与恢复后不丢失。
- **被否决的备选**：①仅提高精度不改口径——数字更细但冷启动失真仍在；②冷启动后口径按「首个回合之后」近似——回合边界与调用边界不对齐，误差不可控；③首调缺失时显示与主指标相同的值——把臆造伪装成事实，违反诚实性原则。
- **影响范围**：US1.1、US3.3；SDR-001 e) 的会话级整数精度由本记录 b) 取代；架构文档 §2 精度与计算规则同步；ROADMAP 分批记录。

### SDR-005（2026-11-01）会话级统计条的输入构成按计价档位拆分展示

- **背景与动机**：会话级统计条此前把输入呈现为一个合计数字（缓存读取 + 未缓存输入 + 缓存写入三桶之和）。但这个合计在金额上没有意义：三桶的计价档位相差一个数量级——缓存读取通常只按标准输入价的一小部分计费，未缓存输入按标准价全额计费，缓存写入按高于标准价的单价计费。会话越长，合计数字被便宜的缓存读取越推越大，用户看到的「输入」既在涨得快（每次调用都重报整段上下文），又无法判断涨的是便宜的那一档还是贵的那一档。用户的真实诉求是判断「这个会话在花钱上健不健康」，而合计数字恰恰把这个判断遮住了。命中率百分比虽然存在，但它只回答「折扣比例」，回答不了「便宜与昂贵的绝对量各是多少」；在命中率很高时，剩下的那部分未命中输入才是真正的成本来源，却在合计数字里留不下痕迹。

- **决策**：a) 会话级统计条的输入构成**按计价档位分为三段独立呈现**：缓存读取、未缓存输入、缓存写入，各自为独立分组，不提供三桶合计的单一「输入」数字。b) 输出保持独立分组不变（输出不可缓存、不参与输入计价，与 SDR-001 b 一致）。c) **命中率口径完全不变**：分母仍是三桶之和、分子仍是缓存读取（SDR-001 a 不变），拆分只改变呈现粒度，不改变任何比率；「计费输入」作为三桶之和的口径术语与命中率分母的实现保留，仅从会话统计条的呈现层消失。d) 缓存写入段以「会话累计值非零」为显示门槛：为零时整段消失，不显示 `写入 0`。会话累计值只增不减，「为零」等价于「本会话从未发生过写入」，省略不掩盖「曾写入而当前为零」的情形。代价是**显式缓存族的会话在尚未发生写入时暂时看不到 `写入 0`**，与回合级明细面板在同一情形下的呈现存在差异（那边按供应商缓存族静态判定，显式族真实 0 照常显示，见 US5/SDR-003）。e) 缓存读取段不设门槛：真实的零是「一次都没命中」的可断言事实，照常显示。f) 统计条中的各项计数（输入三段、输出、回合/步数计数）一律采用**精确千分位**而非紧凑格式：这些数字的用途是判断金额档位，近似值会让用户误判量级；回合胶囊作为入口标签维持紧凑格式。g) 宽度不足时按价值从低到高逐组丢弃：先舍回合/步数计数与冷启动后命中率，再舍输出段，再舍输入构成三段（缓存读取 → 未缓存输入 → 缓存写入）；「缓存命中率」与「未缓存输入」始终保留，任何情况下都可查看完整行。

- **被否决的备选**：①新增「价码当量」——把三桶按单价折算成一个等值输入量，一个数直接回答「贵不贵」——需要在产品内维护一份按模型的计价倍率表，供应商改价、新增模型、倍率变化都会让这个数字在不知不觉中失真，而本域明确不对金额做任何保证性换算（见范围表「货币换算 / 成本金额展示」不覆盖项）；②只拆「命中 / 未命中」两段——把未缓存输入（标准价）与缓存写入（高于标准价）混在同一格，恰好把价差最大、且在冷启动瞬间金额最高的那一档藏了起来，与拆分的初衷相悖；③保留合计数字、只把明细放进悬停——默认视图仍然是一个没有金额意义的巨大数字，用户必须主动悬停才能得到判断依据，等于没解决；④合计与拆分同时并列展示——同一事实两个数字占用状态条宽度，窄屏下拆分反而被优先截断；⑤为写入段立即引入「会话→缓存族」映射以便显式族显示真实 0——需要新增跨越内核传输边界的会话级能力事实，超出本次呈现层改动的范围，而已采纳的非零门槛已保证不撒谎。

- **影响范围**：US1.1、US1.2；US3 的命中率语义与精度不受影响（口径未变）；US2.1 回合胶囊的总量合计**维持不变**——胶囊是入口标签，点击一步可达逐桶明细，不承担金额判断；而统计条没有明细兜底，所以合计必须去掉。US2.2 回合级明细的构成行语义不变（其写入行仍按 SDR-003 的供应商族静态判定）。架构文档 §2.2 计数格式与 §4.1 组序同步；ROADMAP 记录。
