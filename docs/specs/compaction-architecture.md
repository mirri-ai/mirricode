# 上下文压缩 — 架构设计

> 状态：v1 · 2026-09-10 · 含 ADR-001~007 ·
> 本文描述上下文压缩域的**终态技术设计**（机制、数据流、接口形状）；动机只保留抽象问题陈述，现状证据与代码事实见 [compaction-context.md](compaction-context.md)，需求见 [compaction-requirements.md](compaction-requirements.md)。
> 基线说明：本文记录压缩域终态设计，含保留尾、修剪优先、必须变小守护等增强决策（SDR-001~002）；各引擎现状证据与差异见 [compaction-context.md](compaction-context.md)。

## 1. 概念与分层

压缩域由五个角色组成，职责单向依赖：

| 角色 | 职责 |
|---|---|
| **会话日志（wire journal）** | 唯一真相。只增不改的事件流水；压缩全程只追加记录 |
| **上下文记忆（context memory）** | 会话历史的内存权威副本 + token 计量；压缩的落位点 |
| **触发策略（strategy）** | 纯函数判定：给定占用量与模型窗口，是否该压、是否阻塞 |
| **压缩编排（compaction service）** | 单飞互斥、驱动摘要调用、守护校验、溢出恢复接线 |
| **投影（projector / transcript reducer）** | 从日志推导两个只读视图：模型视图（压缩后）与人类视图（全量） |

核心不变量：

1. **日志追加性**——被压缩的原始消息物理上永不删除；"哪些内容已被压缩"不是某个字段里的状态，而是每次从日志重放算出来的纯函数。
2. **模型视图是投影**——同一日志永远算出同一视图；运行时的内存副本是增量缓存。派生视图可从日志**全量重放重建**（复制会话、检查点缺失的兜底、导出导入等场景）；常规会话恢复优先走持久化域的**检查点增量**路径（快照已含压缩后的折叠态），两种路径必须产出同一视图。
3. **两套视图**——模型视图（摘要替换旧段）与人类视图（全量转录 + 摘要作为插入的整理记录）由同一日志投影，不存在第二份需要同步的状态。

## 2. 触发机制

### 2.1 三条触发路径

| 路径 | 时机 | 阻塞性 |
|---|---|---|
| 自动压力 | 每步 LLM 请求前的钩子判定（步骤边界生效，回合内只停等不中止） | 阻塞当前步（压缩完成才发请求） |
| 溢出恢复 | 服务商明确报上下文超限（含 413 且请求量已达有效窗口半数以上）时 | 失败步骤先闭合，再压缩，再新开一步重试 |
| 手动 | 用户命令（可附自定义说明）；低于阈值也可触发 | 会话空闲才受理；运行期间新输入排队 |

### 2.2 阈值判定

- **双口径**：占用 ≥ 窗口 × 触发比例（默认 0.85）；或占用 + 预留空间（默认 50,000）≥ 窗口。
- **有效窗口** = min(配置能力值, 运行时观测值)。观测值在溢出时学习（溢出请求量折算安全系数），按模型记名、单调收紧、跨压缩记忆。
- **计量源**：上下文记忆的实时计量（含待决消息），口径为真实占用（缓存命中计入）。
- **防重复**：压缩完成后记录"压缩后基线"，此后无新增内容（计量未超过基线）不再触发。
- **每回合限额**：自动压缩每回合默认不限次；溢出恢复连续次数默认限 3 次，超限上抛明确错误。

### 2.3 互斥与崩溃安全

- 压缩生命周期以三对落盘记录表达：`begin`（含触发来源与自定义说明）→ `complete` / `cancel`。**日志中存在未配对的 `begin` 即"进行中"**——任何来源的再触发都被拒绝。
- 恢复时识别孤儿 `begin`（上个进程遗留），归位为无压缩进行，不死锁、不续跑（摘要工作不跨进程存活）。

### 2.4 修剪优先（ADR-003）

自动路径的判定流程是**两段称重**：先用原始计量判"是否达到压缩条件"；命中后用"投影修剪后的估算"复测——若正规投影（对较早的、超长的工具输出做占位化）已把压力降到阈值下，跳过摘要调用。修剪是**投影级**行为：只影响模型视图，不修改内存历史与日志。

## 3. 压缩决策流程（五步）

```text
称重 → （修剪复测）→ 切线 → 摘要调用 → 守护校验 → 落位
```

1. **称重**：确认压缩条件成立（§2.2）。
2. **修剪复测**：投影修剪后的估算低于阈值 → 结束（免费手段已够）。
3. **切线**：按保留预算划出保留尾（§4）；找不到合法切点 → 整体放弃、不写任何记录。
4. **摘要调用**：对旧段发起一次 LLM 调用（§5），带四级失败阶梯。
5. **守护校验与落位**：并发变化检查 + 必须变小校验（ADR-004）通过后，替换式落位并追加记录；任一不过 → 保原状收尾。

## 4. 保留尾切线（ADR-001）

- **预算口径**：`窗口容量 × 保留比例`（默认 0.16），或绝对 token 值——两者互斥，加载时校验（同时设置拒绝启动；保留值不低于触发阈值对应量拒绝启动）。
- **切线算法**：
  1. 从最新消息往回累加占用，凑够预算得初始切线；
  2. 切线落在"工具调用 + 结果"配对中间不合法——**只向更老方向退**到合法边界（预算是最少保留，保留尾只增不减）；
  3. 两个放弃条件：数到底预算未凑够（整段历史都在保留预算内）→ 不压；退到头无合法边界 → 不压。
- **切线合法性**的判定与请求投影的配对约束同源：用户消息后、工具结果闭合、无悬空工具调用的边界才可切。
- **溢出路径差异**：溢出恢复时放弃保留预算，取"最大的合法头部区间、但至少保留最新的一个完整不可分割单元"。
- **头部精华保留**：最旧用户输入的头部预算（默认 2,000 token）独立于保留尾保留；与保留尾之间存在省略中间时插入省略说明消息（声明确略规模与去向）。

## 5. 摘要调用

### 5.1 输入构成

`[规则说明（与上轮真实请求逐字相同）] [工具清单（与上轮真实请求逐字相同）] [待压缩旧段] [固定指令]`

- 保留尾不在输入内：少递少付钱；输入开头恰为上轮请求的前缀，天然命中前缀缓存折扣。
- 动态工具的协议公告消息从输入中剥除（防协议文本被抄进摘要）。
- 压缩前钩子注入的附加上下文追加在旧段之后。

### 5.2 指令与输出

- 指令为钉死的第一人称交接笔记模板（SDR-002），支持插值用户自定义说明；表述适配保留尾语义（"最近对话已原样保留"）。
- 输出通道过滤：只有纯文本进入摘要；推理过程与工具调用一律剥掉，原始返回只存在日志中。
- 摘要消息落位时自动附带当前任务清单（从任务清单服务实时取）。

### 5.3 失败重试阶梯

| 级 | 条件 | 动作 | 上限 |
|---|---|---|---|
| L1 | 413 / 媒体格式错 | 输入中媒体替换为文字占位重试 | 1 次 |
| L2 | 摘要请求自身溢出 | 按递减预算从尾部收缩保留（0.7→0.5→0.35） | 3 次 |
| L3 | 响应截断 / 空 | 丢最旧一条 + 清理孤儿工具结果 | 5 次 |
| L4 | 其他可重试错误 | 指数退避 | 5 次 |

每一级的丢弃计数如实进入压缩记录与遥测（`droppedCount`），不静默消失；耗尽后保原状收尾。

### 5.4 并发变化检查

摘要返回时校验：历史前缀自快照以来未变，且新增尾部仅限真实用户输入或钩子附加上下文——否则取消。该检查保证"追加的真实用户输入会被重新纳入保留计算"，其余任何变化（助手消息、工具结果、后台通知追加，或前缀被撤销改变）都导致取消。

## 6. 落位形态

压缩后进入下一次请求的布局：

```text
[规则说明][工具清单][最旧用户输入头部精华]?[省略说明]?[摘要（替换旧段原位）][保留尾][新内容…]
```

- 摘要消息为用户角色、来源标记为"压缩摘要"；带固定的前缀文案（告知模型这是自动生成的整理记录、当既定背景继续，并自行验证）。
- 落位是**替换式**：内存历史被整体重写为上述序列；开放步骤、待决工具结果、延迟缓冲清空。
- **落位后的重注入**：生效目标、可加载工具清单、活跃后台任务提醒等会话级注入物从各自的唯一事实源重新注入，置于摘要之前（紧跟头部豁免段之后、保留尾之前），不依赖压缩前留在历史里的旧注入副本。
- **头部豁免**：规则说明与工具清单在每次请求组装时照常重发，压缩结构性碰不到它们（NFR1）。

## 7. 记录与重放

### 7.1 wire 记录

| 记录 | 内容 |
|---|---|
| `full_compaction.begin` | 触发来源、自定义说明 |
| `full_compaction.cancel` / `complete` | 生命周期闭合 |
| `context.apply_compaction` | 摘要全文、被替换条数、压缩前后计量、保留计数（保留尾条数 / 头部精华条数）、省略标记、丢弃计数 |
| 上下文计量记录 | 落位后的长度与 token |

落位生效前由守护闸门把关：**只有真正应用的压缩才写 `apply` 记录**（被守护拒绝的尝试不产生生效记录，仅遥测）。

### 7.2 重放语义

- 模型视图重放：`apply_compaction` 到达时，基于**压缩前的重放态**重算落位形状（保留计数驱动重建保留尾与头部精华），替换后继续折叠后续记录——重放是纯函数，不依赖 live 时的内存。
- **恢复保真（ADR-005）**：`apply` 记录必须携带足够重建 live 落位形状的保留计数字段；恢复端按计数从压缩前状态重建保留内容，禁止"恢复后只剩摘要"的降级。该重建规则适用于常规恢复（持久化域检查点增量路径之外的压缩记录折叠）、检查点缺失兜底、导出导入与复制会话（fork）——fork 逐条复制压缩记录且复制边界记录不参与压缩折叠，故 fork 会话重放天然得到与源一致的压缩视图。
- 人类视图重放：只按原始追加记录重放，`apply_compaction` 仅插入一条整理记录（摘要文本 + 计量），不删除任何已有条目。
- 事件面：压缩开始 / 阻塞 / 取消 / 完成（含计量）四类事件进入会话事件总线，供 UI 与遥测消费。
- 撤销语义：撤销回退遇到压缩摘要即停（压缩是撤销边界）。

## 8. 配置面

| 键 | 默认 | 约束 |
|---|---|---|
| 触发阈值比例 | 0.85 | 0.5–0.99 |
| 预留空间 | 50,000 token | ≥ 0 |
| 保留比例 | 0.16 | 与保留绝对值互斥；换算后必须低于触发阈值对应量 |
| 保留绝对值 | 未设 | 同上互斥 |
| 溢出恢复重试上限 | 3 | 0 = 仅关闭超限恢复 |

- 配置归属 loop 控制段（与步数/重试预算同段），随画像解析进模型上下文（不同模型可各自生效）。
- **接线要求（US6.3）**：每个声明的键必须有真实消费方；加载时做完整校验（互斥、范围、与阈值的相对关系），非法值拒绝启动。

## 9. 钩子、遥测与呈现

- **压缩前钩子**：触发于 `begin` 之后、摘要输入组装之前；可注入附加上下文（仅并入摘要输入，不进内存历史）。
- **压缩后钩子**：完成或取消时触发。
- **遥测**：完成事件（前后 token、耗时、压缩条数、裁剪条数、重试次数、触发来源、思考强度、请求追踪 id）与失败事件（错误类型、发生阶段、追踪 id）。
- **呈现**：终端压缩面板（进行中可取消、阻塞提示）；网页活动流条目 + 转录分隔条（可展开计量与摘要文本）。压缩期间到达的用户输入进入缓冲队列，压缩结束后按序进入下一轮。

## 10. 决策记录（ADR）

### ADR-001：保留尾切线采用"token 预算 + 配对完整性 + 单向回退"机制

- **编号与日期**：ADR-001 · 2026-09-09
- **背景**：现有落位把历史整体折叠为"部分用户消息 + 摘要"，最近交互的逐字保真丢失（动机详见需求 SDR-001）。
- **决策**：切线按 token 预算从最新往回收（比例制默认 0.16，随窗口缩放，可换绝对值）；配对完整性约束与请求投影的切分规则同源；非法切线只向更老方向修正——预算语义为"最少保留"。头部精华（最旧用户输入 2,000 token）独立保留并配省略说明。
- **被否决的备选**：按条数保留（条目大小不可控）；双向修正切线（可能产出残缺配对）；只保留用户消息（不解决最新交互逐字保真的痛点）。
- **影响**：需求 US2.1–2.3/US2.5；`apply` 记录的保留计数字段扩展（ADR-005）。

### ADR-002：摘要位置统一为"前置替换式"

- **编号与日期**：ADR-002 · 2026-09-09
- **背景**：现有实现对摘要位置的处理不一致——落位路径把摘要放在保留内容**之后**（末尾），恢复重放路径把摘要放在**最前**。位置影响缓存（摘要是历史段的第一个失效点）与语义（摘要应占据被替换旧段的原位）；两端不一致还意味着恢复后的视图与压缩时点的视图不同形（现状证据见 context §1.2）。
- **决策**：统一为前置替换式——摘要占据被替换旧段的原位（保留尾之前），与头部豁免衔接后，请求前缀的失效范围被限定为"摘要位置起的后续"。
- **被否决的备选**：末尾式——摘要位于对话末端，模型的"最近上下文"被一条长摘要切断，且与恢复重放形态不一致。
- **影响**：落位形状（§6）、重放折叠、摘要前缀文案。

### ADR-003：修剪优先作为自动路径的内置前置步骤

- **编号与日期**：ADR-003 · 2026-09-09
- **背景**：超长工具输出是上下文压力的主要来源之一；把它们占位化（原文留日志，可按需取回）不花任何模型调用成本。
- **决策**：自动路径两段称重：原始计量命中压缩条件后，先以投影修剪后的估算复测，缓解即跳过摘要。修剪是投影级（不改内存与日志）、只在压缩条件已成立时发生。
- **被否决的备选**：无条件先修剪（不缺空间的历史一个字都不该动）；独立的手动修剪命令（增加用户负担，收益不明）。
- **影响**：US1.8；触发流程（§2.4）。

### ADR-004：必须变小守护为落位前置闸门

- **编号与日期**：ADR-004 · 2026-09-09
- **背景**：摘要（含固定前缀）可能比它替换的内容更长（模型冗长转述、原文本已高度浓缩），此时压缩是净亏损。
- **决策**：落位前校验"摘要 + 保留尾 + 头部精华"严格短于压缩前历史，不过则整次作废、不写生效记录、按失败观测上报。
- **被否决的备选**：无守护——可能越压越大；守护后二次请求重摘——成本不可控，失败保原状已足够。
- **影响**：US2.4；记录写入时序（§7.1）。

### ADR-005：`apply` 记录携带保留计数字段，恢复端按计数重建落位形状

- **编号与日期**：ADR-005 · 2026-09-09
- **背景**：压缩生效时保留内容（保留尾、头部精华）不出现在独立追加记录里——它们是从压缩前状态派生的；若 `apply` 记录不带派生参数，恢复端重放将无法还原 live 形状，产生"恢复后只剩摘要"的降级。
- **决策**：`context.apply_compaction` 记录必须携带重建所需的全部保留计数（保留尾条数、头部精华条数、省略标记存在性、被替换条数、丢弃计数）；恢复端以压缩前重放态为输入、按计数重算落位形状（复用 live 的同一纯函数，避免两套实现漂移）。
- **被否决的备选**：保留内容逐条另写追加记录——日志膨胀且与"派生投影"哲学冲突；恢复端不保真（接受降级）——违反 US5.4。
- **影响**：wire 契约字段扩展（记录族 schema 由本域所有，版本链递增与未知字段透传遵循持久化域记录族所有权规则，见持久化域 ADR-008）；重放折叠（§7.2）。
- **修订记录**（2026-09-09，M2 实现期）：影响面中沿用的「字段扩展须递增一级」版本链预期已按持久化域 ADR-008 的修订口径收窄——**可选字段追加不递增**（先例：`planText`、`turn.steer`；本次 `retainedTailCount` / `keptHeadUserMessageCount` / `elisionMessage` 三个可选字段即按此不递增 `CURRENT_VERSION` 追加，旧日志缺省回放为旧式记录）；形状改写（语义变更/必填化/删除）必须递增。携带保留计数、按计数重建的决策本身不变。

### ADR-006：跨引擎压缩记录兼容性采用方向性切割

- **编号与日期**：ADR-006 · 2026-09-10
- **背景**：跨引擎恢复是真实场景（同 sessions 目录 + TS 回退路径），机械格式兼容成立（未知字段/记录两侧容忍），但压缩记录语义双向降级——TS v2 回放 Rust apply 记录被 zod 剥离新字段、误入 legacy-tail 分支切近似视图；Rust 回放 TS apply 记录走 legacy clear-everything 分支成 summary-only。完整分析见 compaction-context.md §6。
- **决策**：方向性切割——迁移方向（TS→Rust）做对：Rust reducer 学习 TS apply 记录保留计数族语义（`keptUserMessageCount`/`legacyTail`）重建 legacy-tail 形状，并裁决 v1 legacy toolCalls 形状的物化策略；回退方向（Rust→TS）降级契约文档化（legacy-tail 近似视图 + 恢复时日志/遥测标记），不改 TS 引擎。TS 侧压缩行为维持现状（用户 2026-09-10 M3 裁决：rust-first，TS 回退面文档标注）。
- **被否决的备选**：双向互操作（改两个引擎、zod strip 行为变更有回归面、与 rust-first 冲突、切换后作废）；硬切割打标拒绝（零静默降级但回退用户遇"会话打不开"硬错误）。
- **影响**：`apply` 记录族的 TS 侧字段读取（Rust wire 枚举扩展，按"可选追加不递增版本"纪律——持久化域 ADR-008）；Rust reducer 的 TS 记录分支；回退降级契约的文档与标记；实现另立计划。
- **裁决人**：用户（2026-09-10）。
- **修订记录**（2026-09-10，R2）：回退方向由"降级契约 + 恢复时标记"升级为**存储根切割**（用户裁决）——rust 引擎改写 `v3_sessions/`，跨引擎恢复物理不可能，降级契约整体删除；wire 版本升 2.0 作为新纪元标识（identity 迁移）。v1 legacy toolCalls 形状经查证维持丢弃（v1 引擎自身对未注册 id 的 tool.result 同样丢弃，`context/index.ts:658-662`——Rust 现行为即忠实回放，无需改动）。迁移方向（TS→Rust 记录语义）不变。

### ADR-007：出处链编号采用会话累计逻辑编号（SDR-004 落地设计）

- **编号与日期**：ADR-007 · 2026-09-10
- **背景**：SDR-004 裁决 M4 采用"出处链 + 显式标注"，编号锚点待定。用户裁决（2026-09-10）：采用**会话累计逻辑编号**——每个进入模型可见历史的条目获得一个单调递增编号，压缩与撤销只移除条目、永不重置或回收编号；多次压缩的替换区间互不重叠，摘要中引用的编号跨压缩稳定。
- **决策**：
  - 编号分配：live 侧 `ContextMemory` 维护计数器，每个物化进入 `history` 的消息获得 `entry_seq`；撤销、压缩移除消息但计数器不回退。预算外的容量拒绝条目不进入历史、不占编号。
  - 重放推导：reducer 折叠模拟按同一物化顺序分配编号（与槽位物化同源），live 与重放的编号一致性由 US5.4 往返闸门钉住。
  - 记录形态：`context.apply_compaction` 追加三个可选字段——`firstReplacedEntrySeq` / `lastReplacedEntrySeq`（被替换旧段的编号闭区间）与 `droppedEntrySeqs`（重试阶梯丢弃、连摘要输入都未覆盖的条目编号清单，显式标注"不可覆盖"边界）。可选字段追加，不递增 wire 版本（持久化域 ADR-008）。
  - 摘要指令：告知模型所覆盖的编号区间与编号引用约定；被丢弃条目在指令中显式列出。
  - 消费面：编号为纯载荷 + 呈现（事件面携带区间），重建继续按保留计数派生；读回工具（按编号取原文）归 P-E1。
- **被否决的备选**：压缩时槽位索引（压缩后编号漂移，跨压缩引用失效）；wire 行序号（暴露存储细节，导入导出/换格式作废，且对模型无语义）。
- **影响**：`ContextMemory`/reducer/apply 三写点/摘要指令/事件投影；P-E1 的读回工具以本编号为寻址基础。
- **裁决人**：用户（2026-09-10）。
