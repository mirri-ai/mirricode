## 开放项（每项含背景/痛点/选项与优劣，待用户裁决）

### 开放项 1：头部精华保留（2k）与读回工具并存还是被取代

**背景**（承接压缩域 ROADMAP #2 的重审义务，其背景重述）：压缩域保留尾设计（SDR-001/ADR-001）在保留尾之外**另行保留"最旧用户输入的头部精华"（默认 2,000 token，整条粒度不截断）**——动机是"摘要可能转述失真，最初的任务声明用原文保底"（压缩域 US2.5）。压缩域 ROADMAP #2 早已标注：这是可回溯压缩（P-E1）**落地前的过渡设计，P-E1 立项时重审**——本域即 P-E1 的立项，该重审义务由本项承接（压缩域 #2 备注已互指）。

**痛点**：读回工具落地后，"原文保底"有了更强的形态——模型可按编号把最初请求**完整**读回（不截断、不占常驻窗口）。头部精华 2k 的保底价值被读回覆盖，而其成本仍在：常驻占用窗口、参与每次压缩的保留计算与省空间校验、且 2k 之外的部分本来就没有保底（截断处仍可能失真）。两套语义重叠的机制并存，用户与模型都要理解两遍"最初的请求以什么形态在场"。

**选项**：

| | A. 保留并存 | B. 读回取代（移除头部精华） | C. 保留但缩水 |
|---|---|---|---|
| 做法 | 维持现状：头部精华 2k 常驻 + 读回工具按需 | 头部精华机制整体移除，最初请求仅存于目录卡片描述与读回中 | 保留更小的常驻头部（如 500 token 的任务声明首段）作提示性保底，细节靠读回 |
| 优点 | 改动为零；最初任务声明零成本**常在**（不依赖模型主动翻账，行为最稳） | 释放常驻窗口；"保底"语义统一到读回一处；压缩保留计算少一项；目录卡片必须把最初请求指路指到位（倒逼导航质量） | 折中：常驻成本降、保底仍在 |
| 缺点 | 双重机制语义重叠；2k 截断处仍可能失真；窗口成本永续 | 依赖模型自觉：模型不翻账就完全没有任务声明（多轮长任务中模型可能"忘了要去翻"）；摘要/卡片文案需补指路 | 失真面变小但仍非零；仍是两套机制 |
| 成本 | 零 | 低（压缩域移除 + 摘要指令与目录卡片补指路文案） | 低（改默认值 + 文案） |

**待裁决**：交用户。（R6 义务已尽：移除类提案 B 附上了上方机制分析与逃生门评估——逃生门即读回本身，且现状机制、受影响环节、外部参与方均已列明。）

### 开放项 2：搜索范围（仅本会话 vs 跨会话全文）

**背景**：US-R4"搜历史"有两种天然范围：仅当前会话的完整历史（含被压缩段——编号可直接读回），或跨会话的全部历史。既有事实：会话列表已有**名称级**搜索（会话管理/持久化域；检索需求挂会话管理域 ROADMAP 开放项、归档可见性待评审）；**跨会话全文搜索**（在全部会话的对话内容中检索）尚无任何域承接——本域是最近的候选承接方。

**痛点**：本会话搜索实现直接（单一日志、编号坐标系现成、结果可直接读回兑现）；跨会话搜索价值真实（"上次哪次会话里聊过 X"）但复杂度跳档：需扫描/索引多份日志；**编号坐标系跨会话无意义**（他会的编号无法在本会话读回，只能引用）；结果如何进入本会话上下文需要新的注入语义；权限面扩大（读到其他会话的敏感内容——别的会话可能不在当前工作区/不含当前用户预期可见的集合）。

**选项**：

| | A. 仅本会话 | B. 本会话 + 跨会话定位式结果 | C. 完整跨会话全文搜索 |
|---|---|---|---|
| 做法 | 搜索工具只扫当前会话日志 | 本会话全文检索 + 跨会话仅返回定位与摘要行（哪次会话、编号附近、一句话），原文不注入本会话 | 跨会话返回原文片段，与读回同构注入 |
| 优点 | 最小闭环；编号寻址直接可用；权限面不扩大 | 覆盖"找旧话题"主场景；只读定位不引入注入语义与窗口失控 | 能力最全 |
| 缺点 | "上次聊过 X"场景无解 | 跨会话侧仍需索引/扫描机制（与开放项 3 耦合）；用户需自己跳去那次会话看全文 | 权限面复杂（其他会话的敏感内容）；注入可能污染本会话上下文；与读回的量控哲学（NFR-R4）冲突 |
| 成本 | 低 | 中 | 高 |

### 开放项 3：检索索引形态（顺序扫描 vs 索引；数据量阈值）

**背景**：会话日志是纯追加的文本流水（wire.jsonl），无任何检索结构。既有先例可援引：会话持久化域的**会话索引**（S4）确立"可整体丢弃重建的只读缓存、目录枚举发现事实、索引只加速"的原则（其本身即 SQLite 文件——仓库内已有 SQLite 元数据索引的讨论语境）；本域 ADR-001 也已把"不建第二份**事实源**"钉死——索引属加速物、非事实源，不与之冲突。

**痛点**：顺序扫描对小日志够用（零维护、零一致性风险、实现最快）；但长任务的会话日志随时间线性累积，每次搜索全量扫描的延迟随之增长，NFR-R3 的体感底线（不阻塞正常对话）可能在大日志下被打破。引入索引则带来写入路径开销、重建时机、与"日志是唯一真相"的一致性边界维护。

**选项**：

| | A. 顺序扫描（先落地） | B. 会话级检索索引（SQLite 或同质物，随会话数据落位） | C. 阈值混合：小日志扫描、超阈值才建索引 |
|---|---|---|---|
| 做法 | 每次搜索线性扫日志文件 | 为每会话（或每工作区桶）维护可丢弃重建的搜索缓存 | 按数据量阈值切换两种路径 |
| 优点 | 零维护、零一致性风险；实现最快 | 大日志检索稳定快；援引 S4"可丢弃缓存"原则，无事实双源 | 兼顾两边 |
| 缺点 | 大日志延迟随体积线性涨（体感底线靠上限与不阻塞保证兜住） | 写入路径开销；缓存失效/重建时机需设计；首次搜索有建索引延迟 | 两套路径都要维护；阈值是经验值，两侧行为不一致 |
| 成本 | 低 | 中 | 中高 |

**裁决提示**：与开放项 2 耦合——若裁决含跨会话（B/C），几乎必然需要某种索引形态；若仅本会话，A 的顺序扫描可先行、索引延后按实测延迟数据再立项。

### 开放项 4：工具权限面（自动放行 vs 用户确认）

**背景**：读回/搜索是模型发起的**只读**工具。既有事实：工具调用域有统一调用校验管线（强制点在调用执行前），只读类内建工具（文件读取、内容搜索）默认自动放行不需确认；工具结果照常呈现给用户（天然可见性）。读回的特殊性：读取的是**本会话自己的历史**——若开放项 2 裁决为仅本会话，则无跨域敏感面；压缩的动机是空间整理而非保密，"被压掉的内容"没有隐藏语义。

**痛点**：逐次确认打断任务流——模型一次翻账常是连续多次读回（目录 → 区间 → 细读），每次都确认会把"翻旧账"变成"审批流"；完全自动放行则用户对"模型在看什么"的感知只来自工具卡片的事后呈现。

**选项**：

| | A. 自动放行（与只读内建工具同级） | B. 每会话首次确认 | C. 逐次确认 |
|---|---|---|---|
| 做法 | 与文件读取/内容搜索同级，直接放行 | 每个会话第一次读回时提示一次，此后放行 | 每次读回/搜索都需用户确认 |
| 优点 | 体验最顺；与既有只读工具口径一致 | 一次性告知，此后顺畅 | 感知最强 |
| 缺点 | 无事前感知（事后可见性已有——工具卡片呈现读回了什么） | 中间态，一次确认的实际收益有限 | 打断严重；连续翻账场景体验崩坏 |
| 成本 | 零 | 低 | 低 |

注意：无论裁决为何，需求 §4 的硬约束不变——必须经统一调用校验点，拦截与放行对称。

### 开放项 5：目录卡片/现状卡的触发策略（压缩后自动 vs 用户指令）

**背景**：卡片的生成时机未定。既有事实：压缩落位是一次原子事件（事件面有 `compaction.completed`，携带区间与丢弃计数——卡片装配的现成挂点）；卡片是模型上下文中的导航物，其价值在"模型下次需要翻账"时才兑现。

**痛点**：每次压缩后自动生成——模型永远有目录在手（导航完备），但卡片本身占窗口（多次压缩逐张累积），模型从不翻账的会话里卡片是纯开销；按需生成（模型经工具/用户经命令触发）——零常驻浪费，但"不知道有什么可翻"的冷启动问题回来（现状卡更小、可先给全貌缓解）。

**选项**：

| | A. 压缩后自动全量（目录卡 + 现状卡） | B. 现状卡自动 + 目录卡片按需 | C. 全按需 |
|---|---|---|---|
| 做法 | 每次压缩落位即生成两类卡 | 现状卡随压缩自动重写（全貌常在）；明细目录卡经工具/命令按需展开 | 两类卡都按需生成 |
| 优点 | 导航完备；实现挂点现成（completed 事件） | 全貌常在、明细按需——窗口成本最小化 | 零常驻成本 |
| 缺点 | 卡片逐次累积占窗；不翻账的会话纯浪费 | 目录卡片需额外生成入口（一个工具 + 命令）；冷启动靠现状卡兜底 | 冷启动盲区最重（模型不知可翻什么） |
| 成本 | 低 | 中 | 中 |
