# 会话持久化与索引 — 架构设计（面向 Rust 核心）

> 状态：v1 基线 · 2026-09-09 · 待需求评审后校准 ·
> 本文是会话持久化域设计侧的唯一事实源（内部规格文档，不进文档站构建，中文单语）。
> 需求契约：见 [session-persistence-requirements.md](session-persistence-requirements.md)（本设计的验收依据）；现状证据（TS 参照基线、差距矩阵、缺陷清单）见 [session-persistence-context.md](session-persistence-context.md)；执行状态见 [session-persistence-ROADMAP.md](session-persistence-ROADMAP.md)。
> 引擎分层锚点：`rust-core-design/00-overview.md`（mirri-core 内核 / mirri-session-index 存储 / mirri-embedded 接线）；协议契约登记于 mirri-proto 注册表。
> 术语规范：S1 会话恢复、S2 归档会话、S3 工作区桶、S4 会话索引的定义见 [glossary.md](glossary.md)。

## 1. 目标与设计原则

本设计描述**终态**：Rust 核心中会话持久化域的完整架构（TypeScript 引擎现行行为为本设计的参照基线；双引擎并存期的行为一致性保证见 §9）。

设计原则（对应需求编号）：

1. **磁盘是唯一事实源**：一切可重建的派生物（索引、检查点）都只是缓存或加速——任何时刻删除它们，行为退化为"慢一点"而非"坏掉"（US7.1）。
2. **崩溃安全原语唯一**：所有落盘写都经由同一组原子原语（临时文件 → fsync → 原子重命名 → 尽力目录 fsync），不存在第二条写路径（US1.1）。
3. **损坏做减法不做灾难**：任何单条数据的损坏只影响它自己的可见性（列表跳过、恢复降级为缺省元数据），永不阻塞启动或其他数据（US1.2）。
4. **组织与身份对齐**：目录结构按工作区桶组织，桶名由工作区路径确定性派生，跨引擎同构（US5.3、N6）。
5. **版本演进单向、向前容忍**：旧版本日志自动迁移到当前版本一次；超前版本原样重放不改写（US5.1/US5.2）。
6. **缓存故障不升级**：索引的一切读写都是尽力而为——写失败告警、读冷缺失回源补齐，绝不把缓存问题变成用户可见的失败（US7.2）。

## 2. 域模型

### 2.1 核心概念

- **会话存储单元（session store unit）**：一个会话在磁盘上的独立目录，含三个文件——元数据文档（`state.json`，AtomicDocument）、追加式操作日志（`wire.jsonl`，JsonlAppendLog）、可选的状态检查点（`snapshot.json`，SnapshotStore）。目录即完整性边界：拷走目录 = 拷走整条会话。
- **工作区桶（S3）**：会话目录的父级目录，名为工作区键（`wd_<slug>_<hash12>`），由工作区路径确定性派生（§4.2）。桶与工作区一对多容忍：同一物理目录的历史大小写变体会产生多个桶，读取端合并。
- **会话索引（S4）**：磁盘会话数据的只读清单缓存（SQLite，WAL），行从磁盘派生、可整库丢弃重建；工作区注册表镜像到 `workspaces.json`（跨引擎共享的身份事实源）。
- **归档标记（S2）**：元数据文档中的布尔字段；归档 = 置位 + 收起，恢复 = 复位 + S1 会话恢复。

### 2.2 会话数据生命周期

```
创建 ──运行中(追加 wire.jsonl)──► 收起(写 snapshot.json 检查点)
  ▲                                              │
  │              S1 会话恢复(检查点后重放增量)      ▼
  └────────────────────────────────────────── 归档(置标记，保留全部数据)
                        │                        ▲
                        ▼                        │
                     恢复(清标记 + S1 恢复)◄── 归档态
                                                 │
                                              删除(整目录移除 + 索引行清除)
```

- **收起**：会话从运行态退出时写检查点，把"到此为止的折叠状态"冻结——恢复只处理检查点之后的日志增量（US2.1）；检查点写失败降级为全量重放，不阻断收起。
- **归档**：永远不删数据，只置标记；对"未在运行"的会话归档是纯元数据写入（US6.1 的"不因没开着而报错"）。
- **删除**：唯一不可逆路径，必须清整目录与索引行（US8.1）。

## 3. 存储布局

### 3.1 终态布局

```
<会话数据根>/
  blobs/                # 全局内容寻址附件存储（<sha256> 文件名，跨会话共享去重；ADR-007）
  <工作区桶 wd_slug_hash12>/
    <会话 id>/
      state.json        # 元数据（AtomicDocument 原子写）
      wire.jsonl        # 追加式操作日志（带协议版本头）
      snapshot.json     # 可选检查点（收起时写）
  workspaces.json       # 工作区注册表（跨引擎共享的身份事实源）
  session-index.db      # 会话索引（Rust 侧读模型缓存；TS 侧的同类文件在 cache/ 子目录，不冲突）
```

- 会话数据根：注入了个人数据目录（home）的部署使用 `<home>/sessions`（与 TS 引擎同根）；未注入的本地形态使用 `<工作区根>/.mirri/sessions`。
- 索引文件位置与 TS 的缓存目录刻意分离（`<home>/session-index.db` vs TS 的 `<home>/cache/session-index.db`），两引擎同机共存互不踩踏。

### 3.2 兼容读（双布局）

读取端按**结构探测**区分两种布局，不依赖任何登记表：

- 一级子目录直接含元数据文档 → 平铺布局的会话目录（历史遗留形态）
- 否则 → 视为工作区桶，扫描其二级子目录为会话

同一读取面（列表、搜索、导出、恢复）都经由同一布局探测逻辑，不存在只认一种布局的旁路。平铺形态在一次性迁移（§7）后仅作为兼容读保留。

## 4. 数据契约

### 4.1 元数据文档（state.json）

跨引擎共享文档，字段集为两引擎字段集的并集：

| 字段 | 写入方 | 说明 |
|---|---|---|
| `title` / `tags` / `createdAt` / `updatedAt` | 双方 | 基础元数据 |
| `archived` | 双方 | 归档标记（S2） |
| `workDir` | 双方 | 会话归属的工作区路径（桶派生与归属回填的依据）；TS 侧历史文件用 `cwd` 键写入，读取端按别名兼容 |
| `lastPrompt` | 双方 | 最后一条用户消息预览；Rust 侧 send 时写入、随元数据持久化并在回合结束时刷新 `updatedAt`（ADR-009） |
| `version` | 双方 | 布局代际锚点：TS 写 `2`，Rust 写 `3`（v3 存储根时代）；读取端容忍缺失（ADR-010） |
| `customTitle` / `isCustomTitle` / `custom` / `forkedFrom` / `agents` | TS 起源 | Rust 侧读取时保留、写回时透传（不理解的字段不丢弃） |
| `archivedAt` / `compressed` / `compressedAt` / `preCompressedSize` | 归档存储管理域（ADR-018 登记） | 归档时点、压缩态标记、压缩时点、压缩前体积；所有权与写入时机归该域，存储布局与版本链仍归本域 |

- **时间戳双拼法**：读取端同时接受 RFC 3339 字符串（Rust 写入形态）与 epoch 毫秒整数（TS 写入形态）；写入端统一 RFC 3339。
- **损坏容忍**：文档存在但不可解析时，按"无元数据"降级处理——列表跳过该会话、恢复退回缺省元数据（US1.2 的两个分支）。

### 4.2 工作区键派生（wd_id）

```
wd_id = "wd_" + slug(basename(词法规范化绝对路径)) + "_" + sha256(词法规范化绝对路径).hex[0..12]
```

- **词法规范化**：仅拼接与消解 `.`/`..`/重复分隔符，**不解析符号链接**——符号链接解析会改变哈希输入，破坏跨引擎一致性。
- slug 规则：小写化 → 非 `[a-z0-9._-]` 连续段折叠为单个 `-` → 首尾去 `-` → 截断至 40 字符 → 再去首尾 `-` → 空串/`.`/`..` 兜底为 `workspace`。
- 该派生与 TS 引擎逐字节一致（互操作性的事实基础，US5.3）。

### 4.3 操作日志（wire.jsonl）与版本迁移链

- 首行为元数据头（含协议版本号），其后每行一条操作记录，判别字段为 `type`（历史遗留的 `op` 拼法在迁移时归一）。
- 每条操作记录（元数据头除外）在追加层统一携带 `time`（epoch 毫秒）——事件级时序由存储层保证，而非各记录族自行填写；旧读端对未知字段透传，重放兼容（ADR-011）。
- **记录族所有权**：各记录族的语义与字段 schema 由产出域所有并在其域架构文档中定义；本域管辖存储、版本链与未知字段透传（ADR-008）。
- 版本链 `1.0 → … → 1.6`，每级迁移是纯记录变换；迁移在**恢复时**执行（读到旧版本 → 迁到当前 → 落盘一次，此后不再付成本；磁盘写失败时在内存中迁移，恢复不中断，US5.1）。
- **超前版本容忍**：日志版本高于当前内核时不迁移、不改写，原样尽力重放（US5.2）。

### 4.4 检查点（snapshot.json）

- 内容：折叠后的代理状态 + 覆盖到的操作序号。
- 写入时机：会话收起时（尽力而为——失败仅意味着下次恢复走全量重放，US2.1 的降级分支）。
- 读取时机：恢复时，只重放序号之后的日志增量。
- **降级分支（无/失效检查点）的有界性**（ADR-017）：从头重放的处理成本随记录字节数**线性**——折叠状态就地演进，不做"每条记录整体复制"式的超线性放大；一次重开内对同一记录流的多次消费共享一次折叠结果，不重复折叠。

## 5. 会话索引（S4）

### 5.1 定位

SQLite 只读清单缓存，**不是**事实源（US7.1 的架构表达）：

- 打开：WAL 模式 + 5s 忙等待 + 启动时尽力 checkpoint（截断残留 WAL，冷读不重放大日志）——多进程并发下读者不阻塞、写者短暂等待而非报错（US4.1）。
- 无 home 注入的部署不建索引：一切索引路径缺位时回退为磁盘扫描，行为不变（可用性诚实——不存在"建了索引才有"的功能）。

### 5.2 表结构

```sql
sessions:  id PK, workspace_id, cwd, title, tags(JSON),
           created_at, updated_at,      -- 定宽 RFC 3339 文本（见 ADR-003）
           archived, custom, state_mtime,
           archived_at, compressed, compressed_at  -- ADR-018 登记（归档存储管理域）
  索引: (workspace_id, updated_at DESC)
workspaces: id PK, root, name, created_at, last_opened_at, sort_order
```

- `sort_order` 为会话排序真相的**缓存列**——排序真相在会话管理域的顺序文档（该域 ADR-001 将本列定位收窄为缓存），本表仅承载读模型加速。
- `workspaces` 表经 `workspaces.json` 镜像写通（§6）。

### 5.3 写通与对账

- **写通点**：创建、收起、归档/恢复、改名、元数据更新、回合结束（turn settle，ADR-009）——每点都是尽力而为，失败告警不失败请求（US7.2 第三条）。
- **读模型**：列表经由"目录枚举发现 (桶, 会话) 对 + 每行从索引取摘要 + 冷缺失回源磁盘读并回填"的路径——目录枚举仍是发现事实，索引只加速摘要（US3.1 的三条验收对应此结构）。
- **对账（converge）**：启动时比对每行 `state_mtime` 与磁盘元数据文档的修改时间——缺失/过时的行回源重读回填；磁盘上已消失的行清除（孤儿回收）。对账范围限定在本引擎绑定的工作区桶（跨桶行属其他引擎实例，不越界清扫）。
- **输出一致性**：索引加速的是读取，不改变输出——列表排序、字段形状与纯磁盘扫描逐字节一致。

## 6. 工作区注册表（workspaces.json）

- 身份事实源（跨引擎共享）：工作区的 id、根路径、名称、创建时间、最近打开时间。
- Rust 侧对注册表**读入 + 写通镜像**：启动时读入并为索引的 `workspaces` 表播种（不覆盖既有 `sort_order`）；注册/更新工作区时原子写回（保留 TS 侧的删除墓碑等本域不理解的字段）。
- 同一 home 下 TS 引擎因此仍能看到 Rust 引擎注册的工作区（US5.3 双引擎一致性）。

## 7. 一次性布局迁移

- 触发：引擎启动后、首个对外的会话操作前**内联等待完成**（派发的后台迁移可能与首个恢复竞争文件位置——内联保证恢复看到的是迁移后的位置）。
- 步骤：结构探测找出平铺会话目录 → 读其 `workDir`（缺失则以当前绑定工作区路径补写回填）→ 派生目标桶 → 原子重命名进桶。
- 安全性：目标已存在则跳过并告警（**绝不覆盖**，US5.3 第三条）；中断后重跑从中断处继续（幂等，US5.3 第四条）；失败只告警不阻断启动。
- 归属取舍（ADR-001）：平铺时代的会话未记录归属，统一归入当前绑定的工作区桶并回填 `workDir`——单引擎绑定单工作区的运行形态下这是唯一可用归属推断。

## 8. 崩溃安全原语（共享底座）

| 原语 | 保证 | 消费方 |
|---|---|---|
| AtomicDocument | 元数据文档整写整旧或整新（US1.1） | 元数据、注册表、迁移回填 |
| JsonlAppendLog | 追加日志的行完整性 | 操作日志 |
| SnapshotStore | 检查点原子写 | 收起路径 |
| write_file_atomically | 同一原子语义的通用文件写 | 全域其他落盘（如鉴权令牌） |
| 会话目录 advisory lock（`lock` 文件 + OS 锁，ADR-018 登记） | 会话目录级跨进程互斥（进程崩溃即释放）；常驻锁文件的存在性不是活跃信号，只有锁持有状态有意义 | 归档存储管理域（压缩/还原/删除） |

## 9. 双引擎并存期的一致性保证

- **布局**：双方按同一派生规则写桶；Rust 读端双布局兼容，TS 的历史大小写分裂桶在读取面合并。
- **元数据**：字段并集 + 双拼法时间戳；不认识的字段透传不丢（§4.1）。
- **索引**：各引擎各持一份索引文件（位置分离），互为黑盒；一致性各自对账于同一磁盘事实。
- **归档标记**：双方语义一致（置位/复位 + 默认列表排除）。

## 10. 决策记录（ADR）

### ADR-001 会话目录按工作区桶组织

- **背景与动机**：单层平铺的会话根目录混合所有工作区的会话，数据量增长后不可导航、无法按工作区整体备份/排查；TS 引擎已按工作区分桶。
- **决策**：新会话一律写入工作区桶；遗留平铺会话由一次性迁移归置（§7）；读取端保留双布局兼容直至迁移完成。
- **否决的替代**：仅读取兼容不迁移写入（平铺继续膨胀，问题不收敛）；登记表驱动的布局映射（结构探测已足够，登记表多一份要维护的事实源）。
- **影响面**：US5.3、US1.2；`workDir` 成为必记字段（迁移与归属的依据）。

### ADR-002 会话索引采用 SQLite 读模型（含工作区表）

- **背景与动机**：列表是热路径，逐会话开文件拼装（N+1）随数量线性劣化；TS 同问题的解是"目录枚举发现 + 索引取摘要 + 冷缺失回源"。工作区元数据入索引是为承载"会话管理"域的排序契约（JSON 注册表整文件重写不适合高频排序更新）。
- **决策**：独立存储 crate 提供 SQLite 索引；磁盘数据为事实源，索引整库可弃（US7.1）；写通 + 启动对账保持温热；索引缺位时全路径回退磁盘扫描。
- **否决的替代**：纯文件方案（排序更新需整文件重写、多进程写竞争）；把索引放进内核包（存储关注点不应进入引擎内核，接线层持有）。
- **影响面**：US3.1、US7.2、US4.1；`workspaces.json` 镜像随之引入（§6）。
- **修订记录**：本 ADR 中"`workspaces` 表承载'会话管理'域的排序契约"的定位已被**会话管理域 ADR-001** 收窄为"顺序文档真相 + `sort_order` 缓存列"（§5.2 已同步口径）——工作区表入索引的决策本身不变。

### ADR-003 索引时间戳采用定宽 RFC 3339 文本

- **背景与动机**：TS 同表用 epoch 毫秒整数；Rust 侧会话时间戳携带亚毫秒精度，截断为毫秒会改变对外可见的列表值（字节级一致性约束）。
- **决策**：`created_at`/`updated_at` 以定宽（纳秒位补齐）RFC 3339 文本入库——定宽保证字典序即时间序，SQL 排序语义不损失；`state_mtime` 仍为 epoch 毫秒整数（对账比较用）。
- **否决的替代**：epoch 毫秒（丢精度，破坏一致性）；RFC 3339 变宽文本（字典序与时间序可能不一致）。
- **影响面**：仅索引内部；无对外契约变化。

### ADR-004 归档建模为元数据标记而非"关闭"

- **背景与动机**：归档曾等价于"以收起语义结束会话"，对未在运行的会话直接失败（用户可见的"Session not found"）；TS 侧同操作是静默无操作——两者都不满足"对已收起的会话归档是合法操作"。
- **决策**：归档 = 运行中会话先收起再置标记；未运行会话直接置标记。标记持久化于元数据文档（跨重开保持，US6.3），恢复路径负责清标记。
- **否决的替代**：对未运行会话静默无操作（TS 现状——用户点归档却毫无反馈，可用性不诚实）。
- **影响面**：US6.1/US6.2/US6.3；默认列表过滤在数据读取层执行（界面隐藏不合格）。

### ADR-005 wire.jsonl 跨引擎不引入独立迁移功能

- **背景与动机**：两引擎日志版本存在差异（当前 Rust 1.6 / TS 1.5），但差异仅为 Rust 自有历史载荷的归一化，对 TS 写入的日志是恒等变换。
- **决策**：不建独立的"引擎间会话迁移"功能——恢复时自动版本迁移链 + 超前容忍 + 布局双读已构成完整互操作面。
- **否决的替代**：显式 `migrate` 命令作为必需步骤（自动迁移已覆盖该场景，额外步骤徒增升级成本；命令保留为运维可选路径）。
- **影响面**：US5.1/US5.2。
- **修订记录**（2026-09-10，R1）：用户裁决存储根切割——rust 引擎的会话根改写 `<home>/v3_sessions/`（工作区本地路径为 `.mirri/v3_sessions/`），跨引擎会话共享由"布局双读互操作面"改为"物理隔离 + 显式迁移命令"（`migrate-sessions`，运维可选路径从 ADR-005 否决项转正为用户主路径）。本决策取代"恢复时自动版本迁移链 + 超前容忍 + 布局双读已构成完整互操作面"对 rust 侧的适用；wire 版本升 2.0（identity 1.6→2.0）。TS 侧行为不变。裁决人：用户（2026-09-10）。

### ADR-006 子代理记录按身份分片于会话目录（按身份分片的记录流）

- **背景与动机**：子代理身份存活于主会话生命周期内——会话是其全部持久化资产的容器（子代理域 ADR 同构）。现状是 Rust 子代理对话**完全未持久化**（子代理 turn 从未获得记录器，2026-09-09 复核，见 context §1.5），主 agent 对话与会话层操作混在单一 `wire.jsonl`；TS 参照为每身份一条独立记录流（`agents/<agentId>/wire.jsonl`）+ 元数据文档中的 agents 注册表。
- **决策**：会话目录成为"会话本体 + 各身份记录流"的容器（对齐 TS 布局，用户已裁决；注意术语：「子会话」指派生的独立会话，见 glossary G3——本条的记录流**不是**会话）：
  - `agents/<agentId>/wire.jsonl`——每身份一条独立记录流，**含 main agent**（`agents/main/`）；子代理的用量 ops 记入自己的记录流
  - `agents/<agentId>/snapshot.json`——每身份一份检查点（收起时写，规则同 §4.4）
  - 会话级 `wire.jsonl` 收窄为会话层操作（goal/plan/todo/cron/metadata）+ 派发面镜像
  - 身份注册表（装配、归属、最近终态）持久化于元数据文档的 `agents` 字段——跨引擎并集契约的既有槽位（§4.1），对齐 TS 的 AgentMeta 形状
  - 恢复时序（子代理域确认项 8 的裁决）：注册表先行 → 主 agent 记录流重放为会话就绪门槛 → 子代理记录流**懒重放**（续作/查看时按需重建）；单一身份记录流损坏时该身份保留并标记损坏、续作时明确报错——单点损坏不做全局灾难（US1.2 对称）
  - 存量迁移：混合 `wire.jsonl` 一次性拆分（main-agent 消息操作移入 `agents/main/`，会话层操作留存），wire 版本链递增一级承载该变换
- **否决的替代**：子代理记录独立于会话目录存储（破坏"目录即完整性边界"：拷走目录 ≠ 拷走整条会话；删除级联与导出打包都要另做）；维持单一混流（按身份截断/回放/导出不可能实现）；身份只在内存（重启即失忆，续作承诺失去事实支撑）。
- **影响面**：导出/归档/删除按目录边界天然级联（US8.1 不变；附件本体除外——全局共享存储，ADR-007）；会话级用量 = Σ 各身份用量（聚合口径），派发面归因由子代理域在镜像中承载；事件按身份过滤由消费侧投影承担（事件已携带身份标识与独立 wire turn id，无需按身份的事件索引）。

### ADR-007 附件采用全局内容寻址存储（跨会话共享）

- **背景与动机**：附件（对话中引用的媒体）在三套实现里都存在**会话域内**（TS v1/v2：`<agent 目录>/blobs/<sha256>`；Rust：`<会话目录>/blobs/<sha256>`；另有 TS 的 `<会话目录>/media-originals/` 会话属主原文件，2026-09-09 复核见 context §7）。fork 的痛点暴露了按会话管理的代价：复制会话被迫连带复制附件本体（存储随分叉次数翻倍）；删除会话可能带走分叉会话仍在引用的附件（无跨会话引用保护）；同一附件在不同会话各存一份（无跨会话去重）。内容寻址本身已是三套实现的既成事实（sha256 指纹 + 排他写幂等去重 + `blobref:` 引用），缺的只是把存储根从"会话域内"上移到"全局"。
- **决策**：附件存入**数据根下的全局内容寻址存储**（`<会话数据根>/blobs/<sha256>`，§3.1）：
  - 会话日志只记录指纹与格式信息（`blobref:<mime>;<sha256>` 现有引用形状不变），不存文件本体
  - 同一内容全服务只存一份：字节相同即同指纹，跨会话、跨 agent、跨引擎自然去重；存在即复用，写入幂等
  - **保留中立**（2026-10-23 修订，见 ADR-018）：删除会话不**无条件**连带清理附件——附件本体不参与会话目录级联（US8.1 的级联范围不含附件本体，SDR-003）；对话记录中的引用随记录消失，本体由**条件联动回收**（所有删除入口统一、引用感知 + 老化窗口，归档存储管理域定义）按引用裁决
  - **回收延迟且引用感知**：孤儿附件（无任何会话引用）回收；只要有会话——含被恢复、被分叉出的——仍引用着某附件，即跳过不删
  - 溢出文件（工作目录之外的临时大文件，如模型生成的媒体原文件）同样按引用感知回收，并保留 **30 天老化窗口**后才纳入清理范围——为恢复/分叉出的会话留引用缓冲
  - 导出/打包：会话目录边界完整性对"引用"保持（引用在记录里、随目录走），对"本体"显式豁免——导出时被引用附件本体随包内联，导入时回填全局存储并命中既有指纹去重
- **否决的替代**：维持按会话/agent 目录存（三引擎现状——fork 被迫复制本体、删除有跨会话误伤、无跨会话去重）；fork 时复制附件本体（存储随分叉翻倍，且与"共享文件世界"的产品裁决相悖，会话管理域 SDR-007）；删除会话时做即时引用计数裁决（恢复/分叉等异步出现的引用者无法在删除时刻枚举，误删风险高——延迟回收正是为此）。
- **影响面**：§3.1 布局新增全局 blobs 根；US8.1 级联范围排除附件本体（SDR-003）；会话管理域 US5.1 附件共享条款的实现底座；存量迁移——三引擎既有会话域内的 blobs 一次性上移合并到全局根（同指纹天然去重，§7 一次性布局迁移）；wire 引用形状不变（无协议版本递增）。

### ADR-008 记录族 schema 由产出域所有，本域管辖存储、版本链与透传

- **背景与动机**：wire.jsonl 中混装多个产出域的记录族——会话层操作、上下文追加、压缩记录族（`full_compaction.*` / `context.apply_compaction`）、子代理记录流等。压缩域已出现扩展 `apply` 记录保留计数字段的诉求（压缩域 ADR-005）；若不确立所有权规则，各域自行改记录格式会绕过版本链纪律，威胁跨引擎互操作与超前容忍。
- **决策**：记录族的**语义与字段 schema 由产出域所有**，在其域架构文档中定义（压缩记录族见压缩域 §7.1）；本域保证存储布局、**版本链递增**（字段级扩展递增一级版本承载）、迁移变换与**未知字段透传**（读端不理解的字段不丢弃）。任何产出域的记录族字段扩展，须在本域版本链递增一级承载，并在扩展侧 ADR 影响面中指向本 ADR。
- **否决的替代**：全部记录族集中在本域定义（产出域语义与存储格式耦合，域边界崩坏）；产出域自由改格式不走版本链（超前容忍与迁移链失效）。
- **影响面**：§4.3；压缩域 ADR-005；子代理域记录流契约（ADR-006）。
- **修订记录**（2026-09-09，M2 实现期）：决策中「字段级扩展递增一级版本承载」的版本链纪律已收窄为「**可选字段追加不递增**（先例：`planText`、`turn.steer`——可选字段对旧读端缺省、对未知读端透传，不破坏超前容忍与迁移链）；形状改写（语义变更/必填化/删除）必须递增」——压缩域 ADR-005 的三个可选保留计数字段（`retainedTailCount` / `keptHeadUserMessageCount` / `elisionMessage`）即按此不递增版本追加。记录族所有权、本域管辖存储与透传的决策本身不变。

### ADR-009 会话元数据含 `lastPrompt`，回合结束时刷新 `updatedAt` 并写通

- **背景与动机**：会话列表依赖的两个信号——"最后一条消息预览"（`lastPrompt`）与"最近活跃时间"（`updatedAt`）——在 Rust 侧均不成立：元数据结构不含 `lastPrompt`（该 TS 起源字段仅透传，一次 load-mutate-save 即被抹回空），`updatedAt` 创建后从不推进（列表的"最近活跃"永远等于创建时刻，`updated_at DESC` 排序失真）。双引擎并存期，同一份会话列表在两引擎下口径漂移（现状证据见 context §8 与会话审计报告）。
- **决策**：
  - scope 层 `SessionMetadata` 增加 `last_prompt: Option<String>`，send 时写入（最后一条用户消息文本，TS parity：`updatePromptMetadata`）；
  - 每次回合结束（completed/failed）统一执行：内存 bump `updated_at` → `save_state` 落盘 → SQLite 索引 upsert——对齐 TS v2 `SessionMetadataService.applyUpdate` 的 `updatedAt: Date.now()` + write-through 语义；
  - 回合结束刷新为尽力而为：持久化或索引失败时告警，不让其打断回合结果（US7.2 同款纪律）。
- **否决的替代**：`lastPrompt` 只存索引不进元数据（磁盘是唯一事实源——load-mutate-save 抹除、索引整库重建即丢，两处口径继续漂移）；`updatedAt` 只在索引层推进（与磁盘 state.json 不一致，启动对账会按磁盘回填把它改回去）；逐事件刷新（写放大，列表排序噪音）。
- **影响面**：§4.1（`lastPrompt` 由 TS 起源改为双方写入）、§5.3（写通点新增回合结束）；US7.2；§9 双引擎一致性。

### ADR-010 `state.json` 携带顶层 `version` 字段

- **背景与动机**：state.json 没有文件内的版本锚点，格式代际只能靠结构猜测（有无 state.json、是否桶布局），格式演进时兼容层长期维护成本高；TS 侧同文件已写 `version: 2`，Rust 侧缺位使两引擎产物在文件层面不可判别代际。
- **决策**：Rust 写盘的 state.json 增加顶层 `version` 字段，值 `3`（v3 存储根时代的代际，ADR-005-R1）；读取端容忍缺失（历史文件无版本，缺省处理）。TS 布局 `version: 2` 语义不变。
- **否决的替代**：不写版本（结构探测脆弱，代际判定无文件内依据）；复用 wire 头的协议版本作锚点（state.json 字段集与 wire 记录格式是两条独立演进轴，锚点不能共用）。
- **影响面**：§4.1（字段表新增 `version`）；读取端兼容（缺失容忍，无迁移）。

### ADR-011 操作日志记录在追加层统一注入 `time`

- **背景与动机**：wire.jsonl 中除首行元数据头外的事件均无时间戳，会话重放、调试工具与审计排错失去事件级时序，只能靠行序近似推断；TS 侧每条事件携带毫秒时间戳，两引擎的日志消费面不一致。wire 契约中"时间戳由持久层处理"的声明一直未被兑现。
- **决策**：`JsonlAppendLog::append` 在序列化后统一插入顶层 `"time": <epoch_ms>`（元数据行除外——TS 元数据头只携带 `created_at`）；行内已存在 `time` 时保留原值（TS 日志重写场景）。`WireOp` 的 internally-tagged 反序列化默认忽略未知字段：旧读端对新增 `time` 透传不炸，重放天然兼容。
- **否决的替代**：各记录族产出点自行填写 `time`（绕过统一纪律，易漏——恰是现状）；迁移旧日志回填（追加式日志永不重写）；递增 wire 版本承载（可选字段追加不递增，ADR-008 修订记录的既定纪律）。
- **影响面**：§4.3；无版本链递增；旧读端/重放兼容。

### ADR-012 `usage.record` 磁盘拼写保持 Rust 自有，客户端口径由投影层负责

- **背景与动机**：Rust 与 TS 的用量记录字段拼写不同（`inputTokens`/`outputTokens`/`cacheReadTokens`/`cacheCreationTokens` vs `inputOther`/`output`/`inputCacheRead`/`inputCacheCreation`），且 OpenAI/DeepSeek 的隐式缓存语义在账面上呈现"首次调用无缓存创建、后续调用命中缓存读"的表面矛盾，被审计标记为口径不兼容。若为对齐客户端口径而改写磁盘拼写，等于对既有日志做形状改写——违反版本链纪律（2.0 是纪元标记，记录形状未变），且新旧日志混杂后消费端更不可判别。
- **决策**：
  - 磁盘（wire.jsonl）保持 Rust 自有拼写：`inputTokens` / `outputTokens` / `cacheReadTokens` / `cacheCreationTokens`；
  - 客户端事件投影层（`event_projection` 的用量投影）负责对齐 TS 消费口径（`inputOther` / `output` / `inputCacheRead` / `inputCacheCreation` 拼写、`usageScope` 与 `time`、`model` 记 alias）——磁盘口径与客户端口径分层，各自稳定；
  - 隐式缓存语义显式化：OpenAI/DeepSeek 的 `prompt_tokens` **含**已缓存部分，故 `input_tokens = prompt_tokens − cached_tokens`、`cache_creation_tokens` 恒为 0；首次调用 creation=0、后续调用 read>0 是预期行为，非账目错误。
- **否决的替代**：改写磁盘拼写对齐 TS 1.5（形状改写违反版本链纪律，既有日志新旧混杂）；记录层双写两套口径（两份"事实"漂移，消费端更混乱）；把隐式缓存差值虚记入 creation（编造 Anthropic 显式缓存口径的语义，账目失真）。
- **影响面**：§4.3 记录族所有权（ADR-008——usage 记录族语义属其产出域）；事件投影层；§9 双引擎消费面。
- **口径澄清与响应面登记（2026-09-13，主控复核）**：`usageScope`/`time`/`model` 记 alias 描述的是 TS 的**磁盘** usage.record 行；TS 客户端事件契约本身不携带这三键（时间维度由通知包络的 RFC3339 `timestamp` 承载）。据此执行：事件投影按 TS 事件消费口径（`event.turn.step.completed` / `event.subagent.completed` 的 usage 四桶拼写）对齐。响应面盘点：`agent.getUsage` 当前返回 `{usage:{…}}` 包装 + Rust 拼写，与 TS 契约（裸 `UsageStatus` + TS 拼写，存在真实消费者）不符，**列入修复**；session.get/list 的 `SessionUsageView` 与 message.send wait 模式 `turn.usage` 为 Rust 拼写但无 TS 消费者，**维持现状登记**；model.generate usage 为显式文档化的 passthrough，**维持**。

### ADR-013 Bash 工具结果以纯文本记录（弃用 JSON 包装）

- **背景与动机**：Bash 工具结果把 `{exitCode, stdout, stderr, timedOut}` 的 JSON 字符串填入 tool.result 的 text part，形成双重编码（文本里嵌一层转义 JSON）——UI/重放工具直接渲染出 raw JSON（含 `\n` 转义）而非多行输出；TS 侧同位置是纯文本，两形状并存使消费端必须双兼容。
- **决策**：弃用 JSON 包装；Bash 工具结果的输出 = 捕获的 stdout/stderr 文本 + 状态行，镜像 TS `foregroundCompletionResult` 语义（成功空输出给占位文案、失败带 `Command failed with exit code: N.` 状态行、超时保留提示）。
- **否决的替代**：维持 JSON 包装 + 投影层解包（双重编码不消失，双形状永久共存）；结构化结果走独立 part 形状（超出对齐目标，TS 消费面无此形状）。
- **影响面**：§4.3 记录族（记录族语义属工具调用域，ADR-008）；本域承载其存储兼容——旧日志中的 JSON 包装形状按既有内容透传，不做回写迁移。
- **版本裁决（2026-09-13，主控复核）**：不递增 wire 版本。`tool.result` 的**记录形状**（`{type, callId, result:{output:[…]}}`）未变化，本次仅改变 text part 的**内容产生方式**（工具输出策略），属工具调用域的内容策略，非 wire schema 变更；TS 1.5 在同一记录形状内即为纯文本。故不触发 ADR-008 的"形状改写须递增版本"纪律。

### ADR-014 任务输出三层存储保留（有意冗余）

- **背景与动机**：同一份工具输出同时存在于三处——`tasks/<id>/output.log`（实时尾随）、`tasks/<id>.json`（任务恢复快照）、wire.jsonl（对话重放），被审计标记为存储膨胀与不一致风险。
- **决策**：三层保留，各司其职：`output.log` 服务实时尾随（append-only、低延迟消费）、任务 JSON 服务任务恢复快照（结构化终态与状态机）、wire.jsonl 服务对话重放（自包含的会话记录，目录即完整性边界）。冗余为有意设计：单份千字节级的重复，相对三个独立消费者的解耦收益是可接受的存储成本。
- **否决的替代**：wire 只存引用、正文以 tasks/ 为准（会话重放/导出需跨文件装配，且任务文件的清理生命周期与对话记录不同步）；去任务快照（任务恢复能力重造）；去 output.log（实时尾随退化为轮询整个 wire 日志）。
- **影响面**：无契约变化；存储成本为接受项（回收归任务域生命周期管辖）。

### ADR-015 双索引并存维持至 TS 退役

- **背景与动机**：TS 侧索引（`<home>/cache/session-index.db` + v1 兼容的 `session_index.jsonl`）与 Rust 侧索引（`<home>/session-index.db`）并存，不同入口看到的会话集合不一致，被审计标记为索引分裂。
- **决策**：维持并存（§3.1/§9 既定：各引擎各持一份索引文件、位置分离、互为黑盒、各自对账于同一磁盘事实）直至 TS 引擎退役；`mirri migrate-sessions` 把会话迁入 v3 根后，迁移会话进入 Rust 列表靠启动对账（reconcile，冷缺失回源磁盘读并回填）+ 磁盘扫描兜底保证，不依赖索引预置。
- **否决的替代**：两引擎共用同一索引文件（跨进程锁与写竞争，schema 演进互相锁死）；实时双向同步（复杂度高，且两引擎存储根已物理分离——ADR-005-R1——需同步的集合本身在收缩）；强制废弃 v1 jsonl 清单（存量 TS 入口仍在读，退役前不可）。
- **影响面**：§3.1、§5.3、§9；迁移命令的对账依赖（读模型冷缺失回源兜底）。

### ADR-016 子代理 journal envelope 与主日志统一口径

- **背景与动机**：会话审计 session-30c0d8bb（P2-1）发现子代理 wire.jsonl 的 metadata 行写秒级 `created_at` + `protocol_version: "2"`，而主会话 journal 为毫秒 + `"2.0"`——两处 envelope 构造各自手写（`child_wire_log` 与 `materialize_child_wire_logs`），口径分叉。按毫秒解析子代理时间戳会得到 1970 年的值。
- **决策**：统一复用主日志写法：`protocol_version` 取 `mirri_persistence::CURRENT_VERSION`（"2.0"），`created_at` 取毫秒时间戳；两处写点收敛到同一构造。
- **兼容性**：存量 `"2"` + 秒的子代理 journal 读取不受影响（`detect_version` 对未识别版本走空迁移链原样读；`created_at` 不参与 replay reducer）。
- **影响面**：§4.3——envelope 口径修正属拼写统一，不构成记录族形状改写，不递增 wire 版本（ADR-008 纪律）。

### ADR-017 恢复路径的就地折叠与单一折叠结果（SDR-005 的技术形状，2026-10-15）

- **背景与动机**：实测重开大会话出现秒级以上等待与数十 GB 量级瞬时内存尖峰（调查报告 `docs/specs/reports/rust-v3-session-cold-open-perf-20261015.md`，代码事实见 context §9）。三个叠加成因——重放成本随记录数超线性、同一记录流在一次重开内被重复折叠、记录流加载期间多份全量数据驻留——均不改变恢复语义，纯属性能债。
- **决策**：
  - **就地折叠**：折叠状态机提供就地应用接口（状态可变、逐条演进）；既有纯函数接口保留为"复制+就地应用"的薄包装，兼容既有调用方与属性测试。折叠语义不变——同一记录流折叠结果与改造前逐字段等价（验收标准）。
  - **单一折叠结果**：一次重开内，主日志的折叠只执行一次；转向缓冲、任务通知对账等只读消费面复用该次折叠结果，不各自重放。快照存在时，只读消费面优先走"快照 + 增量折叠"，无快照时共享同一次全量折叠。
  - **流式加载**：记录流按行流式解析，消灭"原文行 → 解析树 → 强类型记录"的多份全量驻留；转换接口按值消费，不再为借用而深复制整条记录。
  - **子代理懒重放的执行遵从**（ADR-006 恢复时序的落地承诺，非新决策）：会话就绪只等待主日志折叠；子代理记录流不预载，其上下文在续作/查看时按需折叠，重建记忆完整。就绪路径保留两件轻量必需品：身份注册表（元数据来源）与**回合标识上界扫描**（扫每份子代理记录流的回合类记录、不折叠——防重启后回合标识重铸触发既有重复检测告警的硬性前置）。
- **否决的替代**：折叠状态机整体改为持久化数据结构或引用计数的消息载荷（改动类型面并波及快照序列化与 schema 生成，为一个性能问题引入全局类型污染）；子代理并行预折叠（抬高峰值而非摊平，且绝大多数子代理永不被再次使用）；仅提高检查点频率（不治降级分支，且子代理记录不在检查点覆盖内）。
- **影响面**：§4.4（降级分支有界性）；ADR-006（懒重放的执行遵从）；需求 SDR-005 / US2.1；非功能域 E2；执行计划与验收见本域 ROADMAP。

### ADR-018 归档存储管理域对存储契约的扩展（2026-10-23，回写登记）

> 本条为跨域回写登记（治理规则："需求/设计变更必须写回被修改文档本身"）。需求的决策记录与完整技术形状见 [session-retention-architecture.md](session-retention-architecture.md)（其 ADR-006 为本条的对应指针）。

- **背景与动机**：归档会话磁盘占用持续增长且无回收机制，新立的会话归档存储管理域（自动压缩 + 手动删除）需要扩展本域的四项资产。
- **登记的扩展**（所有权与写入方归该域，存储布局与版本链仍归本域）：
  - **`state.json` 字段集（§4.1 表）**：新增可选字段 `archivedAt` / `compressed` / `compressedAt` / `preCompressedSize`——归档时点的起算事实、压缩态标记、压缩时间与压缩前体积。时间字段沿用双拼法规则；老版本读取端按"不认识的字段透传保留"。
  - **会话索引 schema（§5，本域 ADR-002 管辖）**：新增 `archived_at` / `compressed` / `compressed_at` 列（行从磁盘派生、可重建，自愈规则不变）。
  - **附件存储删除语义（本域 ADR-007 的影响面修订）**：ADR-007 原表述"删除会话不连带清理附件"修订为"删除会话不**无条件**清理附件——条件联动回收（引用计数归零 + 老化窗口）由归档存储管理域定义并仅随删除动作触发"；全局内容寻址、跨会话共享的存储形态本身不变。
  - **新增原语**：会话目录级 `lock` 文件 + OS advisory lock（跨进程互斥原语，进程崩溃即释放）；`wire.jsonl.gz` 压缩形态与双形态读（`JsonlAppendLog` 读契约扩展）。磁盘形状是压缩态唯一判定真值源。
- **否决的替代**：字段所有权归本域（写入时机全是对方域动作，语义割裂）；不回写、由对方文档单向声明（治理规则禁止）。
- **影响面**：§4.1 字段表、§5 索引 schema、ADR-007 影响面、§8 崩溃安全原语清单；消费方：会话归档存储管理域全部批次。
